# عقد G6-A — التقويم الشهري التشغيلي المشتق من الطلبات

**الحالة:** DRAFT / G6-A — يحتاج مراجعة PR قبل الدمج.
**النطاق:** قراءة شهرية هاتفية لمواعيد تسليم الطلبات التشغيلية المحلية الموجودة، مشتقة من سجلات المواعيد الحالية دون إنشاء سجل جديد أو تغيير سجل سابق.

## 1. سؤال القرار

يساعد هذا العقد صاحب المشروع على الإجابة عن السؤال التالي:

> **ما الأيام التي تحمل التزامات طلبات قائمة هذا الشهر، وأيها متأخر أو مزدحم أو يفتقد وقتًا معروفًا؟**

هذه قراءة تشغيلية للتنقل والمراجعة، وليست تقويمًا عامًا أو حجزًا أو وعدًا بالتوافر.

## 2. مصدر الحقيقة ومسار القراءة

يمر التدفق عبر:

```text
React UI → ScheduleService → PrototypeLocalStore → IndexedDB
```

يقرأ `ScheduleService` سجلات `ScheduleEntry` والطلبات المرتبطة بها وتفضيل `dailyScheduleCapacityMinutes` الموجود أصلًا. لا يتصل React بـIndexedDB، ولا يحفظ هذا العقد `MonthOverview` أو أي بيانات شهرية جديدة.

الموعد يدخل القراءة عندما يكون وضعه `scheduled` أو `postponed` ويكون الطلب المرتبط غير `delivered` أو `settled` أو `cancelled`، وفق قواعد `/schedule` الحالية. المواعيد المكتملة أو المغلقة لا تعود التزامات تشغيلية نشطة في الشهر، حتى لو احتفظ التخزين بتاريخها.

## 3. عقد الشهر والزمن المحلي

حقل الشهر هو `YYYY-MM`، مثل `2026-08`، ويُفسر في المنطقة الزمنية المحلية التشغيلية `Asia/Amman`. لا يستخدم التجميع تاريخ UTC الخام لتحديد اليوم أو الشهر الظاهر للمستخدم.

يرفض Application الشهر غير المطابق للصيغة أو خارج الأشهر `01` إلى `12`. تعرض الواجهة اسم الشهر بالعربية، بينما يبقى مفتاح الشهر الداخلي والأرقام الرقمية بصيغة ASCII/LTR.

## 4. نموذج القراءة

يعيد `ScheduleService.monthOverview(month)` قيمة `MonthOverview` التالية:

| الحقل | المعنى |
|---|---|
| `month` | مفتاح الشهر المطلوب بصيغة `YYYY-MM`. |
| `days` | يوم لكل تاريخ في الشهر، بترتيب زمني، بما في ذلك الأيام التي لا تحمل موعدًا. |
| `scheduledCount` | عدد المواعيد النشطة في نطاق الشهر. |
| `overdueCount` | عدد المواعيد النشطة في الشهر التي يسبق تاريخها اليوم المحلي عند القراءة. |
| `scheduledMinutes` | مجموع مدد المواعيد التي لها وقت ومدة معروفان فقط. |
| `unknownTimingCount` | عدد مواعيد الشهر التي يفتقد وقتها أو مدتها؛ لا يتحول إلى دقائق صفرية معروضة للمستخدم. |
| `dailyCapacityMinutes` | السعة اليومية المعلنة الموجودة أصلًا، أو `null` إن لم يحددها المستخدم. |

كل عنصر في `days` يحمل:

| الحقل | المعنى |
|---|---|
| `date` | التاريخ المحلي `YYYY-MM-DD`. |
| `items` | المواعيد النشطة لذلك اليوم، مرتبة وفق ترتيب الجدول الحالي. |
| `scheduledMinutes` | دقائق ذلك اليوم المعروفة فقط. |
| `unknownTimingCount` | عدد مواعيد اليوم ذات الوقت أو المدة غير المعروفين. |
| `conflictCount` | عدد المواعيد الداخلة في تعارض زمني مع موعد آخر في اليوم نفسه، وفق قاعدة التعارض الحالية. |
| `overCapacity` | `true` فقط عندما تكون السعة اليومية معلنة وتتجاوزها الدقائق المعروفة؛ لا تمنع الحفظ ولا تعني أن بقية الوقت متاح. |

## 5. قواعد التجميع والدلالة

يستخدم التعارض تقاطع فترتين معلومتين في اليوم نفسه. لا يدخل الموعد المجهول الوقت أو المدة في حساب التعارض أو الدقائق المعروفة، لكنه يظهر صراحة كـ«وقت غير محدد».

يستخدم التأخر معنى `ScheduleService` الحالي: موعد نشط تاريخه قبل اليوم المحلي عند لحظة القراءة. لا يستنتج العقد سبب التأخر، ولا يحوله إلى خسارة أو حالة مالية.

إذا لم توجد مواعيد نشطة في الشهر، تكون القراءة فارغة (`scheduledCount = 0` و`scheduledMinutes = 0` مع `unknownTimingCount = 0`). معنى الفراغ هو **لا توجد مواعيد تشغيلية مسجلة للمتابعة في هذا الشهر**؛ لا يجوز عرضه كـ«متاح بالكامل» أو كقدرة صفرية/كاملة مخترعة.

إذا كان الشهر يحتوي مواعيد مجهولة الوقت فقط، يبقى `scheduledCount` موجبًا و`scheduleMinutes` مساويًا لصفر داخليًا، لكن الواجهة تسمي الدقائق «دقائق معروفة» وتعرض عدد المجهول نصيًا بدل الإيحاء بأن اليوم بلا عمل.

## 6. سلوك الواجهة المسموح

تعرض `/schedule` شبكة شهرية RTL phone-first مع انتقال واضح إلى الشهر السابق والتالي، وعنوان شهر عربي، وتمييز يوم اليوم بعلامة نصية/شكلية لا تعتمد على اللون وحده. تعرض الخلية ملخصًا صغيرًا: عدد المواعيد، وقتًا معروفًا إن وجد، وحالة تحذير أو مجهول عند وجودها دون حشر أسماء الطلبات.

الضغط على خلية يوم يفتح قراءة اليوم داخل نفس السطح أو يقود إلى تفاصيل المواعيد القائمة. لا ينشئ الضغط موعدًا ولا يفتح محررًا جديدًا. لا يغير التنقل الشهر أو اليوم أو حالة الطلب أو أي حقيقة مالية.

## 7. ما لا يغطيه العقد

لا يعرّف هذا العقد التكرار أو القوالب المتكررة أو المهام العامة أو الإشعارات أو cron أو Service Worker جديدًا أو Google Calendar أو iCal أو WhatsApp أو الحجز الذاتي أو الموارد والموظفين أو قدرة المواد أو نوافذ زمنية جديدة. ولا يغير سياسة القدرة اليومية القائمة.

لا يضيف هذا العقد schema أو export/import أو IndexedDB مباشرًا أو تخزينًا شهريًا. إذا احتاج التنفيذ إلى migration أو export/import أو معنى قدرة جديد، يتوقف الوكيل ويطلب قرارًا مستقلًا بدل توسيع G6-A.

لا يضيف هذا العقد أثرًا على السعر أو الكاش أو الذمة أو التكلفة أو `CostSnapshot` أو نتيجة الطلب أو G5. تغيير الموعد نفسه يظل محكومًا بعقد الموعد الحالي، بسبب وسجل تاريخي؛ G6-A قراءة وتنقل فقط.

## 8. معايير القبول

يجب أن تثبت الاختبارات والـQA أن شهرًا فيه يوم بوقت معروف ويوم بوقت مجهول يفرّق بينهما صراحة، وأن التعارض وتجاوز السعة يظهران كتحذير دون منع أو تعديل، وأن الشهر الفارغ لا يدعي التوافر، وأن الانتقال لا يغير سجلات، وأن الضغط على اليوم يعرض مواعيده الصحيحة، وأن السطح يعمل RTL وLight/Dark على عروض 360 و390 و430 بكسل دون أن يحجب BottomNav محتوى اليوم.
