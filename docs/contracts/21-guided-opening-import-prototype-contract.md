# عقد الاستيراد الافتتاحي الموجّه — Micro G8.2

**الحالة:** `CURRENT / G8.2 CONTRACT GATE`
**النطاق:** إدخال موقف افتتاحي محدود لمشروع قائم في Prototype المحلي، بعد تحقق الاستعادة المحلية في G8.1.

## 1. سؤال القرار

يريد صاحب مشروع قائم أن يبدأ من موقف معروف بتاريخ محدد دون تحويل دفتره التاريخي أو ملف Excel إلى أحداث مالية مختلقة. يجيب هذا العقد عن سؤال واحد: **ما الذي يمكن إدخاله كبداية محدودة وقابلة للتفسير، وما الذي يجب أن يبقى خارج السجل حتى يملك مصدرًا ومعنى؟**

## 2. أقل نطاق آمن

يقبل المعالج ملف JSON افتتاحيًا صريحًا، لا ملفًا تاريخيًا شاملًا. يحتوي الملف على:

| المجال | ما يقبل | المعنى |
|---|---|---|
| `profile` | اسم النشاط فقط، مع `currency: JOD` و`activityType: custom_craft` في النسخة الحالية | تعريف محلي للنشاط، وليس إثباتًا ماليًا؛ القيد `custom_craft` حد Prototype لا إعلان أن مشاريع مختلطة مدعومة في الاستيراد |
| `cashWallets` | محفظة أو أكثر، باسم ونوع، مع رصيد افتتاحي غير سالب | كاش موجود في تاريخ البداية كما أعلنه المالك |
| `materials` | مادة وكمية افتتاحية وقيمة افتتاحية اختيارية معلنة | موقف مخزون افتتاحي، لا استهلاك ولا COGS |
| `openingNotes` | ملاحظة مصدر عامة اختيارية | توضح ما يبقى غير معروف |

كل قيمة افتتاحية تتضمن `source`, `knowledge`, `occurredOn`, و`note`. المبلغ بوحدة JOD الصغرى الصحيحة، والكمية بوحدة milli داخلية صحيحة. لا تقبل الواجهة أرقامًا محلية غير قابلة للتفسير؛ تستخدم أرقام ASCII/LTR.

## 3. ما يمر عبر النظام

بعد التحقق الكامل، يحول Application Service كل محفظة إلى `CashContinuityService.openWallet` بعملية idempotency مستقلة، وكل مادة إلى مسار Domain/Application المخزون الافتتاحي بعملية idempotency مستقلة. لا تتصل React مباشرة بـIndexedDB. تتم الكتابة كوحدة واحدة أو لا تتم؛ إذا لم يدعم المسار الحالي commit ذريًا متعدد المجالات، يرفض المعالج الملف قبل الكتابة بدل تنفيذ نصفه.

الاستيراد لا ينشئ طلبًا أو اتفاقًا أو قبضًا أو مصروفًا أو دينًا أو ربحًا أو نتيجة فترة. رصيد الكاش الافتتاحي ليس مبيعات، وقيمة المادة الافتتاحية ليست COGS، والملاحظة ليست حدثًا ماليًا.

## 4. ما يرفضه المعالج

يرفض المعالج Excel/CSV أو JSON غير المعرّف، أي سجل تاريخي متعدد الأحداث، تواريخ بلا مصدر، مبالغ سالبة أو كسرية، عملة غير JOD، تصنيفًا متخمنًا، رصيدًا أو دينًا مجهول المصدر، قيمة لا يمكن ربطها بمحفظة/مادة، ملفًا ناقصًا أو تالفًا، نسخة غير مدعومة، أو ملفًا يحاول تعديل سجل موجود. لا يحول الكاش إلى إيراد أو رأس المال إلى مبيعات، ولا يستنتج دينًا أو التزامًا من وصف حر.

## 5. سلامة الحالة وإعادة المحاولة

تبدأ العملية بـ`preview` لا يكتب شيئًا. لا يحدث `confirm` إلا بعد موافقة صريحة، وبعد التحقق من أن Store فارغ؛ إذا كان Store غير فارغ فالحالة `non_empty_store` ويجب أن يصدّر المستخدم بياناته أو يبدأ استيرادًا جديدًا بقرار صريح خارج هذا العقد. لا توجد كتابة جزئية. لكل عملية مفتاح idempotency ثابت مشتق من `importId` وموضع السجل؛ إعادة المحاولة تعيد النتيجة السابقة ولا تضاعف الأثر.

فشل parsing أو التحقق أو التخزين يترك snapshot الحالي كما هو. لا يستبدل المعالج طلبًا أو Snapshot أو حدثًا موجودًا بصمت، ولا يدمج افتتاحًا فوق تاريخ قائم.

## 6. درجات المعرفة

`known` يعني أن القيمة ومصدرها وتاريخها معلنة. `estimated` يعني أن المالك قدرها صراحة، ولا تصبح حقيقة دقيقة. `needs_review` يعني أن القيمة لا تدخل كسجل قابل للاستخدام حتى يصححها المالك. البيانات الناقصة ليست صفرًا؛ تظهر في تقرير الرفض مع فعل تالٍ واضح.

## 7. حالات القبول الإلزامية

| الحالة | النتيجة المتوقعة |
|---|---|
| ملف صحيح مع Store فارغ | preview ناجح، ثم confirm ذري، وتقرير مقبول لكل سجل |
| ملف ناقص | رفض قبل الكتابة مع أسماء الحقول، وبقاء Store دون تغيير |
| ملف تالف | رفض JSON/البنية قبل الكتابة، وبقاء Store دون تغيير |
| نسخة غير مدعومة | رفض صريح دون محاولة migration تخمينية |
| Store غير فارغ | رفض آمن؛ لا merge أو overwrite صامت |
| إعادة المحاولة | نفس `importId` يعيد النتيجة السابقة، دون أثر مضاعف |
| قيمة ناقصة/مجهولة | رفض القيمة أو إبقاؤها خارج السجل مع `needs_review`؛ لا تحويلها إلى صفر |

## 8. حدود ما يبقى غير معروف

لا يثبت هذا الاستيراد ربحًا سابقًا، أو دينًا سابقًا، أو مصدرًا محاسبيًا للتاريخ، أو كاشًا موزعًا على مبيعات، أو تكلفة بيع، أو ملكية مخزون قانونية. بعد الاستيراد يظل على المالك تسجيل الأحداث الجديدة من لحظتها، ومراجعة أي قيمة تقديرية يدويًا. لا توجد مزامنة أو نقل تلقائي بين الأجهزة.

لا يضيف قرار النواة والـProfiles أي `activityType` أو ملف mixed إلى هذا العقد. أي توسعة للاستيراد لأنشطة متعددة تحتاج نسخة format جديدة، Preview، fixtures، migration متوافقة، وعقدًا يوضح أنها لا تخمن سياقًا أو توزيعًا تاريخيًا.

## 9. بوابة التنفيذ

لا تبدأ واجهة G8.3 قبل دمج هذا العقد وfixtures واختبارات القبول. التنفيذ التالي يجب أن يضيف Application/Domain/LocalStore adapter ومسارًا واضحًا للتقرير، مع export/import versioning صريح واختبارات round-trip، دون تعديل `apps/prototype-web/client/public/__manus__/version.json`.
