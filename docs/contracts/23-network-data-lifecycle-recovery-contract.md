# Micro — عقد دورة بيانات الشبكة والاستعادة N-05

**الحالة:** `CURRENT / EXPANSION E-00 / CONTRACT ONLY`
**المالك:** Manus Agent 1
**تاريخ القرار:** 27 أغسطس 2026

## Major Discussion Points

## 1. سؤال القرار والنطاق

يعالج هذا العقد سؤالًا لا يحل بـ«سنحفظها في السحابة»: **«أي بيانات تنتمي إلى Micro Manage المحلي وأيها تنتمي إلى طبقة الشبكة، وكيف تبقى المسودة والحالة والتاريخ والاستعادة صادقة عند فقد شبكة أو هاتف أو فشل رفع؟»**

هذا العقد لا يقرر مزود قاعدة بيانات أو مزود ملفات أو مدة احتفاظ قانونية. يحدد دورة حياة تمنع فقد المسودات، أو تسريب بيانات، أو تحويل حالة لم تؤكدها جهة خارجية إلى واقع نهائي.

## 2. الحدود بين البيانات المحلية وبيانات الشبكة

| فئة البيانات | موضع الحقيقة | ما يسمح به الربط | ما يمنع |
|---|---|---|---|
| مال Manage وطلبات وسجلات وSnapshot ومخزون وكاش وذمم | محلي في Manage خلال L. | Owner يختار مرجعًا محدودًا أو تسجيل واقعة منفصلًا. | نسخ تلقائي لطبقة الشبكة أو كشفه لمورد/Courier/Admin. |
| مسودة Market/Delivery المحلية | جهاز Owner قبل النشر/الإرسال. | حفظ صريح واستئناف أو حذف من Owner. | اعتبارها منشورة أو مرئية لشخص آخر. |
| احتياج/رد/Quote/Status شبكة عند A | طبقة الشبكة المتصلة. | Attention محلي أو إشعار ملخص عند نجاح المزامنة. | إنشاء أثر Manage أو اعتبار cached copy الحقيقة الوحيدة. |
| Listing وMedia | مورد وطبقة شبكة بعد الموافقة. | عرض عام لما وافقت عليه Moderation فقط. | رابط عام قبل النشر أو ملف بلا مالك/حالة. |
| Audit | طبقة الشبكة عند A. | ملخص محدود لصاحب السجل أو Admin المخول. | حذف صامت أو تصدير واسع بلا Policy. |

## 3. حالة السجل بدل وهم المزامنة

| الحالة | ما تعنيه | ما يراه المستخدم | الفعل التالي |
|---|---|---|---|
| `local_draft` | موجود على الجهاز فقط. | «مسودة على هذا الجهاز». | تعديل، متابعة، حذف، أو إرسال صريح عند التفعيل. |
| `pending_submission` | اختار المستخدم الإرسال ولم يتأكد الخادم بعد. | «بانتظار الإرسال؛ لا يراه الطرف الآخر بعد». | انتظار، إعادة محاولة بالمفتاح نفسه، أو إلغاء حيث يسمح العقد. |
| `submitted` | قبلت طبقة الشبكة الأمر وحددت مرجعًا. | وقت وحالة الجهة التالية. | انتظار رد أو فتح سجل. |
| `sync_failed` | لم يثبت وصول العملية. | سبب مفهوم ومسودة لا تضيع. | مراجعة الاتصال أو إعادة المحاولة. |
| `needs_review` | تعارض/بيانات ناقصة/تغيير لا يمكن اختياره آليًا. | ما الذي يحتاج قرارًا ومن أي طرف. | مراجعة صريحة؛ لا حل بآخر كتابة. |
| `closed` أو `archived` | انتهى المسار مع تاريخ وسبب. | ملخص قابل للقراءة بحد الدور. | فتح التاريخ أو بدء مسار جديد. |

هذه الحالات مستقبلية لعقد التطبيق المتصل. في تجربة L لا تدعي الواجهة `submitted` أو اتصالًا؛ تستخدم مسودات ومحاكاة مصنفة بوضوح.

## 4. التكرار والترتيب والتاريخ

كل عملية إنشاء/إرسال/قبول/نشر/تحديث حالة/رفع وسائط في طبقة الشبكة تحصل على `idempotency_key` أو معرف عملية ثابت. تعيد المحاولة النتيجة نفسها أو تبين التعارض؛ لا تضاعف Need أو Response أو Quote أو Status Event. يحمل الحدث فاعلًا وWorkspace ووقت عميل/خادم عند وجودهما ومصدره وسبب الاستثناء.

إذا وصل Event متأخرًا أو كان انتقاله لا يطابق الحالة الحالية، لا يعاد ترتيب التاريخ بصمت. ينتقل السجل إلى `needs_review` أو يرفض الانتقال مع سبب قابل للفهم. لا تستخدم الساعة المحلية وحدها لترتيب حقيقة مشتركة عند A.

## 5. الاستعادة والحذف والاحتفاظ

قبل A، يستخدم Owner Export/Import المحلي الحالي ضمن Manage وفق عقوده. لا يحمل Export المحلي وعدًا باستعادة Market/Delivery المتصلة لاحقًا، ولا يصبح ملف Export وسيلة دعوة أو مشاركة مع مورد/شركة.

عند التفعيل، توثق سياسة منفصلة ومراجعة قانونية محلية: ما الذي يحتفظ به النظام، مدة ذلك، من يستطيع طلب حذف/تصحيح، ما الذي يبقى كحد أدنى من Audit، وكيف يصدّر الشخص بياناته ضمن نطاقه. لا يقرر هذا العقد رقم أيام أو حقًا قانونيًا غير متحقق.

فقد الهاتف أو تغيير الحساب أو تعطيل جهة لا يحذف بيانات Network تلقائيًا. يعرض النظام مسار استعادة يثبت الهوية أولًا، ويوقف الوصول أو العضوية عند الحاجة مع حفظ سجل قرار مناسب. لا يغير ذلك أي سجل مالي محلي في Manage.

## 6. ما لا يشمله العقد

لا مزامنة Manage الكاملة، ولا offline-first متعدد الأجهزة، ولا CRDT، ولا نسخ احتياطي تلقائي، ولا مزود ملفات، ولا حذف قانوني مفصل، ولا Analytics أو AI. أي اختيار تقني أو تغير في `localSchemaVersion` أو `localExportVersion` يحتاج قرار Migration/Export/Import منفصلًا قبل الكود.

## 7. سيناريوهات القبول

| الحالة | النتيجة المطلوبة |
|---|---|
| ينقطع الاتصال بعد ضغط Owner «إرسال» | المسودة وحالة pending/failed واضحتان؛ لا يدعي النظام أن المورد رآها. |
| يعيد Owner الطلب نفسه | لا يتكرر السجل أو Attention بسبب المفتاح نفسه. |
| يصل تحديث Courier متأخرًا | لا يعيد كتابة تاريخ مكتمل أو يخفي استثناء؛ يرفض/يراجع بوضوح. |
| يصدّر Owner Manage المحلي | لا تظهر بيانات شبكة حساسة أو صلاحيات كأنها جزء من Export بلا عقد صريح. |
| يفشل رفع صورة | لا تظهر للعامة ولا يضيع وصف Listing أو قرار المراجعة. |
| يطلب Supplier حذف/إيقاف Listing | يتغير العرض وحالته مع سجل، ولا تحذف تعاملات تاريخية أو Audit بصمت. |
