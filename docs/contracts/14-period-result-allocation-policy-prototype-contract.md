# Micro — عقد سياسة نتيجة الفترة الأوسع والمصاريف المشتركة G3

**الحالة:** `CURRENT / G3-A CONTRACT BEFORE IMPLEMENTATION`
**المالك:** Manus Agent 1
**تاريخ القرار:** 23 أغسطس 2026

## 1. سؤال القرار والنطاق

يعالج هذا العقد سؤال صاحب المشروع: **«ما النتيجة التي سجّلتها لهذه الفترة بعد أن أدخلت المصروفات التي تخص المشروع، وما الذي يمنع اعتبارها مكتملة؟»**

لا يحوّل Micro إلى دفتر أستاذ قانوني، ولا يعرض «صافي ربح نهائي»، ولا يعيد تسعير طلبات قديمة، ولا يوزع مبلغًا مشتركًا على طلب أو منتج لمجرد وجوده. يوسّع فقط قراءة نتيجة الفترة الحالية لتكشف بوضوح كيف دخل المصروف التشغيلي إلى الفترة، وما إذا كانت حصة مشروع مشتركة مسجلة، وما الذي ما زال غير معروف.

> **قرار حاكم:** في هذه المجموعة، «تحميل المصروف المشترك» يعني إدخال **حصة المشروع المسجلة** إلى نتيجة الفترة مرة واحدة. لا يعني توزيعها على طلب أو منتج أو وحدة أو ساعة.

## 2. ما يدخل وما لا يدخل

| البند | يدخل في نتيجة الفترة الأوسع | لا يحدث في هذه المجموعة |
|---|---|---|
| طلب مسلّم بنتيجة `final` | إيراده وتكلفته المباشرة المعترف بها من Snapshot | لا تتحول حركة مادة فعلية إلى COGS تلقائيًا |
| مصروف `relationship: project` | يدخل مرة واحدة حسب `occurredOn` | لا يُحمّل على اسم عمل أو طلب من دون عقد لاحق |
| مصروف `relationship: shared` | يدخل فقط بالمبلغ المسجل باعتباره حصة المشروع | لا يدخل إجمالي فاتورة البيت، ولا تنشأ نسبة مخفية |
| مصروف مستحق ثم تسديده | يدخل عند الاستحقاق مرة واحدة | لا يضيف التسديد مصروفًا ثانيًا |
| حدث قديم بلا سياق | لا يحذف ولا يفسر تلقائيًا؛ يبقى مبلغًا مسجلًا وحدًا معرفيًا | لا يعامل كصفر أو «للمشروع» افتراضيًا |
| رأس المال والسحب والتحويل والافتتاح | لا تدخل النتيجة | لا يعاد تصنيفها مصروفًا أو مبيعات |

## 3. سياسة الحصة المشتركة

### 3.1 نقطة الإدخال

يبقى `FinancialEvent.amountMinor` في المصروف المشترك هو **حصة المشروع فقط**، كما في عقد التصنيف G1. إذا كانت فاتورة البيت 50.00 د.أ وحصة المشروع التي عرفها المستخدم 15.00 د.أ، تسجل الواقعة التشغيلية هنا بـ15.00 د.أ فقط. لا تحفظ المجموعة الثالثة إجمالي الفاتورة المنزلية، ولا تسجل كاشًا لم يدفعه المشروع.

هذه قاعدة متعمدة لمنع خلط مصروف البيت بمصروف المشروع ولمنع أن يصبح التخزين المحلي ناقلًا لدفتر عائلي غير مكتمل. إذا لم يعرف المستخدم الحصة، لا يسجل 50.00 ولا 0.00؛ يبقى السؤال ناقصًا حتى يحدد حصة أو يترك أثر النقص ظاهرًا.

### 3.2 مصدر الحصة ودرجة المعرفة

يعتمد تنفيذ G3-B على امتداد اختياري متوافق مع السجل القديم داخل `OperatingExpenseContext` للمصروف المشترك فقط:

```ts
type SharedProjectShareBasis =
  | "agreed_fixed_share"
  | "owner_estimate"
  | "needs_review";

type SharedProjectShare = {
  basis: SharedProjectShareBasis;
  note: string | null;
};
```

لا يدخل هذا الامتداد في أحداث `relationship: project`. وجوده يوضح **كيف عرف المستخدم أن هذا المبلغ هو حصة المشروع**، لكنه لا ينشئ معادلة نسبة، ولا يغيّر مبلغ الحدث أو تاريخ وقوعه. تطابق المعرفة الإلزامي هو:

| أساس الحصة | المعرفة المسموحة | معنى النتيجة |
|---|---|---|
| `agreed_fixed_share` | `known` | حصة ثابتة معلنة للمشروع؛ تدخل النتيجة المسجلة، مع بقاء حدود Prototype العامة |
| `owner_estimate` | `estimated` | تدخل مرة واحدة، لكن سطح النتيجة `incomplete` ويذكر أنها تقديرية |
| `needs_review` | `needs_review` | تدخل مرة واحدة، لكن سطح النتيجة `incomplete` ويظهر فعل المراجعة |

تقبل الأحداث القديمة والمصروفات المشتركة التي لا تحمل هذا الامتداد، لكن القراءة تعرضها **«حصة مشتركة بلا مصدر موثق»** وتصبح النتيجة `incomplete`. لا تهاجر البيانات القديمة إلى قيمة مفترضة.

### 3.3 حد التوزيع

`purpose: order` أو `product` يصف ما قصده المستخدم عند تسجيل المصروف فقط. لا يجوز له في هذه المجموعة أن يغيّر `recognizedCostMinor`، أو `CostSnapshot`، أو هامش اسم العمل، أو فرق مادة الطلب، أو مؤشر التغطية. التوزيع على منتج/خدمة، إن ثبتت الحاجة إليه، يأتي بعد الكتالوج في المجموعة الرابعة بعقد مستقل ومصدر أساس قابل للمراجعة.

## 4. نموذج قراءة نتيجة الفترة الأوسع

تظل النتيجة مشتقة لحظة القراءة من الطلبات والأحداث المحفوظة، ولا تحفظ كحدث مالي جديد:

```text
إيراد طلبات مسلّمة final
- تكلفتها المباشرة المعترف بها في Snapshot
- مصروف مشروع مباشر مسجل
- مصروف عام/فترة مسجل
- حصة مشروع من مصروف مشترك مسجلة
= نتيجة الفترة الأوسع المسجلة
```

يعرض سطح G3-B التفصيل التالي بجانب الناتج، بدل رقم مجمل مضلل:

| الحقل | التعريف |
|---|---|
| `projectExpenseMinor` | مصروفات `relationship: project` في الفترة |
| `sharedProjectExpenseMinor` | حصص المشروع المشتركة المسجلة في الفترة |
| `legacyUnclassifiedExpenseMinor` | مصروفات قديمة بلا سياق؛ تعرض منفصلة ولا يختفي أثرها |
| `sharedEstimatedCount` | عدد الحصص المشتركة التقديرية أو التي تحتاج مراجعة |
| `legacyUnclassifiedExpenseCount` | عدد مصاريف الفترة بلا سياق |
| `status` | `recorded_only` أو `incomplete`، ولا توجد حالة «نهائية» |
| `reasons` | أسباب معرفة قابلة للقراءة وفعل تالٍ محدد |

لأن المصروف القديم حقيقي ومسجل لكن سياقه مجهول، يبقى ضمن مجموع المصروف التشغيلي المسجل حفاظًا على استمرارية السجل؛ إلا أن التفصيل و`status: incomplete` يمنعان اعتباره مكافئًا لمصروف مصنف ومعروف.

## 5. الاختيارية وعدم كسر النظام

المشروع الذي لا يملك مصروفًا مشتركًا لا يرى إعدادًا إلزاميًا جديدًا؛ يستمر بمصاريف `project` كما هي. المشروع الذي لا يعرف الحصة لا يُمنع من استخدام الكاش أو الطلب أو المورد أو المخزون، لكن Surface النتيجة يذكر بدقة أن الصورة ناقصة بالنسبة إلى السؤال المالي المتأثر. وضع أساس الحصة خيار يظهر فقط مع `relationship: shared` ولا يحوّل كل مستخدم إلى استبيان محاسبي.

## 6. التخزين والتاريخ

يحتاج G3-B إلى schema/export migration صريحة لأن سياق المصروف المخزن سيمتد بحقل اختياري جديد. يجب أن تبقى migration آمنة للأحداث القديمة: لا حذف، ولا تعديل مبلغ، ولا إنشاء أساس افتراضي. وتبقى واجهة React بعيدة عن IndexedDB؛ يمر الإدخال والقراءة عبر `ProjectFinancialService` و`PrototypeLocalStore`.

## 7. سيناريوهات القبول

| الحالة | النتيجة المطلوبة |
|---|---|
| مصروف مشروع معروف 20.00 د.أ | يظهر ضمن `projectExpenseMinor` مرة واحدة، وتبقى النتيجة مسجلة إذا لم يوجد نقص آخر |
| حصة كهرباء متفق عليها 15.00 د.أ | تدخل مرة واحدة ضمن `sharedProjectExpenseMinor`، ويظهر أساسها الثابت، ولا تدخل هامش أي طلب |
| حصة إنترنت تقديرية 8.00 د.أ | تدخل مرة واحدة، لكن `status: incomplete` ويظهر أنها تقديرية |
| مصروف مستحق 12.00 د.أ ثم تسديده | يظهر المصروف 12.00 مرة واحدة في الفترة الصحيحة؛ التسديد يغير الكاش والذمة فقط |
| مصروف قديم بلا سياق 10.00 د.أ | لا يحذف ولا يصنف تلقائيًا؛ يظهر منفصلًا ويجعل النتيجة ناقصة |
| حصة مشتركة بلا مصدر توثيق | تبقى ضمن الإجمالي، مع سبب «مصدر الحصة غير موثق»؛ لا تفترض `known` |
| تغيير سياق مصروف عبر تعديل تاريخي | غير مسموح؛ التصحيح يحتاج عكسًا/حدثًا موثقًا خارج هذه الشريحة |
| حركة استهلاك مادة للطلب | لا تعدل النتيجة الأوسع أو `CostSnapshot` بصمت |

## 8. خارج الشريحة

لا تشمل G3 ضرائب، إهلاك، قروض، أصول، مرتجعات، COGS فعلي، تحميلًا حسب وحدات أو ساعات أو إيراد، توزيعًا على منتج/طلب، تغيير Snapshot، أو صافي ربح قانوني. يبقى مؤشر التغطية الحالي محافظًا، ويعاد تقييمه في المجموعة الخامسة مع سياسة هامش مساهمة مستقلة.
