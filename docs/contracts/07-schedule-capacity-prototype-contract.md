# عقد الموعد والقدرة — Prototype

**الحالة:** CURRENT / Slice F.  
**النطاق:** موعد تسليم طلب محلي، يوم ووقت ومدة، وتحذير تعارض وقدرة؛ لا حجوزات خارجية ولا إدارة فريق ولا تذكير خلفي.

## القاعدة

موعد الطلب حالة تشغيلية مستقلة. تعديله أو إكماله لا يغير السعر أو الكاش أو الذمة أو نتيجة الفترة. يظهر الوقت والمدة فقط عندما يعرفهما المستخدم؛ غيابهما يعني **وقت غير محدد**، لا مدة صفرية ولا توافرًا كاملًا.

| البند | عقد Prototype |
|---|---|
| اليوم | `scheduledFor` بصيغة `YYYY-MM-DD` محلية في `Asia/Amman`. |
| الوقت والمدة | زوج اختياري: `scheduledTime` بصيغة `HH:mm` و`durationMinutes` من 15 إلى 720، بمضاعفات 15. لا يحفظ أحدهما دون الآخر. |
| التعارض | يتداخل موعدين عند تقاطع فترتين معلومتين في اليوم نفسه. هو تحذير ظاهر، لا حظر للطلب ولا استنتاج لعدم القدرة. |
| القدرة اليومية | اختيار محلي صريح بالدقائق. إذا لم يحدده المستخدم، يعرض Micro وقتًا مجدولًا فقط ولا يقرر ضغط القدرة. إذا تجاوزه، يظهر تحذير ولا يمنع الحفظ. |
| التعديل | تغير اليوم يتطلب سببًا. تغير الوقت أو المدة يسجل حدث `timing_changed` مع السابق والجديد. لا يمحى سجل الموعد. |
| الإكمال | تسجيل تسليم الطلب يكمل موعده التشغيلي تلقائيًا وبشكل idempotent. فشل مزامنة الموعد لا يلغي حقيقة التسليم؛ يعاد التوفيق عند قراءة الجدول. |

## ما تعرضه الواجهة

يعرض `/schedule` اليوم والقادم والمتأخر، ثم صفًا أسبوعيًا من سبعة أيام. كل يوم يبين عدد المواعيد والوقت المعروف المحجوز، ويظهر التعارض أو ضغط السعة بالنص والرمز، لا باللون وحده. لا يبنى عرض شهر؛ لا توجد بيانات كافية فيه لتقديم قرار أفضل من اليوم والأسبوع.

## ترحيل البيانات والاستيراد

ترقي قاعدة البيانات المحلية إلى schema 8. الموعد القديم ينتقل صراحة إلى `scheduledTime: null` و`durationMinutes: null`، وتملأ حقول تاريخ الأحداث الجديدة بـ`null`. يتطلب ملف التصدير الجديد version 4؛ ملف version 3 لا يستورد بصمت لأن عقد الموعد تغير.

## حدود مؤجلة

التكرار، النوافذ الزمنية، الموارد المتعددة، قدرة المواد، حجز العميل الذاتي، Google Calendar، الإشعارات الخلفية، والـdispatch خارج Prototype. لا تعني علامة التعارض أن Micro يعرف كل وقت المالك أو كل موارده.
