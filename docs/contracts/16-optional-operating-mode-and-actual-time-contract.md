# Micro — عقد وضع التشغيل الاختياري والوقت الفعلي للطلب G4-B

**الحالة:** `CURRENT / IMPLEMENTED AND MERGED ON BRIDGE — PR #108`
**المالك:** Manus Agent 1
**تاريخ القرار:** 23 أغسطس 2026

## 1. سؤال القرار

يعالج هذا العقد سؤالين منفصلين لكن متكاملين:

1. **«كيف ينجز هذا المشروع عمله غالبًا، لكي لا يسألني Micro عن قدرة غير مناسبة؟»**
2. **«هل استغرق هذا الطلب وقتًا مختلفًا عن الوقت الذي خططت له؟»**

لا يقرر وضع التشغيل ما هو صالح ماليًا، ولا يمنع مشروعًا من تسجيل طلب أو كاش أو مادة أو مصروف. ولا يحوّل تسجيل الوقت إلى أجر أو COGS أو نتيجة ربح أو تسعير جديد.

> غياب وضع التشغيل أو وقت فعلي لا يعني صفر وقت أو أن ربحية العمل مكتملة. يحد فقط من دقة المقارنة التي يستطيع Micro عرضها.

## 2. وضع التشغيل المحلي الاختياري

```ts
type OperatingWorkMode = "material_focused" | "time_focused" | "mixed";

type OperatingModePreference = {
  workMode: OperatingWorkMode | null;
  actualTimeTrackingEnabled: boolean;
  updatedAt: string;
};
```

| الاختيار | متى يساعد | ما الذي يغيره |
|---|---|---|
| `material_focused` | حرفة أو طعام أو إعادة بيع يكون فرق المادة أكثر فائدة فيها | يقدّم بطاقة المادة المنفذة على Surface الطلب |
| `time_focused` | خدمة أو عمل يدوي يكون الوقت فيه مؤثرًا | يقدّم تسجيل الوقت الفعلي دون إلزام |
| `mixed` | طلبات فيها مادة وتنفيذ بوقت مؤثر | يظهر مدخلا المادة والوقت بوزن متقارب |
| `null` | المستخدم لا يريد أو لا يعرف الاختيار | لا يكسر أي تدفق؛ تعرض الأدوات عند الحاجة فقط |

تسجل التفضيلات في LocalStore محليًا وتبقى قابلة للتعديل أو المسح. لا تعيد كتابة `activityType` أو السجل التاريخي، ولا تغيّر `CostSnapshot`، ولا تنشئ حدثًا ماليًا، ولا تحول الإعداد إلى استبيان بدء طويل.

## 3. سجل الوقت الفعلي الأدنى

```ts
type ActualTimeRecord = {
  id: string;
  orderId: string;
  minutes: number;
  recordedOn: string;
  note: string | null;
  createdAt: string;
  operationKey: string;
  reversalOfId: string | null;
  reversalReason: string | null;
};
```

| القاعدة | القرار |
|---|---|
| الوقت | عدد صحيح موجب من الدقائق، يظهر بإدخال ASCII LTR؛ لا ساعات عشرية عائمة |
| الربط | يسجل فقط لطلب محلي موجود؛ لا ينشئ فاتورة أو حضور موظف أو calendar event |
| التكرار | يعاد طلب `operationKey` نفسه بنفس السجل بدل تكرار الدقائق |
| التصحيح | لا تعديل أو حذف صامت؛ يسجل عكسًا بدقائق سالبة وبسبب، مرة واحدة فقط |
| الوقت المتعدد | يسمح بمداخل متعددة للطلب نفسه، مثل تنفيذ اليوم وتعديل لاحق |
| الخصوصية | لا يتطلب اسم عامل أو موقع أو تتبع مباشر أو مؤقت يعمل في الخلفية |

## 4. المقارنة المسموحة

تقرأ خدمة Application الوقت المخطط من `order.costSnapshot.time.minutes`، وتجمع فقط سجلات الوقت غير المعكوسة المرتبطة بالطلب:

```text
وقت فعلي مسجل = Σ دقائق سجلات الوقت غير المعكوسة
فرق الوقت = وقت فعلي مسجل − وقت مخطط في Snapshot
```

| الحالة | المعنى للمستخدم |
|---|---|
| `not_recorded` | لا يوجد سجل وقت فعلي؛ ليس معناه صفر دقيقة أو أن العمل لا يحتاج وقتًا |
| `recorded` | يوجد وقت فعلي، ووقت Snapshot معروف |
| `needs_review` | يوجد وقت فعلي لكن وقت Snapshot تقديري أو يحتاج مراجعة |

تظهر المقارنة على صفحة الطلب وضمن مرجع العمل عندما يوجد سجل، بوصفها **«فرق وقت مسجل»**. لا تضرب الدقائق بسعر ساعة جديد، ولا تغير `recognizedCostMinor` أو `recognizedRevenueMinor` أو `directMarginMinor` أو نتيجة الفترة أو الكاش أو الذمم.

## 5. الاختيارية والتوجيه

- لا يظهر نموذج وقت عند كل طلب تلقائيًا. يظهر فعل «سجل وقتًا فعليًا» في الطلب فقط عندما يفعّل المستخدم تتبع الوقت أو يختار وضع `time_focused`/`mixed`.
- يظل الفعل متاحًا بطريقة غير مزعجة للمستخدم الذي لم يحدد وضعه، لأن بعض الحرف تستخدم وقتًا أحيانًا.
- لا يظهر سؤال «لماذا لم تسجل الوقت؟» ولا تحذير يومي؛ تظهر حدود المعرفة عند قراءة هامش مرجع العمل أو عند فحص طلب فيه فرق مادة/وقت.

## 6. القراءة التفسيرية للهامش والهدر والتحميل

يبقى `directMarginMinor` قراءة G4-A الأساسية:

```text
الإيراد المعترف به للطلبات final المرتبطة صراحة
− التكلفة المباشرة المحفوظة في CostSnapshot
= الهامش المباشر المسجل
```

تعرض قراءة مرجع العمل فترة محلية معلنة، وعدد الطلبات `final`، والإيراد والتكلفة والهامش، ثم تفصل الأدلة التالية دون خلطها بالهامش: فرق المادة المنفذة مقابل Snapshot، وفرق الوقت الفعلي مقابل Snapshot، والهدر المرتبط بطلب أو Catalog Item أو Template revision، والهدر العام أو غير المحمل. غياب السجل يظهر `not_recorded` أو `incomplete` أو `needs_review` ولا يتحول إلى صفر.

سياسة التحميل الاختيارية لا تُطبق افتراضيًا، ولا تنشئ كاشًا أو مصروفًا أو COGS أو تعديلًا لـ`CostSnapshot` أو `recognizedCostMinor` أو نتيجة الفترة. الأسس الوحيدة هي `manual_amount` و`per_output_unit` و`actual_time` و`completed_revenue_percentage`. تحمل السياسة فترة ومرجعًا ومصدرًا وسببًا وملاحظة و`idempotencyKey` وحالة وتاريخ نفاذ. إذا نقصت كمية الناتج أو الوقت الفعلي أو الإيراد `final`، تبقى قراءة «الربح بعد التحميل حسب سياستك» غير مكتملة مع فعل تالٍ واضح. تعديل السياسة ينهي النسخة السابقة وينشئ خليفة مؤرخًا غير حاذف.

## 7. سياق الهدر الصريح

يُحفظ الهدر كـ`InventoryMovement` من النوع `waste` مع سياق واحد من خمسة فقط: `order`، أو `catalog_item`، أو `catalog_template`، أو `general_project`، أو `unallocated`. يثبت Application وجود الطلب أو Catalog Item أو Template revision قبل الحفظ، ويهاجر الهدر القديم بلا سياق إلى `general_project` فقط دون تخمين. يظل الهدر قيمة مخزون حقيقية إن كانت الحركة صالحة، لكنه لا يدخل COGS أو المصروف أو الهامش تلقائيًا؛ والعكس يحفظ الأصل والعكس بسبب ومفتاح idempotency.

## 8. ما لا يدخل G4-B

| غير داخل | السبب |
|---|---|
| timesheet لموظف أو حضور أو رواتب | المستخدم الأول فرد واحد، وهذه طبقة موارد بشرية لا سؤال طلب |
| تحويل الوقت إلى أجر أو تكلفة فعلية | يحتاج سياسة أجر مالك/عامل ومصدر سعر ساعة وعقد تكلفة لاحق |
| تعديل Snapshot أو السعر أو الهامش المسجل | يحافظ Snapshot على قرار الاتفاق التاريخي؛ الفرق قراءة تفسيرية فقط |
| تحميل مصروف عام على الوقت أو منتج | يحتاج أساس توزيع معلن وعقد منفصل |
| توصية سعر أو قبول/رفض طلب | الوقت المسجل لا يكفي لإعطاء توصية موثوقة وحده |
| calendar أو قدرة شهرية أو timer خلفي | قدرة تشغيل منفصلة تحتاج Pilot ونمط مواعيد متكرر |

## 9. التخزين والاستعادة

يحتاج G4-B إلى schema/export migration صريحة. الإصدار الحالي لهذا التنفيذ هو schema `25` وexport `16`. تهاجر التفضيلات القديمة إلى `workMode: null` و`actualTimeTrackingEnabled: false`، وتبقى الطلبات القديمة بلا سجلات وقت، ويُطبع الهدر القديم بلا سياق إلى `general_project` فقط. لا تُنشأ سياسة تحميل للبيانات القديمة. يقبل الاستيراد السابق من دون اختراع وقت أو وضع تشغيل أو سياسة، ويشمل export الجديد التفضيل والسجلات والعكس والهدر والسياقات والسياسات. يرفض الاستيراد سجل وقت بلا طلب، أو هدرًا بمرجع مكسور، أو سياسة بلا Catalog Item، أو نطاقًا متداخلًا، أو عكسًا غير متوازن أو سبب عكس مفقود، قبل replacement الذري.

## 10. سيناريوهات القبول

| الحالة | النتيجة المطلوبة |
|---|---|
| مستخدم لا يختار وضع تشغيل | ينشئ طلبًا ويستخدم المال والمادة والكتالوج كما قبل |
| خدمة تختار `time_focused` | يظهر فعل تسجيل الوقت، ولا ينشئ مخزونًا أو سعر ساعة |
| طلب مخطط له 60 دقيقة وسجل فعلي 75 | يعرض فرقًا +15 دقيقة، ولا يغير Snapshot أو هامشًا أو كاشًا |
| سجل 75 دقيقة ثم عكس بسبب خطأ | يعود إلى `not_recorded` إذا لم يبق سجل آخر، مع حفظ الأصل والعكس |
| Snapshot وقت تقديري وسجل فعلي | يعرض `needs_review`، لا `recorded` أو نتيجة نهائية |
| هدر مرتبط بطلب أو مرجع أو قالب أو عام أو غير محمل | يحفظ سببًا وسياقًا؛ يظهر تفسيريًا ولا يخصم من الهامش أو COGS تلقائيًا |
| غياب سياسة تحميل | يعرض الهامش المباشر فقط ولا يختلق ربحًا بعد التحميل |
| كل أساس تحميل من الأسس الأربعة | يحسب فقط من دليله الصريح، ويظهر `incomplete` عند نقصه |
| تعديل سياسة من تاريخ جديد | يحفظ خليفة مؤرخًا ويغلق السابقة دون إعادة كتابة الماضي |
| export/import سابق | يتلقى إعدادات فارغة وسجلات وقت فارغة بلا اختراع |
| إعادة تسجيل بالمفتاح نفسه | لا تضاعف الدقائق أو فرق الوقت |
