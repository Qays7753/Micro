# Micro — عقد Moderation والموافقة والتدقيق A-01

**الحالة:** `CURRENT / EXPANSION E-00 / CONTRACT ONLY`
**المالك:** Manus Agent 1
**تاريخ القرار:** 27 أغسطس 2026

## Major Discussion Points

## 1. سؤال القرار والنطاق

يعالج هذا العقد سؤال الثقة الأدنى: **«من يراجع Listing أو وسيطًا أو بلاغًا، كيف يشرح قراره، وما البيانات التي لا تنتقل إلى طرف آخر إلا بموافقة صريحة؟»**

Admin هنا دور داخلي محدود يحمي جودة النشر والخصوصية. لا يصبح وسيط بيع أو مشغل Delivery أو مديرًا ماليًا لصاحب المشروع. هذا العقد يحدد القرار والسجل والإفصاح؛ لا ينشئ فريقًا أو Queue أو مزود تخزين أو سياسة قانونية مكتملة.

## 2. قرارات Moderation المسموح بها

| الشيء | قرار Admin | المدخل الأدنى | النتيجة الصريحة |
|---|---|---|---|
| `supplier_listing` | approve، changes_requested، reject، pause، archive. | المرجع، القرار، السبب، الفاعل، الوقت. | نشر/عدم نشر ظاهر للمورد وسجل تدقيق. |
| `listing_media` | approve، changes_requested، reject، remove_from_public_view. | المرجع والسبب والسياسة. | لا تصبح عامة أو تزال من العرض العام مع حفظ التاريخ. |
| بلاغ | acknowledge، request_information، restrict، close. | التصنيف والمرجع والسبب والفعل التالي. | لا حكم مخفي ولا وعد بنتيجة تجارية. |

لا يوجد `delete` صامت لListing أو Media بعد فعل حساس. إذا فرضت سياسة إزالة، يبقى Audit Event بالحد الأدنى الذي يحمي الخصوصية ويشرح سبب الحالة والفاعل والوقت.

## 3. الموافقة والإفصاح

| قرار Owner أو Supplier | ما يجب أن يراه قبل التأكيد | أثره | كيف يسحب أو يصحح |
|---|---|---|---|
| نشر احتياج Market | الحقول التي ستصبح مرئية ونطاق المنطقة/الفئة. | يجعل نسخة نشر محددة قابلة للرد. | إلغاء/تعديل ينشئ revision ولا يغير ردودًا سابقة. |
| نشر Listing/وسيط | المحتوى والوسائط والحالة قبل المراجعة. | يسمح لـAdmin بالمراجعة ولا يعني نشرًا تلقائيًا. | سحب/إيقاف/تعديل ثم إرسال مراجعة جديدة. |
| كشف تفاصيل Delivery | Preview بما يراه Courier حسب المرحلة. | يحدد Scope الإفصاح للمهمة فقط. | قبل الحجز يعدل/يلغي؛ بعده يسجل تغييرًا أو استثناءً. |
| تسجيل واقع داخل Manage | المرجع الخارجي فقط والحقول المالية التي سيدخلها Owner. | يربط ملاحظة خارجية بسجل محلي اختياري. | عكس/تصحيح حسب عقد Manage، لا تعديل واقع الشبكة لإخفائه. |

لا تُجمع أرقام هواتف أو عناوين أو صور أو تفاصيل عميل «تحسبًا» للاستخدام. الغرض الأدنى والمرحلة والجهة هي مبرر كل حقل. لا يشارك Admin محتوى حساسًا مع مورد أو Courier إلا إذا كانت السياسة والواقعة تبرران ذلك.

## 4. سجل التدقيق

`network_audit_event` يوثق الأفعال الحساسة، ومنها محاولة وصول مرفوضة، دعوة/عضوية، نشر/سحب Listing أو Media، قرار Moderation، تغيير Scope إفصاح، إرسال/قبول Quote، وتحديث Status استثنائي، وقراءة عضو Courier لبيانات `delivery_scoped` (عنوان أو هاتف) من سجل مهمة يصل إليها بدوره — حدث القراءة يسجل الفاعل والمرجع والوقت دون نسخ محتوى الحقل (تعديل E-12؛ التدقيق مطلب مانع لبوابة A وفق `ACTIVATION-OPERATIONAL-READINESS-AND-SAFETY-GATE.md` §9). يحتوي على فاعل وسياق Workspace وفعل ومرجع ووقت ونتيجة وسبب عند الحاجة؛ لا يحتوي على كلمات مرور أو Tokens أو كامل بيانات مالية محلية.

السجل قابل للقراءة بحدود الدور والسياسة، وغير قابل للحذف أو إعادة الكتابة الصامتة. لا يستخدم لتقييم الناس أو إنشاء نظام نقاط أو مراقبة دائمة؛ غرضه تصحيح المسؤولية وفهم ما حدث عند خطأ أو بلاغ.

## 5. الأخلاقيات والحدود

لا ننشئ بيانات مزيفة لموردين أو شركات أو صور أو تقييمات أو شهادات كي يبدو السوق حيًا. لا نعرض ترتيبًا مدفوعًا أو تفضيلًا تجاريًا أو إعلانًا مموّلًا من دون وسم واضح وسياسة مستقلة. لا تستعمل بيانات Manage المالية أو أرقام العملاء لتوجيه عروض أو إعلانات أو تدريب نموذج أو مشاركة طرف ثالث بلا حاجة وموافقة وسياسة معلنة.

أي إبلاغ عن خطر مباشر أو محتوى غير قانوني أو إساءة يحتاج مسار سياسة/قانون مستقل قبل الإطلاق الحقيقي؛ لا يحسم Agent أو منطق Moderation التلقائي قضية حساسة بلا مراجعة بشرية وسياسة منشورة.

## 6. ما لا يشمله العقد

لا نظام Reviews أو Ratings، ولا آلية فض نزاع، ولا عقد تجاري، ولا سياسة تسعير أو عمولة، ولا KYC، ولا حذف قانوني أو مدة احتفاظ نهائية. هذه تحتاج دليل Pilot ومراجعة قانونية ومحلية قبل التفعيل متعدد الأطراف.

## 7. سيناريوهات القبول

| الحالة | النتيجة المطلوبة |
|---|---|
| Supplier يرسل صورة جديدة | تبقى خاصة/قيد المراجعة ولا تظهر في Owner search قبل الموافقة. |
| Admin يطلب تعديلًا | يرى Supplier سببًا واضحًا وحالة قابلة للإصلاح، ويسجل القرار بتاريخه. |
| Owner يريد Delivery لعميل | يرى Preview للعنوان/الهاتف قبل الإفصاح ويستطيع تعديل/إلغاء المسودة. |
| Owner يقبل Quote | لا يكشف النظام بيانات فوق Scope الموافق عليه، ولا يسجل مالًا. |
| محاولة حذف قرار Moderation | لا تمحو الحدث؛ تستخدم حالة لاحقة أو restriction مع سبب. |
| طلب بيانات مالية لـOwner من سياق Market | مرفوض ولا يظهر في Audit إلا بالحد الأدنى الآمن. |

## Action Points

- [ ] قبل Pilot، تحول الحدود أعلاه إلى سياسة خصوصية وTerms قصيرة قابلة للمراجعة القانونية المحلية.
- [ ] قبل رفع أي ملف حقيقي، يحدد مزود التخزين ومدة الاحتفاظ والاستعادة والحذف والوصول الموقّع في قرار تقني منفصل.
- [ ] أي قرار Moderation آلي أو ميزة سمعة/تقييم يحتاج أثرًا وتحليل تحيز واختبارًا مستقلًا؛ لا يدخل E-01 أو Beta الأولى.
