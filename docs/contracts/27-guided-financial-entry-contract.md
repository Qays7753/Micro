## 2. وسم التصنيف البشري (`categoryLabel`) — بُعد قراءة لا نوع حدث

| البند | الحكم |
|---|---|
| الشكل | `OperatingExpenseContext += categoryLabel?: string \| null` — نص حر اختياري داخل سياق المصروف فقط |
| التطبيع | قصّ الطرفين، دمج الفراغات الداخلية، الفارغ → `null`؛ الحد ٨٠ حرفًا **بعد التطبيع** (نفس القاعدة في المجال والاستيراد) — الرفض صريح برسالة عربية، لا قصًّا صامتًا |
| الأثر المالي | **صفر**: لا يغيّر أيًّا من الدلتا الخماسية ولا `sharedProjectShare` ولا `resultMinor` (اختبار التوائم على مستوى المجال والخدمة يحرسه) |
| التجميد | مجمّد مع الحدث؛ `editEvent` و`restoreEvent` والتراجع تنسخه حرفيًا؛ تغييره = تراجع موثق + سجل جديد — لا أدوات إعادة تسمية/دمج تُعيد كتابة التاريخ |
| المقترحات | نموذج قراءة مشتق فقط (`expenseCategorySuggestions`): أوسمة مستعملة (الأحدث أولًا، ٦) ∪ بذور شائعة (بنزين/رواتب/إيجار/كهرباء/مواد/توصيل/تسويق/أدوات عمل) حتى ٨؛ الرقاقات اختيارية بنقرة واحدة، ولا تسجيل فهرس ولا كتابة أبدًا |

| المسار السريع | رقاقة وسم اختيارية واحدة في ورقة الإضافة (≤٦) بعد الحقول وقبل سطر الأثر؛ المبلغ يبقى الإلزامي الوحيد |

## 3. الإدخال الموجّه — تسلسل الأسئلة وأثره

تسلسل المحرر (`/finance/new/operating_expense_*`): **شو صار** (النوع والعنوان) → **قدّش**
(المبلغ/إجمالي المشترك ونسبته) → **من وين طلع المبلغ؟** (وجهة الصرف — مدفوع فقط، مفردات
ورقة الإضافة نفسها) → التاريخ → الجهة → طبقة «أضف سياقًا للمصروف» (تصنيف أولًا →
طبيعته «ثابت ولا بتغير؟» → العلاقة «للمشروع ولا مشترك؟» → نمط الحصة + **بطاقة مراجعة
التوزيع** → حالة الرقم) → الوصف (مطلوب) → الحفظ.

- **المسار السريع** يبقى: مبلغ إلزامي واحد + وجهة اختيارية + وسم اختياري بنقرة — أقل
  من إدخالين إلزاميين قبل الحفظ، كما يقتضي عقد التجربة.
- **معاينة الأثر** (`EventEffectPreview`) مشتقة من نية الالتزام الفعلية: نفس توسيع
  `record` (`expenseRecordIntent` — وحدة واحدة يستهلكها الحفظ والمعاينة) ثم محاكاة جافة
  عبر `createFinancialEvent` نفسها؛ الناقص/غير الصالح يعود للنص الثابت. منطقة ارتفاع
  محجوز ثابت (لا اهتزاز فوق حقول الإدخال). الأسطر: الأثر الأولي باسم المحفظة، والسلبيات
  المجمعة «بلا حركة أمانة ولا سحب مالك»، وسطر الوسم «لا يغيّر الأثر المالي».
- **بطاقة مراجعة التوزيع** (`AllocationReviewCard`): صفوف «تسمية: قيمة» (لا معادلات
  مضمّنة)؛ الحصة تُشتق بـ`calculateSharedProjectShareMinor` نفسها؛ «المتبقي غير موزّع»
  مرئي (صفر عند التوزيع الكامل، الإجمالي كاملًا عند التأجيل، «إجمالي المصدر غير محفوظ»
  عند الثابت/التقدير). التقدير والتأجيل يُعلنان بصدق — لا دقة زائفة.
- **وجهة الصرف**: بعد الحفظ الناجج تُنسب للمحفظة بـ`distributeUnallocated` بمصدر
  `expense` ومفتاح `${idempotencyKey}:attribute` (نفس توقيع الورقة — لا تخصيص مزدوج).
  فشل النسبة **لا يمس الحدث**: يبقى النص الصادق ووصلة السجل ظاهرين قبل أي انتقال،
  والمال محفوظ ضمن غير الموزع.
- **صدق المعرفة في المسار السريع**: `knowledge: "known"` صادقة (المالك أدخل المبلغ
  المدفوع فعليًا)؛ `behavior: "unknown"` بُعد آخر مختلف.
- **تمييز المسارات**: شراء الخامات → مسار نصي فعلي إلى الموردون والمشتريات؛ الأصول
  طويلة الاستخدام والقروض الشخصية → سطر تأجيل صادق («مساراتها قادمة لاحقًا») — لا
  يُخترع مسار مالي بديل ولا يُكذب على المستقبل.
- **مسودة محفوظة** (`micro.finance-draft.<type>.v1`): مدخلات فقط لا سجلات؛ تُكتب عند
  الوسخ (لقطة الوسخ مثبتة برمز مستقر — إصلاح وصحي مع هذه المجموعة)، وعرض الاسترجاع
  عند الفتح بفعل صريح، والتجاهل/الحفظ يمسحان؛ لا تحويل سجل تلقائي أبدًا.

## 4. قراءة الفترة الواحدة (الكانون)

`ProjectFinancialService.readRecordedPeriodResult` هو المنتج الوحيد لرقم الفترة:
مالي (القراءة الكاملة) والكشف (`statementService.read` يستدعيه حرفيًا) والمؤشرات
(`readFinancialInsights`) ومال المالك (الدليل) كلها تستهلكه. لا صفحة تجري حساب فترة
داخليًا — جمع «الإيراد المعترف به» انتقل إلى `StatementReading.recognizedRevenueTotalMinor`
مشتقًّا في الخدمة. `null` قيمة معلنة تتطابق أسبابها عبر الأسطح.

**المسارات المحوطة خارج الكانون (توثق لا أن تُعد منافسة):** هضم غياب المالك
(`homeControlCenterService` — إجمالي آخر يوم تسجيل لا نتيجة فترة)، مدخلات G5
(`g5Service.expenseInputs` — عقد ١٤ §٦)، و`allocation.resultMinor` في recurring-margin
(مفهوم مختلف يشترك في الاسم فقط).

**الحارس:** `periodResultCanonical.test.ts` — تطابق الكائن الكامل بين القارئ والكشف
والمؤشرات + تجسّس الاستدعاء (أي تنفيذ ثانٍ منافس يتوقف عن استدعاء الكانون فيفشل
الاختبار) + اتساق المجموع المشتق. null يُفحص كقيمة (بيع بتكلفة مجهولة → نفس الحالة
والأسباب في كل سطح).

## 5. فحص سلامة مالي (الأساس القرائي)

`/tools/integrity` سطح قارئ تحت أدواتي (البديل `/tools`) + باب نصي في قسم الحقيقة
بمالي. **«يقرأ أرقامك ولا يغيّر شيئًا»** ملزم معماريًا: الفحص لا يستدعي إلا مسارات
قراءة، ولقطة المخزن قبل/بعد متطابقة (اختبار)، ولا إصلاح تلقائي أبدًا — الفحص يشير
والمسار الموثق في سطح الأصل يصحّح.

| المعرف | الفحص | مشتق من |
|---|---|---|
| MIC-1 | تطابق نتيجة الفترة عبر الأسطح (القارئ/الكشف/المؤشرات) — null قيمة تتطابق أسبابها | القانون الكنسي §٤ |
| MIC-2 | بنية الكاش: أزواج التحويل متوازنة، التراجعات تشير لأصول قائمة، المفاتيح غير مكررة على الوحدات، sourceRef مقترن | عقود استمرارية الكاش + فحص الاستيراد |
| MIC-4 | سلامة الأحداث والتوزيع: إعادة بناء كل حدث بدوال المجال ومقارنة الدلتا الخماسية، وإعادة اشتقاق الحصة بالنسبة نفسها | `createFinancialEvent/Reversal` + `calculateSharedProjectShareMinor` |
| MIC-7 | الأمانات: المجموع ≥ صفر (كاشف تجاوز الاستيراد) ومطابق للموقف | `summarizeFinancialEvents` + `readPosition` |
| MIC-9 | صدق المعرفة: غياب الرقم ⟺ تكلفة غير معروفة معلنة؛ الحالات المعلقة تحذير «قرار معلق، ليس خطأً» | صيغة القارئ (resultMinor/null) |

- المعرفات `MIC-3/5/6/8/10` **محجوزة** للمجموعات اللاحقة التي توسّع السجل نفسه —
  أشكال النتائج ثابتة (`{id, titleAr, status, detailAr, driftMinor?, offenderCount?, offenderSampleIds?, deepLink?}`).
  استهلكت المجموعة ٢ (عقد ٢٨) المحجوز **MIC-8** لسلامة المخزون والمواد؛
  يبقى `MIC-3/5/6/10` محجوزًا للمجموعات اللاحقة.
- الحالات المعلنة تحذير لا خللًا: رصيد محفظة سالب من سحب مالك/ضبط (مراجعة لا كسر)،
  وغير الموزع، والتقديري. الفشل محجوز للكسر البنيوي والتلف.
- الحالة كلمة وأيقونة (سليم/تحذير/خلل) لا لونًا وحده؛ الروابط العميقة تُبنى بـ`withFrom`
  إلى الصف المركّز (`?layer=events&event=`) أو دفتر المحفظة.

## 6. إصلاحات موثقة رافقت المجموعة (عيوب سابقة مكتشفة بالفحص)

1. **دورة عكس التحويل عبر التصدير/الاستيراد:** `cash.transfer` يكتب زوجًا مقترنًا
   بمفتاح عملية واحد، وعكسه زوج تراجع بمعرف تحويل خاص — فحص الاستيراد كان يفرد
   المفتاح لكل سطر ويُدخل كل زوج تراجع في مجموعات التحويل، فيرفض أي ملف فيه تحويل
   أو عكس تحويل. الحكم الجديد: **المفتاح وحدة إيداع** — يُقبل تكراره فقط للزوجين
   الموثقين (تحويل بمعرف واحد، أو عكس تحويل بمعرف واحد)، وأمان التراجع يكفله
   `reversesEntryId` الأحادي ومطابقة المعكوس. (قرار D-025)
2. **حراسة الوسخ في محرر الأحداث:** `useFormDirty` بلا رمز يعيد اللقطة كل رندر فيبقى
   الوسخ كاذبًا سلبيًا دائمًا — مرّر رمز مستقر (`type`) فاشتغل الحارس والمسودة معًا.
3. **عدّاد الكثافة النصية:** قسم الحقيقة بمالي خارج القياس تاريخيًا (تفكك حالة الآلة
   قبل وصوله) — وسم الباب النصي الجديد يقع في المنطقة غير المقيسة ذاتها؛ المقيس لم
   يتغير (١٨١) فلا رفع سقف مطلوب، والظاهرة موثقة هنا وبسجل القرار (D-026).
