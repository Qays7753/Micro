# عقد نسخة التكلفة

**الحالة:** CURRENT / يقرأ مع [`05-financial-p0-policies.md`](05-financial-p0-policies.md) قبل أي Use Case تكلفة.
**الغرض:** ضمان أن السعر والنتيجة يعتمدان على المدخلات التي كانت معروفة وقت القرار، لا على أسعار لاحقة.

## بنية النسخة

كل `cost_snapshot` يحتوي على:

| الحقل | المعنى |
|---|---|
| `snapshot_id` | معرف ثابت للنسخة |
| `workspace_id` | ملكية السجل وعزل الحساب |
| `source_type` | مخطط أولي، اعتماد سعر، تأكيد طلب، تعديل، أو إتمام |
| `created_at` | وقت إنشاء النسخة |
| `currency` | عملة الحساب؛ الأردن والدينار الأردني في الشريحة الأولى |
| `material_items` | خامة، كمية، وحدة، سعر، تاريخ السعر، والمصدر |
| `time_estimate` | مدة تقديرية وسعر الساعة إن أدخله المستخدم |
| `packaging` | تكلفة التغليف إن انطبقت |
| `delivery` | تكلفة التوصيل إن انطبقت |
| `waste` | هدر تقديري أو فعلي إن أدخله المستخدم |
| `customization` | أثر التخصيص أو النسخة الخاصة |
| `knowledge_state` | `known` أو `estimated` أو `partial` أو `incomplete` أو `stale` أو `variable` |
| `calculation_version` | إصدار قواعد الحساب؛ مؤجل في Domain Core المحلي الحالي ويجب أن يضاف قبل تثبيت نتائج قابلة للمقارنة عبر إصدارات مختلفة |
| `freshness_days` | حداثة اختيارية قابلة للاختبار؛ إذا لم يحدد المستخدم سياسة حداثة فلا تُدّعى حالة `stale` |

هذه بنية العقد الكامل. في Domain Core المحلي الحالي لا تعني حقول مثل `workspace_id` و`calculation_version` وطبقة التخزين التجاري أنها منفذة؛ يحدد `docs/implementation/02-domain-contract-coverage.md` ما هو مطبق وما هو مؤجل.

## قواعد التحديث

لا تعدل نسخة تكلفة مرتبطة بطلب مؤكد في مكانها. عند تغير خامة أو وقت أو مواصفات، أنشئ نسخة جديدة واربطها بحدث يوضح سبب التغير. يحتفظ الطلب بنسخة القرار السابقة، ويمكن للمستخدم رؤية الفرق.

إذا كان السعر أو المدة أقدم من سياسة الحداثة، تكون الحالة `stale` وتظهر مراجعة مطلوبة. في Domain Core الحالي تُطبق السياسة فقط عندما يحدد `freshness_days` صراحة في الإدخال؛ وإلا لا تُنشأ حالة `stale` اصطناعيًا. لا تحول البيانات الناقصة إلى صفر. في مسار الحرفة، إذا كان `time` مفقودًا (`null`) تكون الحالة `incomplete` حتى مع وجود المواد؛ لا يوجد في الشريحة الحالية تصريح يجعل الوقت المفقود صفرًا أو يتجاهله دون أثر.

## حساب القطعة المخصصة

```text
material_cost = Σ(quantity × unit_price)
time_cost = estimated_minutes ÷ 60 × hourly_rate
planned_cost = material_cost + time_cost + packaging + delivery + waste
unit_cost = planned_cost ÷ quantity
price_floor_per_unit = unit_cost + safety_buffer_per_unit
```

كل قيمة غير مدخلة تؤثر على النتيجة يجب أن تسجل كناقصة أو مقدرة. إذا لم يدخل المستخدم `time` أصلًا، لا تُحسب تكلفة وقت ولا تُعرض النتيجة `known`؛ يظهر النقص والفعل التالي. وإذا أدخل وقتًا بسعر ساعة تقديري، تكون الحالة `estimated` وفق سياسة P0.

## التخصيص والتعديل

التخصيص ليس نصًا تجميليًا فقط إذا كان يغير الخامة أو الوقت. عند تغيير المقاس أو اللون أو العدد أو طريقة التنفيذ بعد الاتفاق، ينشأ `revision` يوضح. ويجب أن تطابق كمية Snapshot المعدلة كمية الطلب الأصلية؛ اختلافها يفشل العملية بدل تغيير معنى السعر أو التكلفة:

- ما الذي تغير.
- من أي نسخة إلى أي نسخة.
- أثر التغير على التكلفة والسعر والمتبقي.
- هل يحتاج موافقة جديدة من الزبون.

## معايير القبول

يمر العقد إذا احتفظ الطلب القديم بسعره ونسخته عند تغير سعر خامة جديدة، وظهر سبب النقص عندما لا يدخل الوقت أو التغليف، وصُنّف غياب وقت الحرفة `incomplete`، وأمكن مقارنة نسختين بعد تعديل المواصفات مع تطابق الكمية، ولم تُقبل كمية أو سعر أو yield غير صالح.
