# عقد G5 — هامش المساهمة، نقطة التعادل، والسيولة القصيرة

**الحالة:** `CURRENT / CONTRACT FOR G5 IMPLEMENTATION`

**النطاق:** G5-A سياسة هامش المساهمة، G5-B نقطة التعادل المفككة، G5-C قراءة السيولة القصيرة، G5-D التجربة التفسيرية.

**العملة والفترة:** JOD بوحدة نقدية صغرى صحيحة، وفترة محلية شاملة `from/to` وفق `Asia/Amman`.

## 1. سؤال القرار والمستخدم

المستخدم هو صاحب مشروع صغير أو منزلي يدير الطلبات والمصاريف والكاش بنفسه أو مع فريق محدود. يظهر الاحتياج عندما يريد مراجعة فترة مسجلة، أو يعرف مقدار الهامش اللازم لتغطية تكاليفها، أو يفهم هل الكاش المسجل مع التحصيلات والالتزامات التي أعلنها يكفي للمدى القصير.

> **سؤال G5 الوحيد:** كم يلزم من هامش مساهمة مسجل وبافتراضات معلنة لتغطية هذه الفترة؟ وهل الكاش المسجل، مع التحصيلات والالتزامات القريبة التي صرّح بها المالك، يكفي للمدى القصير؟

هذه قراءة تفسيرية مشتقة من السجل والتصنيفات والإعلانات التي أدخلها المالك. لا تنتج قرار شراء أو اقتراض أو سحب أو تسعير، ولا تحول التوقع إلى حدث مالي.

## 2. العلاقة بالعقود القائمة

يتبع G5 سياسات [`05-financial-p0-policies.md`](05-financial-p0-policies.md) في العملة والتقريب والفترة وفصل الربح عن الكاش وعدم تغيير التاريخ. يبني على نتيجة الفترة الأوسع وحصة المصروف المشترك في عقد G3 [`14-period-result-allocation-policy-prototype-contract.md`](14-period-result-allocation-policy-prototype-contract.md)، لكنه لا يعيد تنفيذ G3 أو يوزع حصة مشتركة على طلب أو منتج. ويحافظ على فصل هامش اسم العمل المسجل عن معنى الكتالوج الاختياري في عقد G4 [`15-catalog-reference-prototype-contract.md`](15-catalog-reference-prototype-contract.md). أما عقد القراءة السابق [`12-financial-insights-g5-prototype-contract.md`](12-financial-insights-g5-prototype-contract.md) فيبقى مرجعًا للسطوح المحافظة التي سبقت هذا العقد؛ هذا العقد يضيف سياسة المساهمة وإعلانات المدى القصير وحالاتها الصريحة.

## 3. طبقات الحقيقة ومصادر الأرقام

| الرقم أو الحالة | المصدر المسموح | ما لا يعنيه |
|---|---|---|
| إيراد المساهمة | طلبات مسلّمة داخل الفترة بنتيجة `final` و`recognizedRevenueMinor` في الطلب | ليس كل المبيعات، ولا الكاش المحصل |
| التكلفة المتغيرة المباشرة | `recognizedCostMinor` في Snapshot للطلبات النهائية الداخلة | ليست COGS فعلية للمخزون، ولا تعيد كتابة Snapshot |
| التكاليف الثابتة | أحداث مصروف تشغيلي في الفترة ذات `behavior: fixed` وسياق مشروع أو حصة مشتركة معلنة | لا تشمل الأصول أو التمويل أو السحب أو التسويات |
| العناصر المتغيرة العامة | أحداث ذات `behavior: variable` لا تملك ربطًا مباشرًا قابلًا للإثبات بالطلبات | لا تحمل على الوحدات تلقائيًا؛ تبقى خارج الهامش وتمنع الادعاء باكتمال نقطة التعادل |
| العناصر المختلطة أو غير المعروفة | أحداث `mixed` أو `unknown` أو حصة مشتركة بلا مصدر | لا يوزعها النظام ولا يحولها إلى صفر |
| الكاش المسجل | قراءة الوضع المالي المحلي، مع إبقاء المحافظ والكاش غير الموزع منفصلين في العرض | ليس كاشًا متوقعًا ولا رصيدًا قابلًا للسحب تلقائيًا |
| التحصيلات والالتزامات القريبة | `ShortCashDeclaration` فعالة، بمصدر معلن ومبلغ وتاريخ ودرجة معرفة | ليست قبضًا أو دفعًا فعليًا، ولا تعدّل ذمة أو كاشًا أو حدثًا ماليًا |
| الذمم أو الالتزامات غير المؤرخة | الطلبات ذات الدين ومشتريات/مصروفات المورد ذات الرصيد دون إعلان زمني مطابق | لا تدخل في توقع قصير برقم مخفي؛ تظهر سبب نقص المعرفة |

## 4. سياسة التصنيف للفترة

التصنيف يطبق على كل عنصر مصروف في الفترة التي وقع فيها، لا على المشروع إلى الأبد. `fixed` هو عنصر تشغيلي مسجل يفترض ثباته نسبيًا داخل الفترة، و`variable` يتغير مع النشاط ويمكن ربطه مباشرة بتكلفة الوحدات أو يظل عنصرًا متغيرًا عامًا، و`mixed` يجمع سلوكًا ثابتًا ومتغيرًا لا يملك النظام أساسًا معلنًا لفصله، و`unknown` يعني أن السلوك غير معروف.

يدخل المصروف الثابت في مقام نقطة التعادل كقراءة `available` فقط إذا كان مبلغه موجبًا، وسياقه للمشروع أو حصة المشروع المشتركة معلنة، ودرجة معرفته `known`. المصروف الثابت المقدّر لا يختفي؛ يمكن أن يدخل في قراءة رقمية موسومة `needs_review` إذا اكتملت بقية الشروط، مع إظهار الافتراض. المصروف المشترك الذي لا يحمل أساس حصة لا يدخل كحصة معروفة ويجعل النتيجة `incomplete`.

لا يوزع النظام المصروف المختلط أو غير المعروف بين ثابت ومتغير. ولا يعتبر `purpose: order` أو `purpose: product` وحده ربطًا مباشرًا؛ يلزم مصدر ربط صريح في القدرة القائمة، وإلا يبقى العنصر مستبعدًا مع سبب ظاهر.

## 5. هامش المساهمة

لكل طلب نهائي صحيح داخل الفترة:

```text
هامش الطلب المباشر المسجل = recognizedRevenueMinor - recognizedCostMinor
```

وعلى مستوى الفترة:

```text
هامش المساهمة المسجل = مجموع إيراد الطلبات النهائية - مجموع تكلفتها المتغيرة المباشرة
هامش المساهمة للوحدة = هامش المساهمة المسجل ÷ مجموع الكمية النهائية
```

يستخدم النظام كمية موجبة مسجلة ومزيج الطلبات النهائية الفعلي في الفترة. تحفظ حدود الحساب الكمية الصحيحة على مقياس الألف `quantityMilli` بحيث `1.000 = 1000`، ولا تدخل كمية عشرية غير قابلة للتمثيل الدقيق أو كمية غير صالحة كصفر. إذا ارتبط الطلب بمرجع كتالوج، تستخدم وحدة الكتالوج؛ وتجمع الكميات فقط بعد تطابق الوحدة أو تطبيق تحويل G4-A صريح داخل البعد نفسه وبناتج صحيح آمن. اختلاف الأبعاد أو غياب التحويل الدقيق يجعل كمية التعادل `null` وحالة القراءة `incomplete` بدل جمع وحدات غير متوافقة. لا يدخل قبض العربون أو التحصيل المتبقي أو الدين أو السحب أو الاستثمار في الهامش، ولا تدخل حركة المخزون الفعلية لتعديل Snapshot تاريخي. يعرض السطح الفترة والمصادر والاستبعادات والافتراضات واسم العمل المسجل والوحدة عند توفرها، لكنه لا يسمي الناتج ربحًا نهائيًا أو ربحية كتالوج.

## 6. نقطة التعادل المفككة

تحسب نقطة التعادل المعيارية فقط عند وجود طلبات نهائية بكمية موجبة قابلة للتوحيد، وتكاليف ثابتة موجبة قابلة للإسناد، وهامش مساهمة موجب، وعدم وجود طلب نهائي مستبعد أو عنصر مؤثر مختلط/غير معروف أو حصة مشتركة بلا أساس. لا يسمح الحساب بالتقريب الخفي: يحول هامش الوحدة إلى قيمة `minor` بعد قسمة صحيحة آمنة، ويقرب الناتج النهائي إلى عدد وحدات صحيح باستخدام `ceil` مرة واحدة. الصيغة هي:

```text
وحدات التعادل = ceil(التكاليف الثابتة المسجلة للفترة ÷ هامش المساهمة للوحدة)
```

يعرض الناتج دائمًا: `from/to`، التكاليف الثابتة، الإيراد، التكلفة المتغيرة، الهامش الكلي، الهامش لكل وحدة، المزيج المسجل، مصادر الأرقام، الاستبعادات، والافتراضات. المزيج هو مزيج الطلبات النهائية المسجلة، وليس توقعًا لمبيعات منتج جديد.

| الحالة | `status` | رقم وحدات التعادل |
|---|---|---:|
| كل الشروط مكتملة ومعروفة | `available` | موجود |
| الشروط الحسابية موجودة لكن مبلغًا أو حصة أو مزيجًا معلنًا تقديري | `needs_review` | موجود وموسوم بأنه يحتاج مراجعة |
| بيانات مؤثرة مفقودة، أو طلب نهائي مستبعد، أو mixed/unknown بلا فصل | `incomplete` | `null` |
| الهامش غير موجب، أو الكمية/التكلفة غير صالحة، أو التكاليف الثابتة الموجبة غير قابلة للتطبيق | `invalid` | `null` |

لا تعرض الواجهة `0` بدل رقم غير ممكن. إذا كانت الفترة بلا تكلفة ثابتة موجبة مسجلة، لا تخترع نقطة تعادل؛ تذكر أن شرط التغطية غير متوفر.

## 7. السيولة القصيرة كتوقع معلن

تبدأ القراءة بالكاش المسجل الحالي، ثم تضيف فقط التحصيلات وتطرح فقط الالتزامات التي أعلنها المالك داخل أفق `from/to` وبمبلغ وتاريخ ومصدر ودرجة معرفة. الصيغة المفاهيمية:

```text
التوقع بعد التدفقات المعلنة = الكاش المسجل
  + التحصيلات المعلنة داخل الأفق
  - الالتزامات المعلنة داخل الأفق
```

تعد المشتريات أو الالتزامات المسجلة ذات `dueOn` داخل الأفق تدفقًا التزاميًا مؤرخًا من المصدر القائم. أما الرصيد الذي لا يحمل تاريخًا كافيًا، فلا يضاف أو يطرح من رقم التوقع؛ يظهر كرصيد غير مؤرخ يمنع اكتمال القراءة. الإعلان المرتبط برصيد قائم يحده ولا يكرره؛ لا يسمح بمجموع إعلانات يتجاوز الرصيد.

يعرض السطح في حقول منفصلة: الكاش المسجل، التحصيلات المعلنة، الالتزامات المعلنة، الذمم غير المؤرخة، الالتزامات غير المؤرخة، والتوقع بعد التدفقات المعلنة. لا تعتبر الذمة كاشًا، ولا تعتبر الإعلان قبضًا أو دفعًا، ولا يدخل المخزون أو الربح في هذا التوقع.

| الحالة | متى تستخدم | التوقع |
|---|---|---:|
| `available` | توجد إعلانات فعالة مؤرخة، مصادرها معلنة، ولا توجد ذمم/التزامات مؤثرة بلا تاريخ أو إعلان مطابق، وكلها `known` | موجود |
| `needs_review` | الشروط مكتملة لكن إعلانًا أو أكثر `estimated` أو `needs_review` | موجود مع وسم ومصدر الافتراض |
| `incomplete` | دين عميل أو التزام مؤثر بلا تاريخ/إعلان مطابق، أو لا توجد بيانات كافية لبناء أفق قصير | `null` |
| `invalid` | مبلغ أو تاريخ أو علاقة إعلان غير صالحة، أو إعلان يتجاوز رصيدًا معروفًا عند ربطه بكيان | `null` |

عدم وجود تحصيلات أو التزامات معلنة لا يساوي أن الأفق آمن؛ إذا لم يوجد أساس كافٍ، يعرض النظام الكاش المسجل فقط ويطلب تسجيل النقص بدل رقم توقع بديل.

## 8. إعلان التحصيل أو الالتزام والتصحيح الآمن

الإعلان سجل محلي مستقل عن الحدث المالي:

```ts
type ShortCashDeclaration = {
  id: string;
  kind: "declaration" | "reversal";
  direction: "collection" | "commitment";
  amountMinor: number;
  dueOn: string;
  source: string;
  knowledge: "known" | "estimated" | "needs_review";
  note: string;
  relatedOrderId: string | null;
  relatedEventId: string | null;
  idempotencyKey: string;
  reversalOfId: string | null;
  createdAt: string;
};
```

المصدر إلزامي، والمبلغ موجب بوحدة صغرى صحيحة، والتاريخ `YYYY-MM-DD` صالح محليًا، و`relatedOrderId` أو `relatedEventId` اختياريان لكن لا يثبتان قبضًا أو دفعًا. إعادة إرسال نفس نوع العملية مع `idempotencyKey` نفسه تعيد السجل دون تكرار. تصحيح إعلان قائم لا يعدّل السجل القديم؛ ينشئ سجل `reversal` مرتبطًا به، ويظل أصل التصحيح قابلًا للتدقيق. لا يسمح النظام بعكس إعلان غير موجود أو عكسه مرتين أو عكسه بمبلغ/اتجاه مختلف.

## 9. طبقات التنفيذ والتخزين

يلتزم التنفيذ بالمسار:

```text
React UI → Application Service → G5 Domain → PrototypeLocalStore Port → IndexedDB
```

حسابات G5 pure ولا تقرأ IndexedDB ولا React. تفصل طبقة Domain state عن `ShortCashDeclarationRecord` المحفوظ وعن View Model الذي يقرأه السطح. لا تحفظ نتيجة مشتقة إذا أمكن اشتقاقها من الطلبات والأحداث والإعلانات الفعالة.

إضافة الإعلانات تحتاج ترحيلًا صريحًا من `schema 18 / export 9` إلى `schema 19 / export 10`: مخزن محلي جديد، مصفوفة في `LocalStoreSnapshot`، تحقق قبل الاستبدال، ودعم round-trip. يرحّل الملف القديم بإعلانات فارغة فقط، دون إنشاء مواعيد أو مبالغ مفترضة. الملف الناقص أو الإصدار غير المدعوم يفشل قبل الكتابة ويحافظ على الحالة الحالية.

## 10. ما لن يتغير وما هو خارج G5

لا يغير G5 `CostSnapshot` أو الطلبات التاريخية أو الأحداث المالية أو الكاش أو الذمم أو مشتريات الموردين بسبب العرض. لا ينفذ COGS فعليًا، أو أجرًا، أو ضريبة، أو قرضًا، أو إهلاكًا، أو POS، أو Calendar موسعًا، أو PWA، أو Auth، أو Sync، أو AI. لا يصدر أمر شراء أو سحب أو اقتراض أو تسعير تلقائيًا. لا يعرض صافي ربح نهائيًا ولا يضمن تحصيل دين.

## 11. الفعل التالي التفسيري

يقتصر الفعل التالي على تسجيل النقص أو مراجعة افتراض معلن: مراجعة سعر/تكلفة مؤثرة، تصنيف سلوك المصروف، تسجيل حصة مشروع مشتركة بمصدرها، تحديث موعد تحصيل، أو تسجيل التزام قريب. إذا تعذر الحساب، تشرح الواجهة السبب ولا تعرض رقمًا بديلًا.
