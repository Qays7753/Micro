# عقد مرجع الكتالوج ونواة G4-A

**الحالة:** `MERGED TO bridge/financial-decision-core-g3-g5 VIA PR #105 / PENDING FINAL ACCEPTANCE`
**المالك:** Manus Agent 1
**تاريخ التحديث:** 26 أغسطس 2026

## 1. سؤال القرار والنطاق

يعالج هذا العقد سؤالًا محدودًا وواضحًا: **«كيف أكرر عملًا أو خدمة أو إنتاجًا من دون أن يغير المرجع الجديد اتفاقًا أو Snapshot قديمًا؟»**

الكتالوج هنا مرجع اختياري لتنظيم الأعمال المتكررة، وليس متجرًا أو قائمة مخزون أو محرك أسعار. يبقى الطلب هو الاتفاق التاريخي، وتبقى `CostSnapshot` نسخته المالية في وقت الاتفاق. لا يغير تعديل الكتالوج أو وحدته أو تحويله أو قالبه طلبًا أو سعرًا أو تكلفة أو نتيجة سابقة.

> **قرار حاكم:** وجود اسم في الكتالوج لا يعني أن كلفته الفعلية معروفة، ولا أن كل طلب يحمل الاسم نفسه متطابق، ولا أن النظام يملك حق اقتراح سعره أو تحويل كميته بالتخمين.

## 2. كيان الكتالوج المتوافق

```ts
type CatalogItemKind = "product" | "service";

type CatalogItem = {
  id: string;
  kind: CatalogItemKind;
  name: string;
  unitLabel: string | null;       // تسمية العرض التاريخية
  unitId?: string | null;         // مرجع منظم اختياري
  active: boolean;
  createdAt: string;
  updatedAt: string;
  createdOperationKey: string;
};
```

يبقى `unitLabel` كما هو للتوافق والعرض. السجلات القديمة تهاجر إلى `unitId: null` فقط؛ لا تنشئ الترقية وحدة أو تحويلًا أو قالبًا من الاسم.

| الحقل | القرار |
|---|---|
| `kind` | يغير لغة العرض فقط: منتج أو خدمة. لا يفرض مخزونًا على الخدمة ولا وقتًا فعليًا على المنتج. |
| `name` | اسم عملي قصير مطلوب، فريد بعد التطبيع ضمن النوع النشط؛ لا يحول `itemName` التاريخي إلى مرجع تلقائي. |
| `unitLabel` | اختياري، مثل «قطعة» أو «جلسة». ليس وحدة مخزون ولا yield ولا SKU. |
| `unitId` | رابط اختياري إلى وحدة منظمة. لا يمنع حفظ المرجع عند غيابه، ولا يغير التاريخ. |
| `active` | يوقف اختيار المرجع للطلبات الجديدة، ويحفظ روابط الطلبات التاريخية كما هي. |
| `createdOperationKey` | يمنع إنشاء الكتالوج مكررًا عند إعادة المحاولة محليًا. |

إنشاء Catalog Item لا ينشئ مخزونًا أو سعرًا أو تكلفة أو طلبًا أو استهلاكًا أو COGS أو وقتًا فعليًا.

## 3. ربط العمل بالكتالوج والتاريخ

يبقى `catalogItemId` اختياريًا في المسودة والطلب المخزن محليًا. يختار المستخدم المرجع عند إنشاء مسودة جديدة أو قبل تثبيت الطلب. لا يكتب التطبيق الرابط في طلب تاريخي لمجرد تطابق `itemName`، ولا يغير الرابط تلقائيًا عند إعادة تسمية الكتالوج أو تعطيله.

تقرأ طبقة Application فقط الطلبات النهائية المرتبطة صراحة بعنصر كتالوج، وتعرض **هامشًا مباشرًا مسجلًا حسب مرجع العمل** من `recognizedRevenueMinor - recognizedCostMinor` في الطلب النهائي. لا تسمى القراءة ربحية نهائية ولا COGS فعلية، ولا تدخل القوالب أو yield أو تحويلات التخطيط كتكاليف.

## 4. وحدات القياس ذات البعد

الأبعاد العامة المسموحة في G4-A هي:

```text
count | mass | volume | time | distance | area
```

```ts
type MeasurementUnit = {
  id: string;
  nameAr: string;
  dimension: UnitDimension;
  symbol: string | null;
  active: boolean;
  createdAt: string;
  updatedAt: string;
  createdOperationKey: string;
};
```

الوحدة اختيارية للكتالوج والقالب. الاسم وحده ليس دليل تحويل: «كوب» و«قطعة» لا يتحولان لمجرد تشابه النص. لا يوجد في هذا العقد كثافة أو وزن قطعة أو وصفة غذائية أو افتراض قطاعي. لا تفرض الوحدة على منتج أو خدمة، ولا تمنع الطلب العادي عند غيابها.

تخزن كميات القالب والتحويل بقاعدة مقدار الألف `quantityMilli` كأعداد صحيحة آمنة موجبة. يرفض النظام صفرًا أو سالبًا أو ما يتجاوز `Number.MAX_SAFE_INTEGER`.

لا تحذف وحدة مستخدمة. تعطيل الوحدة يمنع الاختيار الجديد فقط، مع بقاء المرجع والقالب والتحويل والبيانات السابقة قابلة للقراءة.

## 5. التحويلات المباشرة الصريحة

```ts
type DirectConversion = {
  id: string;
  fromUnitId: string;
  toUnitId: string;
  dimension: UnitDimension;
  numerator: number;
  denominator: number;
  note: string;
  active: boolean;
  createdAt: string;
  updatedAt: string;
  createdOperationKey: string;
};
```

العامل هو صراحةً: `الناتج = الكمية × numerator ÷ denominator`. يجب أن تكون الوحدتان نشطتين ومن البعد نفسه عند الإنشاء، وأن يكون البسط والمقام موجبين وآمنين، وأن تشرح الملاحظة سبب العامل. إذا تعذر تمثيل الناتج بدقة في `quantityMilli` يرفض النظام العملية؛ لا يوجد تقريب خفي.

| الحالة | النتيجة |
|---|---|
| كغ → غ | يسمح بعامل محفوظ مثل `1000/1` ويعطي ناتجًا دقيقًا. |
| قطعة → دزينة | يسمح فقط إذا أنشأ المستخدم تحويل العدد الصريح. |
| لتر → مل | يسمح ضمن الحجم بعامل صريح. |
| كغ → لتر | يرفض؛ لا يفترض كثافة. |
| وحدة موقوفة | لا يمكن استخدامها لتحويل جديد، وتبقى التحويلات السابقة قابلة للقراءة. |
| زوج نشط مكرر أو متناقض | يرفض الإنشاء الصامت؛ يعطل القديم وينشئ المستخدم نسخة موثقة عند الحاجة. |

G4-A يبني تحويلًا مباشرًا فقط. لا يوجد graph أو تحويل متعدد الخطوات أو اختيار أفضل مسار أو اشتقاق اتجاه عكسي غير محفوظ.

## 6. قالب العمل والمكونات والعائد

لكل Catalog Item، وبفعل المستخدم فقط، يمكن حفظ قالب عام لتذكر ما يتكرر في التجهيز أو الإدخال وما الناتج المتوقع. القالب ليس Recipe قطاعية، ولا BOM متعدد المستويات، ولا أمر إنتاج، ولا استهلاك مخزون.

```ts
type CatalogTemplate = {
  id: string;
  catalogItemId: string;
  title: string | null;
  note: string | null;
  components: readonly {
    id: string;
    name: string;
    quantityMilli: number;
    unitId: string;
    note: string | null;
  }[];
  yield: { quantityMilli: number; unitId: string } | null;
  yieldReadiness: "not_configured" | "ready" | "needs_conversion";
  revision: number;
  sourceTemplateId: string | null;
  active: boolean;
  createdAt: string;
  updatedAt: string;
  createdOperationKey: string;
};
```

المكونات اختيارية وتضم اسمًا عمليًا وكمية موجبة ووحدة منظمة وملاحظة اختيارية. `yield` اختياري؛ إن اختير فهو موجب وله وحدة معلومة. إذا اختلفت وحدة الناتج عن وحدة مخرج الكتالوج، لا يصبح `ready` إلا بوجود تحويل مباشر محفوظ من وحدة الناتج إلى وحدة المخرج داخل البعد نفسه. وإلا يحفظ القالب بحالة `needs_conversion` مع فعل تالٍ صريح، من دون تخمين أو تقريب.

القالب بلا yield صالح بحالة `not_configured`. والعمل بلا قالب صالح تمامًا. لا توجد حالة نقص مالية بسبب غياب القالب أو الوحدة أو yield.

تعديل القالب لا يحرر السجل السابق in-place: تنشئ المراجعة الجديدة علاقة `sourceTemplateId` ورقم `revision` وتاريخًا، وتعطل السابق بعد نجاح العملية الذرية. تبقى المراجعات القديمة قابلة للقراءة.

## 7. الحدود المالية والتشغيلية

| الطبقة | ما تعنيه | ما لا تنشئه |
|---|---|---|
| Catalog Item | مرجع عمل اختياري وربط صريح | لا سعر، لا طلب، لا مخزون، لا وقت، لا كاش |
| Measurement Unit | معنى كمية وبعد عام | لا تكلفة ولا تحويل تلقائي |
| Direct Conversion | عامل مباشر موثق داخل بعد واحد | لا تسعير ولا COGS ولا كاش |
| Template Component | تذكر تخطيطي لمكوّن | لا Purchase ولا Inventory Movement ولا Consumption ولا Waste |
| Template Yield | ناتج متوقع للتخطيط وحالته | لا إنتاج مخزون نهائي ولا إيراد ولا هامش |
| Recorded Margin | قراءة من طلب نهائي مرتبط صراحة | ليست ربحًا نهائيًا ولا COGS مكتملة |

لا يرتبط مكوّن القالب تلقائيًا بـ`Material` أو `SupplierPurchase` أو حركة مخزون. أي استعمال فعلي لاحق يحتاج عقدًا وحدثًا صريحين.

## 8. المسار المعماري والتخزين

المسار الملزم هو:

```text
React UI → CatalogService → Catalog Domain → PrototypeLocalStore → IndexedDB
```

أضيفت منافذ LocalStore للوحدات والتحويلات والقوالب، وخرائط MemoryLocalStore، ومخازن IndexedDB التالية:

```text
measurement-units | direct-conversions | catalog-templates
```

رفع التطبيق `schemaVersion` إلى `24` و`localExportVersion` إلى `15`. ترقية CatalogItem القديمة تضيف `unitId: null` فقط، وملفات التصدير السابقة تضيف مصفوفات `measurementUnits` و`directConversions` و`catalogTemplates` الفارغة. لا تنشئ الترقية بيانات مشتقة أو روابط بالاسم.

الإنشاءات الجديدة حساسة لإعادة المحاولة عبر `createdOperationKey`. مراجعة القالب تستخدم commit ذريًا للنسخة السابقة واللاحقة. الاستيراد يتحقق من المعرفات والعلاقات والأبعاد والعوامل والكمية والعائد وحالة المراجعات قبل `replaceSnapshot` الذري؛ الملف التالف أو الناقص أو غير المدعوم لا يغير Store الحالي.

## 9. UX والاختيارية

يبدأ `/catalog` بمرجع العمل: نوع واسم ووحدة منظمة اختيارية، ويمكن حفظه دون فتح أي إعداد متقدم. القياس والتحويلات في لوحة فرعية اختيارية. القالب لا يظهر كواجب إعداد؛ يختاره المستخدم فقط عند الحاجة.

الواجهة عربية RTL، وتعزل المقادير بعرض ASCII/LTR حتى ثلاثة منازل عشرية، وتعرض Light/Dark وحالات empty/error/needs-conversion. الرسائل تقول صراحةً إن القالب تخطيطي ولا يسحب مخزونًا أو يغير تكلفة قديمة، وتضع الفعل التالي عند غياب التحويل المتوافق. تفاصيل العامل والعقد مخفية خلف الإفصاح أو تظهر عند الطلب، ولا تستخدم للمستخدم مصطلحات developer مثل schema أو graph أو ratio.

## 10. سيناريوهات القبول

1. إنشاء منتج وخدمة يبقيهما اختياريين ولا ينشئ أي منهما مخزونًا أو سعرًا أو استهلاكًا أو COGS أو وقتًا أو طلبًا.
2. إنشاء وحدة عدد ووزن وحجم ووقت ومسافة ومساحة؛ رفض الاسم الفارغ والعامل صفر/سالب.
3. حفظ تحويل دقيق مثل كغ → غ وإعادة المحاولة بالمفتاح نفسه بلا تكرار، ورفض الزوج المكرر أو كغ → لتر.
4. رفض كمية لا يمكن تمثيلها بدقة في مقدار الألف بدل التقريب الخفي.
5. تعطيل وحدة أو تحويل مستخدم يمنع الاختيار الجديد ويحافظ على القراءة القديمة.
6. Catalog بلا قالب، وقالب مكونات بلا yield، وقالب yield موجب متوافق، وقالب yield يحتاج تحويلًا صريحًا.
7. مراجعة قالب أو تحويل لا تغير طلبًا نهائيًا أو `CostSnapshot` أو `recognizedCostMinor` أو هامش الكتالوج المسجل أو نتيجة الفترة.
8. طلب تاريخي باسم مماثل بلا `catalogItemId` يبقى غير مربوط.
9. لا تتحول المكونات إلى Purchase أو Inventory أو Consumption أو Waste أو COGS أو كاش.
10. schema/export migration وround-trip ورفض ملف ناقص أو cross-dimension أو علاقة revision مكسورة بلا لمس Store الحالي.
11. idempotency وreload وcommit ذري للقالب ومراجعته.
12. تحقق يدوي لاحق على 360/390/430 وLight/Dark وRTL وkeyboard/focus/back وCloudflare/الأجهزة/Pilot؛ لا يرفع فحص sandbox إلى قبول إنتاجي أو بشري.

## 11. خارج النطاق

لا يدخل G4-A: POS، قائمة أسعار أو سعر افتراضي أو AI، SKU، صور، مخزون منتج نهائي، حجز، عمولات، ضرائب، صلاحية/LOT/حساسية، كثافة وزن-حجم، BOM متعدد المستويات، استهلاك تلقائي، COGS تلقائية، تحميل مشترك، وقت فعلي/أجر، Auth، Sync، Cloud أو Backend، ولا أي Profile قطاعي.
