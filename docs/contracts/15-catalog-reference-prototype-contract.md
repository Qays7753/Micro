# Micro — عقد الكتالوج الاختياري وربط العمل المتكرر G4-A

**الحالة:** `CURRENT / G4-A CONTRACT BEFORE IMPLEMENTATION`
**المالك:** Manus Agent 1
**تاريخ القرار:** 23 أغسطس 2026

## 1. سؤال القرار والنطاق

يعالج هذا العقد سؤالًا محدودًا وواضحًا: **«أي أعمال أو منتجات أكررها، وما الذي أعرفه فعلًا عن هامشها المباشر المسجل؟»**

الكتالوج هنا مرجع اختياري لتنظيم الأعمال المتكررة، وليس متجرًا أو قائمة مخزون أو محرك أسعار. يبقى الطلب هو الاتفاق التاريخي، وتبقى `CostSnapshot` نسخته المالية في وقت الاتفاق. لا يغير تعديل الكتالوج طلبًا أو سعرًا أو تكلفة أو نتيجة سابقة.

> **قرار حاكم:** وجود اسم في الكتالوج لا يعني أن كلفته الفعلية معروفة، ولا أن كل طلب يحمل ذلك الاسم متطابق، ولا أن النظام يملك حق اقتراح سعره.

## 2. كيان الكتالوج الأدنى

```ts
type CatalogItemKind = "product" | "service";

type CatalogItem = {
  id: string;
  kind: CatalogItemKind;
  name: string;
  unitLabel: string | null;
  active: boolean;
  createdAt: string;
  updatedAt: string;
  createdOperationKey: string;
};
```

| الحقل | القرار |
|---|---|
| `kind` | يغير لغة العرض فقط: منتج أو خدمة. لا يفرض مخزونًا على الخدمة ولا وقتًا فعليًا على المنتج. |
| `name` | اسم عملي قصير، مطلوب، فريد بعد التطبيع ضمن النوع النشط؛ لا يحول `itemName` التاريخي إلى مرجع تلقائي. |
| `unitLabel` | اختياري مثل «قطعة» أو «جلسة» أو «صينية». ليس وحدة مخزون ولا yield ولا SKU. |
| `active` | يوقف اختيار المرجع للطلبات الجديدة، ويحفظ روابط الطلبات التاريخية كما هي. |
| `createdOperationKey` | يمنع إنشاء الكتالوج مكررًا عند إعادة المحاولة محليًا. |

لا يحتوي G4-A على سعر افتراضي، وصفة، BOM، SKU، صورة، عميل، مخزون منتج نهائي، خصم، ضريبة أو مورد. هذه الحقول ستدفع المستخدم إلى إدخال ثقيل قبل أن تغيّر قرارًا موثوقًا.

## 3. ربط العمل بالكتالوج

يصبح `catalogItemId` اختياريًا في المسودة والطلب المخزن محليًا:

```ts
type OrderDraft = { /* ... */ catalogItemId: string | null };
type StoredCraftOrder = { /* ... */ catalogItemId: string | null };
```

يُختار المرجع عند إنشاء مسودة جديدة أو قبل تثبيت الطلب. لا يكتب التطبيق الرابط في طلب تاريخي لمجرد تطابق `itemName`، ولا يغير الرابط تلقائيًا عند إعادة تسمية الكتالوج أو تعطيله. تظل الطلبات القديمة بلا رابط صالحة وتبقى قراءتها المجمعة حسب الاسم منفصلة وموسومة بحدها.

## 4. القراءة التي يسمح بها G4-A

تقرأ طبقة Application فقط الطلبات النهائية المرتبطة صراحة بعنصر كتالوج، وتعرض لكل عنصر:

| المعلومة | مصدرها | الحد |
|---|---|---|
| عدد الطلبات/الكمية النهائية | الطلبات النهائية ذات `catalogItemId` المطابق | لا تمثل كل الطلبات التاريخية ذات الاسم نفسه |
| الإيراد المعترف به | الطلب النهائي | لا يساوي الكاش المحصل |
| التكلفة المباشرة المعترف بها | `recognizedCostMinor` في Snapshot الطلب | ليست COGS فعلية |
| الهامش المباشر المسجل | الإيراد ناقص التكلفة المباشرة المعترف بها | لا يحمل كهرباء أو تسويقًا أو وقتًا فعليًا غير مسجل |
| فرق المادة | قراءة G6 إن وجدت | يظل فرقًا تفسيريًا ولا يغير الهامش |

يسمى السطح **«هامش مباشر مسجل حسب مرجع العمل»**، ولا يسمى «ربحية منتج نهائية». إذا لم توجد طلبات مرتبطة، يظهر Empty State يشرح أن الكتالوج لا يعيد كتابة التاريخ.

## 5. درجة المعرفة والاختيارية

الكتالوج اختياري بالكامل. من لا يبيع عملًا متكررًا يستمر بالطلبات و`itemName` من دون منع أو نقص في الكاش أو الذمم أو نتيجة الفترة. ما ينقص فقط هو سؤال المقارنة المنظم حسب مرجع العمل.

لا يرفع وجود كتالوج درجة معرفة الطلب. تبقى `resultStatus` و`CostSnapshot.knowledgeState` وفرق المادة المنفذة مستقلة. عدم تسجيل الوقت الفعلي أو الهدر أو أساس تحميل مصروف عام لا يتحول إلى صفر، ويظهر بعبارة: **«العناصر الفعلية غير المسجلة لا تدخل في هذا الهامش.»**

## 6. ما لا يشمله G4-A

| غير داخل الآن | السبب | موضعه إن ثبتت الحاجة |
|---|---|---|
| وقت فعلي لطلب | يحتاج عقد إدخال وحفظ وعكس/تصحيح وحدود أثر مستقلة | G4-B بعد دمج الكتالوج |
| تحميل كهرباء أو تسويق على منتج | يحتاج أساس توزيع معلن ومراجع | عقد لاحق بعد G3 والكتالوج |
| COGS فعلي | المادة وحدها لا تكفي؛ الوقت والهدر والإرجاع وغيرها غير مكتملة | مرحلة تكلفة فعلية مستقلة |
| سعر مقترح أو توصية AI | الهامش المسجل لا يثبت أن السعر الصحيح معروف | لا يدخل تلقائيًا |
| POS أو مخزون منتج نهائي | الكتالوج ليس دليل بيع سريع متكرر | Pilot POS القطاعي فقط |
| تعديل طلب مسلّم أو Snapshot | يحذف تاريخ الاتفاق أو يغير قراءة سابقة بصمت | تصحيح موثق مستقل فقط |

## 7. التخزين والاستعادة

يحتاج G4-A إلى `schema 17` و`export 8` صريحين. تضاف مخزنات كتالوج محلية وحقول رابط اختيارية، وتهاجر المسودات والطلبات القديمة إلى `catalogItemId: null`. لا ينشئ الترحيل عنصرًا من `itemName` ولا رابطًا تخمينيًا. يعالج `schema 17` أيضًا نسخة محلية وصلت سابقًا إلى 16 بلا مخزن كتالوج، ثم يضيف الرابط الفارغ بأمان. يقبل الاستيراد v7 ويطبع الحقول الجديدة إلى الفراغ، ويظل الاستيراد ذريًا.

## 8. سيناريوهات القبول

| الحالة | النتيجة المطلوبة |
|---|---|
| إنشاء «صندوق هدايا» كمنتج و«تغليف هدايا» كخدمة | يحفظان كمراجع منفصلة، ولا ينشئان مخزونًا أو وقتًا تلقائيًا |
| ربط مسودة جديدة بمنتج | ينتقل الرابط إلى الطلب المخزن عند التثبيت، ولا يغير Snapshot |
| طلب تاريخي اسمه «صندوق هدايا» بلا رابط | يبقى بلا رابط ولا يدخل قراءة المرجع تلقائيًا |
| تعطيل مرجع | لا يظهر للطلبات الجديدة، وتبقى قراءة طلباته التاريخية صحيحة |
| هامش مرجع له طلب نهائي | يعرض إيرادًا وتكلفة مباشرة معترفًا بها وهامشًا مباشرًا مسجلًا، لا COGS فعليًا |
| فرق مادة G6 | يظهر كفرق تفسيري فقط ولا يغير الهامش أو النتيجة |
| export/import v7 | يقبل، وينتج نموذج v8 مع `catalogItemId: null` للبيانات القديمة |
| إعادة إرسال إنشاء مرجع بالمفتاح نفسه | لا تنشئ عنصرًا ثانيًا |
