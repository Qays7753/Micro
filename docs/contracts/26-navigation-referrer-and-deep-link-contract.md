## 2. المصدر والرجوع الآمن (`?from`)

### 2.1 القواعد

1. كل مسار قابل للفتح من أكثر من سياق يستقبل مصدره عبر `?from=<internal-path>`.
2. زر الرجوع/الخروج في المسار العميق يستعمل `useReturnPath()` — يعيد `?from` الصالح أو
   البديل القانوني الموثّق في `canonicalReturnFor()` (نفس سلوك ما قبل المجموعة ١ عند غياب المصدر).
3. الخروج بعد حفظ ناجح يعود للمصدر نفسه (لا لصفحة ثابتة) — مثال: DirectSaleEditor.
4. قيمة `from` تُقبل فقط إن كانت مسارًا داخليًا آمنًا (`isSafeInternalPath`): يبدأ بـ`/`،
   بلا مخطط خارجي، بلا `//`، وبلا محارف تحكم. غير ذلك يُهمل بصمت ويسقط للبديل القانوني.
5. المصدر الذي يساوي المسار الحالي يُهمل (لا دوران).
6. لا تُكتب أهداف رجوع ثابتة في الصفحات عندما يكون المصدر معروفًا.

### 2.2 البدائل القانونية (canonical fallbacks)

| المسار العميق | البديل عند غياب `?from` |
|---|---|
| `/orders/:id`، `/orders/draft*`، `/direct-sales/*`، `/orders/new` | `/orders` |
| `/schedule/:id` | `/schedule` |
| `/finance/*` (أحداث/سحب/حق المالك/G5) | `/finance` |
| `/suppliers/purchase/*` | `/suppliers` |
| `/cash/*` (محافظ/تحويل/توزيع/عدّ/عكس) | `/cash` |
| `/inventory/*` (مادة/حركة/عكس) | `/inventory` |
| `/profile` | `/` |
| مسار غير معروف | `/` |

صفحات المستوى ٢ تحمل بديلها الخاص عند فتحها من السياق الأعلى: مثلاً `/cash` مفتوح من
`/finance` يعرض رجوعًا لـ`/finance`؛ مفتوح من الرئيسية (`?from=/`) يرجع للرئيسية.

### 2.3 من يرسل المصدر (مطبّق في المجموعة ١)

- الرئيسية (كل الصفوف والبطاقات والأقسام) ترسل `?from=/`.
- العمل (الطلبات/المبيعات/المسودات/المواعيد) يرسل `?from=/orders`.
- مالي يرسل `?from=/finance` لكل مساراته الصادرة (٢١ رابطًا).
- أدواتي يرسل `?from=/tools` في جسر التقدير→المسودة.
- صفحة الأساس ترسل `?from=%2Ffoundation` لبطاقة الاستيراد الموجه.
- المحافظ/الموردين/الأطراف/المواد/الجدول ترسل مصدرها في صفوفها.

## 3. معجم الوصلات العميقة

```
?focus=<known-focus>   فتح قسم أو فعل معيّن داخل الصفحة الهدف
?layer=<known-layer>   فتح طبقة عرض داخل الصفحة (مالي)
?mode=cover            طبقة كاملة فوق الشاشة القائمة (محجوز)
?event=<event-id>      تركيز حدث مالي محدد (مالي — قائم قبل المجموعة ١)
?from=<internal-path>  مصدر الرجوع
?to=<destination>      وجهة داخلية (محجوز للمجموعات اللاحقة)
```

### 3.1 قيم `focus` المعتمدة (توسيع القاموس يتطلب تحديث هذا الملف)

| القيمة | الشاشة الهدف | ماذا تفتح |
|---|---|---|
| `capacity` | `/schedule` | طبقة «التكرار والسعة» حيث يُقرأ ضغط اليوم ويُحدَّد |
| `recurrence` | `/schedule` | نفس الطبقة (مصدر التكرار) |
| `guided-import` | `/settings` | بطاقة «إدخال موقف افتتاحي» مباشرة مع تمرير إليها |
| `export` | `/settings` | محجوز — حماية البيانات/التصدير |
| `today` | `/` | محجوز — قائمة اليوم |
| `priority` | `/orders` | محجوز — الأولوية الآن |

### 3.2 قواعد دفاعية (مُختبرة في navigationContract.test.ts)

- أي قيمة مجهولة أو مشوهة تُهمل وتفتح الصفحة كالمعتاد — لا انفجار ولا سلوك غامض.
- `?event` يقبل فقط `[A-Za-z0-9_-]{1,64}`.
- البدء البارد والتحديث يحفظان النية لأن المسار+المعاملات في URL نفسه (wouter history)؛
  PWA navigateFallback يخدم `/index.html` فتظل الوصلة تعمل دون اتصال.
- تنبيه الرئيسية لا يهبط أبدًا على قائمة عامة غير مفلترة: بند «اليوم» يفتح مصدره
  (الطلب/المسودة/الموعد) مباشرة، وبند السعة يفتح `/schedule?focus=capacity`.

## 4. سياق الطلب في الوصلات العميقة (Scope E)

`/inventory/movement/consume?order=<order-id>&from=/orders/<order-id>`:
- `order=` يعبّئ الطلب مسبقًا في محرر الاستهلاك (ينتقل إلى المجموعة المالية لاحقًا
  مع ربط أعمق؛ حاليًا تعبئة اختيار فقط).
- `from=` يعيد المحرر إلى تفاصيل الطلب الأصلي بعد الحفظ أو الرجوع.
- نفس النمط ملزم لأي محرر مستقبلي يُفتح من سياق سجل (تصحيح المورد، تعديل سعر الطلب...).

## 5. حماية المدخلات غير المحفوظة

- المحررات العميقة: الحوار ثلاثي الخيارات القائم (`UnsavedChangesGuard`) —
  «ابقَ / احفظ واستمر / اخرج دون حفظ» مع حارس popstate/beforeunload.
- ورقة الإضافة العابرة (Scope B): سؤال هادئ من خيارين عند وجود مدخل مكتوب:
  «في رقم مكتوب — تسجّله أو تتجاهله؟» → «سجّله الآن» / «تجاهل ما كتبت».
  الإغلاق النظيف بلا سؤال. لا إعادة تعيين صامتة أبدًا.
- الإعداد الأول: المسودة تُحفظ محليًا أثناء الكتابة (`micro.setup-draft.v1`)
  وتُستعاد بإشعار — لا حاجة لحوار لأن شيئًا لا يُفعلًا يُفقد.

## 6. أنماط التغذية الراجعة المشتركة (ملزمة للمجموعات اللاحقة)

| الحالة | النمط | الأداة القائمة |
|---|---|---|
| نجاح | ماذا حدث + القيمة المتغيرة المهمة، دون إجبار مغادرة الشاشة | وصل ورقة الإضافة (`micro-sheet-receipt`)، `micro-save-note` |
| خطأ | المشكلة + الفعل التالي بالعربية، من رسالة الخدمة لا نص مختلق | `micro-field-error` برسالة الخدمة |
| فراغ | يعلّم ما هذه الشاشة + فعل أول مناسب | `micro-empty-state` / `micro-empty-inline` |
| مجهول | «غير محدد بعد» / «غير متاح» + الخطوة التالية — لا صفر مختلق | بطاقات حقائق الرئيسية |
| محلي/دون اتصال | «بياناتك محفوظة على هذا الجهاز» فقط عند الصلة؛ لا ادعاء مزامنة | `micro-home-locality`، `micro-local-truth` |
| دون اتصال فعلي | يظهر فقط عند غياب الشبكة فعليًا أو عند عمر تصدير ذي صلة | PWA runtime notice |

قواعد عامة: لا نجاح معلن قبل اكتمال الكتابة المحلية؛ لا ادعاء سحابي أو نسخ تلقائي؛
العملة `د.أ` بعد الرقم؛ الحالة لا تُ بلون وحده (أيقونة + نص).

## 7. ما لم يتغير

- القشرة الخمسية كما هي — لا مقعد سادس؛ `/profile` سطح يُفتح من الترويسة/الإعدادات.
- `/review` يقود إلى `/finance`.
- المسارات الداخلية لمسودة-الاتفاق-التكلفة تبقى تسلسلًا داخليًا ثابتًا (لا ping-pong).
