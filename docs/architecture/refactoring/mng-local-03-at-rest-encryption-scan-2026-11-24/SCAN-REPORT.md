# مسح قراءة-فقط — موضع تشفير سجلات IndexedDB في المخزن (MNG-LOCAL-03، الشطر الثاني)

**المرجع:** أمر المالك `MNG-LOCAL-03-06-PASSWORDLESS-REMEDIATION-PROMPT-EN.md` (12AA) §4A.4 «احمِ بيانات IndexedDB نفسها لا الملف فقط» و§5 البوابة الهيكلية · الفرع `manus/mng-local-03-06-remediation-20261124` · الشجرة الممسوحة = شجرة العمل الحية عند بدء هذا التقرير (رأس الكود الحامل بعد تنفيذ شطر التصدير) · 2026-11-24.
**نوع المسح:** قراءة-فقط على الشجرة الحية، نطاقه **البنية المعنية بالطلب** (طبقة التخزين المحلي ومسارات النقل) لا المستودع كله — البوابة الهيكلية المطلوبة هنا مُثارة بموضع واحد محدد، والمسح لا يفتح بوابة إعادة تنظيم عامة.

## ١. الوقائع المقاسة على الشجرة الحية (لا انطباعات)

| القياس | القيمة | الأثر |
|---|---|---|
| دوال `IndexedDbLocalStore` | 154 | كل قراءة/كتابة سجل تمر بها |
| معاملات IndexedDB مباشرة داخل المهايئ (`database.transaction`) | 52 + 2 في `indexedDbSnapshot.ts` | التزامن الحرج أدناه |
| مواضع كتابة سجلات (`put`/`add`) | 95 | كل واحد يستلزم تشفيرًا قبل فتح المعاملة |
| مواضع قراءة نتائج (`get`/`getAll`/`openCursor`/`index()`) | 98 | كل واحد يستلزم فكًا بعد الإتمام |
| نقطة تردد واحدة مشتركة | `indexedDbPrimitives.ts` (٥ دوال مفردة) + `connection()` | تغطي جزءًا فقط — المعاملات المتعددة لا تمر بها |
| دقة التزامن: تسليم النتائج | داخل معالجات نجاح IDB **متزامنة** (`request.onsuccess = () => resolve(...)`) | WebCrypto غير متزامن حصرًا — لا يمكن إدخال فك داخل المعالج دون تغيير الترتيب الدلالي |

**الصراع التقني الموثق:** AES-GCM عبر WebCrypto غير متزامن حصرًا؛ بنية المهايئ الحالية (52 معاملة مباشرة) تحسم قراءة كل سجل وتفتح معاملاتها داخل `new Promise(resolve => {...})` — إدخال codec مشفّر لكل سجل يتطلب: (١) تشفير القيم **قبل** فتح المعاملة (المعاملة تلقائيًا تلتزم عند خلو الطابور فلا يمكن تأخير put بعد فجوة غير متزامنة)، (٢) فك النتائج **بعد** إتمام المعاملة ثم الحسم — أي إعادة هيكلة توقيع/تسليم 52 مسار قراءة/كتابة من أصل 154 دالة، مع مسار السلاحف الحرج: التحقق داخل معاملة واحدة (مثل `commitOrderUpdate`: get → validate → put **داخل المعاملة نفسها**) الذي يفقد إمكانية التحقق المتزامن إذا أُدخل فك غير متزامن بين الخطوتين. هذا **تغيير هيكلي** بحكم أمر المالك §5، لا «إصلاح محدود».

## ٢. تصنيف النتائج (المعيار الرباعي)

| النتيجة | التصنيف | المبرر |
|---|---|---|
| `indexedDbPrimitives.ts` (٥ دوال مفردة) | **PRESERVE** | نقطة تردد نظيفة قائمة — موجة A تبدأ منها بلا إعادة كتابتها |
| المعاملات المفردة-المخزن (52 معاملة، 95 موضع كتابة) | **FIX_NOW (بعد قرار المالك — موجة B)** | جذر الشطر الثاني: بدونها يبقى السجل في المخزن نصيًا |
| `indexedDbSnapshot.ts` (read/replaceSnapshot ذريّ متعدد المخازن) | **PRESERVE مع تعديل موجة B** | الدور الذري محفوظ؛ التعديل = فك/تشفير خارج المعاملة لا داخلها |
| ترحيل السجلات القائمة (نصي → مشفّر) | **FIX_NOW (موجة C)** | يخص «إعادة تعميد السجلات المستوردة فورًا» (§4A.7) المعلّقة على البوابة نفسها |
| بوابة قفل جلسة الإقلاع (مراسم المصادقة قبل أول قراءة) | **DEFER** | القرار المنتج: متى تُطلب مراسم الفتح — عند كل إقلاع أم عند أول فعل حساس؛ يقرره المالك مع الموجات |
| `MemoryLocalStore` | **PRESERVE** | توافق المهايئين قائم؛ الموجة B تُطبق عليه ميكانيكيًا بالاختبار نفسه |
| نقل ملفات أو «طبقة features/» أو تقسيم المهايئ | **OUT_OF_SCOPE** | ممنوع صراحة (§5) ولا يلزم لهذه الغاية |
| التشخيص (localStorage) ومفاتيح المسودات | **OUT_OF_SCOPE** | خارج نطاق MNG-LOCAL-03 (سجل الأمن يحدد سجلات IndexedDB) |

## ٣. الموجات الدنيا المقترحة (لا تنفيذ قبل قرار المالك)

- **الموجة A — أساس الكودك (غير مدمّر):** وحدة `sealedRecordCodec` (AES-256-GCM بمفتاح الجلسة نفسه من مراسم 12AA القائمة، مفتاح لكل قاعدة بمعرف مخزن منفصل داخل المراسم) + تحويل الدوال الخمس في `indexedDbPrimitives.ts` للتشفير قبل المعاملة والفك بعدها. **القبول:** sentinel مالي غير موجود في أي قيمة مخزنة عند الفحص المباشر للمخازن + دورة كاملة بالاختبارات القائمة للمهايئين بلا تعديل + أداء القراءة الشائعة داخل 1.25×. **الرجوع:** الموجة معزولة بقيمة راية في الوحدة — إيقافها يعيد السلوك الحالي حرفيًا.
- **الموجة B — المعاملات المتعددة (95 موضعًا، آلي):** نقل التشفير/الفك خارج جسم المعاملات الـ52 (تشفير القيم قبل `database.transaction`، فك النتائج بعد `oncomplete` قبل الحسم) مع الحفاظ على البنية الذرية؛ **مخاطرة موثقة:** التحقق المتزامن من قيم مقروءة (نمط get → validate → put داخل المعاملة نفسها) يتطلب فكًا غير متزامن قبل الحسم — نقطة أعلى خطورة في الخريطة كلها، تُدار بنمط «اقرأ-فُكّ-افتح-المعاملة» موثقًا باختبار مضاعف لكل مسار. **القبول:** مجموعة توافق المهايئين كاملة خضراء + جرد عدّي: 95/95 موضعًا مطبقًا. **الرجوع:** كل مسار مستقل — فشل مسار واحد يوقفه وحده.
- **الموجة C — الترحيل الآمن المتقطع-الاستئنافي:** لكل سجل: اقرأ، فُكّ-أو-مرر (مظروف سليم = مهاجر)، شفّر، اكتب فوقه، تحقق قبل إسقاط النسخة النصية (لا نسخة نصية تُسقط قبل تحقق نظيرها المشفّر)؛ الانقطاع في أي لحظة يترك قاعدة قابلة للاستئناف (كل سجل مستقل). **القبول:** اختبار انقطاع مصطنع في منتصف الترحيل ثم استئناف = صفر فقدان (جرد عدّي) + سجلات متبقية نصية = 0. **الرجوع:** النسخة النصية لا تُمس حتى تحقق المشفّر — حد رجوع ذاتي.
- **الموجة D — بوابة جلسة الإقلاع (قرار منتج):** مراسم WebAuthn عند أول قراءة لقاعدة مشفّرة (تعتمد الموجتين A-C). **القبول:** لا قراءة تتم دون مرسمة ناجحة + لا مطالبة كلمة مرور مكتوبة + إقلاع قاعدة غير مشفرة بلا مرسمة (توافق قديم). **الرجوع:** راية تعطيل → سلوك اليوم.

**الترتيب والتبعيات:** A ← B ← C (C تعتمد B)؛ D موازية بعد C. أثر الحزمة: ~+3-5KB gzip في قطعة transfers الكسولة (لا مسار إقلاع). أثر أداء متوقع: O(1) لكل سجل (AES-GCM ~µs) بلا تغيير بنية المعاملات؛ القياس الفعلي مطلوب بعد الموجة B على أضعف جهاز مدعوم (يُدمج مع قياس MNG-LOCAL-06 نفسه).

## ٤. ما نُفّذ خارج هذه البوابة الآن (شطر الملف — مكتمل)

مظروف النسخ المشفّر AES-256-GCM (الثنائي `MCR1`) + مراسم مفتاح WebAuthn-PRF + تشفير أسطح التنزيل الثلاثة + استيراد المظروف/الوارث + فتحة المفتاح (مخطط 43) — مفصّلة في `EXECUTION-REPORT-AR.md`. **الشطر الثاني (تشفير السجلات في المخزن) لم يُنفّذ ويستقر عند هذه البوابة بانتظار قرار المالك بالموجات أعلاه.**

**قرار المالك الأصغر المطلوب:** إقرار الموجات A→D (أو تعديلها) — لا تنفيذ هيكلي قبل إقرار صريح وفق §5 من الأمر نفسه.
