## 1. الملخص التنفيذي

يمسح هذا التقرير الهيكل الكامل للمنتج المتصل على الفرع الحي: عامل BFF بإنتاج 7,454 سطرًا (زائد 3,096 سطر اختبار فوق workerd حقيقي و515 سطر SQL بخمس ترحيلات و29 جدولًا حيًا)، و13 صفحة متصلة lazy-loaded تستهلك باب الشبكة الوحيد، وقشرة واحدة (Shell واحد لا قشرتين) تحمل اليوم تنقلًا مالكًا-المركز ثابتًا. النتائج الرأسية الثلاث:

1. **البنية المتصلة محكومة ومختبرة لكنها مبنية على D1 بلا طبقة Workspace، والقرار المالكى الجديد (PostgreSQL واحد عبر Hyperdrive + هوية/قشرة مشتركة) يمر من مفصل واحد رقيق وعريض.** كل وصول قاعدة البيانات يمر بواجهة `Db` وحيدة (`worker/db/d1.ts:10-13` — `prepare`+`batch` فقط) لكن الاستعلامات نفسها مضمنة في 22 ملفًا (215 عبارة مُعامَلة) مع قائمة محصورة تمامًا من الصياغات الخاصة بـSQLite/واجهة D1 (4×`INSERT OR IGNORE`، 12×`json_extract`، 2×`batch`، 10×`meta.changes`، 5×`AUTOINCREMENT`، علامات `?` الموضعية) — كلها محصورة بمواضعها في §10 أدناه، ما يجعل التبديل إلى PostgreSQL تعديلًا ميكانيكيًا واسعًا لكن محدود المخاطر إن سُيّج بترحيلات PostgreSQL مرتبة وحزمة اختبار على قاعدة حقيقية. **لا يوجد أي مفهوم Workspace/tenant/عضوية متعددة** — `network_membership` الوحيدة تحصر الدور في `admin` فقط (`0001_init.sql:23-30`)؛ مورد/سائق مشتقان من جداول ملفاتهما وقت الطلب (`authorization.ts:46-113`).
2. **قشرة واحدة خماسية اليوم لا تعرف الجلسة ولا السياق:** بوابة الإقلاع المحلية تدفع كل زائر أول إلى `/setup` ولو كان ضيف سوق أو سائقًا (`StartupGate.tsx:67`)؛ الجلسة تُجلب صفحة-صفحة (13 جلبًا مستقلًا) بلا مزوّد قشرة، وحقلا `session.driver`/`session.vendor` حمولة ميتة في العميل؛ الشريط السفلي ثابت لكل الأدوار؛ بوابة السائق بلا أي مدخل داخل التطبيق (رابط خارجي فقط). هذه ليست عيوبًا في المسار السابق (كانت خارج نطاقه) لكنها **فجوات FIX_NOW أمام قرار المالك الجديد** (هوية واحدة + قشرة بمداخل أربعة + سياق سائق مقيّد + Ask Micro في كل سياق مصرح) — كلها مركّبة في أربعة ملفات قشرة معروفة الحدود (§4).
3. **Ask Micro غير موجودة إطلاقًا ككود** (إعلان «قريبًا» صادق فقط — `futureServices.ts:33-37` + عنصر قائمة واحد في `AppHeader.tsx:173-179`)، وOD-18/OD24 اللذان أجّلاها **يُزيحهما قرار المالك الجديد لهذه المهمة حصرًا** (تسجيل Phase A)، وفجوات الجاهزية المصدّقة سابقًا (تدقيق `delivery_scoped` والمرفوضات، OD18 للتقييم الذاتي، حد معدل `driverPublicProfile`، حل البلاغات، `role=alert`، عزل `bdi`، Cron/Pages) كلها **مؤكدة حية بالكود في هذا المسح** وتُغلق داخل الأطوار المرخصة أو تُصنف بدقة (§8).

## 3. جرد الوحدات وحدود الميزات (البعد ١)

**المنتج اليوم وحدتان حقيقيتان داخل قشرة SPA واحدة** (`main.tsx → App.tsx → PrototypeServicesProvider → MicroRouter → MicroAppShell`):

### 3-أ. Manage المحلي (محفوظ — خارج نطاق أي موجة هيكلية)

- المسار الإلزامي React → Application (39 بيتًا + `resultCodes`) → Domain (`src/domain/` نقي بموجب ESLint `eslint.config.js:26-68`) → `PrototypeLocalStore` → IndexedDB (قاعدة `micro-prototype-local`، **41 مخزنًا**، `indexedDbStores.ts:11-101`) + قاعدة استعادة منفصلة `micro-prototype-restore`.

- الثوابت: `localSchemaVersion=41`/`localExportVersion=34` + 28 زوجًا موروثًا — مقيدة بنحو 15 ملف اختبار مثبت القيم الحرفية (`exact-values.cross-surface.test.ts:239-240` وغيرها). **أي جسر Manage لا يلمسها** (انظر F-24).

### 3-ب. الطبقة المتصلة (Market/Delivery/Driver)

- **العامل:** 7,454 سطر إنتاج في `apps/prototype-web/worker/` (أكبر الملفات: `api/marketListings.ts` 600، `api/deliveryExecution.ts` 499، `api/deliveryRequest.ts` 437، `api/deliveryChange.ts` 405، `api/market.ts` 392، `api/marketReview.ts` 375، `migrations/0001_init.sql` 374، `api/deliveryReview.ts` 371). 77 مسار API (11 أساس + 24 سوق + 42 توصيل) عبر موجّه محلي؛ كلها معلمة 100% عدا 3 عبارات ثابتة حرفية بلا مدخلات مستخدم.

- **الهوية/الجلسة:** OIDC Google بتحقق صارم (`oidc.ts:55-169`)؛ جلسات D1 مجزأة SHA-256 بلا سر توقيع (`session.ts:30-45`)؛ CSRF مزدوج Origin+ترويسة (`csrf.ts:33-42`)؛ bootstrap أدمن مرة واحدة بشرط صفر مدراء + مطابقة بريد (`session.ts:119-140`).
