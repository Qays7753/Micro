## 0. سلسلة السلطة — إلزامية نصًّا

```text
AGENTS.md والعقود (وأعلى منها: السياسات المالية الحية والكود حيث تحكم)
    → REFACTORING-PLAN-A-TO-Z.md (v1.3 — المرجع المعماري الكنسي)
        → هذه المهارة (إجراء تنفيذ وتفتيش)
            → إجراءات المسح/الفحص/الموجات
```

**هذه المهارة ليست سلطة معمارية ثانية.** هي إجراء تشغيلي مشتق بالكامل من الخطة الكنسية، وكل بند تفتيش فيها يشير إلى بند الخطة الذي اشتُق منه (§13). بالتالي فهي:

- **لا** تعيد صياغة سياسة مالية أو معنى محاسبيًا (سلطة العقود وAGENTS)؛
- **لا** تستبدل `AGENTS.md` أو عقدًا أو الخطة الكنسية أو `OWNERSHIP-AND-TRUTH-REGISTRY.md`؛
- **لا** تفوّض تغييرًا بنيويًا بذاتها — التفويض يأتي من قبول المالك المسجل فقط؛
- **لا** تحوي سرًا أو رمز وصول أو قيمة اعتماد (أبدًا)؛
- **لا** تحمل قائمة أعمال حقيقية ثانية أو سجل ملكية ثانيًا؛
- **لا** تصنف طيارًا (pilot) اكتمالًا — أبدًا (الخطة §9؛ عقد التنفيذ §10.3).

## 1. محفزات الاستدعاء — متى يجب استدعاء هذه المهارة

تُستدعى **قبل** أيٍّ من التالي (لا بعده):

1. أي مسح بنيوي/معماري/تنظيم كود (قراءة فقط أو تنفيذ)؛
2. أي موجة من موجات إعادة الهيكلة (A→Z) أو فتح شريحة منها؛
3. أي نقل أو تقسيم أو إعادة تسمية ملف إنتاج أو اختبار أو سكربت؛
4. أي إعادة كتابة استيراد أو إنشاء باب عام (barrel / public door)؛
5. أي استخراج منفذ قدرة (capability port) أو تغيير واجهة التخزين؛
6. أي عزل/تحريك محوّل (IndexedDB / Memory / Transfer / Clock / Diagnostics)؛
7. أي إضافة أو تشديد أو تحديث حارس أو أساس راتشة؛
8. أي تحديث لسجل الملكية أو جرد الحجم/المسؤولية أو خريطة الاختبارات؛
9. أي تصنيف ملف جديد داخل نطاق المسح (إنتاج/اختبار/سكربت/مولّد/عهدة/إعداد)؛
10. أي استثناء معماري أو إعفاء أو ADR أو بطاقة إصلاح (Repair Card).

القاعدة (من الخطة §11 وعقد التنفيذ §1.1): **المرجع أولًا** — تُقرأ الخطة الكنسية كاملة من المستودع الحي قبل أي استنتاج أو اقتراح حد أو لمس ملف.

## 2. التحقق المسبق الإلزامي (Preflight + Live-SHA)

قبل أي عمل (مسحًا كان أو موجة):

1. **اقرأ الخطة الكنسية كاملة من المستودع الحي** (`docs/architecture/refactoring/REFACTORING-PLAN-A-TO-Z.md`) — لا مقتطفًا مخزنًا ولا ملخص محادثة — ووثّق إصدارها وتاريخها وحالتها والتزام المسار الحي.
2. **تحقق من الرأس الحي:** `git fetch origin --prune` ثم `git rev-parse origin/main` — قارن مع نقطة الأساس المقبولة؛ عند أي اختلاف سجّل `STATE_DRIFT` وأعد التثبيت على الرأس الحي (لا تعيد التشغيل ولا تكتب فوق التاريخ).
3. **افحص حالة التنسيق:** PRs المفتوحة، Workstreams النشطة (`python3 scripts/operations-control/validate.py`)، نظافة الشجرة (`git status --porcelain`)، Claim النشط.
4. **اقرأ ذيول السجلات الحية:** آخر قيدين من `AGENT-SEQUENTIAL-WORKLOG.md`، رأس `OWNERSHIP-AND-TRUTH-REGISTRY.md`، رأس `FILE-SIZE-AND-RESPONSIBILITY-REGISTER.md`، و`current-state.md` §8.2.
5. **صحّة البيئة:** أعلن `ENVIRONMENT_HEALTH: NORMAL | HIGH_LOAD | LOW_DISK | PROCESS_LIMIT | UNKNOWN` قبل أي تحليل/اختبار/بناء مكلف؛ اتبع ترتيب الاسترداد الآمن عند الضغط (لا `git clean -fdx`، لا `git reset --hard` كإجراء أداء، لا حذف ملفات مجهولة الملكية).
6. **مفرد الكاتب:** تأكد من كاتب واحد فقط على الفرع في أي لحظة؛ المراجعون والمدققون قراءة فقط بين الكتابات.

## 3. إجراء المسح القرائي — خمسة اختصاصيين (من الخطة §7-C وعقد التنفيذ §6)

عند فتح مسح (كامل أو محدود)، يعمل خمسة اختصاصيين **قراءة فقط** (يجوز التوازي لأنهم قراءة؛ يُمنع عليهم أي كتابة في المستودع أو الفرع أو PR أو السجلات):

| الاختصاصي | النطاق الحصري |
|---|---|
| **S1 — حدود الوحدات والميزات والمسؤوليات** | حدود الحزم/مساحات العمل، الملكيات، الخرائط الحالية والهدف، الأبواب العامة والاكتشافية، الملفات المتضخمة والمختلطة، التركيب (domain/application/storage/adapter/presentation)، تصنيف كل ملف: مكتمل/جزئي/محفوظ/مؤجل/غير مصنف |
| **S2 — سلامة المجال والتخزين والبيانات والتوافق** | ملكية المجال وثوابته، `PrototypeLocalStore` ومجموعات القدرات، محولا IndexedDB/Memory، حراس الكتابة والذرية، النقل/التصدير/الاستيراد والتوافق التاريخي، إصدارات المخطط والترحيلات واللقطات وحدود الرجوع، مصادر الحقيقة والقيم المكررة، العواقب المالية/الحساسة — **دون أي تغيير سلوك** |
| **S3 — الاعتماديات والأسطح العامة والطبقات والدورات والنمو** | اتجاه Presentation→Application→Domain، علاقات Application بالمنافذ والمحوّلات، الاستيراد العميق والأبواب الناقصة، حدود UI→مجال وتطبيق→عرض **على مستوى الاعتمادية فقط**، الدورات التشغيلية والنوعية، البراميل والشيم، تغطية الحراس الحالية، الراتشات، قيود الحزمة والأداء |
| **S4 — الاختبارات والعقود والتوثيق والعمليات** | مشهد الاختبارات كاملًا، مطابقة اختبار→وحدة، العقود وسجلات القرار، ملكية الملفات المولدة ومسارات إعادة التوليد، مصادر Operations Control وviews المولدة، Provenance الفروع/PRs/الSHAs/التقارير، السجلات المتقادمة أو المتناقضة، أدلة القبول والرجوع |
| **S5 — المراجعة المعادية المستقلة** | يتحدى S1–S4 والتوليف: مصدر حقيقة ثانٍ خفي؟ طيار موصوف اكتمالًا؟ ملف ضخم غير مصنف؟ مشكلة مخبأة داخل PRESERVE بلا دليل؟ تغيير دلالي مخبأة داخل نقل؟ شيم بلا شرط إزالة؟ استثناء بلا مالك/سبب/تاريخ مراجعة؟ حارس لا يفشل فعلًا على انتهاك اصطناعي؟ تقرير يدعي فحصًا أو دمجًا لم يُتحقق؟ عمل منصات مستقبلية يهرب إلى العمل البنيوي؟ |

**قاعدة التوليف:** مُولِّف واحد يصالح الاختلافات وينتج **تقريرًا كنسيًا واحدًا** (لا تقارير اختصاصيين دائمة منفصلة). كل خلاف يُحسم بالدليل ويُسجل في جدول مصالحة.

## 4. أصناف الأدلة — ستة بالضبط (لا يُضاف صنف)

لكل عبارة مادية في أي تقرير أو بطاقة أو سجل موجة، صنف واحد:

- `VERIFIED` — مُثبت بأمر مُشغَّل أو فحص حي أو بصمة/قيمة مطابقة؛
- `INFERRED` — استنتاج من أدلة حية غير مباشرة (يُذكر الأساس)؛
- `UNVERIFIED` — قول لم يتحقق بعد (لا يُستخدم لإغلاق بند)؛
- `NOT_EXECUTED` — فحص واجب لم يُشغَّل عن قصد (يُذكر السبب والنطاق)؛
- `DEFERRED` — مؤجل بقرار موثق (يُذكر القرار)؛
- `BLOCKER` — مانع يحجز البند (يُذكر المانع وحد التوقف).

## 5. تصنيفات المالك — خمسة بالضبط (من الخطة §5) + شريط WATCH

- `FIX_NOW` — توثيق أو حارس أو دريفت دون تغيير معنى؛
- `PRESERVE` — سليم ومثبت؛ لا يُنقل لمجرد النظافة؛
- `DEFER` — فكرة مستقبلية أو مساحة رفيعة؛
- `OUT_OF_SCOPE` — كود أو معنى أو مخطط أو UI خارج الموجة؛
- `OWNER_DECISION_REQUIRED` — تعارض لا يجوز تخمينه.

شريط الحجم (الخطة §7.3) إشارة مراجعة لا أمر تقسيم: `NORMAL` <400 / `WATCH` 400–799 / `SPLIT_CANDIDATE` 800–1,199 / `SPLIT_NOW` ≥1,200 متعدد المسؤوليات (أو خرق حدود خطير بأي حجم). ملف كبير أحادي المسؤولية المتماسكة قد يبقى بسبب ومالك وحد نمو.

## 6. قائمة تفتيش A-to-Z (من الخطة §7 — جدول الموجات)

كل حرف يُقوَّم ضد تعريفه في الخطة §7 لا ضد نطاق برنامج سابق:

| الحرف | الموجة (الخطة §7) | شرط الخروج |
|---|---|---|
| A | Freeze & Charter | اعتماد المالك للميثاق |
| B | Scan Reconciliation | تقرير فجوات ومصادر أدلة واضح |
| C | Read-only Structure Scan | تقرير مصنف (VERIFIED/INFERRED/UNVERIFIED) + سجل حجم ومسؤولية وتغطية كامل |
| D | Parity Baseline | خط أساس محفوظ وPass/Fail صريح وحدود توافق ورجوع |
| E | Findings Acceptance | **بوابة Micro الإلزامية** — المالك يقبل المسح والخريطة |
| F | Ownership Registry | تغطية كاملة أو تعارضات مسجلة |
| G | Architecture Target Rules | قبول قواعد الهدف دون فرض مسارات نهائية |
| H | Guard Observe | خط أساس حتمي مع استثناءات واضحة |
| I | Guard Ratchet | CI يرفض مخالفة جديدة دون تعديل Production |
| J | Public Surface Pilot | Typecheck واختبارات وحارس ناجحة |
| K | Import Consolidation | انخفاض Deep Imports بلا تغير Bundle أو سلوك |
| L | File-Move Pilot | الملف مطابق والاختبارات خضراء ولا مستهلكين مجهولين |
| M | Measured Consolidation | تحسن مقاس دون زيادة Coupling |
| N | Port Inventory | كل Method مصنف بمالك ومستهلك وسلوك |
| O | Port Extraction | Local وMemory ينجحان في نفس Contract Tests |
| P | Adapter Boundary | Conformance وRound-trip وEntity Touchpoints ناجحة |
| Q | Test & Documentation Map | Coverage لا تنخفض والوثائق تطابق Registry |
| R | Semantic Repair Track | مسار مستقل بقرار مالك — لا يُحسب Structural Completion إلا بعد إغلاقه |
| S | Schema/Export Track | لا تغيير Version أو Bytes أو Historical Meaning |
| T | UI Boundary Track | يفتح فقط بقرار مالك — بواة UI مستقلة |
| U | Vector Portability | عند مستهلك غير TypeScript فعلًا |
| V | Mobile Gate | عند قرار محمول حقيقي |
| W | Python/API Gate | عند حاجة API/Auth/Sync حقيقية — Python لا يملك الحقيقة المالية |
| X | Service Extraction Assessment | ADR بأرقام التشغيل والفشل والتكلفة والرجوع |
| Y | Completion Audit | لا Drift غير مفسر وكل Finding مغلق أو مقبول مؤجلًا |
| Z | Closure & Moratorium | توقيع المالك على Structural Completion |

**عائلات التفتيش السبعة عشر** (كل موجة/مسح يثبت أيها يمسها): (1) حدود الوحدات والميزات؛ (2) الملكية والمصدر الواحد للحقيقة؛ (3) تركيب التخزين والمنافذ والمحوّلات؛ (4) حدود المحوّلات والطرفيات؛ (5) اتجاه الطبقات؛ (6) الأسطح العامة والاكتشافية؛ (7) الدورات والاستيراد العميق؛ (8) أحجام الملفات وشرائطها؛ (9) الاختبارات المباشرة وCharacterization/Contract/Golden؛ (10) العقود وسجلات القرار (ADRs)؛ (11) التوثيق والفهارس؛ (12) الملفات المولدة ومسارات إعادة توليدها؛ (13) حدود الأمان والصلاحيات؛ (14) الأداء والميزانية والحزمة؛ (15) حدود الرجوع والاستعادة؛ (16) التوافق التاريخي والتصدير/الاستيراد؛ (17) سجلات العمليات وProvenance.

## 7. متى يكون كل مُنتج إلزاميًا (من الخطة §7.1)

|---|---|
| **Repair Card** (بطاقة إصلاح) | كل مكتشف يدخل موجة — بمعرف ثابت ونطاق وحدود مسموحة/ممنوعة ومعايير قبول وحد رجوع |
| **Consumer Inventory** (جرد مستهلكين) | كل نقل/تقسيم/تقسيم استيراد/استخراج منفذ — قائمة مستهلكين حية كاملة قبل أي حركة |

| **Contract Test** (عقد اختبار) | كل قدرة مستخرجة — المحوّلان (IndexedDB/Memory) ينجحان في نفس العقود (الخطة §7-O) |

| **Guard** (حارس قابل للتشغيل) | كل قاعدة نريد حمايتها (الخطة §7.1-3) — مع اختبار إيجابي **وسلبي** يثبت أنه يفشل فعلًا على انتهاك اصطناعي |
| **Rollback Plan** (خطة رجوع) | كل موجة — Base SHA وحد رجوع؛ ومبدأ 18: لا يوصف revert بأنه آمن للبيانات تلقائيًا بعد كتابة بنمط جديد |

## 8. البوابات (من الخطة §7-A/E وعقد التنفيذ §10)

1. **بوابة التقرير فقط (Report-only):** المسح لا يكتب شيئًا في المستودع؛ ناتجه قسم مؤرخ واحد في الخطة/التقرير الكنسي + PR تقرير واحد **لا يُدمج**.
2. **بوابة قبول المالك (Owner-acceptance):** لا موجة بنيوية قبل قبول المالك المسجل في worklog/Operations Control. لا يُستنتج القبول من CI أخضر أو توصية تقرير أو طيار سابق أو وجود التعليمة ذاتها.
3. **بوابة الموجة (Per-wave):** الفحوص المركزة + CI خضراء على رأس الموجة قبل الانتقال للتالية؛ أي فشل = توقف عند الحد الآمن وتسجيل المانع.
4. **الاستثناء الوحيد بعد التفويض المجمع** (عقد التنفيذ §10.1): حزمة قرار واحد موحدة عند أي تغيير يمس المعنى المالي/المخطط/التصدير-الاستيراد/التاريخ/الأمن/الصلاحيات/UI المحمي/عقدًا أعلى سلطة/منصة جديدة/عملية دمج أو حذف تتطلب قرارًا منفصلًا.

## 9. قواعد الموجة وPR المضبوطة (من الخطة §7 وعقد التنفيذ §12)

- **كاتب واحد** في أي لحظة؛ مراجعون/مدققون قراءة فقط بين الكتابات.
- **فرع طويل العمر واحد** للبرنامج + حدود PR/commits قابلة للمراجعة المستقلة.
- **لا كتابة مباشرة على `main`** — أبدًا.
- **حدود الكتابة لكل موجة** من جدول الموجات المقبول حصرًا (مسارات مسموحة/ممنوعة)؛ أي توسع خارج الحدود = توقف وتسجيل.
- **السجلات:** حدّث مصادر JSON ثم شغّل المولد الرسمي (لا تحرير يدوي لملفات `generated/` أو Excel)؛ قيد worklog لكل موجة (التاريخ، Base SHA، المنفذ، الفحوص بأكواد خروجها، حد الرجوع، التسليم التالي).
- **لا نقل جماعي أعمى** — كل حركة بجرد مستهلكين ودليل تكافؤ.

## 10. الممنوعات وشروط التوقف (من الخطة §6/§8 وعقد التنفيذ §13/§14)

**ممنوعات دائمة:** كتابة مباشرة على main؛ نقل جماعي أعمى؛ تعديل/اختلاق معنى مالي (معادلات/تقريب/تصنيفات/سياسات/حالات نتائج/مصطلحات)؛ تغيير `localSchemaVersion=38` أو `localExportVersion=30` في عمل بنيوي؛ مس الترحيلات/اللقطات/بايتات التصدير-الاستيراد/القبول التاريخي/ترتيب الرفض؛ حذف شيم توافق قبل إثبات المستهلكين وقبول المالك؛ حذف فروع/PRs قديمة/سجلات/تقارير/اختبارات/عهدات كتنظيف؛ لمس UI/UX البصرية (CSS/tokens/DOM/تنقل/نصوص)؛ إنشاء `common`/`utils`/`shared`/`services` كأوعية إلقاء؛ منصات مستقبلية أو بنية خلفية؛ إضعاف/تخطي/إزالة حارس أو اختبار لتمرير موجة؛ إخفاء تغيير دلالي/مالي/مخطط/أمني داخل diff بنيوي؛ ادعاء فحص أو دمج أو نشر لم يُتحقق؛ طباعة أو تخزين أسرار.

**توقف فورًا وسجّل المانع عند:** انحراف حالة لا يمكن مصالحته؛ عمل غير ملتزم سيُكتب فوقه؛ سجل قرارات مالك غائب أو ملتبس؛ حركة بلا جرد مستهلكين/دليل مصدر حقيقة/إثبات تكافؤ/رجوع؛ فعل يغير سلوكًا ماليًا/دلاليًا/مخططًا/تصديرًا/تاريخيًا/UI/أمنيًا/صلاحيات؛ فشل فحص أو CI واجب؛ توسع diff خارج الموجة المقبولة؛ شيم لا يمكن إثبات أمان إزالتها؛ ملف لا يمكن تصنيفه حاضرًا/تاريخيًا؛ الحاجة لسر أو workflow محمي؛ مسار مستقبلي بلا محفز حقيقي؛ تقرير يناقض الشجرة الحية.

## 11. تحقق كل موجة والتدقيق النهائي (من الخطة §9 وعقد التنفيذ §15/§16)

**لكل موجة (عقد 13 عنصرًا):** المعرف والحالة؛ المستودع/الفرع/Base/Head SHAs وPR؛ النطاق المقبول؛ المراجعون؛ الملفات المتغيرة وغير المتغيرة؛ جرد المستهلكين ودليل مصدر الحقيقة؛ الأوامر المشغَّلة بأكواد خروجها؛ نتائج CI؛ بيان أثر (مالي/مخطط/تصدير/تاريخ/UI/أمن/أداء)؛ نتيجة معايير القبول؛ حد الرجوع؛ المتبقي والخطوة التالية؛ صنف الدليل لكل ادعاء مادي.

**معيار الإصلاح الجذري (عقد التنفيذ §10.3):** لكل مكتشف مقبول، سجّل: `ROOT_CAUSE` / `SHORT_TERM_SAFETY_MEASURE` / `LONG_TERM_REMEDIATION` / `WHY_THIS_BOUNDARY_IS_THE_RIGHT_OWNER` / `WHAT_PREVENTS_REGRESSION` / `EXIT_EVIDENCE`. **لا يكفي:** راتشة فوق ملف متضخم قائم؛ حارس يترك انتهاكًا قائمًا بلا تفسير ومالك؛ توثيق مصدر مكرر بلا دريفت أو توحيد؛ طيار يوصف اكتمالًا؛ رفع سقف ميزانية دون تنميط وتقليل أولًا؛ `DEFER`/`WATCH`/`PRESERVE` بلا مبرر طويل الأجل موثق (مالك/سبب/حد نمو/محفز مراجعة/شرط خروج).

**التدقيق النهائي (Y):** مدقق مستقل عن المنفذ؛ يعيد fetch ويتحقق من كل SHAs الدمج؛ يعيد تشغيل الحراس كاملة والجناحين المطلوبين؛ يقارن الشجرة النهائية بمصفوفة A-to-Z؛ يتحقق من غياب مصدر حقيقة ثانٍ نشط، وشرط إزالة لكل شيم، وتوثيق كل استثناء، وإغلاق كل SPLIT_NOW غير UI ببيان أو قبول مالك، وتغطية القدرات والمحوّلات والاختبارات والعقود والمولدات، وثبات المخطط/التصدير/التاريخ/الدلالة المالية إلا بمسار معتمد منفصل.

**الإغلاق (Z) — معايير الخطة §9 الأحد عشر:** مسح حي مصالح مقبول؛ سجل يغطي الوحدات والمفاهيم والمستهلكين؛ حراس تعمل في CI وتمنع الزيادة؛ كل Move/Import Rewrite بجرد مستهلكين؛ الاختبارات واللقطات والتصديرات والاستيرادات المتوافقة متكافئة؛ لا تغيير مخطط/تصدير/تفسير تاريخي؛ لا تسلل UI أو منصة؛ لا حساب مالي مكرر غير مفسر؛ كل الاستثناءات مسجلة ولا تزداد ولا SPLIT_NOW غير مصنف؛ المالك يراجع تدقيق الإكمال ويوقع؛ ثم مجمد يمنع التوسع البنيوي بلا سبب مقيس وقرار جديد.

## 12. قاعدة الصيانة والترقيم

- تُحدَّث هذه المهارة **فقط** عند: (أ) تغير الخطة الكنسية (إصدار جديد)؛ (ب) تغير إجراء التشغيل نفسه.
- كل تحديث: رقم إصدار أعلى + تاريخ + سبب في §13؛ ويُعاد التحقق من التطابق مع الخطة قبل الالتزام.
- **لا تباعد صامت** عن الخطة أبدًا؛ إذا تعارض نص هنا مع الخطة، فالخطة تحكم ويُصلح هذا الملف.
- المهارة لا تصبح «مكتملة» إلا بحضورها مقروءة كاملة ومطابَقة للخطة ومُشارَكة من الموجة التالية.
