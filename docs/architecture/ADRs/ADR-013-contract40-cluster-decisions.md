# ADR-013: The three Contract-40 residence clusters — per-cluster decisions

**Status:** Accepted (Wave G — STR-611 — 2026-10-03)
**Owner:** Micro owner; per-cluster owners and exit conditions below.
**Context:** Thirteen services / ~6,833 production lines remain in `application/finance/` as three contract-40-relevant clusters: Integrity & Diagnostics, Recurring Planning, Financial Read Models. Contract 40 (the technical ownership map) is a higher authority than this program's plan: any move contradicting a residence row requires a contract amendment — a separate owner decision. Blanket preservation is not acceptable (STR-611); each cluster is evaluated independently on live evidence.

**Decision:**
1. **Integrity & Diagnostics — PRESERVE residence (contract-anchored).** `integrityCheckService.ts` (1,430 nbLOC) has an explicit contract-40 §2 row: owner **المالية**, residence `application/finance/integrityCheckService.ts`, read-only promise guarded by a before/after snapshot test; the §6 row reiterates «حارس الإقامة في application/finance/». Cohesion is proven: it is the financial record's own integrity checker — it reads the entire record through the port and owns no financial rule. **Owner:** the finance cluster (contract 40). **Growth bound:** the file is SPLIT_NOW by size — its Wave F card performs an **internal responsibility split** (MIC-1..16 check families into sibling files inside the same finance home; the service remains the orchestrator) with no semantic change and no residence change. **Review trigger:** any new MIC check; any band escalation (ratchet); any attempt to add write paths. **Exit condition:** if diagnostics grows into a multi-surface module (beyond `/tools/integrity` + settings), the owner amends contract 40 and opens a move decision.
2. **Recurring Planning — split decision.** `recurringWorkService.ts` (557 nbLOC): contract-40 §2 anchors it explicitly (allocation-policy owner **المالية**, path `application/finance/recurringWorkService.ts`) → **PRESERVE** (moving requires a contract amendment; not sought). `recurringExpenseService.ts` (784 nbLOC, WATCH): **NOT contract-anchored** — contract 40 names no row for it, and contract 41 scopes the recurring-expense reminders domain exactly as contract 42 scoped the already-moved budgets cluster → **MOVE to `application/recurring/` in Wave E** by the proven 4B/#307 mechanical pattern (file move + compatibility unit in `finance/` for the frozen-UI consumers + non-UI consumers migrated + ratchet/guard baselines updated in the same PR + direct tests move with the responsibility). **Rationale:** the sub-domain has its own contract (41), its own storage capability (extracted first in Wave C group 1), and the same independence profile the budgets move had — keeping it in `finance/` would be the folder-avoidance pattern the radical-remediation standard rejects. The two recurring services share no imports (verified live) — the "family" argument for co-residence does not hold. **Owner:** the recurring-expense domain (contract 41). **Growth bound:** stays WATCH-band; any crossing triggers the ratchet plus a split card. **Review trigger:** Wave E slice completion; contract-41 amendment discussions. **Exit condition:** the `finance/` compatibility unit is removed when the UI track migrates its consumers (same trigger as the other compatibility units).
3. **Financial Read Models — PRESERVE residence (contract-anchored core, cohesive family).** `projectFinancialService.ts` (1,503 nbLOC) is the contract-40 canonical reader (single-definition guard; §8 row: القارئ الكنوني في بيته المالي). Its read-model siblings (period comparisons, presets, due dates, upcoming, statement + markdown, profit-to-cash bridge, short-cash horizon) read **through** the canonical reader and form its wing inside `finance/`; the analysis wing already moved to `financial-analysis/` in 4A. **Owner:** finance read models (contract 40). **Growth bound:** `projectFinancialService` is SPLIT_NOW by size — its Wave F card performs an **internal responsibility split** (read-path families into sibling files, same home, canonical-reader identity preserved) with no formula/rounding/classification move. **Review trigger:** ratchet escalation; any new read model; any second-source-of-truth attempt (single-definition guard). **Exit condition:** a read model gaining its own write path or independent module ownership becomes its own owner decision.

**Consequences:** STR-611 closes with three independently-decided clusters: two preserves (each with proven contract anchoring and a complete justification chain) and one evidence-based move (`recurringExpenseService`, Wave E). Contract 40 is NOT amended by this ADR. Rollback: this ADR reverts as a file; the Wave E move reverts as its own commit.

**Evidence class:** VERIFIED (contract-40 rows read live; file sizes measured; the two recurring services' import graphs checked — zero shared imports; consumer sets enumerated).
