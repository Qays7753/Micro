# ADR-011: Dependency-direction policies — UI→domain value edges and application→presentation formatting edges

**Status:** Accepted (Wave G — STR-609, resolving STR-106 and STR-203 — 2026-10-03)
**Owner:** Micro owner; review triggers and migration conditions below.
**Context:** The target direction is Presentation → Application → Domain (plan principle 5). Two edge families violate it and are frozen by the 4E boundary guard at the accepted baseline (13 UI→domain value edges across 8 pages; 14 application→presentation value edges across 12 application files importing `presentation/formatters`, `presentation/activityLabels`, `presentation/orderAgreementPresentation`). 4E delivered freeze + ratchet, **not** a policy resolution (STR-622). An unreviewed permanent exemption is not acceptable (STR-609).

**Decision:**
1. **UI→domain value edges (STR-106) — time-boxed exception, not permanent.** Policy: UI pages may import **pure domain values (types/constants/pure functions) only**, never domain services with state or storage. Current frozen baseline: 13 value edges / 8 pages (guard R2 rejects any new edge). **Migration condition (measurable):** when the owner opens the UI track (Wave T), each edge is rerouted through an application-level read service or a presentation-layer adapter until the count reaches 0; the guard's baseline then ratchets down. **Review trigger:** any guard failure (new-edge attempt), or the UI track opening, whichever first. **Exit condition:** 0 edges, or an owner-signed renewal of this ADR with fresh justification.
2. **Application→presentation formatting edges (STR-203) — root-cause redirection in Wave B.** The 14 edges import pure formatting/label primitives (`formatters.ts` — 199 lines, Intl-only, no React/DOM; `activityLabels.ts`; `orderAgreementPresentation`'s `getAgreementPresentation`). Policy: application must not depend on the presentation layer. **Decision:** extract the pure primitives consumed by application into a direction-neutral pure formatting home (Shared-Kernel-eligible per plan principle 9: pure, no I/O, ≥2 consuming modules, named owner, entry budget), with `presentation/formatters.ts` re-exporting for its UI consumers (compatibility; frozen UI untouched). **Migration condition (measurable):** application→presentation edges 14 → 0 in the Wave B card; guard R3 baseline updated in the same PR (a reduction, never an increase). **Review trigger:** Wave B completion, or any new application→presentation import attempt (guard rejects). **Rollback:** revert the extraction commit — pure module move, no behavior change (byte-identical strings; the suites + goldens + a before/after formatter-output characterization test prove it).
3. Neither policy converts the frozen baselines into permanent exemptions; both carry owner, reason, measurable migration condition, review trigger, and exit condition as plan §7.1-5 requires for temporary layers.

**Consequences:** STR-609 closes with two owned policies instead of silent waivers. The Wave B card (STR-615 batch) executes the redirection under the bundle-margin plan (ADR-012). No code change in this ADR.

**Evidence class:** VERIFIED (edge counts and import sites re-measured live at Wave A/G; formatter purity inspected: Intl-only, no React/DOM imports).
