# ADR-006: Legacy retirement requires consumer proof

**Status:** Accepted (W6 of the foundation run; executed at scale in the completion run, including the census-scope correction)
**Context:** Retiring legacy CSS prematurely breaks surfaces; leaving it forever creates dead weight and duplicate sources of truth. A first migration attempt missed `app/StartupGate.tsx` because its census covered only `pages/` — the audit caught an unstyled recovery button shipped as "zero legacy remaining".
**Decision:** A legacy rule may be removed ONLY when a re-census proves zero consumers (grep + guards), and the removal lands in the same change as the consumer migration that obsoleted it. **Censuses must cover ALL source roots — `pages/`, `components/`, `app/`, `pwa/`, `contexts/`** — enforced mechanically by `client/src/legacyClassCensus.test.ts` (any retired class in non-test source, or any returning CSS definition, fails the build). Waves: the foundation run retired dead tokens, the dead tooltip + radix dependency, and 16 byte-identical duplicates; the completion run migrated every remaining `micro-button*` usage (299 across 80 files, all roots), retired 22 legacy rules (`.micro-status-chip`, `.micro-g5-choice`, the dead agreement-page descendant, and the button family), retargeted 20 descendant context selectors to `.micro-prim-button`, and removed 75 exact-duplicate rule blocks (44 duplicated definitions; cascade-idempotent, first occurrence kept).
**Consequences:** "Dead code for later" is not an acceptable state. Intentional survivors are enumerated with reasons in `MIGRATION_STATUS.md`. Claims of "zero legacy" are only as good as the census scope — the guard, not the sentence, is the proof.
