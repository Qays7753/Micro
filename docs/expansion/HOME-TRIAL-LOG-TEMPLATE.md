# Expansion — قالب سجل تجربة البيت Local-first

**الحالة:** `TEMPLATE / START ONLY AFTER L-00 TO L-04`
**الخصوصية:** لا تحفظ بيانات عميل أو مورد أو شركة أو صورة أو عنوان حقيقي في Git. استخدم معرّفات مستعارة أو مساحة خاصة محمية عند الحاجة.

## Major Discussion Points

## 1. سجل ملاحظة يومي أو لكل واقعة

| التاريخ | الجهاز/المتصفح | الدور المحاكى | السيناريو | ما أردت فعله | ما حدث | الفهم/التردد | الأثر المالي المرئي | التصنيف | الدليل الآمن | القرار |
|---|---|---|---|---|---|---|---|---|---|---|
|  |  | Owner/Supplier/Courier/Admin | S-xx |  |  |  | لا شيء/مفهوم/ملتبس | UX/Domain/Storage/Access future/فرضية | لقطة بلا بيانات حساسة أو وصف | إصلاح/عقد/اختبار/تأجيل |

يكتب «لا شيء» في الأثر المالي عندما يكون هذا هو السلوك الصحيح. لا يكتب «عمل» أو «لم يعمل» بلا وصف للفعل التالي الذي فهمه المستخدم.

## 2. سجل أسبوعي

| الأسبوع | سيناريوهات مكتملة | مسودات ضاعت؟ | حالات مكررة؟ | حالة مالية مضللة؟ | صعوبة وصول للخدمات؟ | Export/Restore | Offline/Refresh/Back | أهم قرار |
|---|---:|---|---|---|---|---|---|---|
|  |  | لا/نعم + رابط | لا/نعم + رابط | لا/نعم + رابط | لا/نعم + رابط | ناجح/فشل + سبب | ناجح/فشل + سبب |  |

## 3. مقياس الفهم القصير

بعد كل سيناريو رئيسي، يجيب Owner من دون مساعدة زائدة:

1. ما الحالة التي وصلت إليها الآن؟
2. هل وقع شراء أو مصروف أو تسليم أو قبض فعليًا داخل Manage؟ ولماذا؟
3. ما الفعل التالي الذي تتوقعه ومن المسؤول عنه؟
4. ماذا سيحدث إن خرجت الآن أو فشل الاتصال؟

أي جواب خاطئ عن الحقيقة المالية أو فقدان المسودة أو الدور يسجل عيبًا حرجًا ولا يخفى خلف تقييم عام إيجابي.
