# Expansion — بطاقة قرار السيولة والنموذج التجاري

**الحالة:** `TEMPLATE / OWNER DECISION REQUIRED / NO CODE AUTHORIZATION`
**السلطة:** تكمل هذه البطاقة `DECISIONS.md` وبطاقة أول Wedge ولا تحل محلهما. لا تفوض رسومًا أو دفعًا أو عمولة أو Checkout أو إعلانًا أو توسعًا أو تغييرًا في حقيقة `Micro Manage`.

## Major Discussion Points

## 1. لماذا نحتاج بطاقة منفصلة

`Micro` ليس سوقًا عامًا يُقاس بعدد الصفحات أو التسجيلات. إذا أصبح `Market` أو `Delivery` متصلًا لاحقًا، فالقيمة تأتي من تفاعل صغير قابل للتكرار بين جهتين ضمن فئة ومنطقة وزمن محددين. لذلك يلزم توثيق من يستفيد، وما الذي يفعله كل طرف الآن، وكيف نعرف أن التفاعل وجد تطابقًا مفيدًا قبل التفكير في الرسوم أو التوسع.[1] [2]

هذه البطاقة لا تفترض أن Micro ستصبح منصة تدفع أو تتقاضى عمولة. في المرحلة الأولى قد يظل المسار **مجانيًا ومحدودًا** كي يثبت منفعة Owner والفئة والشريك، أو ينتهي إلى قرار `Discovery` أو `Defer` أو `Reject`. يبقى Manage منتج المالك المحلي، ولا تتحول أرقام السوق أو الرسوم الافتراضية إلى كاش أو ربح أو ذمم داخله.[3]

## 2. ما الذي تحسمه وما الذي لا تحسمه

| تحسمه بطاقة المالك لاحقًا | لا تحسمه ولا تبدأه |
|---|---|
| التفاعل الأول الضيق بين الأطراف وضرره ونتيجته. | سوق عام أو فئة/مدينة ثانية أو طلب «لكل الأردن». |
| من يبدأ أولًا: Owner أو مورد/شركة توصيل شريكة محددة، ولماذا. | تسجيل مستخدمين عشوائيين أو حوافز أو عمولات أو إعلانات. |
| عتبة سيولة/فشل مفهومة للفئة والمنطقة والزمن المحددين. | تقييمات أو ترتيب آلي أو توصية أو ضمان جودة. |
| هل يبقى المسار المجرب مجانيًا أم يحتاج لاحقًا فرضية نموذج تجاري واحدة. | Checkout أو دفع أو تحصيل أو تسوية أو KYC أو ضريبة. |
| صاحب قرار الإيقاف أو التبسيط أو التوسع بعد دليل Pilot. | توسع تلقائي بسبب عدد مستخدمين أو GMV أو طلب واحد ناجح. |

## 3. تعريف التفاعل الأول والسيولة

السيولة هنا ليست «عدد الأشخاص في التطبيق». هي احتمال أن يصل Owner إلى رد أو Quote أو حالة حركة قابلة للفهم في الوقت المعقول المتفق عليه ضمن نطاقه. يمكن أن تكون محلية جدًا: نوع احتياج واحد في حي أو مدينة واحدة، أو حركة واحدة تتكرر مع شريك توصيل محدد.[1] [2]

| الحقل | إجابة المالك | الدليل قبل البناء | ما لا يكفي |
|---|---|---|---|
| الفئة والمنطقة |  | `EX-O01` و`EX-O02` وبطاقة Wedge. | رغبة عامة في «سوق للمشاريع». |
| التفاعل الذري | `Need → Response → قرار Owner` أو `Request → Quote → Status`. | موقف متكرر موجود خارج Micro. | قائمة Features أو ثلاثة مسارات معًا. |
| جهة البذرة الأولى | Owner أو موردان أو شركة توصيل/شريكان محددان. | استعداد موثق لتجربة محدودة مستقبلًا. | حسابات وهمية أو افتراض أن التسجيل يجلب العرض. |
| عتبة السيولة | وقت رد/Quote، نسبة إكمال، وفهم الحالة ضمن فترة محددة. | فرضية وسبب وحد نجاح وحد فشل. | التنزيلات أو الجلسات أو GMV وحدها. |
| علامة عدم السيولة | لا رد، رد غير مناسب، إلغاء متكرر، أو التباس بالخطوة التالية. | سجل سبب وفعل تعديل/إيقاف. | إخفاء الفشل أو توسيع النطاق لتعويضه. |

## 4. قرار النموذج التجاري: بعد القيمة وليس قبلها

تستخدم المنصات المتعددة الأطراف عادةً رسوم تفاعل أو اشتراكًا أو رسوم ظهور أو خدمة إضافية، لكن الاختيار يعتمد على من يتلقى قيمة متكررة، وحساسية الأطراف للسعر، وهل وصلت الفئة الضيقة إلى سيولة كافية.[1] [3] لا تصلح هذه الخيارات كقرار افتراضي لـMicro، ولا يجوز وضعها في UI أو سجل مالي قبل تفعيل منفصل ومراجعة قانونية ومالية.

| الخيار المستقبلي | سؤال صالح للمالك | شرط حتى يُدرس | الحظر الحالي |
|---|---|---|---|
| مجاني/Discovery | هل نحتاج دليل منفعة أولًا؟ | ضرر محدد وشريك أو مقابلات موثقة. | لا تسويق مزيف أو وعد تشغيل عام. |
| اشتراك Owner اختياري | هل يوجد تحسين متكرر خارج Market/Delivery يستحق دفع المالك؟ | منفعة Owner مثبتة ومستقلة عن الوصول إلى الطرف الآخر. | لا ربط بالـManage المحلي أو سحب مال تلقائي. |
| رسوم جهة مورد/توصيل | هل تتلقى الجهة قيمة قابلة للوصف من تفاعل محدد؟ | سيولة وفهم وموافقة ومسار قانوني/تشغيلي لاحق. | لا fee أو priority أو ترتيب مدفوع في L أو Pilot الأول. |
| رسم نجاح/عمولة | هل يوجد تعريف قانوني وتشغيلي واضح لنجاح موثق؟ | دفعات وهوية وتسوية وضريبة ونزاع وعقد مستقل—وكلها خارج البداية. | لا GMV أو عمولة أو تسوية أو احتجاز مال. |
| خدمة إضافية لاحقة | هل تقلل خدمة محددة ضررًا ثبت بعد السيولة؟ | دليل مستقل وقبول بوابة عالية المخاطر. | لا دفع/تأمين/تمويل/تتبع أو ترويج تلقائي. |

## 5. أسئلة المالك المفتوحة

لا يملأ Agent هذه الحقول ولا يستبدل بحثًا محدودًا بإجابة مفترضة.

| المعرف | القرار المطلوب من المالك | متى يحسم | أثره |
|---|---|---|---|
| EX-O06 | ما التفاعل الذري وعتبة السيولة/الفشل في أول Wedge؟ | قبل L-00 ثم L-03 أو L-04. | يحدد السيناريو والقياس وقرار الإيقاف. |
| EX-O07 | أي جهة تُبذَر أولًا، وهل يوجد التزام فعلي محدود من شريك أو أكثر؟ | قبل L/Pilot ذي صلة. | يمنع منصة فارغة أو شريكًا وهميًا. |
| EX-O08 | هل يبقى أول مسار مجانيًا، أم توجد فرضية نموذج تجاري واحدة تُدرس فقط بعد دليل قيمة؟ | بعد L ودليل Pilot؛ قبل أي A/B تجاري. | يمنع عمولة أو رسومًا أو دفعًا مبكرًا. |

## 6. بوابة القرار ونتيجته

| النتيجة | متى تستخدم | الفعل المسموح التالي |
|---|---|---|
| `Build Local L` | اكتمل التفاعل والضرر والجهة والعتبة بلا حاجة لبيانات حقيقية. | Slice محلية واحدة وفق العقد والسيناريو، لا اتصال أو رسوم. |
| `Discovery` | يوجد ضرر محتمل لكن لا يوجد دليل كافٍ عن الطرف أو السيولة. | مقابلات/ملاحظات محصورة وتحديث البطاقة، لا Feature متصل. |
| `Defer` | الوقت أو الشريك أو نطاق المنطقة لا يسمح بتجربة عادلة. | توثيق السبب ومراجعة بتاريخ لاحق، لا توسع تعويضي. |
| `Reject` | لا ضرر متكرر أو لا سيولة واقعية أو يوجد خطر يفوق القيمة. | لا بناء للمسار، وتسجيل الدرس فقط. |

## Action Points

- [ ] يملأ المالك EX-O06…EX-O08 مع بطاقة Wedge؛ لا يختار Agent الفئة أو المنطقة أو الطرف أو الرسوم.
- [ ] لا يبدأ L-03 أو L-04 قبل تعريف التفاعل الذري والعتبة والنتيجة المسموحة من الجدول أعلاه.
- [ ] لا يبدأ أي نموذج تجاري أو رسوم أو دفع أو ترتيب مدفوع قبل دليل L/Pilot وبوابة مستقلة للعقود والهوية والخصوصية والقانون والتسوية.
- [ ] إذا تعارض قياس النمو أو الإيراد مع وضوح Owner أو حقيقة Manage أو الحد الأدنى للبيانات، يرفض التوسع ويظل Measure مسجلًا كدليل لا كحكم آلي.
