## 5. ما لم يُنفذ عمدًا (NOT_EXECUTED — حدود الأمر الصلبة)

1. **أي تطبيق مخطط على Neon أو أي كتابة/إعداد مزود** (Cloudflare/Neon/R2/OAuth) أو أي تكلفة — الترحيلات 0003–0006 ملفات مستودعية حصرًا؛ التطبيق بيد المشغل (§8).
2. **أي نقل بيانات حقيقية أو قراءة/تحوير لبيانات متصفح المالك** — مسار الترحيل مختبر بمظاريف اصطناعية فقط؛ لم يُفترض أن حالة «لا بيانات حقيقية» ما زالت قائمة (يُعاد التحقق عند البوابة الفعلية).
3. **أي تفعيل حقيقي لوضع القطع** لأي مساحة — العمود افتراضي 0 ولا مسار يبدله.
4. **أي PR أو دمج أو كتابة على main أو حذف فروع** — الفرعان يبقيان غير مدموجين (`NO_CLEANUP`).
5. **أي نشر إنتاجي** — الدفع لا ينشئ إلا معاينة Pages غير الإنتاجية المصرح بها فقط (إن وجدت)؛ لم يُدَّعِ «حي» أو «مُهاجَر» أو «جاهز إنتاج» في أي موضع.
6. **أسئلة الاحتفاظ/الحذف/التصدير/الخصوصية/الاسترداد للبيانات الحقيقية** — بقيت أسئلة مالك موثقة (§7) ولم يُخترع لها رقم ولا ادعاء.

## 6. حدود الرجوع (كل موجة التزام مستقل قابل للrevert)

- **M1** توثيق فقط — الrevert يعيد العقود/السيناريوهات/المطالبة (يُستلزم إغلاق DOC-040 بعده).
- **M2/M3/M4/M5/M6** كل منها التزام كود واحد فوق سابقه؛ الrevert المنفرد يعيد السلوك (الترحيلات لا تُطبق تلقائيًا على أي قاعدة إنتاج فلا أثر إنتاجي لأي منها).
- **نقطة الأمان الدائمة**: حتى مع تطبيق المشغل للترحيلات، القدرة معطلة افتراضيًا ولا ربط بلا إثبات مزدوج ولا ترحيل بلا سر المالك ولا قطع بلا قرار المشغل — أربع بوابات متسلسلة كلها فشل مغلق.

## 7. أسئلة المالك المفتوحة (قبل أي بيانات حقيقية — لا أرقام مخترعة)

1. مدد الاحتفاظ بالسجلات المالية المتصلة ومن يستطيع طلب الحذف/التصدير (مراجعة قانونية محلية — PDPL الأردني ضمنًا).
2. سياسة النسخ الاحتياطي للخادم (إن وجدت) — لا يُدعى شيء قبل قرار.
3. اعتماد الترحيل الفعلي (بعد فحص فراغ حديث) وخطوات القطع التشغيلية وMFA/إعادة التحقق ما قبل الربط (قرار مستقل قائم في البوابة §2-ب-4).

## 8. خطوات المشغل (Manus) — بالترتيب، كلها خارج نطاق Z AI

1. تطبيق ترحيلات `apps/prototype-web/worker/db/migrations-pg/0003..0006` بالترتيب على مشروع/فرع Neon المعتمد ثم التحقق (مثال: `\dt manage_*` وفهرس `idx_manage_owner_linked_one`).
2. تفعيل القدرة لمساحة المالك: `UPDATE workspace SET manage_enabled = 1 WHERE id = '<مساحة المالك>';` — بعد ذلك يظهر مسار الربط في ملف الحساب.
3. الربط: المالك يولّد سر الإثبات داخل Manage (ملف الحساب → «ربط Manage المتصل» → «ولّد سرًا») ويحتفظ به، ثم «ابدأ الربط» و«أكّد الربط» داخل الجلسة نفسها.
4. (عند البوابة النهائية فقط) الترحيل الفعلي: تصدير محلي متحقق + تقديم المظروف مع السر نفسه عبر مسار التطبيق — ثم مراجعة الإيصال (العدادات/البصمة/بصمة المحتوى) وقبول المالك الموثق.
5. (بعد مراجعة الترحيل والاسترداد النهائية وقرار المالك الصريح فقط) تفعيل وضع القطع: `UPDATE workspace SET manage_online_only = 1 WHERE id = '<مساحة المالك>';` — عندها فقط تُرفض الكتابة المالية المحلية ويصبح «محفوظ» خادميًا حصرًا.
