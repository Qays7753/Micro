## 1. التوصية المعمارية وحدود الحقيقة

التوصية الواحدة للمرحلة الأولى **AR01**: بوابة سائق ويب هاتفية مستقلة قابلة للتثبيت كـPWA على Origin مخصص، وبناء واجهة مستقل عن واجهة صاحب المشروع، ضمن مستودع Micro واحد مبدئيًا. هوية Micro مشتركة ومنافذ جلسة محكومة لكل بوابة، وخلفية/API مشتركة منظمة بوحدات وصلاحيات خادمية. D1 مرشح مخزن الشبكة، وليس اعتمادًا نهائيًا قبل دليل العزل والتزامن والتكلفة. R2 مرشح الملفات الخاصة. تفاصيل المفاضلة والمصادر والتكاليف في §21.

بوابة السائق المستقلة وهوية Micro والمتصل قرارات مالك. PWA/Origin وطريقة البناء والمستودع والخلفية والمخزن توصية مهنية؛ لا يفرض استقلال مستوى فصل المستويات الأخرى. لا تطبيق Native أو مستودع مستقل دون حاجة مثبتة ثم مسح واعتماد؛ لا مسار بديل فعلي مطلوب الآن.

المكتوب سابقًا عن React/TypeScript/Vite/Wouter وGoogle وCloudflare خط أساس موثق لا وصف حي. يحافظ التنفيذ على UI → Application → Domain → Ports/Adapters حيث يثبت توافقه بعد المسح، دون ترقية أو تبديل تلقائي أو نقل ملفات في هذا التسليم.

قاعدة الشبكة مصدر حقيقة الحجز والاتفاق والتصريحات والتأكيدات والسمعة. ليست مصدر حقيقة دفاتر Manage المحلية؛ لا نقل ذمم أو تغيير دقة المال أو استدعاء خدماته. لا تكامل تلقائي من إعلان Market إلى حجز ولا دمج ملفات المورد والسائق.

الهدف نسخة تعمل بين حساب سائق فعلي وحساب مشروع منفصل على جلستين وجهازين وبحفظ خادمي. يسمح ببيانات اصطناعية ومراجعة قيس اليدوية من جهة موثوقة. Mock أو اختيار دور محلي مفيد لاختبار الواجهة لكنه لا يحقق المتصل. My Ask Micro واختيار الوحدات ليسا تبعية أو مرحلة تنفيذ هنا.

تضاف مصالحة تقديم ذاتي ودعوة وعضوية سائق وحالات الاعتماد والنشاط وقبول المتصل، مع رفع اختبار العزل إلى API والملفات والعدادات. هذا إعداد لعقود المستودع، لا ادعاء أنها عُدلت. لا يعود المنفذ للعقود المالية الملغاة من الإصدار 1.0 ليعيد فرض نطاق لم يعد مطلوبًا.

UI لا يكتب D1 أو IndexedDB أو R2 مباشرة. Application ينسق؛ Domain لا يستورد React أو Auth أو HTTP. Adapters تعالج النقل والتخزين دون تغيير قواعد العمل. أسماء الوحدات ليست تطبيقات منفصلة أو مطلب إنشاء مجلد لكل صف.

## 5. هوية Micro والجلسات والصلاحيات

هوية شخصية واحدة ثابتة في Micro، وليست هوية مالك محلية أو حسابًا شخصيًا ثانيًا للسائق. يستهلك الدخول مزود Micro المعتمد بعد التحقق من الموجود؛ Google خط أساس موثق. إن استُخدم Google يتحقق الخادم من التوقيع والجهة والجمهور والانتهاء ومعرف subject، ولا يدمج أشخاصًا بتطابق بريد فقط [S3-current]. لا يُفرض Supabase Auth جديد على مشروع له مزود معتمد، ولا يُدعى تشغيله هنا. إذا كشف المسح غياب أساس هوية شبكة، تُنشأ قدرة هوية Micro المشتركة مرة واحدة بمزود مدار مناسب لدخول Google/OIDC، ويثبت اختيار Adapter ودورة الجلسات في تقرير التحضير قبل شريحته. لا تبنى كلمات مرور أو حماية منزلية خاصة بالسائق، ولا يستبدل حساب تجريبي محلي مصادقة المتصل.

| الطبقة | التمثيل والمسؤولية |
| --- | --- |
| الشخص | معرف Micro واحد مرتبط بموضوع مزود الدخول الموثوق |
| جلسة البوابة | جلسة دخول خادمية مقيدة بالبوابة، لا Cookie عامة لكل Micro؛ نفس الشخص يمكن أن تكون له جلسات مستقلة |
| ملف السائق | بيانات ومركبة ومراجعة ونسخ عامة/خاصة؛ لا صلاحية تنفيذ من مجرد وجود السجل |
| صفة/عضوية السائق | entitlement أو grant مخول مرتبط بهويته وحالة اعتماده؛ ليس عضوية في مشروع العميل أو حساب شركة مطلوب |
| اعتماد السائق والمركبة | قرار قيس المخول لكل موضوع ونسخة؛ دعوة أو ملف مكتمل ليس اعتمادًا |
| النشاط | استقبال الجديد بعد أهلية وخدمة وتوفر صالحين؛ منفصل عن الهوية واعتماد الملف |
| المشروع/المورد | ملفات وعضويات مستقلة إن سمحت السياسة؛ لا وصول تلقائي من صفة السائق |

المرجع الهندسي للجلسات: BFF أو ingress محكوم على Origin كل بوابة، يمكن أن تنفذه الخلفية المشتركة نفسها. Cookie host-only دون Domain أب واسع، Secure وHttpOnly وSameSite مدروس لدورة الدخول، وتجديد وإلغاء خادميان. لا حاجة لنسخ token عبر localStorage أو query string أو مشاركة Cookie بين جميع النطاقات. لا تجديد أو جلسة Google مفترضة؛ تختبر دورة الدخول والخروج على المتصفح وPWA.

الـOrigin المختلف يعزل IndexedDB/Web Storage في المتصفح [S6]؛ لا يمنح عزل API أو مصادقة بذاته. Cookies تتبع نطاقها الخاص، وSameSite لا يغني عن CSRF أو فحص Origin، خصوصًا بين subdomains لنفس الموقع [S7]. عند اتصال عبر Origins يكون CORS بقائمة دقيقة وبلا wildcard مع اعتماد الجلسة [S13]؛ الطلب المسموح من المتصفح لا يساوي فعلًا مخولًا. المصدر الرسمي يوصي بإعادة فحص الصلاحية لكل طلب [S8].

ينشأ سياق البوابة في جلسة/قيد خادمي موثوق. لا يختار body.actor أو role أو portal من المتصفح ليمنح صلاحية أوسع. تشمل حراسة الفعل: هوية وجلسة ساريتان، بوابة مصرح بها، صفة وحالة، صلة بسجل معين، نسخة وحالة أعمال، وحقول مسموحة. صاحب الدورين في جلسة السائق لا يستدعي واجهات مشروعه أو المورد من هذه الجلسة؛ الانتقال المخول لتجربة أخرى صريح وبسياقها، دون شاشة اختيار وحدات الآن.

| القدرة | المالك ضمن تجربته | السائق ضمن بوابته | قيس ضمن إجراء مخول |
| --- | --- | --- | --- |
| التقديم/الملف | لا اعتماد نيابة عن السائق | تقديم ذاتي أو دعوة وملفه فقط | مراجعة وطلب استكمال واعتماد مسبب |
| اعتماد الشخص/المركبة | لا | لا | المخول فقط، مع أثر هوية/وقت/نسخة |
| قبول أو عرض سعر | قبول عرض/تعديل يخص مشروعه | وارد مستهدف له بعد الاعتماد والنشاط | لا قبول نيابة عن الطرف |
| بيانات مستلم كاملة | حجز مشروعه | تعيينه والحد اللازم للمرحلة | بلاغ مخول يحتاجها فقط |
| تصريح/تأكيد نتيجة أو مبلغ | تأكيد المالك أو اعتراضه | تقرير تنفيذ/مبلغ فقط، لا اعتماد المالك | لا يؤكد تواصلًا أو قبضًا أو تسليمًا مكان الطرف |
| ملفات ووثائق مراجعة | لا | وثائقه فقط | ضمن المراجعة؛ ليست عامة |
| مالية Manage أو Market | لا وصول من Delivery يغير بياناتها | لا واجهات أو بيانات أو وظائف من بوابة السائق | لا صلاحية مالية عامة |

دعوة تقديم تمنح سياق دعوة فقط، لا driver_active أو قفزًا للمراجعة. اختيار هندسي أولي: إصدار الرابط لقيس أو مالك مشروع مخول، token عشوائي يحفظ تمثيل تحقق آمن له، صالح 7 أيام وقابل للإلغاء، واستعماله لإلحاق طلب هوية واحدة لا لإعادة تفعيله لحسابات أخرى. إن وجه لشخص محدد تربط هويته بعد دخول موثوق، ولا يدمج حساب بمجرد البريد. الدعوة العامة أو المنتهية لا تمنع التقديم الذاتي، ولا تنشئ عضوية في مشروع الداعي. هذه تفاصيل تنفيذية موثقة قابلة للتهيئة، لا شروط أهلية تجارية جديدة. مراجعة يدوية تعني قرارًا خادميًا من قيس المخول، لا زر تطوير مكشوفًا. سحب صفة أو إيقاف الجديد يعاد فحصه في كل قبول، ولو كانت الجلسة قديمة. الإيقاف لا يحجب معالجة القائم والأغراض والبلاغات ولا يلغيه أو ينقله؛ الاستثناءات الإجرائية غير المعتمدة لا تخترع.

المشرف يستعمل حماية الدخول المناسبة للمزود المشترك، مع فصل صلاحية المراجعة عن حساب عادي. الخروج يمسح بيانات بوابته الخاصة فقط دون حذف Manage المحلي أو بيانات دور آخر. بيانات الهوية والجلسة لا تستعاد من Export محلي.


### سياسة الإثبات والصلاحية البسيطة

الحد الأدنى هو صورة الهوية وصورة رخصة القيادة، وإثبات بسيط أن السيارة للسائق أو لديه إذن باستخدامها عند تسجيلها؛ لا شرط ملكية شخصية ولا تفضيل نوع سيارة أو رقم لوحة. قيس/المراجع المخول يرى الصور ويقرر يدويًا. لا OCR أو تحقق قانوني/جنائي/طبي أو مستندات أخرى مطلوبة.

يرتبط الملف بالهوية وبالمركبة عند اللزوم، مع حالات uploaded/pending_review/needs_update/approved/expired/superseded ونسخة مراجعة، وتاريخ انتهاء فقط عند وضوحه. غياب التاريخ ليس انتهاءً ولا يبرر اختراعه؛ المراجع يسجل «غير واضح/غير مذكور» ويمكنه طلب صورة أوضح من نفس الإثبات. لا يُدخل العميل approved أو يفرغ expires_on ليلغي انتهاء نسخة معتمدة؛ القرار والنسخة النافذة من الخادم والمراجع.

قبل استقبال/قبول حجز جديد، أو قبول عرض يحول طلبًا غير مؤكد إلى مهمة جديدة، يفحص الخادم صلاحية الإثباتات المعتمدة حتى لو تأخر عامل التنبيه. إذا انتهى إثبات لازم يمنع الجديد حتى مراجعة صورة محدثة واعتمادها. رفع ملف جديد لا يرفع الحجب بذاته؛ النسخة المنتهية وتاريخها يبقيان مرجعيين حتى قرار صحيح. لا يمس هذا الحارس قراءة/معالجة الحجوزات والأغراض والبلاغات القائمة أو يغلقها/يلغيها/ينقلها؛ تبقى الإجراءات المخولة للقائم منفصلة.

توصية تشغيلية أولية، لا قرار مالك: تذكير واحد قبل 7 أيام من تاريخ معلوم، وتنبيه عند الانتهاء إذا بقيت الحاجة؛ مفاتيح تمنع تكرار التنبيه لنفس نسخة الإثبات. لا تواريخ أو تذكير متكرر عند فتح الصفحة، ولا جدول تصعيد. اعتماد نسخة جديدة يوقف تنبيه القديمة المناسب، دون تغيير اتفاق أو مهمة. الصور لا تنشر ولا تستخدم كصور عرض؛ قراءتها للسائق ومراجعيه المخولين فقط، بما فيه metadata والروابط والتصدير.

## 7. تمثيل المال والوقت والشروط

DeliveryAmount قيمة صحيحة بدقة 1/100 د.أ ومتوافقة مع MoneyMinor الحالي، لكنها ليست قيدًا في دفتره. 3.00 = 300، و20.00 = 2000. null يعني غير محدد، وصفر يعني مبلغًا مجانيًا مصرحًا. يرفض الإدخال بأكثر من منزلتين بدل تقريب صامت. يرسل API عددًا صحيحًا آمنًا؛ ترفض قيمًا خارج التمثيل الصحيح الآمن برسالة تقنية، دون تسميته سقف COD تجاريًا. المجاميع الوسيطة تستخدم حسابًا صحيحًا لا يفقد الدقة.

MarketPrice في السوق ذو عقد مستقل؛ لا تحويل بينهما بصبّ نوع. لا تغيير لدقة Manage أو بياناته التاريخية، ولا مزامنة من كشف التوصيل إلى «مالي». جمع مبالغ بنود كشف للعرض المعلوماتي مسموح؛ احتساب خصم أو دين أو تخصيص قبض أو عمولة غير مسموح.

الأوقات UTC في التخزين وتعرض Asia/Amman. اليوم المحاسبي هنا مجرد يوم كشف محلي، لا تاريخ إقفال مالي. يحفظ الموعد اليومي لتسليم المال المتفق عليه، وليس «نهاية اليوم» غير المعرفة. المهل وقت خادم، ونسختها مع الطلب لا تفسر بساعة العميل.

قواعد الخدمة بيانات typed: enabled، pricing_mode مجاني/سعر/عرض، amount، deadline_rule، max_attempts، retention_limit، applicability_stage. الحقول الشرطية لازمة عند تفعيل الخدمة. free يحتاج صفرًا صريحًا، وrequires_quote لا يسمح بتنفيذ مدفوع قبل قبول سعر محدد.

السقف مرتبط بنوع الخدمة والمسار وله إصدار ونفاذ. كل عرض مدفوع يتحقق من سقفه؛ لا حد أدنى ولا سقف لقيمة المنتج. تفاصيل الحجز تحفظ أسعار وشروط كل احتمال، ولا تحسب تكاليف الاحتمالات كأنها استحقت كلها. خدمة غير مختارة لا تتحول لمبلغ واجب لمجرد وجودها بالبروفايل.

## 8. الحجز والعرض والتوفر

المسار القياسي: draft → pending_driver → confirmed. رفض/سحب/انتهاء يغلق طلب القبول بلا تنفيذ أو مال. المسار الخاص: quote_requested → quoted → owner_accepted → confirmed. إعداد العرض تصريح موافقة السائق المشروطة؛ قبول المشروع هو آخر موافقة، مع إعادة فحص السعة والأهلية والمهلة والسقف.

رد السائق 1800 ثانية. صلاحية العرض والتعديل 1800 ثانية كقيمة هندسية أولى، قابلة للتهيئة دون تغيير الطلبات الحالية. لا بث ولا قبول بعد الانتهاء. قبل إصدار عرض جديد تلغى النسخة السابقة، ولا يقبل مشروع رابطًا لعرض قديم.

قدرة أولية بوحدة حجز واحد لكل نافذة ذات حد إنتاجية. المحجوز + المستهلك لا يتجاوز الحد؛ المهام عبر المحافظات تشترك في نافذة السائق لا حدود مستقلة متراكبة. قدرة حمولة المركبة مستقلة. لا ترفع الحد تلقائيًا عند بقاء بضاعة معه. إن كانت الفترات متداخلة يلزم مرجع قدرة مشترك يمنع العد مرتين؛ الأسهل في v1 منع تداخل نوافذ إنتاجية السائق أثناء التهيئة.

الطلبات المعلقة والعروض لا تحجز سعة حصرية؛ التأكيد يحجز ذريًا. إن تأكد حجز آخر أولًا يظهر capacity_unavailable ويطلب خيارًا جديدًا. الإلغاء قبل بدء التنفيذ يحرر الحجز وفق الحالة. الإنجاز يحول الاستخدام إلى مستهلك في نفس النافذة، ولا يتيح إنتاجية لا نهائية.

بانتظار تأكيد المشروع لا يستبقي قفل قبول عام على السائق. يستخدم مسار التنفيذ المصرح وحامل الأغراض لتحديد العمل الجاري، مع بقاء الاستهلاك التاريخي. لا يدعي النظام تخطيط مسار أو قياس حمولة متبقية آليًا من مجرد انتهاء إجراء.

## 9. عقد الأمر والمعاملة

لكل أمر: actor من الجلسة، سياق مخول، target، expected_version، idempotency_key، schema_version ومدخلات محددة. role وapproval وworkspace لا تعتمد من العميل دون تحقق خادمي. الاستجابة نتيجة محفوظة ومعرف وإصدار ووقت خادم؛ الأحداث تضاف مرة واحدة منطقيًا.

الخطوات: تحقق الهوية والصلة؛ استرجع إيصال الأمر المتطابق إن وجد؛ اقرأ الحالة الحالية؛ نفذ Domain والحراس داخل وحدة الكتابة؛ احفظ التغيير والتخصيصات والإيصال وOutbox؛ ثم أرسل التنبيه بعد commit. يعاد فحص الإذن قبل إعادة إيصال قديم. نفس المفتاح مع payload مختلف يعيد تعارضًا.

المعاملة الذرية لقبول الحجز تضم صلاحية النسخة/المهلة/السائق/إثباتاته/السقف، حجز السعة والتعيين والحالة والإيصال والحدث. قبول تعديل وقت يحفظ القدرة القديمة إذا تعذرت الجديدة. السحب مقابل القبول يخرج بنتيجة واحدة. فشل شرط يجب أن يرجع كل الآثار؛ UPDATE صفر صفوف ليس نجاحًا ولا خطأ SQL تلقائيًا.

D1 batch يوفر معاملات عند فشل statement [S1]؛ **الاستنتاج الهندسي:** يلزم تصميم حارس وقيد يحول فشل شرط الأعمال إلى فشل كامل قبل اعتماد القبول. لا يكفي فحص rows بعد أن أثبتت المعاملة آثارًا أخرى. تثبت آلية D1 المختارة باختبار تزامن فعلي قبل تعميمها، دون وعد بقفل موزع من المتصفح.

## 10. التنفيذ والتواصل وتأكيد المشروع

كل تصريح تنفيذ append-only مع علاقة تصحيح، وتأكيد المشروع مرتبط بمعرف التصريح ونسخته والاتفاق الجاري. يقبل expected_version ويرفض تأكيدًا لنتيجة جرى استبدالها، مع عرض الجديدة. لا last-write-wins.

| الأمر | الحارس والنتيجة |
| --- | --- |
| report_pickup | تعيين صالح وتطابق أو فرق مقبول؛ يسجل حامل الأغراض السائق |
| report_delivery | أغراض مصرح باستلامها وتعيين؛ نتيجة تنتظر المشروع، دون طلب رمز/صورة |
| report_failed_delivery | سبب ومحاولة اتصال بالمشروع مسجلة أو سبب تعذرها، وانتظار ظاهر؛ لا إغلاق |
| report_contact | نتيجة no_answer/contacted/unable_to_call؛ مجرد tel_open حدث واجهة لا يؤكدها |
| acknowledge_outcome | المالك يوافق/يعترض على النتيجة المحددة؛ contacted يحتاج إقرارًا صريحًا منفصلًا |
| select_followup | خدمة متاحة/سعر وموعد وشروط معلومة؛ موافقة الطرفين تحفظ خطة رجوع/احتفاظ/محاولة |

إذا قدم المشروع الإلغاء بنفسه يسجل إقراره ضمن نفس الأمر؛ لا يصطنع واجهة تأكيد ذاتي ثانية. الرفض/السحب/الانتهاء قبل تأكيد الحجز ليست ادعاءات تسليم ولا تحتاج موافقة متبادلة.

لا تنقل صلاحية المشرف إلى acknowledgment. يستطيع تسجيل أنه راجع البلاغ أو أن الطرفين أبلغا اتفاقًا، ويظل المصدر صحيحًا. لا delivered_verified أو received_verified بمعنى إثبات مستقل؛ استخدم driver_reported/owner_acknowledged مع نص واضح.

عدم رد المشروع يترك acknowledgment pending ويعرض «بانتظار تأكيد صاحب المشروع» دون TTL يغلقه. تذكير واحد بعد 24 ساعة هندسيًا؛ انتهاء مدة الاحتفاظ يرفع attention فقط. لا يولد إلغاء أو رسومًا أو تصرفًا بالأغراض. يستمر السائق بعمله دون انتهاء حالة تاريخية كاذبة.

## 11. سجل المبالغ والكشف اليومي

money_agreement يحفظ مقدار المنتج المطلوب تحصيله، إن كانت الأجرة ضمنه، ودافع الأجرة، وآلية دفعها، وطريقة/موعد تسليم المال اليومية، وصافي مبلغ اختاره الطرفان إن اتفقا عليه. لا تفويض ذمم أو قفل رصيد Manage.

collection_statement تقرير السائق بما قبضه فعلًا؛ التصحيح إصدار مرجعي مع السبب، لا overwrite. الاختلاف أو الدفع المباشر للمشروع يحتاج مراجعة وتواصل وتغيير اتفاق، ولا يستدعي collectFromSheet أو API محفظة. لا يزعم التطبيق منع دفع مكرر عبر نظام مالي مستقل.

daily_handover يحتوي مشروعًا وسائقًا ويومًا وقائمة بنود بالنسخ والمبلغ الذي يصرح بتسليمه. عند التقديم تجمد القائمة؛ يحتفظ بسجل طريقة الأجرة/الصافي المتفق عليه دون حساب خصم تلقائي. لا بند من مشروع آخر، ولا إدراج نفس تصريح التحصيل في كشفين مقدمين/مؤكدين. لا تخصيص مبلغ جزئي لأي بند. لا تسوية جزئية في v1، ولا أكثر من كشف ينتظر التأكيد للزوج واليوم نفسيهما؛ الكشف التكميلي بعد التأكيد الأول يضم تصريحات جديدة فقط.

المشروع يؤكد **كامل النسخة المعروضة** أو يبلغ فرقًا. لا يقبل confirm_amount جزئيًا؛ الواجهة لا تعرض زر «تسوية جزئية». ملاحظة أنه استلم أقل معلومة خلاف، وليست تأكيدًا جزئيًا أو قبضًا في Manage. تعديل كشف غير مؤكد يحتاج إصدارًا جديدًا يعاد تأكيده. التصحيح بعد تأكيد كامل يفتح سجل تصحيح/بلاغ مرتبطًا يحفظ القديم، ولا يعيد طرح نفس التحصيل كمبلغ جديد واجب الدفع.

لا جداول رصيد أو net receivable أو settlement allocation أو cross-wallet transaction. يمكن اشتقاق عدادات «كشوف تنتظر تأكيدًا» و«تصريحات غير مدرجة» للتنبيه فقط؛ لا تسميها ذممًا مؤكدة أو أرباحًا.

## 13. السمعة والملفات

نجوم 1–5 لحجز delivered وowner_acknowledged، من المالك، دون الذات وبقيد فريد. rating_state مستقل عن comment_state pending/approved/rejected؛ تجميع المتوسط من النجوم المؤهلة غير الملغاة بسبب مثبت. حذف/حجب نص لا يحذف تقييمًا سلبيًا تلقائيًا. تغيير أهلية بسبب احتيال يحتاج قرارًا مسجلًا وتحديثًا متسقًا للعدادات. لا تعديل ذاتي في v1؛ التصحيح عبر البلاغ بسجل تاريخ.

R2 خاص لصور الهوية والرخصة وإثبات السيارة/الإذن المطلوبة وللمرفقات الاختيارية. الصور العامة إن أضيفت أصول منفصلة ونسخ مشتقة معتمدة؛ لا تُشتق من صور الإثبات الخاصة. upload intent مرتبط بالهوية والمالك ونوع الملف، بمفتاح جديد لا يختاره العميل. يفحص الحجم والنوع الفعلي وسلامة المحتوى ويزال metadata الحساس من نسخة العرض، ولا يستبدل أصل مرتبط بنسخة أخرى خفية.

اختيارات هندسية أولية: JPEG/PNG/WebP لصور الإثبات المطلوبة، وPDF لمرفق بلاغ اختياري إن احتاجه المستخدم، دون إلزام بمستند إضافي؛ حد 5 MiB للصورة و10 MiB للمستند و5 مرفقات للبلاغ، دون فيديو أو تسجيل مكالمات. هذه حدود رفع تقنية لا حدود مالية أو أوزان حمولة. جميع الرفوع خاصة حتى اعتماد نسخة العرض.

قراءة الوثائق عبر Proxy يفحص الجلسة والإذن كل مرة. الروابط الموقعة تمنح حاملها وصولًا مؤقتًا [S4-current]؛ لا تستخدم كرابط دائم لوثيقة هوية، ولا تعتبرها هوية لمستلم. تنظيف ملفات غير مرتبطة بعد 24 ساعة اختيار هندسي، مع حماية كل ملف له مراجعة/حجز/بلاغ.

## 14. الإشعارات والمهل

يحفظ الحدث وOutbox مع الأمر. المستهلك يتحمل التكرار والتأخر والترتيب المتغير، ويعيد قراءة الحالة قبل فعل مشتق. Queues يضمن at-least-once وقد يكرر الرسالة [S2]؛ لا يعني ذلك exactly-once لأحداث أعمالنا. إيصال/قيد فريد يحمي كل أثر. يمكن البدء بعامل جدولة يقرأ Outbox ضمن الخدمات المشتركة إذا كفى الحمل؛ Queue ليست شرطًا لإنشاء خدمة مستقلة.

صندوق التطبيق داخلي دائم. Push اختياري من الخدمة المشتركة وبإذن الجهاز؛ SMS أو بريد تشغيلي مدفوع ليس ضمن افتراض البداية. فشل Push لا يلغي حجزًا ناجحًا. الإقرار من مزود إشعارات لا يعني القراءة، والاتصال البشري ليس تكامل هاتف آليًا.

انتهاء قبول/عرض/تعديل يحكمه وقت الخادم حتى لو تأخر عامل الجدولة. قرار accept يتحقق من expires_at بنفسه. عامل الانتهاء يحدث الحالة/التنبيه idempotently. لا مسار وقت يغلق تأكيد مالك معلق أو يشغل إرجاعًا/رسومًا تلقائيًا.

تذكير الإثبات البسيط مرتبط بنسخته وتاريخه المعلوم وفق §5؛ لا يصنع تاريخًا أو يغير القائم. أحداث الحد الأدنى: request.sent/accepted/declined/expired، quote.submitted/accepted، agreement.changed، pickup.reported، outcome.reported/acknowledged/disputed، contact.reported/acknowledged، followup.agreed، handover.submitted/acknowledged/difference، driver.reviewed، review.submitted/moderated، case.updated. هذه أحداث شبكة لا تستهلكها خدمات مال Manage.

## 15. بوابة السائق وPWA والاتصال

تبقى امتدادات صاحب المشروع تحت تبويب التوصيل في تجربته. السائق يصل إلى frontend مستقل وبناء دخول مستقل، لا نسخة من Shell صاحب المشروع بأزرار مخفية. لا تستورد بوابته مالي Manage أو Market أو StartupGate يفرض إنشاء مشروع، ولا تقرأ IndexedDB الخاص بهما. تحدد مواقع الملفات بعد المسح الشامل واعتماد خريطة الهدف، لا قبل ذلك.

AR01 يوصي بـPWA على Origin سائق مخصص وبناء مستقل في مستودع Micro. Manifest بهوية واسم وأيقونات وstart_url وscope مناسبة للسائق، وHTTPS في البيئة المتصلة؛ التثبيت والدعم يختلفان حسب الجهاز والمتصفح [S5]. scope يحدد تجربة التنقل وليس مصادقة أو منع وصول [S12]. لا يُشترط Service Worker كدليل وحيد على التثبيت؛ إن استُخدم فلتخزين الأصول العامة المناسبة وتحديثها ضمن Origin السائق، دون cache تلقائي لـAPI خاص أو مستندات أو بيانات مالية [S5]. لا تصميم واجهة My Ask Micro أو اختيار وحدات.

التثبيت اختياري للاستخدام، لكنه ضمن التوصية واختبارات AT52. تشغيل الأيقونة يعيد للوحة السائق أو حالة الطلب أو دخول Micro ثم السياق؛ لا يفتح رئيسية مالية أو اختيار منتجات. تحديث البناء لا يمحو طلبًا أو اتفاقًا، والخروج/تبديل حساب ينظف cache البوابة الخاص دون حذف دفاتر Manage.

القبول والتصريح والتأكيد لا تظهر نجاحًا offline قبل حفظ الخادم. ضياع الرد يستعلم عن مفتاح الأمر نفسه بدل إنشاء أمر جديد. المسودة المحلية إن احتاجت تخزينًا تكون محمية ومقيدة بالهوية، ولا تعد حجزًا مرسلًا. المرشح الأبسط للبداية cache لأصول واجهة عامة فقط، مع بيانات أعمال من الخادم؛ لا التزام بعمل معاملات دون اتصال أو تتبع GPS خلفي لمجرد تثبيت PWA.

الهاتف وRTL وأرقام 0–9 وLight Mode ومكونات Micro المعتمدة محفوظة. تختبر أحجام 360×800 و390×844 و430×932، ومعها تثبيت/إعادة فتح على هاتفين مستهدفين فعليين مناسبين لـAndroid وiOS حيث يتاح الاختبار. وجود اسم جهاز أو viewport لا يثبت اختبار جهاز؛ تسجل النتيجة والحد أو BLOCKED إن لم يتوفر. اختلاف دعم الإشعار/التثبيت لا يسمح بادعاء PASS شامل.

## 16. الخصوصية والتشغيل والاستعادة

أقل إفصاح من Manage بعد معاينة المالك. كل DTO عام قائمة سماح؛ بيانات الزبون قبل التعيين مختزلة للمسار، وهاتف المشروع والسائق متاحان لطرفي الطلب الموجه. وثائق وحجوزات ومبالغ الآخرين لا تدخل البحث أو عدادات أو تحميلات مخفية.

logs تشخيصية دون أرقام هواتف وعناوين وصور وثائق وTokens وروابط تمنح إذنًا أو مبالغ خاصة. Audit يسجل الفاعل والفعل والهدف والوقت والنتيجة والسبب، ويمكن أن يحيل لسجل أعمال خاص بدل تكرار محتواه. TLS وأسرار بيئة ومدخلات ومعدل وأحجام مفحوصة. لا بيانات حقيقية في fixtures.

يلزم سجل احتفاظ يحدد لكل نوع بيانات الغرض والمدة وطريقة الحذف، متوافق مع سياسة Micro المشتركة قبل تشغيل أشخاص حقيقيين؛ لا يخترع هذا التسليم التزامًا قانونيًا أو مدة احتفاظ تجارية لم تعتمد. ضوابط بناء محافظة: لا حذف آلي لاتفاقات/تصريحات مرتبطة بحجز مفتوح أو بلاغ؛ صور الهوية والرخصة وإثبات السيارة/الإذن ترفع وتحفظ خاصة للمراجعة وفق قرار المالك، ولا يستعاض عنها بمجرد معاينة أصل؛ لا إطلاق جمع مستند حساس قبل ضبط غرضه ومدة الاحتفاظ به في إعداد التشغيل. هذه مهمة تشغيل محددة، لا سؤال عن مفهوم المنتج.

الاستعادة تشمل D1 ومراجع R2 والجلسات والصلاحيات وOutbox. تعاد مطابقة الأحداث التي أرسلت خارج DB، مع منع تكرار إشعار أو موافقة. لا تعتبر استعادة DB عكسًا لما حصل بين الناس أو تحويلهم الخارجي. تجربة استعادة ببيانات مصطنعة قبل التجربة الحقيقية شرط قبول.

المراقبة: أقدم طلب رد، قبول فاشل/سعة، أقدم تأكيد مشروع، تجاوز مواعيد احتفاظ/إرجاع، كشوف غير مؤكدة، مراجعات وتعليقات وبلاغات، Outbox متأخر، رفض وصول، وأداء تحميل. مؤشرات الثقة: إعادة التعامل وسائقون محفوظون وتأكيدات ومشكلات؛ لا تنسب بيعًا أو ربحًا من فتح ملف.

## 21. AR01 — التوصية المهنية المبررة ومصادرها

**الخيار المرجح:** PWA سائق هاتفية على Origin مخصص، ببناء واجهة مستقل في مستودع Micro مبدئيًا؛ هوية Micro، جلسة بوابة محدودة، Backend/API مشتركة بوحدات Delivery وIdentity وإجراءات قيس، ومخزن شبكة علائقي مرشح D1 وR2 للملفات الخاصة. لا تُربط بداية السائق بنشر Market أو نقل Manage أو إضافة ميزات مؤجلة. هذه توصية للتبني بعد المسح والاعتماد، لا بنية منفذة.

| مستوى الفصل | المعنى والقرار المرجح | ما لا يستنتج منه |
| --- | --- | --- |
| تجربة واجهة مستقلة | مدخل ولوحة وتنقل ومكونات سياقية للسائق؛ مؤكد من المالك | لا يستلزم Native أو حساب شخصي آخر |
| PWA قابلة للتثبيت | تطبيق ويب يعمل من المتصفح ويمكن تثبيته وفق الجهاز؛ المرجح | لا يجعلها Native ولا يثبت GPS خلفيًا أو معاملات offline |
| Native في المتاجر | تطوير/توزيع واختبارات وقدرات منصة مخصصة؛ لا يوصى به الآن | الحاجة إلى متجر لا تثبت وحدها أن الحل يجب أن يكون Native |
| Origin مخصص | حد لتخزين المتصفح وأصول بوابة السائق؛ المرجح | لا يعزل API أو صلاحيات الخادم أو Cookies الأب تلقائيًا |
| مستودع واحد | مشاركة عقود ومكونات مع بناءين وحدود استيراد؛ المرجح بعد المسح | لا يعني نشرًا واحدًا أو Shell واحدًا أو صلاحيات واحدة |
| Backend/API مشتركة | واجهات وأوامر مفصولة منطقيًا مع AuthZ خادمي | لا يعني كشف كل الموارد لكل بوابة أو جدولًا موحدًا للملفات |
| DB واحدة للبيانات الشبكية | المرشح الأبسط مع ملكية وقيود وصلاحيات خادم؛ D1 رهن الإثبات | لا تشمل مالية Manage، ولا تعني دمج ملف المورد والسائق |
| DB منفصلة | قد تحتاجها حدود تشغيل/عزل مثبتة لاحقًا | لا تحقق صلاحيات آمنة وحدها، وقد تعقد ذرية الحجز |

السبب: العمل الأساسي واحد بين مشروع وسائق على نفس الحجز، والنسخ والقبول تحتاج حقيقة مشتركة. واجهتان وبناءان مستقلان يعزلان التجربة ويتيحان دورة نشر للسائق دون تكرار الهوية والعقود. Vite يدعم مداخل بناء متعددة وpnpm يدعم مشاريع متعددة في مستودع واحد [S9–S10]؛ هذا لا يثبت ملاءمة المصدر الحي أو يجيز ترقيته للإصدارات الحديثة في الوثائق.

الفصل داخل تطبيق واجهة واحد ممكن تقنيًا لكنه أقل وضوحًا لحدود الاستيراد والتخزين المطلوبة؛ لهذا لا أختاره كبداية متصلة عند توفر بناء مستقل منضبط. المستودعات المنفصلة تضيف إدارة نسخ عقود ومكونات وتنسيق تغييرات ودعم هوية، بلا حاجة مثبتة الآن. الفصل التقني هنا يبقى داخل منتج Micro.

**بوابات تغير التوصية، وليست بدائل مفتوحة الآن:** حاجة مثبتة لتوزيع متجر أو GPS خلفي مستمر أو قدرات Native/معاملات offline لا يحققها الويب بعد اختبار أجهزة، أو فصل فرق/صلاحيات وصول للكود لا يحققه المستودع الحالي. تقدم دراسة حاجة وأثر وتكلفة للمراجعة قبل أي تغيير. لا توصى Native أو عدة مستودعات استباقيًا.

**البديل الوحيد المشروط:** إبقاء الواجهتين والهوية والعقود كما هي ونقل مخزن الشبكة فقط إلى Postgres/خدمة علائقية مناسبة إذا فشل D1 في دليل العزل أو ذرية القبول أو الحمل/التكلفة المطلوبة. ليس تغييرًا إلى مالية Manage أو ترخيصًا بإنشاء Backend لكل بوابة؛ يسبق البديل دليل فشل ومقارنة واعتماد، لا تبديل صامت.

الدورة المتصلة المطلوبة: مستخدم سائق يقدم ذاتيًا، ومستخدم/حالة أخرى تصل بدعوة، وقيس من جلسة مخولة يراجع الشخص والمركبة يدويًا، ثم يجهز السائق الخدمة والنشاط. حساب صاحب مشروع منفصل يختاره ويرسل حجزًا، والسائق يقبل ويصرح، وصاحب المشروع يؤكد أو يعترض. يعاد الدخول/التحميل وتقرأ الحالات المحفوظة من الخادم ومن الجهاز المقابل. تختبر تكلفة/سعة قبولين متزامنين وأوامر مباشرة عابرة للأدوار والملفات والعدادات، وتثبت عدم تغير Manage بأي تصريح أو تأكيد.

الحساب التجريبي الفعلي هو حساب تقبله الخدمة وتتحقق من جلسته وصلاحياته وتحفظ بياناته؛ اسم في مصفوفة fixtures أو تبديل role في الواجهة ليس حسابًا فعليًا. يجوز تزويد الحسابات والأدوار يدويًا من جهة موثوقة وإجراء المراجعة يدويًا، لكن لا يستخدم ذلك لتجاوز الاعتماد أو كشف زر grant للمستخدم. لا يلزم إرسال دعوات لأشخاص فعليين أو شراء SMS لتجربة دعوة؛ تختبر رابطًا آمنًا ضمن بيئة الاختبار.

لكل AT: الرأس والبيئة والخطة/المخزن المستخدم والجهاز/المتصفح وهوية أدوار تجريبية بلا أسرار وخطوات وأمر ووقت ونتيجة ودليل. تظل NOT_RUN حتى ينفذ فعليًا. منجز الوثائق لا يغيرها؛ لا نتائج أو خدمات جرى اختبارها في هذه المهمة.

## 23. شرط المسح البنيوي قبل أي موجة

قبل إنشاء أو نقل أو فصل تطبيق/حزمة أو تعديل حدود استيراد أو schema/سلطة بيانات، يجرى **مسح شامل قراءة فقط** يغطي: حدود الوحدات والاعتماديات المباشرة والعكسية، مسارات الإقلاع والتوجيه والجلسات والتخزين، الملفات الكبيرة ومسؤولياتها، التكرار ومصادر الحقيقة، الاختبارات والأوامر الحالية والوثائق والعقود، وخريطة هدف للبناءين والخلفية والصلاحيات.

تخرج النتائج مصنفة fix now/preserve/defer/out of scope بدليل وسبب وأثر وملفات ومستهلكين؛ كبر ملف وحده ليس سبب تقسيمه. يقدم الفرق بين الحالي والمستهدف واعتماديات ومخاطر وخطة موجات صغيرة قابلة للمراجعة. يراجع المالك ويعتمد النتائج وخريطة الهدف قبل أي موجة بنيوية. لم يجر هذا المسح هنا؛ لا تعني مواضع الملفات المقترحة تفويضًا بها.
