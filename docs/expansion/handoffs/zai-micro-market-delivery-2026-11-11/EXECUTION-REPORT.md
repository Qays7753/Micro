## 2. الخريطة المستقلة للنظام الحالي (كتبت قبل المقارنة مع تقرير المسح)

### 2.1 المكدس ونقاط الدخول

- مساحة عمل pnpm (`pnpm-workspace.yaml`: `apps/*`, `tools/*`): تطبيق واحد `apps/prototype-web` (`@micro/prototype-web`) + أداة داخلية `tools/micromatch-shim` (تحصين micromatch). الجذر `package.json` بلا اعتماديات تشغيلية.
- الواجهة: React 19 + Vite 7 + Tailwind 4 + `wouter` (توجيه) + `vaul` + `lucide-react`؛ TypeScript صارم (`tsconfig.json`: `NodeNext`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`).
- الدخول: `apps/prototype-web/client/index.html` (`lang="ar" dir="rtl"`، بلا أي نداء شبكة — الوسم التحليلي أزيل ووثق بتعليق) ← `client/src/main.tsx` (يشغّل `registerPwaServiceWorker()`) ← `App.tsx` (ErrorBoundary → PrototypeServicesProvider → ThemeProvider → `MicroRouter`).
- التوجيه: `client/src/app/MicroRouter.tsx` — نحو 60 مسارًا بتحميل كسول، منها `/market` و`/delivery` كإعلانَي «قريبًا» صادقين (التفصيل §2.6).
- القشرة: `components/layout/MicroAppShell.tsx` مع شريط سفلي خماسي معرف في `client/src/app/navigation.ts` `primaryNavigation`: `المالية (/finance) | الطلبات (/orders) | الرئيسية (/) | التوصيل (/delivery) | السوق (/market)` — قرار NAV-001 §1 المنفذ.

### 2.2 الطبقات وحدود الميزات

### 2.4 الهوية والأمن والخصوصية (الوضع الحالي المنفذ)

- **لا يوجد أي Auth/جلسة/دور/صلاحية/مستأجر في الكود** — تحقق بالمسح الشامل: لا `auth|login|oauth|jwt|supabase|firebase` في `src/` أو `apps/`؛ الهوية الوحيدة مالك محلي `local-owner-profile` (`application/owner/ownerProfileService.ts`) بحقول مزود مستقبلية `null`.

- التشخيص محلي بثمانية حقول ثابتة (`application/diagnostics/localDiagnosticsService.ts`) بلا أي مسار إرسال (اختبار يثبت غياب fetch/XHR/sendBeacon).

## 5. تفضيل المالك (نموذج محلي/محاكى أولًا) مقابل تعريف القبول المعتمد (تجربة متصلة)

يفترض المالك تفضيل البدء بنموذج مستقل ببيانات محلية/محاكاة وإدارة أدوار يدوية قبل أي API لطرف ثالث. **المواصفات المعتمدة لا تلغي هذا التفضيل لكنها تحدد قيمته بدقة:**

- **OD-06 (Market) وOD23 (Delivery):** القبول المطلوب هو **تجربة متصلة** ببيانات محفوظة فعليًا وحسابات وجلسات وأجهزة مختلفة؛ «المحاكاة المحلية وبيانات الاختبار لا تثبت القبول المتصل»، والبيانات الاصطناعية والإدارة اليدوية الموثوقة مقبولتان داخل التجربة المتصلة.
- **الترجمة العملية (رأي مهني):** يجوز بناء نموذج محلي/محاكى كخط تحضيري داخلي (وقد يكون مفيدًا للواجهات والحالات) لكنه **لا يُعد إنجازًا ولا دليل قبول**، ولا يبرر ادعاء اتصال. الإدارة اليدوية للأدوار مقبولة داخل التجربة المتصلة نفسها (OD23) — أي أن تفضيل المالك متوافق مع القرار إذا فُهم كترتيب تحضيري لا كبديل عن القبول.
- **ما لا يجوز:** اختيار مزود أو أتمتة API بصمت لمجرد أن القرار يطلب اتصالًا — اختيار المزود (Google IdP الفعلي، DB، تخزين، إشعارات) يبقى قرارًا تقنيًا منفصلًالً ببوابة A/OD-20 يتطلب إثباتًا واعتمادًا.

## 21. تشخيص فشل بناء Cloudflare Pages — الأدلة والإصلاح (الالتزام 587a5b80)

### 21.1 الدليل: سلسلة البناء خضراء كاملة من جهة الكود

`pnpm --filter @micro/prototype-web build` (= `vite build && check-bundle-budget && check-bundle-surfaces && build-worker`) **PASS كاملة** على الشجرة النهائية: entry 602,503/650,000 خام و146,910/155,300 gzip (السقوف الملكية كما هي)؛ precache 200 مدخلًا؛ `_worker.js` = 105,535 بايت (سقف 1MB)؛ ومحاكاة بيئة Pages الحقيقية (`CF_PAGES=1` + `CF_PAGES_COMMIT_SHA`) عبر حارس أسطح الحزمة **PASS** مقابل أساس cloudflare-pages المرساة (محليًا وفي CI عبر بروتوكول identity-hash الموثق). **إذن الكود يبني وينشر نظيفًا؛ الفشل في إعداد بيئة البناء لدى المزود.**

### 21.2 الأسباب المرشحة بالترتيب (كل واحد يفشل البناء فشلًا كاملًا)

1. **لا سكربت build جذري كان موجودًا** — أي أمر بناء افتراضي من قالب إطار عمل (`npm run build` / `pnpm build`) يفشل فورًا بـ«Missing script: build». **أُصلح من جهة المستودع (587a5b80):** سكربت جذري `build` = `pnpm --filter @micro/prototype-web build`.

3. **إصدار Node** — vite 7.3.7 يرفض الإقلاع على Node أقدم من 20.19/22.12 وminiflare 4 يتطلب ≥22؛ بلا ملف تثبيت كانت الصورة الافتراضية للمزود تحكم. **أُصلح من جهة المستودع (587a5b80):** `.nvmrc` + `.node-version` بـ**22.23.3** (نفس إصدار CI المرساة عليه بيئة github-actions) — تلتقطهما Pages تلقائيًا بلا أي تغيير إعدادات.
