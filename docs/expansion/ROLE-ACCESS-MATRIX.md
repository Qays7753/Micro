# Expansion — مصفوفة الأدوار والوصول والإفصاح

**الحالة:** `CURRENT / E-00 / FUTURE-AUTHORIZATION SPECIFICATION` *(مُصالح 2026-11-12 مع قرارات المالك المعتمدة 2026-11-09: زائر بلا هوية للاستكشاف OD-04، بدء مسار المورد لأي مستخدم مسجل OD-03/OD-16، البحث على النطاق الوطني OD-01/OD-02؛ ودور السائق ببوابة مستقلة بهوية Micro OD01/OD21/OD22 مع الإثباتات الخاصة OD28–OD31)*
**النطاق:** قرار وصول وتدقيق قبل التنفيذ؛ لا يمثل حماية منفذة في Prototype المحلي.

## Major Discussion Points

## 1. قاعدة المصفوفة

تعرف المصفوفة ما يحق لكل دور أن يراه ويعدله عند التفعيل الحقيقي. لا تنشئ الأدوار من واجهة أو اسم route، ولا يثبت إخفاء زر أن الوصول آمن. كل صف يجب أن يطبق لاحقًا في Database وAPI وApplication والواجهة والبحث والإشعارات والملفات وExport.

> **لا يملك Admin حقًا شاملًا. ولا يمنح Supplier أو Courier حق Manage. ولا يمنح Account الشبكي حق الاطلاع على مال محلي.**

> **ملاحظة مؤرخة 2026-11-13 (EX-D19/EX-D21):** المدخل الشامل لAsk Micro متاح لكل حساب موقع في كل سياق مصرح بما فيه السائق، **لكن صفوف البيانات أعلاه هي الحاكمة لما يصل إليه المساعد**: كل طلب مقصور خادميًا بالفاعل الموثَّب والدور النشط وWorkspace الحالي والسجلات المصرَّحة، والاسترجاع عبر API مصرَّحة حصرًا (لا SQL مباشر ولا كتابات مالية/تشغيلية). كذلك تصبح أحكام §1 ملزمة التنفيذ الآن على هدف PostgreSQL (EX-D20): عضوية Workspace والدور والملكية وتعيين السائق مفروضة خادميًا في كل مسار متصل، مع اختبارات سلبية عابرة للWorkspaces؛ والوصول إلى مناطق المنتج عالمي بالحساب بينما تصريح البيانات محصور — غياب تهيئة Workspace يظهر حالة إعداد/صلاحية صادقة لا منتجًا مخفيًا.

## 3. مستويات الإفصاح عن الحقول

| التصنيف | أمثلة | متى يظهر |
|---|---|---|
| `public_after_approval` | اسم Listing، وصف معتمد، صورة معتمدة، منطقة/تغطية عامة معلنة. | فقط بعد Moderation وموافقة النشر؛ لا تعني تغطية وطنية أو توفرًا حيًا. |
| `interaction_scoped` | كمية أو نافذة أو ملاحظة اختار Owner نشرها لمورد. | بعد نشر Need أو فتح Interaction محدد. |
| `delivery_scoped` | عنوان/هاتف ووصف طرد ونافذة موعد لازمة. | حسب Scope الذي عاينه Owner قبل Quote/Booking؛ متطلب وسيلة النقل يرسل قبل Quote فقط إذا لزم التسعير. |
| `role_private` | مسودة Supplier، سبب داخلي أو إعداد جهة Courier. | للجهة والعضو المخولين فقط. |
| `manage_private` | كاش/دين/ربح/CostSnapshot/عميل/Export. | داخل Manage المحلي لصاحب المشروع فقط. |
| `audit_restricted` | فاعل وسبب قرار أو محاولة وصول مرفوضة. | بحسب سياسة Admin أو Owner ومرجع السجل فقط. |

لا يوجد تصنيف «مفيد ربما»؛ الحقل بلا غرض محدد لا يرسل ولا يخزن في الشبكة. يراجع Owner Preview لما سينتقل عند بدء Delivery أو نشر Need.

## 4. حواجز URLs والبحث والملفات

| مدخل الهجوم أو الخطأ | القاعدة المستقبلية | اختبار القبول |
|---|---|---|
| URL مباشر لمحرف سجل | يعيد الخادم/API رفضًا بلا metadata للسجل. | Owner A وSupplier/Courier غير مخولين لا يعرفون إن كان السجل موجودًا. |
| Search أو فلتر السوق | يعيد Listings المعتمدة فقط ضمن التغطية والسياسة، ثم يطبق Workspace/Role/Scope للتفاعلات الخاصة. | لا اسم أو عداد أو Query أو نتيجة من جهة أخرى ولا ترتيب/توصية خفيان. |
| Notification | مستلم مملوك ومتحقق منه، والفتح يعيد فحص Policy. | رابط إشعار قديم أو مسروق لا يكشف تفاصيل. |
| File URL | إنشاء رابط قصير/Proxy بعد التحقق؛ لا public قبل approve. | Supplier آخر لا يفتح وسيطًا خاصًا، وOwner لا يرى ملفًا مرفوضًا بلا سياسة. |
| Export | نطاق Workspace/الدور والحقول تصفى قبل الإنشاء. | لا تصدر Manage المالية أو بيانات عميل لطرف شبكي. |
| Mutation | حالة سابقة وعضوية ودور ومفتاح تكرار تتحقق قبل الكتابة. | لا تغيير Quote/Status أو Moderation بنسخ request أو تعديل route. |

## 5. اختبار العزل عند A

يُنشأ على الأقل Owner A وOwner B وSupplier X وSupplier Y وCourier X وCourier Y وAdmin محدود. يختبر كل واحد UI وAPI وSearch وNotification وFile URL وExport. يجب أن تفشل المحاولات غير المخولة بأمان، وألا تظهر تفاصيل أكثر من سبب رفض عام حيث يكشف السبب وجود سجل حساس.

## 6. استعادة الوصول لا توسع Scope

| حالة الاستعادة المستقبلية | ما يعود للشخص | ما لا يعود أو يتغير | دليل القبول |
|---|---|---|---|
| Owner يستعيد هوية الشبكة | هويته وMemberships السارية فقط. | Manage المحلي أو Workspace غير مثبت أو مال Owner آخر. | لا يتجاوز UI/API/Search/File/Export Scope بعد الاستعادة. |
| Supplier/Courier يستعيد هوية | بوابة جهته وScope تفاعلاتها فقط. | جهة منافسة أو معلومات Owner الخاصة. | اختبار رفض مباشر ومحاولة Search/URL/File. |
| Admin يستعيد حسابه | Queue/Policy/Audit المحدودة حسب عضويته. | Admin أوسع، Manage، أو انتحال دور تجاري. | MFA/تحقق إضافي وAudit وسبب ومراجعة. |
| طوارئ إدارة المنصة | إدارة المنصة المحدودة ضمن سياسة R-04. | جلسة Owner أو Export أو مال أو تعديل تاريخ. | سجل استخدام الطوارئ ومراجعة لاحقة. |

الآلية التقنية للاستخراج أو Password/OTP/Passkey ليست قرارًا لهذا الجدول؛ المرجع الحاكم لها هو `FOUR-PARTY-PORTAL-AND-ACCESS-RECOVERY-GATE.md` وقرار A-01.
