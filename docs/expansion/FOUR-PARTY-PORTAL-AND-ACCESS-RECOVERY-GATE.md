# Expansion — بوابات الجهات الأربع واستعادة الوصول وAdmin المقيد

**الحالة:** `CURRENT / E-00 / DOCUMENTATION ONLY / NO AUTH IMPLEMENTATION`
**الغرض:** تثبيت ما تعنيه بوابة كل من Owner وSupplier وCourier وAdmin، وكيف تستعاد **هوية طبقة الشبكة** مستقبلًا من دون أن تصبح كلمة مرور أو Admin طريقًا لدخول Micro Manage المحلي أو مال أي Owner.

## Major Discussion Points

## 1. سؤال القرار والنطاق

يعالج هذا المستند السؤال الآتي: **«عند تفعيل طبقة الشبكة لاحقًا، كيف يدخل كل طرف إلى بوابته الصحيحة، ماذا يحدث عند فقد وسيلة دخوله، ومن يملك قرار الاستعادة من دون منح Admin صلاحية شاملة؟»**

> **القاعدة الحاكمة:** Micro Manage المحلي لا يحتاج حساب شبكة في تجربة البيت. أما استعادة الوصول المتصل فهي استعادة `network_identity` أو `network_membership` بعد تحقق مناسب؛ ليست استعادة بيانات Manage المحلية، وليست مفتاحًا عامًا للدخول إلى مال Owner أو طلباته أو Snapshotاته.

لا ينشئ هذا المستند كلمة مرور أو OTP أو Passkey أو مزود هوية أو قاعدة بيانات أو واجهة Login أو قناة دعم أو سياسة قانونية. يثبت فقط قرارات الحد الأدنى وحالات القبول التي يجب أن تسبق تنفيذ A-01 وما بعدها.

## 2. الجهات الأربع والبوابات النهائية

| الجهة | البوابة المقصودة بعد A | ما تمثله | لا تصبح بوابتها |
|---|---|---|---|
| Owner | تجربة Micro الواحدة: Manage المحلي و`الخدمات` وسياق Workspace الشبكي الذي اختاره صراحةً. | إدارة مشروعه وتفاعلات Market/Delivery الخاصة به. | حسابًا يمنح موردًا أو Courier أو Admin رؤية Manage. |
| Supplier member | بوابة جهة المورد وسجلات Listing/Media والتفاعلات المسموح بها. | عرض جهته والرد ضمن Scope محدد. | وصولًا إلى مال/عملاء Owner أو عروض المنافسين. |
| Courier member | بوابة جهة التوصيل لعروضها ومهامها ضمن مرحلة الإفصاح الصحيحة. | Quote وحالة الحركة والاستثناء الموثق لجهته. | Driver Portal أو Dispatch أو رؤية Market غير اللازمة أو مال Owner. |
| Admin | سطح داخلي محدود لطابور Moderation والبلاغات وقراراتها. | تطبيق سياسة مراجعة محددة مع سبب ووقت. | `super_admin` تشغيليًا أو بوابة دعم تتصفح Manage أو تحل محل Owner. |

يعني «بوابة مستقلة» أن اختيار الدور وWorkspace ظاهر في كل طلب، وأن القرار يطبق مستقبلًا في Database وAPI وFile/Search/Notification/Export وApplication، لا بمجرد إخفاء رابط React.[1]

## 3. ما يحدث في كل مرحلة

| المرحلة | Owner | Supplier / Courier | Admin | حقيقة الأمان |
|---|---|---|---|---|
| الآن وE-00 | يستعمل Manage المحلي بلا حساب. | لا يدخل شخص حقيقي. | لا يوجد Admin تشغيلي. | لا توجد Authentication أو Authorization. |
| L — تجربة البيت | قد يبدل Persona في جهاز واحد لاختبار الحالة. | محاكاة محلية فقط ضمن سيناريو QA. | محاكاة Moderation محلية فقط. | وسم ظاهر: «بيئة اختبار محلية — ليست حسابات محمية». |
| A — تفعيل متعدد الأطراف | يدخل بهوية شبكة ويختار Workspace ودورًا. | يدخل كل عضو بهويته وعضويته وجهته. | يدخل بحساب إداري فردي محدود. | تحقق حقيقي متعدد الطبقات، لا واجهة فقط. |
| B — Pilot محدود | يشارك في مسار واحد وافق عليه. | يشارك فقط بعد دعوة/موافقة وبسياسة واضحة. | يراجع ما يقع ضمن اختصاص Pilot. | مراقبة وعزل واستعادة واختبارات رفض مثبتة. |

لا تتجاوز أي دعوة أو وصول خارجي أو استعادة هذه البوابات. فتح الرابط من جهاز ثانٍ أو تبديل Persona في L لا يثبت أن الطرف الصحيح يرى السجل الصحيح.

## 4. نموذج استعادة الوصول: أربعة مسارات لا مسار واحد

| المسار | متى يحدث | ما يُستعاد | ما لا يُستعاد | صاحب القرار/التحقق |
|---|---|---|---|---|
| R-01 — استعادة Manage المحلي | Owner فقد هاتفًا أو متصفحًا أو احتاج نقلًا يدويًا. | بيانات من Export/Import محلي صالح وفق العقد القائم. | هوية شبكة أو عضوية أو وصول طرف آخر. | Owner وملف التصدير؛ لا Admin ولا «نسيت كلمة المرور». |
| R-02 — استعادة هوية شبكة فردية | Owner/Supplier/Courier فقد وسيلة دخول أو غيّر جهازًا. | قدرة الشخص على تسجيل الدخول إلى `network_identity` نفسه بعد تحقق. | أي دور أو Workspace لم تثبت عضويته فيه. | مزود الهوية المختار وسياسة الاستعادة المعتمدة في A-01. |
| R-03 — استعادة عضوية أو جهة | هوية صحيحة لكن العضوية علقت/ألغيت/تغيرت أو احتاجت إعادة دعوة. | Membership محددة أو دعوة جديدة معلنة ومدققة. | توسعة Scope أو نقل ملكية أو دخول Manage. | Owner/جهة مخولة حسب السياسة، مع Audit ومدة وصلاحية. |
| R-04 — طوارئ إدارة المنصة | تعذر وصول مسؤولي Admin العاديين إلى طابور Moderation أو سياسة السلامة. | إدارة المنصة المحدودة فقط، بحساب طوارئ منفصل ومراقب. | انتحال Owner أو قراءة/تصدير Manage أو قرار تجاري نيابة عن طرف. | مسؤولان مفوضان، سياسة طوارئ، Audit ومراجعة لاحقة. |

لا يوجد مسار «أرسل كلمة مرور جديدة إلى Admin» أو «Admin يفتح حساب المستخدم». إذا احتاج الدعم إلى مساعدة، ينشئ **طلب مساعدة محدودًا** لا جلسة انتحال: يحدد صاحبه، نطاقه، سبب التحقق، الإجراء، الوقت، والنتيجة. ولا يرسل أي دعم أو Admin كلمة مرور أو رمز تحقق أو Export حساس عبر قناة غير موثقة.

## 5. قرار كلمة المرور والوسيلة المستقبلية

وجود استعادة وصول أمر شائع في التطبيقات المتصلة، لكن الاختيار ليس ثابتًا بعد. عند A-01 يقارن مالك المنتج والاختصاص التقني بين Password وOTP وPasskey أو هوية اتحادية بحسب فئة المستخدم، قابلية الاستعادة، مقاومة التصيد، الكلفة، العمل في الأردن، وملاءمة جهاز الهاتف. لا يختار هذا المستند الفائز.

إن اختيرت كلمات مرور مستقبلًا، يجب أن تكون الاستعادة عبر قناة تحقق مستقلة وباستجابة لا تكشف وجود الحساب، مع رموز/روابط عشوائية، أحادية الاستعمال ومحدودة العمر، وحماية من الإغراق أو التخمين. لا يغير طلب الاستعادة الحساب قبل تحقق الرمز، ولا يدخل المستخدم تلقائيًا بعد إعادة الضبط.[2]

بعد الاستعادة أو تغيير وسيلة الدخول، يطلب النظام إعادة تحقق قبل تغيير عضوية أو وسيلة اتصال حساسة، ويسجل الحدث ويتيح إبطال الجلسات المتبقية وفق السياسة المعتمدة. هذه مبادئ أمنية مستقبلية، لا ميزة منفذة أو زمن احتفاظ مقترح.[3]

## 6. Admin محدود وآمن

Admin في Micro لا يعالج أموال المالك ولا يدير محفظته ولا يصحح طلبه أو عقده. الدور محدود بمراجعة Listing/Media والبلاغات وحالات السياسة. لذلك يستعاد حساب Admin بوصفه **وصولًا ذا امتياز**، لا كحساب مستخدم عادي.

| الحارس | ما يثبت مستقبلًا |
|---|---|
| فردية الحساب | لكل Admin هوية منفصلة؛ لا حساب مشترك باسم `admin` أو مشاركة كلمة مرور. |
| فصل الاستخدام | حساب الإدارة لا يستخدم للتصفح اليومي أو البريد أو عمل Owner/Supplier/Courier. |
| عامل إضافي وإعادة تحقق | تستخدم MFA/وسيلة مقاومة للتصيد حيث تسمح تقنية A-01، وتطلب إعادة تحقق عند الاستعادة أو تعديل الدور أو سياسة حساسة. |
| أقل صلاحية | لا يرى Admin إلا Queue وAudit اللذين يحتاجهما؛ لا `super_admin` افتراضي. |
| طوارئ محدودة | حسابا طوارئ منفصلان عن العمل اليومي، لا يستخدمان إلا عند فقد إدارة المنصة العادية؛ كل استخدام مراجع لاحقًا. |
| تدقيق واعتراض | كل استعادة أو تغيير Membership أو تقييد/رفع Admin يسجل فاعلًا وسببًا ووقتًا ونتيجة، مع مسار مراجعة داخلي. |

فكرة حسابات الطوارئ المنفصلة والحسابات الإدارية الفردية متسقة مع ممارسات حماية الوصول ذي الامتياز، لكنها لا تمنح Micro حق تقليد نظام مؤسسة كبيرة أو تجاهل فئة المستخدم أو القدرة التشغيلية الفعلية.[4]

## 7. حالات الفشل والقبول قبل A

| الحالة | السلوك المطلوب | ممنوع |
|---|---|---|
| طلب استعادة لهوية غير موجودة أو غير متاحة | رسالة عامة لا تؤكد وجود الحساب، وسجل محاولة محدود. | كشف اسم أو دور أو جهة أو حالة الحساب. |
| رمز/رابط قديم أو مستعمل | رفض آمن، لا تغيير عضوية أو جلسة أو وسيلة دخول. | إعادة استعمال الرمز أو إنشاء جلسة كاملة من رابط منتهي. |
| Owner يستعيد هويته الشبكية | يعود فقط إلى Workspaces/Memberships السارية التي تثبتها السياسة. | فتح Manage محلي على جهاز آخر أو استيراد Export بلا فعل Owner. |
| Supplier/Courier يحاول الاستعادة لجهة أخرى | رفض بلا Metadata عن الجهة أو السجل. | تغيير Workspace عبر route أو دعم يدوي غير مدقق. |
| Admin فقد عاملًا أو حسابًا | مسار privileged منفصل مع تحقق إضافي وAudit ومراجعة. | مسار عام يرفع الدور أو حساب مشترك أو تجاوز دون سجل. |
| دعم يطلب الوصول لمشكلة | طلب محدود ومراجع، أو إرشاد Owner لاستعادة محلية/شبكية بنفسه. | انتحال صامت أو قراءة مال/Export أو نسخ بيانات حساسة. |

## 8. ما لا يحسمه هذا المستند

لا يحدد المستند مزود الهوية، أو رقم الهواتف/البريد المسموح، أو زمن الرموز والجلسات، أو نص شروط الاستخدام، أو مدة الاحتفاظ القانونية، أو نموذج دعم مدفوع، أو KYC. كل ذلك يحتاج قرار A-01 أو سياسة قانونية وتشغيلية محلية، ومقارنة موثقة واختبارات قبل دعوة أول طرف حقيقي.

## Action Points

1. تبقى R-01 قابلة للتطبيق حاليًا فقط بالـExport/Import المحلي القائم؛ لا نضيف كلمة مرور إلى Prototype.
2. قبل A-01، يختار المالك طريقة هوية الشبكة عبر EX-O05، ثم تكتب مقارنة مزود وهوية وUse Cases واختبارات استعادة وعزل مستقلة.
3. قبل B-01، يراجع مسؤول المنتج والسياسة المحلية مسارات الدعم والطوارئ والاحتفاظ، ولا يحول هذا المستند إلى ادعاء امتثال قانوني.
4. لا يغلق E-00.11 إلا بعد مراجعة مستقلة تربطه بعقدي 18 و23 ومصفوفة الدور وبوابة التفعيل وسيناريوهات رفض محددة.
