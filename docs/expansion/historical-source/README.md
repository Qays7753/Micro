## Micro Market وMicro Delivery — النسخة التاريخية

## 1. وضع الحزمة

هذه الحزمة توثق المفهوم المنقح لتوسيع Micro بقدرتين متجاورتين:

- **Micro Market:** مساحة بسيطة لاكتشاف المنتجات والمواد، قريبة من تجربة السوق المفتوح الأردني في الفئات والإعلانات والصور والوصف والسعر والموقع والتواصل.
- **Micro Delivery:** خدمة مستقلة للجلب والإرسال، يمكن ربطها بسجل تفاعل في Market أو استخدامها وحدها.

الحزمة وثائق مفهوم وقرار قبل التنفيذ. لا تمثل قدرة منفذة في `main`، ولا بوابات دخول حقيقية، ولا API، ولا إشعارات خارجية، ولا صلاحية للمورد أو شركة التوصيل في الكود الحالي. ويجمع الملف السادس صورة البناء المطلوبة قبل بدء المواصفة التنفيذية والكود.

## 2. الجهات والبوابات

تثبت الحزمة ثلاث جهات تجارية فقط:

| الجهة | البوابة والمحتوى |
|---|---|
| صاحب المشروع | Micro Owner App: النظام المالي وMarket وDelivery وما يرتبط بمشروعه. |
| المورد | Supplier Portal: منتجاته وListings وتفاعلاته وطلبات التوصيل المرتبطة به. |
| شركة التوصيل | Courier Company Portal: طلبات الجلب والإرسال التي وصلت إليها، وعرض السعر والموعد وتحديث التنفيذ. |

لا توجد بوابة أو شاشة أو حساب للسائق. وإذا احتاجت الشركة إلى ذكر منفذ الرحلة، تدخل اسمه ورقم هاتفه من بوابتها، ويظهران لطالب السيارة بالقدر اللازم.

توجد وظيفة إدارة داخلية لمراجعة Listings قبل نشرها وتجديدها بعد مدة الصلاحية. هذه الوظيفة ليست جهة تجارية رابعة وليست مشغلًا يدير الطلبات اليومية أو يبحث عن سيارة لكل طلب.

## 3. المبادئ الحاكمة

> **الاتفاق التجاري بين صاحب المشروع والمورد خارج Micro.**

> **يمكن تسجيل التفاعل أو الاتفاق الخارجي أو تأكيد المورد اختياريًا داخل Micro للمتابعة والتقييم، دون ادعاء أن Micro نفذ البيع أو ضمن الدفع.**

> **Market يربط صاحب المشروع بالمنتج والمورد؛ Delivery تنظم الجلب والإرسال.**

> **شركة التوصيل تستخدم بوابة Micro يدويًا. لا يوجد API أو Webhook أو ربط تلقائي مع نظام خارجي في المفهوم الحالي.**

> **قبول الشركة ليس حجزًا نهائيًا؛ الشركة تقدم السعر والموعد، ويؤكد طالب السيارة الحجز.**

> **التسليم لا يساوي الدفع أو الربح أو دخول المخزون أو إغلاق الأثر المالي.**

تبقى هوية Micro الأساسية ثابتة: نظام مالي وتشغيلي لصاحب المشروع، عميق في الداخل وواضح ومحترم وphone-first وRTL في الواجهة. لا تجعل هذه الحزمة Micro ERP أو CRM أو متجرًا عامًا أو بنكًا أو شركة توصيل عامة. [1] [2] [3]

## 5. حدود Prototype اللاحق

عند تفويض بناء Prototype، يكون محليًا على جهاز واحد بقاعدة Local، وتستخدم Views منفصلة لمحاكاة بوابة صاحب المشروع والمورد وشركة التوصيل، دون Login أو Authorization أو Cloud أو API أو إشعارات خارجية. لا توجد Driver View.

يستخدم المالك Role/Persona Switcher لأداء الأدوار الثلاثة واختبار دورة Market وDelivery لمدة محددة. ظهور Listing المورد في Owner View، ووصول DeliveryTask إلى Courier View، وعودة الحالات إلى صاحب المشروع، كلها محاكاة محلية لا تثبت تشغيلًا ميدانيًا أو تعاونًا حقيقيًا.

## 6. حالة التنفيذ

لا توجد هذه القدرات في `main` بوصفها Marketplace أو Delivery منفذة. لا توجد في النواة الحالية بوابات موردين أو شركات توصيل أو Auth/Workspace لهذه التوسعة، ولا API/Webhooks أو مزامنة خارجية. تبقى `docs/operations/current-state.md` المرجع الحي عند وصف ما هو منفذ فعلًا. [4]

الوثائق القديمة أو الاختيارات التي تحدثت عن API أو Webhooks أو حساب للسائق أو بوابة للسائق أو مشغل للطلبات اليومية تُعد خيارات مؤجلة أو ملغاة من المفهوم الحالي، ولا تُقرأ كقرار معتمد.
