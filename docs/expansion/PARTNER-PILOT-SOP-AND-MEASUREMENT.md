# Expansion — إجراء Partner Pilot وقياس الدليل

**الحالة:** `FUTURE / RUNS ONLY AFTER ACTIVATION GATE`
**الحد:** لا يستخدم في تجربة البيت، ولا يطلب بيانات/دعوات حقيقية قبل اجتياز بوابة A واعتماد بطاقة Wedge.

## Major Discussion Points

## 1. هدف Pilot

يقيس Pilot إن كان المسار الضيق يحل ضررًا متكررًا لشخص حقيقي مع طرف حقيقي، لا إن كان التطبيق قادرًا على عرض شاشات أو تسجيل حسابات. لا يثبت Pilot تسعيرًا أو سوقًا واسعًا أو التزامًا قانونيًا أو جدوى دفع قبل دليل منفصل.

## 2. التحضير قبل أول دعوة

| البند | دليل الإنجاز |
|---|---|
| بطاقة Wedge مكتملة ومعتمدة | رابط قرار وفئة/منطقة/مسار واحد. |
| بوابة A مكتملة | دليل وصول وملفات وخصوصية واستعادة وAudit، لا مجرد صفحة Login. |
| سياسة مشاركة البيانات | ما يجمع ولماذا ومن يراه ومدة/مسار الحذف والاستعادة بعد مراجعة مناسبة. |
| إجراء دعم واستثناء | مالك كل حالة: لا رد، محتوى مخالف، تسرب، فشل حركة، طلب حذف. |
| شركاء محدودون | عدد محدد والتزام مكتوب أو واضح بالمهمة، لا أسماء/صور وهمية. |
| نقطة نهاية | مدة/عدد تفاعلات وحد نجاح وفشل وقرار نهاية واضح. |

## 3. التشغيل اليومي المحدود

| الخطوة | Market | Delivery | ما لا يفعله Micro |
|---|---|---|---|
| بدء | Owner ينشر Need بموافقة على الحقول. | Owner يرسل Request بعد Preview للإفصاح. | لا يفترض توفرًا أو موعدًا أو دفعًا. |
| رد خارجي | Supplier يرسل Response. | Courier يرسل Quote/توضيح. | لا يقبل نيابة عن Owner أو يسجل مالًا. |
| قرار | Owner يقبل متابعة/يرفض/يغلق. | Owner يقبل Quote/يرفض/يلغي. | لا ينشئ Purchase أو Expense أو Booking ماليًا. |
| نتيجة | يسجل Owner إن حدث واقع في Manage مستقلًا. | Courier يكتب Status/Exception، وOwner يراجع. | لا يثبت تسليم/تحصيل/مخزون تلقائيًا. |
| دعم | Admin يعالج بلاغ/Moderation بسجل سبب. | Admin يعالج استثناءً ضمن سياسة. | لا يفصل نزاعًا ماليًا أو يضمن خدمة. |

## 4. القياس والقرار

| السؤال | الدليل المقبول | ليس دليلًا كافيًا |
|---|---|---|
| هل المشكلة متكررة؟ | سجل موقف/فئة/تاريخ وسياق حل حالي. | انطباع عام أو شاشة مستخدمة مرة. |
| هل أصبح الوصول أسرع أو أوضح؟ | زمن/خطوات حتى رد أو Quote، ومقابلة قصيرة عن الفهم. | عدد تنزيلات أو زيارات. |
| هل رد الطرف الآخر فعلًا؟ | Response/Status حقيقيان بسجل فاعل ووقت. | حسابات تجريبية أو Notifications مصطنعة. |
| هل فهم Owner أن الحالة ليست مالًا؟ | سؤال قبول وسلوك تسجيل واقع صريح أو عدم التسجيل. | غياب خطأ في console. |
| هل الخصوصية والتشغيل مقبولان؟ | مراجعة الإفصاح والاستثناء/البلاغ وحالات رفض الوصول. | ظهور الحقول في UI فقط. |

يسجل القرار بعد كل Pilot كـContinue أو Modify أو Defer أو Stop، مع الدليل والحدود والضرر الباقي. لا يوسع الفئة أو المنطقة أو يضيف دفعًا أو تقييمات أو تتبعًا حيًا من نجاح تعامل واحد.
