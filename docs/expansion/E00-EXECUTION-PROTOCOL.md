## Major Discussion Points

## 1. نقطة الانطلاق

أي Agent يعمل على E-00 يبدأ بـ`git fetch origin --prune` ويقرأ `docs/operations/current-state.md` و`AGENTS.md` ثم `docs/expansion/README.md` و`DECISIONS.md` و`TRACKER.md` والعقد المتصل بالمهمة. يثبت في أول مخرجاته ما قرأه، المعرف الذي يعالجه، الملفات المتوقعة، ما لن يغيره، ومعيار القبول والمجهول.

G19–G23 مسار UX مستقل. لا يغير Agent E-00 Home أو App Shell أو BottomNav أو CSS أو React أو Domain أو LocalStore أو Dependency أو `localSchemaVersion` أو `localExportVersion` أو `todo.md`. إن احتاجت وثيقة تغييرًا في أي واحد، تسجل القرار وتنتظر PR منفصلة بعد بوابتها.

## 3. قالب مراجعة كل عقد

| السؤال | يجب أن يجد المراجع جوابًا واضحًا |
|---|---|
| المستخدم والضرر | من يتأذى وفي أي موقف؟ |
| أقل إدخال/نتيجة | ما الذي يدخل، ماذا يرى، وما فعله التالي؟ |
| الحالة والفاعل | من يغير ماذا، ومن يرفض؟ |
| الخصوصية | ما الحقل الذي يرى كل دور ولماذا؟ |
| المال | ما الذي لا يتغير في كاش/دين/ربح/مخزون؟ |
| التاريخ والتكرار | ما المفتاح والسجل والتصحيح؟ |
| الفشل والاستعادة | ماذا يحدث للانقطاع/رفض/مسودة/ملف/حدث متأخر؟ |
| الحد | ما الذي لم نبنه ولم ندّعِه؟ |

## 4. قبول وتسليم E-00

قبل push: `pnpm install --frozen-lockfile` ثم `pnpm check` و`git diff --check`، مع مراجعة أن الملفات المتغيرة وثائق مصرح بها فقط. في وصف PR يذكر Agent المعرفات والعقود والسيناريوهات وما لم يتغير وحدود التجربة المنزلية والتفعيل المتصل. لا يذكر SHA دمج مستقبليًا، ولا يعلن Pilot أو حماية حقيقية.

المراجع المستقل يقرأ الفرق من رأس PR نظيفًا، ويتحقق من الروابط والسلطة والتعارض مع العقود المالية و`current-state.md`، ثم يعيد الفحوص. إذا احتاج أي تغيير schema/export أو اختيار مزود أو قانون/سياسة خارجية أو كود، يرفض الدمج الجزئي في E-00 ويطلب قرارًا/PR منفصلة.
