## Major Discussion Points

## 1. القرارات المعتمدة

| المعرف | القرار | ما يغيره في البناء |
|---|---|---|
| EX-D01 | Micro منتج واحد في عين Owner؛ Manage هو المركز، وMarket/Delivery قدرات متصلة لا منتجات معروضة. | لا صفحة اختيار ثلاثة منتجات، ولا تسميات تسويقية تنافس إدخال المال والطلبات. |
| EX-D02 | وجهة `السوق` تفتح Market مستقلة في BottomNav، ورمز السيارة في AppBar يفتح قسم Delivery مستقلاً. | لا صفحة خدمات مركزية ولا اختيار ثلاثة منتجات؛ الردود والتنبيهات تظهر داخل مصدرها فقط. |
| EX-D03 | Manage يبقى local-first بلا Login أو Cloud في تجربة البيت. | لا نرحل مال/طلبات/مخزون أو Snapshotات تاريخية إلى طبقة شبكة تلقائيًا. |
| EX-D04 | التوسعة تبدأ محليًا للتجربة الخاصة، ثم تتصل لاحقًا فقط عند دعوة أطراف حقيقية. | محاكي الدور هو QA محلي ولا يساوي Authorization أو أمن. |
| EX-D05 | الاتفاق مع المورد وحالة التوصيل ليسا حدثًا ماليًا. | كل أثر شراء/مصروف/مخزون/تسليم/قبض يدخل Manage بفعل Owner صريح ومراجعة قبل الحفظ. |
| EX-D06 | Market وDelivery مستقلان في Domain وفي الحالات، ويملكان Attention/Notification/Audit مملوكًا للمصدر والمستلم. | لا تخلق Delivery تفاعل Market تلقائيًا، ولا تخلق Market مهمة Delivery إلا عندما ينشئ Owner نية مستقلة. |
| EX-D07 | المورد وشركة التوصيل يملكان بوابات دور منفصلة عند التفعيل. | لا يرون Manage أو مال Owner؛ لا Driver Portal في المسار الحالي. |
| EX-D08 | Admin داخلي محدود لمراجعة Listing/وسائط/بلاغات. | ليس جهة تجارية ولا CRM أو فريق Dispatch ولا مديرًا ماليًا للمستخدم. |
| EX-D09 | لا ميزات منصة عالية المخاطرة في البدايات. | لا دفع أو Checkout أو عمولة GMV أو ratings/نجوم أو Chat مفتوح أو live tracking أو automated pricing. |
| EX-D10 | شريط Micro يتبع ترتيب العمل اليومي: `مشروعي الآن / الطلبات / + إضافة / المراجعة / السوق`؛ رمز `التوصيل` في أقصى يسار AppBar يفتح قسمه فقط. | الإعدادات تبقى بدخول هيدر/المزيد؛ زر `+` يبقى لوقائع Manage لا لطلب Market/Delivery، ورمز السيارة لا ينشئ حركة مباشرة. |
| EX-D11 | لا تجمع طبقة الشبكة حقلًا بلا غرض وتصنيف وScope وموافقة؛ وتبقى بيانات Manage `manage_private`. | لا ينسخ سياق مالي/عميل/مخزون تلقائيًا؛ كل كشف يبدأ من Preview وقرار Owner. |
| EX-D12 | تجربة البيت L تختبر تجربة Owner ومنطق الحالات فقط. | محاكي الأدوار ليس Authentication ولا Authorization ولا عزلًا بين مستخدمين أو أجهزة. |
| EX-D13 | لا دعوة لطرف حقيقي قبل بوابة A: هوية وعزل DB/API/File/Search/Notification/Export وسجل تدقيق وسياسة خصوصية. | لا Login شكلي، ولا اعتماد على إخفاء واجهة، ولا بيانات حقيقية أو Pilot مبكر. |
| EX-D14 | نجاح Market أو Delivery يقاس بحل ضرر واحد متكرر في فئة ومنطقة محددتين، لا بعدد الشاشات أو التسجيلات أو GMV. | لا توسع فئة/منطقة أو دفع/تقييم/تتبع من تعامل واحد أو دليل غير ميداني. |
| EX-D15 | صفحة السوق المستهدفة لها `استكشف` و`احتياجاتي`: بحث وفلاتر ضمن Wedge وListings معتمدة وردود منظمة واتصال خارجي اختياري. | لا Chat أو Recommendation أو Ranking أو Ratings أو مخزون حي أو تغطية مزعومة خارج Wedge. |
| EX-D16 | قسم التوصيل يعرض طلبات وعروضًا وحالات واستثناءات؛ `vehicle_requirement` إن أقره Wedge يصف قدرة النقل فقط. | لا اختيار سيارة أو سائق أو حجز أو توفر حي أو GPS أو Dispatch. |
| EX-D17 | Market وDelivery يظهران من Manage/Orders/Inventory فقط عند نية مفهومة وبـPreview قابل للمراجعة. | لا نسخ تلقائي لسعر أو كاش أو عميل أو Snapshot أو كمية جرد، ولا أثر مالي أو مخزني أو حالة Order تلقائية. |

## 2. السياسة المالية وخصوصية البيانات

> **Market وDelivery يصفان تفاعلًا أو نية أو حالة خارجية. Manage هو المكان الوحيد الذي يسجل حقيقة المشروع المالية أو المخزنية.**

| ما حدث خارج Micro Manage | ما تعرضه التوسعة | ما لا يفعله النظام |
|---|---|---|
| Owner نشر احتياجًا | `market_need` وحالة نشر/رد. | لا ينشئ طلب شراء أو ذمة أو تكلفة. |
| Supplier أرسل عرضًا | رد يحتاج مراجعة Owner. | لا يحجز مخزونًا ولا يثبت سعرًا نهائيًا أو دفعًا. |
| Owner قبل ردًا | قرار Market وسجل attention. | لا يسجل شراءً أو COGS أو حركة مخزون. |
| Owner طلب حركة | `delivery_request` مسودة/مقدمة. | لا يكشف العنوان أو رقم العميل قبل الإفصاح الذي يوافق عليه. |
| Courier أكد/وصل | حدث حالة مؤرخ بفاعل معلوم. | لا يعني تلقائيًا قبضًا أو تسليم طلب أو إدخال مخزون. |
| Owner يريد تثبيت الواقع | زر `سجل ما حدث في مشروعي`. | لا يملأ مبلغًا أو تاريخًا أو حساب كاش أو نوع حدث بلا مراجعة وتأكيد. |

## 3. القرارات التي لا تزال مفتوحة

لا يقرر Agent هذه النقاط من افتراض أو من مثال واجهة. يرفعها للمالك بعناصر بدائل وأثر كل بديل على العقد.

| المعرف | السؤال المفتوح | لماذا يغير البناء؟ |
|---|---|---|
| EX-O01 | ما الفئة الأولى: طعام منزلي أم حرفة أم خدمات؟ | يحدد لغة الاحتياج، بيانات Listing، الوحدة، والصورة/الوصف الأدنى. |
| EX-O02 | ما المدينة/المنطقة الأولى؟ | يحدد معنى الموقع، نطاق التوصيل، وحجم السوق الذي نستطيع اختباره. |
| EX-O03 | ما أول حاجة مثبتة: بحث المورد أم حركة التوصيل؟ | يحدد أول Vertical Slice بعد L-00 wireframes المتفق عليها. |
| EX-O04 | هل يوجد موردان أو شريك توصيل مستعدان لتجربة لاحقة؟ | يحدد إن كانت تجربة البيت تختبر مسارًا واقعيًا أو مجرد محاكاة. |
| EX-O05 | ما طريقة هوية طبقة الشبكة عند التفعيل؟ | لا تؤثر على Manage المحلي، لكنها تغير الدعوة والاستعادة وعزل الحسابات المتصلة. |
| EX-O06 | ما التفاعل الذري وعتبة السيولة/الفشل في أول Wedge؟ | يحدد السيناريو والقياس وقرار الإيقاف؛ لا يقاس النجاح بالتسجيلات أو GMV وحدهما. |
| EX-O07 | من يُبذَر أولًا: Owner أم مورد/شركة توصيل شريكة، وما الالتزام الفعلي المحدود؟ | يمنع بناء منصة فارغة أو افتراض أن التسجيل وحده يجلب العرض أو الحالة. |
| EX-O08 | هل يبقى المسار الأول مجانيًا، أم توجد فرضية نموذج تجاري واحدة تُدرس بعد دليل قيمة؟ | يمنع عمولة أو رسم أو دفع أو ترتيب مدفوع مبكر، ويؤثر لاحقًا في العقود والتشغيل والالتزامات. |
| EX-O09 | ما سياسة صمت الساعي (X-06/E-01): انتهاء مهلة للطلب تلقائيًا بحالة «لم تصل عروض» (الافتراضي الموصوف في العقد 21 §3.1: 48 ساعة)، أم إلغاء يدوي فقط، أم بث بمهلة ضاغطة؟ | يحدد أهم حالة في مسار التوصيل ومخرجاتها ونصها الظاهر؛ المواصفة الافتراضية مكتوبة وتنتظر الحسم فقط. |
| EX-O10 | ما نموذج توجيه طلب الحركة (E-03): اختيار الطالب من دليل سواعي، أم بث لكل سواعي الوتد، أم ساعٍ وحيد؟ | يحدد بنية `routing` وكيان `courier_company_profile` وقاعدة «يرى ما وصل لجهته» ومسألة رؤية السواعي لعروض بعضهم. |
| EX-O11 | حلقة تواصل الردود (X-05/E-10): قناة اتصال منسوخة من Listing معتمد (الافتراضي الموصوف في العقد 24 §3.1)، أم الرد لأصحاب الإعلانات المعتمدة فقط، أم قناة الإعلان وحدها؟ | يحدد إن كان الرد المقبول يقود إلى فعل تالٍ ممكن، وما تدخل Moderation في قناة الرد. |
| EX-O12 | موقع تخزين بيانات الشبكة في المرحلة L ونطاق تصدير المسودات المحلية (E-15): قاعدة IndexedDB منفصلة، أم نفس القاعدة بترقية Schema؟ | يوفق بين بوابة Migration (لا تغيير نسخ) وتخزين L-01.2 ووعد إجراء الاستعادة؛ والقرار معماري/مالك لا Agent. |
| EX-O13 | هل تدعم مبالغ الشبكة عملة واحدة JOD فقط (الافتراضي، العقد 25)، أم عملات متعددة معلنة، أم تحويلًا؟ | يحدد حقول المبالغ وكل قواعد العرض والمقارنة قبل أي DTO. |
| EX-O14 | ما ميكانيكا موافقة العميل النهائي نفسه (إطلاعه/موافقته) على كشف بياناته للساعي؟ (E-11، مؤجل إلى المراجعة القانونية OR-O04/§10) | قد يغير مسار النشر والإفصاح والنصوص قبل أي بيانات عميل حقيقية. |
| EX-O15 | عتبات طابور المراجعة (E-17): هدف زمن المراجعة الافتراضي 48 ساعة عمل وعتبة تصعيد 7 أيام/20 عنصرًا — تُعتمد أم تعدل؟ | تحدد قابلية قياس سياسة الطابور المطلوبة في Pilot B (Tracker B-07). |
| EX-O16 | أرقام ضوابط الإساءة (E-12): حدود الاحتياجات/الردود/العروض اليومية وعتبات تنبيه القراءة — تُعتمد أم تعدل؟ | وجودها مانع لبوابة A (بوابة الجاهزية §9)؛ أرقامها فقط معلقة. |

## 4. بطاقات الخيارات والعواقب للقرارات المفتوحة المضافة (معالجة المرحلة الثامنة — 29 أغسطس 2026)

أضيفت هذه البطاقات من مواصفات المرحلة الثامنة لمعالجة المراجعة الكاملة (بطاقات E-01/E-03/E-10/E-11/E-12/E-14/E-15/E-17). كل بطاقة تسجل الخيارات وعواقبها وافتراضيًا موصوفًا بانتظار حسم المالك — **لا يعد وجود المواصفة الافتراضية قرارًا**، ولا يُبنى عليها كود قبل الحسم.

| المعرف | الخيارات وعواقبها | الافتراضي الموصوف بانتظار الحسم | مكان المواصفة |
|---|---|---|---|
| EX-O09 — صمت الساعي | (أ) مهلة طلب تنتهي تلقائيًا بحالة «لم تصل عروض» مع أفعال صريحة — صادقة وتطابق «missing ≠ zero»، وتكلف تعريف مؤقت زمني؛ (ب) إلغاء يدوي فقط — أبسط تنفيذ لكن حالة الانتظار تبقى غامضة إلى ما لا نهاية؛ (ج) بث بمهلة ضاغطة للسواعي — يغير نموذج التوجيه كله ويرتبط بـEX-O10 ويرهق شركاء قليلين. | (أ) بمهلة 48 ساعة، مع النص «لا يوجد عرض حتى الآن — بيان مسجل، وليس عدم اهتمام». | العقد 21 §3.1 و§3.2 |
| EX-O10 — توجيه طلب الحركة | (أ) الطالب يختار ساعيًا من دليل مقيّد — يحتاج كيان ملف الساعي وقواعد تحديثه؛ (ب) بث لكل سواعي الوتد — يحتاج قاعدة ظهور ومنافسة، وسؤال رؤية كل ساعٍ لعروض غيره (الافتراض الصادق: لا يراها)؛ (ج) ساعٍ وحيد — أبسط ما دام الوتد ضيقًا، لكن خطر الاعتماد على جهة واحدة يُقبل صراحة. | لا افتراض مفروض؛ الحقل موثّق بثلاث دلالاته ولا يُملأ حتى الحسم. | العقد 21 §2 + العقد 24 §3 (`courier_company_profile`) و§3.1 |
| EX-O11 — حلقة تواصل الردود | (أ) قناة اتصال في الرد منسوخة من Listing معتمد — تجعل الرد المقبول قابلًا للفعل، وتوسّع نطاق Moderation ليشمل قناة الرد؛ (ب) الرد لأصحاب الإعلانات المعتمدة فقط — أبسط لكنه يجهض غرض الاحتياجات عند البداية الباردة؛ (ج) قناة الإعلان وحدها — الوضع الراهن: الرد المقبول ينتهي داخل التطبيق بلا فعل تالٍ. | (أ) كحقول موصوفة معلقة (`contact_channel`) لا تدخل Schema قبل الحسم. | العقد 24 §3.1 |
| EX-O12 — تخزين الشبكة في L | (أ) قاعدة IndexedDB منفصلة لبيانات الشبكة — تحترم بوابة Migration (لا تغيير `localSchemaVersion`/`localExportVersion`)، لكن يجب توثيق أن مسودات التوسعة خارج تصدير Manage في إجراء الاستعادة توثيقًا صادقًا؛ (ب) نفس القاعدة مع ترقية Schema — يكسر وعد البوابة ويستلزم عقد Migration كاملًا واختبارات Restore؛ (ج) نفس القاعدة بلا ترقية عبر object stores منفصلة — غير آمن؛ يُرفض. | لا افتراض مفروض؛ الحسم معماري/مالك. بوابة Migration تبقى على حقيقتها الحالية (لا تغيير) حتى الحسم. | بوابة `MANAGE-NETWORK-MIGRATION-EXPORT-GATE.md` (غير معدلة) + إشارة في إجراء تجربة البيت §3 |
| EX-O13 — عملة مبالغ الشبكة | (أ) عملة واحدة JOD — أبسط تمثيل بلا تحويل؛ (ب) عملات معلنة متعددة بلا تحويل — تحتاج حقل عملة لكل مبلغ وتمنع المقارنة المباشرة؛ (ج) تحويل — تحتاج مصدر أسعار وسياسة تقريب ومسؤولية عن الفروق، وممنوعة قبل عقد مستقل. | (أ) — العقد 25 مكتوب على هذا الأساس، وترفض أي عملة غير JOD حتى الحسم. | العقد 25 §3 |
| EX-O14 — موافقة العميل النهائي | الاحتمالات: إطلاع العميل نصيًا عند تسليم بياناته، أو موافقته الصريحة، أو اكتفاء بموافقة البائع إن أجاز القانون ذلك — تختلف قانونيًا وتشغيليًا وتتوقف على رأي الاستشارة (بوابة الجاهزية §10: حماية البيانات الشخصية). | لا افتراض مفروض؛ القاعدة الحالية: موافقة Owner على بيانات عميله + معاينة، وغياب موافقة العميل لا يعتبر رضًا ضمنيًا. | العقد 24 §2 + بوابة الجاهزية §10 |
| EX-O15 — عتبات طابور المراجعة | أرقام أصغر (مثل 24 ساعة) ترفع كلفة التشغيل على مالك بدوام جزئي؛ وأرقام أكبر تترك الموردين في انتظار أعمى؛ و«بلا عتبات» مرفوض لأن السياسة نفسها متطلب Pilot B. | 48 ساعة عمل للمراجعة، وتصعيد عند 7 أيام عمل أو 20 عنصرًا. | العقد 20 §3.4 + Tracker B-07 |
| EX-O16 — أرقام ضوابط الإساءة | أرقام مشددة تحمي الجودة وتخنق البداية الباردة؛ وأرقام فضفاضة تفتح باب الحصاد والسبام عند أول شريك حقيقي؛ وغياب الأرقام يبطل المتطلب المانع لبوابة A. | 5 احتياجات/يوم للمالك، 20 ردًا/يوم للمورد، 20 عرضًا/يوم للساعي + عرض نشط واحد لكل طلب، وتنبيه قراءة عند أكثر من 5 مرات بلا فعل. | بوابة الجاهزية §9 |
