## 1. القرارات المعتمدة

## 1-ب. قرارات المالك المعتمدة — Market (OD-01…OD-21؛ توجيه نهائي 2026-11-09)

**المصدر المجمد (دليل تاريخي فقط):** `docs/expansion/handoffs/zai-micro-market-delivery-2026-11-11/inputs/approved-feature-specs/market/Micro_Market_Execution_Master_AR_v1.md` §«سجل قرارات المالك». بعد هذه المزامنة هذا القسم هو المرجع التشغيلي. هذه قرارات منتج ملزمة لسلوك العقود والوثائق؛ **لا تعني تنفيذًا أو نشرًا أو اختيار مزود**.

| المعرف | القرار المعتمد |
|---|---|
| OD-01 | جميع محافظات الأردن؛ لا حصر لعمّان أو منطقة بعينها. |
| OD-02 | جميع قطاعات المواد ومستلزمات الأعمال؛ المالك يدير القطاعات والفروع وحقولها بأدوات آمنة. |
| OD-03 | أي مستخدم Micro مسجل يستطيع بدء مسار البيع وتجهيز مسودة وصور خاصة من الحساب نفسه؛ التقديم ليس اعتماد مورد أو نشرًا عامًا، ولا يشترط موردًا محترفًا. |
| OD-04 | تصفح وتواصل الزائر مقبولان؛ تفاصيل الإتاحة داخل تطبيق موزع مستقبلًا مؤجلة ولا تثبت Native أو متجرًا. |
| OD-05 | الدخول بزر المتابعة باستخدام Google عبر هوية Micro؛ لا كلمة مرور أو دخول مستقل للمورد أو للسوق. اختيار المزود الفعلي وتفعيله تحقق تقني لاحق لا يلغي القرار. |
| OD-06 | البروتوتايب المطلوب تجربة متصلة تعمل ببيانات محفوظة فعليًا وحسابات وجلسات مختلفة؛ المحاكاة المحلية وبيانات الاختبار لا تثبت القبول المتصل. |
| OD-07 | مجاني تشغيليًا ضمن حدود مضبوطة؛ وسيلة دفع للتفعيل فقط، دون موافقة على رسوم أو ترقية أو خصم تلقائي. |
| OD-08 | مواد جديدة وفوائض وبقايا ومواد مستعملة صالحة؛ الحالة والعيوب والكمية المعلنة واضحة. |
| OD-09 | مراجعة ملف المورد ونسخة الإعلان والصور المطلوبة قبل إتاحتها للعامة؛ السعر العددي والتوفر والإيقاف مباشرة بتحقق وسجل ضمن الحدود المعتمدة. |
| OD-10 | قيس مسؤول المراجعة والبلاغات بالبداية؛ 48 ساعة عمل هدف داخلي هندسي لا وعد علني معتمد. |
| OD-11 | تنبيه بعد 30 يومًا دون تأكيد توفر وإخفاء بعد 60؛ التجديد بعد الإخفاء بمراجعة ولا يرفع إيقاف الإدارة. |
| OD-12 | نشاط مورد واحد يديره شخص واحد في v1؛ الشراء والبيع بالحساب نفسه، دون تحويل كل مشترٍ إلى مورد. |
| OD-13 | النشر والتصفح والتواصل مجانية في v1؛ لا رسوم أو اشتراكات أو عمولات أو تقييمات شراء. |
| OD-14 | Market لا يرفع أو يغير مالية Manage المحلية؛ عقد `MarketPrice` والكميات مستقل عن `MoneyMinor` المالي. |
| OD-15 | Micro المنتج الأساسي وMarket جزء منه؛ مساحة مورد واضحة داخل Market بالحساب نفسه، دون تطبيق أو دخول منفصل أو إعداد مالي أو كشف وظائف غير لازمة. |
| OD-16 | تجهيز وتقديم ملف المورد والإعلان والصور ممكنة قبل اكتمال مراجعة الملف؛ لا نشر قبل قبول جميع الأجزاء اللازمة للعنصر المراد إتاحته. |
| OD-17 | بوابة السائق مستقلة وتخص السائق؛ ملفات المورد والسائق ومراجعاتهما وصلاحياتهما منفصلة، ولا تكامل تلقائي بين إعلان Market وحجز Delivery. |
| OD-18 | My Ask Micro مؤجلة عن هذا التكليف؛ لا شاشات أو أدوات أو API لها، ولا تعد بوابة تمنع Market. |
| OD-19 | اختيار الوحدات عند أول تشغيل مؤجل؛ نحافظ على حدود الهوية والملكية والإقلاع دون بناء تدفق أو نظام إعداد وحدات. |
| OD-20 | التقنيات خط أساس موثق لا حالة حية؛ D1 مقابل Postgres/RLS لا يحسم دون إثبات العزل والأداء والتكلفة والتوافق مع Micro. |
| OD-21 | أي تغيير بنيوي لاحق يسبقه مسح شامل قراءة فقط ثم مراجعة المالك واعتماده قبل أي موجة؛ لا نقل أو إعادة هيكلة من هذه الوثيقة. |

**قراءة حاكمة:** نموذج Market v1 هو **Listing-first** — الإعلان وحدة السوق الأساسية والاحتياجات والردود المنشورة مؤجلة خارج v1 (OD-03 مع REC-01 في المواصفة)؛ النطاق وطني شامل بتجربة متصلة محدودة المشاركين والاستخدام (OD-01/OD-02/OD-06)؛ الحداثة 30/60 (OD-11)؛ والدقة والتمثيل المالي في العقد 25 (OD-14). الأحجام والحصص وآليات المعاملات توصيات هندسية لا أرقامًا اعتمدها المالك شخصيًا.

## 2. السياسة المالية وخصوصية البيانات

> **Market وDelivery يصفان تفاعلًا أو نية أو حالة خارجية. Manage هو المكان الوحيد الذي يسجل حقيقة المشروع المالية أو المخزنية.**

| ما حدث خارج Micro Manage | ما تعرضه التوسعة | ما لا يفعله النظام |
|---|---|---|
| Owner نشر احتياجًا | `market_need` وحالة نشر/رد. | لا ينشئ طلب شراء أو ذمة أو تكلفة. |
| Supplier أرسل عرضًا | رد يحتاج مراجعة Owner. | لا يحجز مخزونًا ولا يثبت سعرًا نهائيًا أو دفعًا. |
| Owner قبل ردًا | قرار Market وسجل attention. | لا يسجل شراءً أو COGS أو حركة مخزون. |
| Owner طلب حركة | `delivery_request` مسودة/مقدمة. | لا يكشف العنوان أو رقم العميل قبل الإفصاح الذي يوافق عليه. |
| Courier أكد/وصل | حدث حالة مؤرخ بفاعل معلوم. | لا يعني تلقائيًا قبضًا أو تسليم طلب أو إدخال مخزون. |
| Owner يريد تثبيت الواقع | زر `سجل ما حدث في مشروعي`. | لا يملأ مبلغًا أو تاريخًا أو حساب كاش أو نوع حدث بلا مراجعة وتأكيد. |

## 4. بطاقات الخيارات والعواقب للقرارات المفتوحة المضافة (معالجة المرحلة الثامنة — 29 أغسطس 2026)

أضيفت هذه البطاقات من مواصفات المرحلة الثامنة لمعالجة المراجعة الكاملة (بطاقات E-01/E-03/E-10/E-11/E-12/E-14/E-15/E-17). كل بطاقة تسجل الخيارات وعواقبها وافتراضيًا موصوفًا بانتظار حسم المالك — **لا يعد وجود المواصفة الافتراضية قرارًا**، ولا يُبنى عليها كود قبل الحسم.

> **تحديث مؤرخ 2026-11-12:** حسم التوجيه النهائي 2026-11-09 عدة بطاقات (انتبار §3): EX-O09 وEX-O10 بقرارات Delivery OD07/OD03، وEX-O11 بالاستبعاد المعتمد للاحتياجات/الردود من v1، وEX-O12 لمخزن مسودات السوق، وEX-O13 بJOD وحده. البطاقات أدناه تبقى تحليل خيارات تاريخيًا؛ مرجع الحالة الحية هو §3 و§1-ب/§1-ج.
