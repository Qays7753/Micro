# Expansion — خريطة التنفيذ والبوابات للجهات الأربع

**الحالة:** `CURRENT / E-00 / EXECUTION MAP ONLY / NO CODE AUTHORIZATION`
**الغرض:** جعل طريق التنفيذ المقصود واضحًا لمالك المنتج وأي Agent: تجربة Micro واحدة للـOwner، وبوابات منفصلة لاحقًا للمورد وشركة التوصيل وAdmin، من دون اعتبار الوثيقة تصميمًا منفذًا أو تفويضًا لبدء A أو Pilot.

## Major Discussion Points

## 1. شكل المنتج الذي لا يتغير

> **يرى Owner منتجًا واحدًا باسم Micro. يرى Manage في المركز، و«الخدمات» لوحة متابعة قصيرة للحاجة التي تستحق قرارًا، لا متجرًا أو صفحة اختيار Market/Delivery.**

Market وDelivery قدرتان منفصلتان في Domain وحالاتهما، لكنهما لا تنقلان مالًا أو طلبات أو كاشًا أو مخزونًا أو COGS تلقائيًا إلى Manage. المورد وشركة التوصيل لا يدخلان Micro Manage؛ لكل منهما بوابة دور مستقلة عند التفعيل الحقيقي. Admin يراجع سياسة وبلاغًا، لا المال أو التشغيل التجاري.

## 2. خريطة البوابات حسب الجهة

| الجهة | قبل التفعيل A | عند التفعيل الحقيقي A | ما يثبت القبول قبل Pilot |
|---|---|---|---|
| Owner | Manage محلي؛ لاحقًا محاكاة L موسومة بوضوح. | هوية شبكة، Workspace Owner، لوحة `الخدمات`، مسودات/تفاعلاته، وPreview صريح قبل أي إفصاح. | لا يرى Owner آخر؛ قبول عرض/حالة توصيل لا تسجل واقعًا ماليًا تلقائيًا؛ روابط/بحث/Export معزولة. |
| Supplier | لا بوابة حية؛ Persona QA فقط في L. | Workspace جهة المورد وListings/Media وتفاعلات Scope المسموح بها. | لا يرى Manage أو العملاء أو عروض المنافسين؛ نشر Media لا يصبح عامًا قبل Moderation. |
| Courier | لا بوابة حية؛ Persona QA فقط في L. | Workspace جهة التوصيل وQuotes/حالات مهامها وفق Scope وإفصاح Owner. | لا يرى سعر Market غير اللازم أو مال Owner أو مهمة جهة أخرى؛ `completed` لا يساوي قبضًا/تسليمًا ماليًا. |
| Admin | لا حساب أو صلاحية حية؛ محاكاة QA فقط عند L حيث يلزم. | حساب فردي محدود لطابور Moderation/بلاغات/Audit. | لا يفتح Manage المالي؛ كل قرار بسبب ووقت؛ الاستعادة لا تمنح امتيازًا أعلى أو انتحال Owner. |

## 3. مراحل التنفيذ وبوابة الانتقال

| المرحلة | الناتج القابل للقبول | ما لا يبدأ بعدها تلقائيًا | دليل البوابة |
|---|---|---|---|
| E-00 — وثائق | قرارات، عقود، سيناريوهات، SOPs، مصفوفات وصول، وسجل استعادة/حوكمة متسق. | لا UI أو Domain أو LocalStore أو Auth أو DB أو Schema/Export. | مراجعة مستقلة لـE-00 وربط دليل كل بند في Tracker. |
| L-00 — تثبيت الأساس | `main` مستقرة بعد G20–G23، وwireframe نصي للشاشات الأربع المقصودة. | لا Market/Delivery code إذا لم يغلق UX أو لم يعتمد Owner أول Wedge. | SHA `main` وفحوصها وقرار Wedge مكتمل. |
| L-01 — محلي وSimulator | Domain/Use Cases/Ports/LocalStore ومحاكي Persona موسوم بحدوده. | لا دعوات، لا حسابات، لا بيانات حقيقية، لا ادعاء أمن. | اختبارات حالة/Role/URL محلية وفشل آمن وقرار Migration مستقل إن لزم. |
| L-02 — خدمات Owner | لوحة خدمات قصيرة وحالات فارغة/معبأة وعودة للمصدر بلا أثر Manage تلقائي. | لا تحويلها إلى Market/Delivery tabs أو Notification/Push متصل. | QA Owner وRTL/mobile وغياب أثر مالي/مخزني تلقائي. |
| L-03 / L-04 — Market / Delivery محليان | محاكاة تدفق واحد لكل قدرة وحالاتها وحدودها. | لا Checkout/GPS/Chat/Driver/Dispatch/ratings/دفع. | سيناريوهات L وExport/Restore محليان وحدود Simulator صريحة. |
| L-05 — تجربة البيت | 1–3 أشهر Owner-only مع سجل ملاحظات وقرارات شهرية. | لا A أو Pilot لمجرد نجاح build أو محاكاة. | دليل ضرر متكرر وفائدة لمسار واحد ومراجعة Owner. |
| A — تفعيل متصل | هوية/عضوية/عزل API/DB/File/Search/Notification/Export وAudit/خصوصية/استعادة. | لا دعوات واسعة أو توسع فئات أو ميزات منصة عالية المخاطر. | اختبارات عزل سلبية وإيجابية على حسابات/أجهزة مستقلة وسياسة بيانات. |
| B — Pilot محدود | فئة ومنطقة ومسار وشريك محددون ومقاييس فشل/نجاح ودعم محدود. | لا GMV/نمو كبديل عن دليل القيمة أو تنفيذ دفع. | تقرير Pilot وقرار مكتوب بالتوسعة/التعديل/الإيقاف/التأجيل. |

## 4. التحويل بين بوابات Owner والسياق

| من أين يبدأ Owner | ما الذي يراه أولًا | الفعل التالي | ما لا يحدث تلقائيًا |
|---|---|---|---|
| Manage | ماله وطلباته وقراره اليومي. | يفتح `الخدمات` فقط عند وجود متابعة أو نية واضحة. | لا ينشأ حساب شبكة ولا ينشر بيانات. |
| الخدمات فارغة | عبارة صادقة ومدخلا «ابحث عن مورد» و«اطلب توصيلًا» بهدوء. | يختار نية مستقلة أو يعود إلى Manage. | لا فرض لإعداد المال/المخزون ولا شاشة تسويق منتج. |
| تفاعل Market | Need/Response/Listing ودرجة المعرفة/الفعل التالي. | يقبل/يرفض/يغلق، ثم خيار منفصل «سجل ما حدث في مشروعي». | لا شراء أو ذمة أو Cost أو Inventory أو COGS. |
| تفاعل Delivery | Request/Quote/Status/Exception والإفصاح الأدنى. | يراجع أو يحدث ما يملكه الدور. | لا قبض أو تسليم طلب أو مصروف أو تتبع حي مفترض. |
| تسجيل واقع في Manage | Preview ومدخلات صريحة يقرها Owner. | يحفظ عبر مسار Manage العادي إن اختار ذلك. | لا تعبئة مبلغ/تاريخ/نوع حدث من الشبكة بلا مراجعة. |

## 5. أسئلة Owner التي لا يجيب عنها Agent

تبقى القرارات EX-O01 إلى EX-O05 للمالك: الفئة الأولى، المنطقة، الضرر الأول، المسار الأول Market أو Delivery، الشريك المحتمل، وطريقة هوية طبقة الشبكة. توثق هذه الإجابات في بطاقة Wedge ثم تحدّث DECISIONS وTRACKER؛ لا تُستنتج من واجهة أو تقرير أو مثال سوق.

## Action Points

1. يستخدم Agent هذه الخريطة بجانب TRACKER، لا بدلًا عنه. لا يبدأ كود قبل بوابة المرحلة ذات الصلة.
2. يبقى العمل التوثيقي والمراجعة المنفصلة ممكنين الآن، لكن L-00 وما بعدها لا تبدأ قبل إغلاق G20–G23 وقرار Wedge من المالك.
3. عند اقتراح Route أو Portal أو Role جديد، يضاف أولًا إلى العقد ومصفوفة الدور والسيناريو وخريطة البوابات، ثم يراجع أثره على Manage والتاريخ والخصوصية.
