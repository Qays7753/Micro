# Expansion — عقد توزيع Owner بين Market وDelivery

**الحالة:** `CURRENT / E-00.14 / INFORMATION ARCHITECTURE ONLY / NO CODE AUTHORIZATION`
**المالك:** Manus Agent 1
**تاريخ القرار:** 28 أغسطس 2026
**الغرض:** تثبيت طريقة وصول Owner إلى Market وDelivery داخل Micro الواحد، ومحتوى الشاشتين وحالاتهما ونقاط الدخول السياقية. لا يغير هذا العقد Prototype الحالي أو يصرح بواجهة أو Domain أو LocalStore أو Auth أو Cloud.

## Major Discussion Points

## 1. القرار الحاكم

يرى Owner منتجًا واحدًا باسم **Micro**؛ يبقى Manage مركز المال والتشغيل. يحل **`السوق`** محل `الخدمات` في BottomNav، ويفتح صفحة Market مستقلة. يفتح رمز سيارة ذي تسمية وصول عربية في أقصى يسار AppBar قسم **`التوصيل`**؛ الضغط عليه لا ينشئ طلب حركة ولا يختار شركة أو سيارة.

لا توجد صفحة أو dashboard مركزية باسم `الخدمات` أو `المتابعات` في هذا النموذج. تظهر Badge أو تنبيه مصدره Market داخل `السوق`، وتنبيه مصدره Delivery داخل `التوصيل`. كل منهما يفتح سجل المصدر ذي الحالة المحفوظة، ولا يجعل الإشعار حقيقة أو قرارًا أو أثرًا ماليًا.

| المكان | الوجهة أو الفعل | ما يفتحه | ما لا يفعله |
|---|---|---|---|
| BottomNav | `السوق` | قسم Market كامل للبحث والـListings والاحتياجات والردود. | لا Delivery ولا صفحة اختيار منتجات ولا عملية شراء. |
| AppBar | رمز `التوصيل` | مركز Delivery وقائمة طلباته وعروضه وحالاته. | لا طلب سيارة أو حجز أو كشف عنوان بالضغط. |
| Manage / Order / Inventory context | `ابحث في السوق` أو `اطلب توصيلًا` عند وجود نية مفهومة. | صفحة/مسودة مستقلة مع Preview للحقول التي اختارها Owner. | لا نسخ تلقائي لكاش أو سعر أو Snapshot أو عميل أو جرد. |

## 2. صفحة السوق المستهدفة

صفحة `السوق` سوق موردين موجّه، لا سوق عام ولا نسخة من منصة إعلانات. تنقسم داخل الصفحة إلى `استكشف` و`احتياجاتي`؛ ليسا BottomNav جديدين ولا منتجين منفصلين.

| السطح | ما يراه Owner | الفعل التالي | حدود الصدق |
|---|---|---|---|
| `استكشف` | بحث نصي، فئة، محافظة/نطاق تغطية مدعوم، ونطاق سعر معلن إن توفر؛ Listings المعتمدة فقط. | يفتح Listing أو يبدأ مسودة Need. | لا ادعاء توفر حي أو سعر نهائي أو تغطية خارج Wedge. |
| Listing detail | الاسم والفئة والمنطقة العامة والوحدة/نطاق السعر وتاريخ التحديث وصورة معتمدة إن وجدت. | وسيلة اتصال خارجية يقرر Owner فتحها، أو `أنشئ احتياجًا`. | لا Chat داخل Micro ولا تقييم أو رتبة أو ضمان جودة. |
| `احتياجاتي` | مسودات Owner واحتياجاته المنشورة وردودها المنظمة فقط، مع Badge لرد يحتاج قرارًا. | يراجع أو يقبل متابعة خارجية أو يرفض/يغلق. | قبول رد لا يساوي شراءً أو دينًا أو مخزونًا أو تكلفة. |

توجد حالات `loading` و`empty` و`no_results` و`error` منفصلة. لا تستخدم صفحة فارغة لتخفي فشلًا، ولا تملأها بعروض أو موردين تجريبيين وكأنهم حقيقيون. البحث والفلاتر يعملان فقط ضمن الفئة والمنطقة/التغطية التي يحسمها Wedge؛ لا تعرض الواجهة كل محافظات الأردن كأنها تغطية مثبتة.

## 3. صفحة التوصيل المستهدفة

صفحة `التوصيل` مركز لطلب الحركة وعروضها وحالاتها واستثناءاتها، لا قائمة سيارات ولا خريطة. تحتوي على `تحتاج إجراء` و`طلباتي` وسجل حالة مختصر؛ تقدم البطاقات الحالة الدقيقة والفاعل والوقت وسبب الاستثناء عند وجوده.

الفعل الأساسي `اطلب توصيلًا` يبدأ مسودة: جلب/إرسال، نطاق مصدر/وجهة، نافذة موعد، وصف طرد، ثم Preview الإفصاح. يجوز لقرار Wedge أن يضيف **`vehicle_requirement`** اختياريًا مثل سيارة عادية أو بيك أب أو تبريد أو «غير متأكد». هذا متطلب قدرة، وليس سيارة أو سائقًا محددًا، ولا وعدًا بالتوفر أو حجزًا أو Dispatch.

## 4. الرسائل والجرد والسياق

`market_response` هو الرد المنظم داخل Micro. إذا اختار Owner متابعة اتصال، يفصح عن وسيلة اتصال أو يفتح رابطًا خارجيًا صريحًا؛ لا يحتفظ Micro بمحادثة حرة أو محتوى رسائل خارجية. إنشاء Chat داخل Micro قرار وعقد خصوصية وModeration واحتفاظ مستقل، وهو خارج E-00.14.

الجرد لا يصبح مصدرًا عامًا لـMarket ولا دليلاً على استلام فعلي من Delivery. تظهر نقطة دخول `ابحث في السوق` فقط عند حاجة Owner واضحة، وتبقى أي كمية أو وصف أو نطاق يخرج من Manage قابلاً للمراجعة والتعديل قبل النشر. حالة Courier أو Response مورد تقترح فقط `سجل ما حدث في مشروعي`، ثم يختار Owner واقعة Manage المناسبة ويحفظها بطريقها المعتاد.

## 5. حدود غير قابلة للتفسير الموسع

لا Chat أو AI matching أو recommendation أو ranking أو paid placement أو Ratings أو Cart أو Checkout أو Payment أو عمولة. لا Listing يعني مخزونًا حيًا أو SKU. لا Vehicle Requirement يعني سيارة/Driver محددًا أو GPS أو Live tracking أو ETA مضمونًا أو COD. لا تنشأ Delivery من Market أو من Order أو Inventory تلقائيًا، ولا تنتج حالة شبكة أثرًا في الكاش أو الدين أو الربح أو COGS أو المخزون أو حالة Order.

## 6. بوابة التنفيذ

هذا العقد يسند التوثيق والـwireframes فقط. قبل أي UI محلي: تكون G19–G23 مغلقة، وتكتمل مراجعة E-00.14 المستقلة، ويملأ Owner بطاقة Wedge للفئة والمنطقة/التغطية والضرر والمسار والشريك والتفاعل الذري. يبدأ L بسلايس واحد بحسب Wedge، لا ببناء Market وDelivery وChat وInventory في فرع واحد.
