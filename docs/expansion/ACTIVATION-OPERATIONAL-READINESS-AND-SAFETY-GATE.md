# Expansion — بوابة الجاهزية التشغيلية والسلامة قبل التفعيل

**الحالة:** `CURRENT / E-00.12 / DOCUMENTATION ONLY / NO CODE AUTHORIZATION`
**السلطة:** هذه بوابة حوكمة وتشغيل قبل دعوة أي شخص حقيقي إلى Market أو Delivery. لا تحل محل عقد الهوية أو الوصول أو البيانات، ولا تختار مزود هوية أو استضافة أو قناة دعم أو التزامًا قانونيًا أو SLA.

## Major Discussion Points

## 1. لماذا توجد هذه البوابة

المنتج المتصل لا يصبح آمنًا أو صالحًا للتجربة لمجرد أن شاشة الدخول أو قاعدة البيانات تعمل. يحتاج الفريق إلى طريقة معلنة للاستعداد، واكتشاف الخطأ، والاستجابة له، والاستعادة منه، ثم تسجيل ما تعلمه قبل توسيع النطاق.[1] كما أن التطوير الآمن يتطلب تتبع المتطلبات والمخاطر وقرارات التصميم عبر دورة العمل، لا فحصًا أخيرًا قبل النشر فقط.[2]

في Micro، تحمي هذه البوابة وعدًا أساسيًا: **Micro Manage يبقى سجل المالك المحلي، ولا تتحول بوابة Market أو Delivery أو Admin أو الدعم إلى طريق خفي لرؤية المال أو تعديل الحقيقة التاريخية.** وهي تضيف نضجًا تشغيليًا إلى العقود الحالية، ولا تضيف قدرة منصة أو واجهة جديدة.

| المبدأ | ما يطلبه قبل التفعيل الحقيقي | ما لا يعنيه |
|---|---|---|
| صراحة حدود الخدمة | يكتب الفريق ما هو محلي وما هو متصل وما لا يستطيع المنتج ضمانه بعد. | SLA أو وعد توفر أو استعادة عامة. |
| أقل بيانات وأقل وصول | كل دعم أو Admin أو Alert يملك نطاقًا وسببًا ووقتًا وسجلًا. | دخولًا شاملًا إلى بيانات Owner أو انتحال جلسة. |
| استجابة قابلة للاستعادة | لكل فشل مهم مالك قرار، أثر معروف، وخطوة احتواء واستعادة واستخلاص درس. | معالجة مالية أو تعديل سجل Manage تلقائي. |
| اختبار قبل التوسع | لا يدعى نجاح الإتاحة أو العزل أو الاستعادة أو Pilot من وجود وثيقة أو build فقط. | التزامًا قانونيًا أو إنتاجيًا بلا دليل ميداني. |
| قياس يخدم القرار | تقاس الفائدة والفهم والفشل ضمن الحاجة المحددة وبأقل بيانات لازمة. | تتبعًا واسعًا أو GMV/التسجيلات بوصفها دليل قيمة وحيد. |

## 2. ما هو موجود أصلًا وما تكمله هذه الوثيقة

الأساس الحالي يغطي فصل Manage، وحالات Market وDelivery، والحد الأدنى للبيانات، وModeration، واستعادة الهوية، وقياس Pilot، وتجربة الهاتف. لا تعيد هذه الوثيقة تلك العقود. تسجل فقط العمل العابر لهذه المسارات الذي تحتاجه المنتجات الجادة عندما يصبح أشخاص حقيقيون وبيانات حقيقية وإصدارات متصلة جزءًا من الواقع.

| المجال | المرجع الموجود | الإضافة هنا |
|---|---|---|
| الوصول والاستعادة | عقد 18، عقد 23، وبوابة الجهات الأربع والاستعادة. | مسار دعم محدود، واستجابة لخلل الامتياز أو فقد الوصول من دون انتحال. |
| الخصوصية وModeration | عقدا 22 و24 وإجراء التفعيل والخصوصية. | سجل مخاطر إساءة الاستخدام، ومسؤول الحادث، وبوابة مراجعة قبل جمع بيانات Pilot الحقيقية. |
| الهاتف ووضوح الخطأ | مرجع UI/UX للهاتف وQA Prototype. | قبول تشغيلي يثبت أن الإتاحة واستعادة جهد المستخدم جزء من الإصدار، لا تجميل لاحق. |
| تجربة/Pilot | SOP تجربة البيت وPartner Pilot. | تعريف مالك الدعم، وقواعد الإيقاف أو الرجوع، وحلقة تحسين مكتوبة. |
| الإصدارات | بروتوكول E-00 وقائمة Agents السبعة. | سجل تغيير، استراتيجية rollback/تعطيل محددة، ومراجعة مخاطر قبل توسيع Audience. |

## 3. نموذج العمل: استعد، اكتشف، استجب، استعد، وتعلم

يعتمد النموذج على دورة مبسطة مناسبة لـMicro: الاستعداد والحوكمة والحماية تسبق الحادث؛ ثم يكتشف الفريق الفشل، يستجيب، يستعيد، ويوثق الدرس للتحسين.[1] لا يحتاج هذا في L إلى نظام مراقبة أو حسابات؛ يتحول إلى التزام تشغيلي قابل للبناء عند A وPilot.

| المرحلة | ما يجب أن يكون موثقًا أو مثبتًا | الدليل المقبول | الحظر الصريح |
|---|---|---|---|
| الآن — E-00 | حدود المنتج، المخاطر المتوقعة، مسار الدعم المقيد، بوابات الإطلاق والقياس، ومعايير عدم الادعاء. | هذه الوثيقة، العقود، السيناريوهات، Tracker، ومراجعة مستقلة. | لا Account أو Log خارجي أو Analytics أو تنفيذ Security. |
| L — تجربة البيت المحلية | سجل مشكلة/فهم، تدريب Owner قصير، تمرين Export/Restore، واختبار أخطاء محفوظة/مسودة/رجوع وإتاحة هاتف. | Home Trial Log ودليل QA محلي لا يتضمن بيانات أشخاص آخرين. | لا ادعاء دعم حي أو عزل مستخدمين أو مراقبة إنتاج. |
| A — تفعيل محدود متصل | هوية وعضوية وعزل منفذ، threat/abuse register، قنوات دعم، سياسة حادث، release/rollback plan، مراجعة خصوصية محلية، واختبارات سلبية. | PRs واختبارات وصول واستعادة، سجل قرار، وتمرين محدود لكل مسار حرج. | لا دعوة أو صور أو أرقام أو عناوين حقيقية قبل اكتمال البوابة. |
| B — Pilot | مالك تشغيل، حدود مستفيدين وشركاء، قياسات منفعة وفشل، triage، تسجيل قرار إيقاف/تعديل/توسيع. | تقرير Pilot وعيّنة أدلة من دون تسريب بيانات حساسة. | لا توسع جمهور أو دفع أو تقييمات أو GPS أو SLA بسبب نجاح أولي. |

## 4. سجل مخاطر التشغيل والثقة الواجب إعداده قبل A

لا يطلب هذا السجل من الفريق حل المخاطر الآن، بل يمنع اكتشافها بعد دعوة طرف حقيقي. لا يعالج Admin نزاعًا ماليًا أو يقرر أن Delivery اكتمل أو أن Owner اشترى مادة؛ تظل تلك حقائق يسجلها المالك صراحة داخل Manage.

| المعرف | الخطر أو الضرر | المنع أو الحد قبل التفعيل | الاستجابة المستقبلية المسموحة | غير مسموح |
|---|---|---|---|---|
| OR-01 | وصول جهة إلى Workspace أو سجل لا يخصها. | عزل workspace في API/DB/File/Search/Notification/Export واختبارات رفض. | إيقاف الجلسة/الدعوة، مراجعة Audit، واستعادة العضوية بعد تحقق. | كشف وجود السجل أو فتح Manage أو نقل جهة بقرار دعم. |
| OR-02 | فقد Owner أو عضو لوسيلة الوصول. | قرار هوية واستعادة، عوامل تحقق، ومراجعة امتيازات Admin. | R-02/R-03/R-04 بسجل سبب ووقت ونتيجة. | كلمة مرور مشتركة أو إرسال رمز/Export بقناة غير موثقة. |
| OR-03 | Listing أو صورة أو رد مضلل أو مخالف، أو إساءة استعمال البلاغات. | حالة Moderation وموافقة وحد أدنى من البيانات ومسار بلاغ. | إيقاف/رفض/تقييد ضمن سياسة وسبب قابل للمراجعة. | ادعاء تحقق جودة أو ضمان طرف أو إخفاء قرار Admin. |
| OR-04 | إفصاح هاتف/عنوان/صورة أو سجل أكثر مما يلزم. | Field dictionary، purpose/scope، مراجعة خصوصية قبل Pilot، وفحص URL/File/Search. | احتواء الوصول، تقييم نطاق الأثر، وإرشاد المتضرر وفق السياسة والقانون المطبق. | مشاركة تفاصيل الحادث أو بيانات الأطراف خارج النطاق. |
| OR-05 | فشل إرسال/تكرار/حالة Delivery أو Market متناقضة. | حالات فشل صريحة وidempotency واختبارات Offline/retry. | وضع `needs_review` أو إعادة محاولة معلنة وفعل تالٍ للمالك. | آخر كتابة صامتة أو تحويل الفشل إلى شراء/كاش/مخزون/تسليم. |
| OR-06 | إصدار جديد يربك Owner أو يخفي زرًا أو يفسد الإتاحة. | مراجعة UX وإتاحة وRTL و360/390/430 وتغيير محدود قابل للرجوع. | تعطيل القدرة أو الرجوع للإصدار الآمن وفق خطة release. | إصلاح صامت يعيد كتابة تاريخ المستخدم أو يكسر Export. |
| OR-07 | دعم أو Admin يطلبان بيانات أكبر من الحاجة لحل مشكلة. | نموذج طلب مساعدة محدود وAudit ومبدأ أقل وصول. | إرشاد المستخدم أو معالجة أثر محدد بموافقة وسجل. | انتحال Owner أو طلب/نسخ مال Manage أو Export حساس. |

## 5. بوابة الإصدار والتشغيل قبل أول Pilot

الإصدار ليس مجرد دمج `main`. قبل توسيع الجمهور، يحدد الفريق ما تغير، من تأثر، كيف يوقف القدرة أو يرجعها، وما الدليل الذي يثبت أن الفشل لا يصنع أثرًا ماليًا أو وصولًا غير مصرح. يعتمد الإطلاق على مؤشرات قليلة تخدم المستخدم، لا مؤشرات كثيرة يسهل جمعها؛ فالمؤشر الجيد يحدد السلوك الذي يهم المستخدم وما الإجراء عند تدهوره.[3]

| البند | شرط الإغلاق قبل B-01 | مسؤول الدليل | لا يكفي وحده |
|---|---|---|---|
| تغيير واضح | PR يذكر العقود والسيناريوهات والبيانات المتأثرة وما لم يتغير، مع changelog مفهوم. | Agent التنفيذ ثم مراجع مستقل. | نجاح build أو لقطة شاشة. |
| رجوع/إيقاف | قرار موثق: هل نوقف feature، نرجع إصدارًا، أو نضع حالة مراجعة؟ ومن يقرر؟ | Owner المنتج ومالك التشغيل. | افتراض أن rollback لا يلزم لأن النظام صغير. |
| وصول واستعادة | اختبارات رفض وعزل وعضوية واستعادة، بما فيها Admin محدود. | Agent الأمن/QA. | إخفاء زر أو نجاح تسجيل الدخول وحده. |
| بيانات وخصوصية | Data map، مراجعة ما يجمع ولماذا ومن يراه، ومراجعة قانونية محلية قبل البيانات الحقيقية. | Owner مع مراجع قانوني مؤهل عند A/B. | هذا المستند أو موافقة شفوية عامة. |
| إتاحة وفهم | اختبار الهاتف وRTL وfocus وkeyboard والأخطاء وحفظ الجهد؛ تتبع الإرشادات المناسبة للهاتف مثل حجم الهدف وإدخال البيانات المكرر والوصول للتركيز.[4] | Agent UX/QA مع Owner تجريبي. | تطابق بصري على سطح مكتب. |
| دعم وحادث | قناة معلنة، مالك لكل حالة، تصعيد محدود، وtemplate للحادث ولدرس ما بعده. | مالك التشغيل/Admin policy. | صندوق بريد بلا رد أو Admin شامل. |
| استعادة بيانات | تمرين restore مناسب للنطاق؛ تبقى بيانات Manage المحلية تحت فعل Owner، وتختبر النسخ والاستعادة دوريًا.[5] | Owner/QA. | وجود زر Export فقط. |

## 6. الدعم والحوادث: حدود صادقة

رسائل الخطأ والدعم جزء من حفظ جهد المستخدم: تشرح ما حدث قرب مصدره، ما إن كان قد حُفظ، والخطوة التالية، ولا تلوم المستخدم أو تمحو إدخاله.[6] في A وPilot، لا يتحول ذلك إلى وعد استجابة أو توفر لم يوافق عليه المالك. يحدد معيار Pilot الداخلي وقت الاعتراف بالحالة وطريقة التحديث، لا SLA علنيًا أو تعويضًا تلقائيًا.

| نوع الحالة | صاحبها الأول | ما يخبر به المستخدم | ما يحفظ في السجل | التصعيد |
|---|---|---|---|---|
| فشل واجهة/مسودة | Owner أو Agent QA في L، ثم دعم مقيد في A/B. | هل حُفظ شيء؟ ما الخطوة الآمنة التالية؟ | الإصدار، السياق غير الحساس، الأثر، والنتيجة. | إذا هدد فقدًا أو وصولًا أو أثرًا ماليًا. |
| خلل وصول/عضوية | مسار الاستعادة المقيد. | لا يكشف وجود Workspace أو سجل لا يخصه. | طلب الاستعادة، دليل التحقق، قرار، وقت، وactor. | Admin privileged مراجع، لا دعم عام. |
| بلاغ محتوى/خصوصية | Admin policy محدود. | استلام البلاغ والخطوة المتوقعة دون حكم مسبق. | scope، policy، السبب، القرار، والإشعار المناسب. | مالك السياسة/قانوني محلي عند البيانات أو ضرر جسيم. |
| حادث تشغيلي | مالك التشغيل. | أثر معروف وحدود مؤقتة وفعل بديل صادق. | detect/respond/recover والدرس والـfollow-up. | Owner المنتج قبل عودة أو توسع القدرة. |

## 7. القياس والتعلم دون مراقبة زائدة

في L لا تجمع Telemetry متصلة. في Pilot، يبدأ القياس من الفرضية وقرار المنتج: هل قلل Micro وقت البحث أو الحركة؟ هل فهم Owner حالته؟ أين توقف؟ لا يبدأ بما يمكن جمعه تقنيًا. توثق كل إشارة: الغرض، الحقل الأدنى، scope، مدة الاحتفاظ، من يراها، وكيف ينسحب المستخدم إن كان ذلك مناسبًا قبل الجمع.

| فئة الدليل | مثال مشروع | قرار قد يغيره | ما لا يثبت وحده |
|---|---|---|---|
| منفعة Owner | وقت البحث/التواصل أو عدد خطوات إكمال طلب حركة. | الاستمرار أو تبسيط المسار. | أن Market أو Delivery نجحا تجاريًا على نطاق واسع. |
| فهم وحقيقة | هل عرف Owner أن Quote ليس شراءً وأن Status ليس قبضًا/تسليمًا ماليًا؟ | تعديل copy أو حالة مراجعة. | دقة الحسابات أو رضا دائم. |
| سلامة وتشغيل | تكرار فشل استعادة أو URL مرفوض أو بلاغ محتوى. | وقف rollout أو تشديد البوابة. | وجود حادث واحد بلا تحليل أو نسبة مئوية بلا سياق. |
| ثقة وجودة | سبب إلغاء أو ترك مسار، مع وصف اختياري مصغر وآمن. | تعديل/رفض Wedge. | عدد تسجيلات أو GMV أو مدة جلسة وحدها. |

## 8. ما يبقى قرارًا للمالك أو مراجعة مستقبلية

هذه البوابة لا تجيب عن أسئلة السوق أو القانون أو التقنية بالنيابة عن المالك. قبل A/B تسجل الإجابة مع مصدرها، ولا تملأ الفراغ بافتراض عالمي.

| المعرف | القرار أو التحقق المطلوب | متى يحسم | لا يحق للـAgent حسمه |
|---|---|---|---|
| OR-O01 | نوع الدعم وساعاته ولغة الرد ومسؤول التشغيل في Pilot. | قبل B-01. | وعد SLA أو فريق دعم أو مستوى خدمة. |
| OR-O02 | فئة الشدة وقواعد إيقاف/استئناف المسار الأول. | قبل A rollout وB-01. | قبول مخاطرة أو الاستمرار رغم دليل ضرر. |
| OR-O03 | ما القياس الأدنى وما نطاق جمعه واحتفاظه، بعد Wedge محدد. | قبل A/B. | Analytics عام أو تعريف نجاح من vanity metrics. |
| OR-O04 | مراجعة الخصوصية والالتزامات القانونية واللغة المناسبة في الأردن/السوق الفعلي. | قبل أول بيانات حقيقية. | فتوى قانونية أو ادعاء امتثال. |
| OR-O05 | آلية تقنية للإطلاق أو التعطيل أو الرجوع ومزودها، إن احتاجها المسار. | بعد architecture/identity decision. | مزود Cloud أو feature flag أو مراقبة مفروضة. |

## Action Points

1. تقبل E-00.12 توثيقيًا فقط بعد أن يراجع مستقل سجل المخاطر وبوابة الإصدار والدعم مقابل العقود 18–24 والسيناريوهات ومصفوفة الوصول.
2. لا تفتح A-01 أو B-01 بمجرد قبول هذه الوثيقة؛ تبقى EX-O01…EX-O05 وOR-O01…OR-O05 وقرار Wedge وتثبيت L أدلة منفصلة لازمة.
3. عند بناء أي مسار متصل، يحول Agent الخطر ذي الصلة إلى Contract وScenario وTest وRunbook قابل للتشغيل، ولا يدعي أن هذا المستند وحده يطبق أمنًا أو امتثالًا.
