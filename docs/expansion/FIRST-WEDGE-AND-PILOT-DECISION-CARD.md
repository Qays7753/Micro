# Expansion — بطاقة قرار أول Wedge وPilot

**الحالة:** `TEMPLATE / OWNER DECISION REQUIRED / NO CODE AUTHORIZATION`
**طريقة الاستخدام:** لا تبدأ E-01 أو L-01 أو أي UI متصل قبل ملء هذه البطاقة واعتمادها. لا تملأها بتخمين أو بيانات اصطناعية تبدو كدليل سوق.

## Major Discussion Points

## 1. قرار واحد مطلوب، لا ثلاثة مشاريع

تختار هذه البطاقة **موقفًا واحدًا متكررًا** لفئة واحدة ومنطقة واحدة. لا تختار «Market وDelivery معًا» أو «كل المشاريع في الأردن». النتيجة ليست قائمة Features، بل قرار build أو discovery أو تأجيل مبني على ضرر ووعد اختبار محددين.

## 2. اختيار المسار الأول

| المسار | اختره فقط إذا | لا تختَره إذا | نتيجة Beta الأدنى |
|---|---|---|---|
| Market Beta | يوجد ألم بحث/مقارنة متكرر، فئة ومنطقة محددتان، وموردان محتملان مستعدان للرد. | لا يوجد مورد أو فئة أو فرق واضح عن بحث عام. | Need → Response → قرار Owner بلا شراء تلقائي. |
| Delivery Beta | توجد حركات جلب/إرسال متكررة، وشركة/شركتان مستعدتان لتحديث الحالات. | المشكلة مجرد «نريد توصيلًا» ولا يوجد شريك أو حالة ميدانية محددة. | Request → Quote → Status صادق بلا تتبع أو دفع. |
| Discovery فقط | لا يكفي الدليل أو لا يوجد شريك. | لا تستخدمه ذريعة لبناء Cloud/Auth أو واجهات حية. | مقابلات/ملاحظات محدودة وقرار تعديل/تأجيل/رفض. |

## 3. بطاقة الفرضية ومقياسها

| الحقل | الإجابة المطلوبة |
|---|---|
| الفرضية | «إذا أتيح لـ[الدور] [أقل مسار]، فإنه يستطيع [نتيجة] في [الموقف] بعبء أقل من [الحل الحالي]». |
| المقياس الأساسي | وقت إلى رد/اتفاق أو إكمال حركة، سبب الإلغاء، وفهم الحالة؛ لا GMV أو عدد تسجيلات وحده. |
| حد النجاح | رقم/سلوك يحدده المالك قبل التجربة، مع سبب اختيار الحد. |
| حد الفشل | ما النتيجة التي تجعلنا نوقف أو نغير أو نؤجل؟ |
| المخاطر | خصوصية، عدم استجابة، وقت تشغيل، التباس مالي، إساءة استخدام، أو إدخال ثقيل. |
| التخفيف | أصغر نطاق، دعوات محدودة، عدم الدفع، Moderation، بيانات اختبار، أو قرار عدم البدء. |
| دليل غير كافٍ | ما الذي لن نعتبره نجاحًا؟ |

## 4. الشريك والموافقة

| الحقل | المطلوب قبل Pilot حقيقي |
|---|---|
| طرف/أطراف محتملون | اسم جهة/نوعها وطريقة تواصل لا تنشر في المستودع العام إن كانت شخصية. |
| الالتزام | ما الذي وافق الطرف فعليًا على تجربته، ومن سيرد أو يغير حالة ومتى. |
| حدود البيانات | ما الذي يحتاجه فقط، وما لن يحصل عليه، ومن يوافق على الإفصاح. |
| بديل عدم الالتزام | Discovery أو Role Simulator؛ لا شريك وهمي أو دليل مصطنع. |
| نقطة الخروج | كيف ينتهي الاختبار ويحذف/يوقف الوصول أو يحتفظ بالسجل وفق السياسة. |
