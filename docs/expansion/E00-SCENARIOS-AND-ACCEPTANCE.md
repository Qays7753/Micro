# Expansion — سيناريوهات E-00 ومصفوفة القبول

**الحالة:** `CURRENT / E-00 / CONCEPT AND CONTRACT ACCEPTANCE`
**الحد:** لا تثبت هذه السيناريوهات سوقًا أو أمنًا ميدانيًا أو نية دفع؛ تثبت فقط وضوح القرار والعقد قبل الكود.

## Major Discussion Points

## 1. قاعدة القبول

كل سيناريو يختبر شخصًا وموقفًا وضررًا ونتيجة وفعلًا تاليًا، ثم يصرح بما لا يتغير ماليًا. لا نغير السيناريو ليبدو العقد ناجحًا؛ إذا لم نعرف الفاعل أو الإفصاح أو الحالة أو الفعل التالي، نعيد العقد ولا نبدأ UI أو Data Model.

## 6. معيار قبول E-00

تقبل E-00 فقط عندما يستطيع مراجع مستقل الإجابة من العقود والمصفوفة على: من فعل هذا؟ ما الحالة السابقة والتالية؟ من يرى أي حقل؟ ما الذي لا يتغير في Manage؟ ما الفعل التالي عند فشل أو تكرار؟ ما الذي يثبت محليًا وما يتطلب A/Pilot؟


## 7. سيناريوهات Manage Online (MO — أمر المالك 2026-11-14 / EX-D23)

> تضاف قبل أي كود M2+ (بوابة المصفوفة: لا قرار منتج بلا صف). الحارس المشترك: لا أثر مالي تلقائي أبدًا؛ كل سيناريو يحفظ 41/34 والـ29 زوجًا والتصدير/الاسترداد المحلي.

| المعرف | الموقف والضرر | النتيجة المطلوبة | الحارس |
|---|---|---|---|
| MO-01 | ضيف غير موثق يفتح أسطح Manage المتصلة. | 401 صادق بلا كشف أي حالة مالك؛ الواجهة تعرض «غير موثق» لا بيانات مالية. | لا مسار شبكي مالي بلا جلسة. |
| MO-02 | هوية موثقة **غير مربوطة** تحاول قراءة مالية متصلة. | رفض خادمي «غير مربوط» مدقق؛ لا مطابقة بريد تلقائية أبدًا. | جدول الربط شرط البوابة. |
| MO-03 | هوية تحاول الربط **بمطابقة البريد الإلكتروني وحده**. | رفض صريح (اختبار سلبي إلزامي): البريد وحده لا يثبت ملكية المال. | بروتوكول §2-ب المزدوج. |
| MO-04 | ربط موثق: سر وُلّد داخل Manage + تأكيد داخل الجلسة السحابية. | الربط يسجل في جدول شبكي الجانب حصرًا؛ لا يمس 41/34 ولا ملف التصدير. | بصمة السر فقط تُخزن. |
| MO-05 | هويتان تتنازعان ملكية Manage لنفس Workspace. | المالك الثاني مرفوض **خادميًا** (قيد مالك واحد) مع تدقيق. | قيد جدولي + بوابة. |
| MO-06 | مورد/سائق/أدمن منصة يحاول مسارًا ماليًا متصلًا. | 403/404 مدقق؛ الأدمن لا يرى مال Manage أبدًا. | requireManageOwner. |
| MO-07 | عبور Workspace في قراءة/كتابة مالية متصلة. | رفض مدقق بلا كشف وجود؛ لا عداد/اقتراح يسرّب. | مفاتيح مركبة + بوابة. |
| MO-08 | قدرة manage معطلة (الافتراضي قبل تطبيق المشغل للمخطط). | كل مسار مالي متصل يفشل مغلقًا بحالة صادقة؛ الواجهة تعرض حالة التهيئة لا بيانات. | تعطيل خادمي لا إخفاء واجهة. |
| MO-09 | مالك متصل مربوط يقرأ بياناته. | القراءة تعيد بيانات مالك Workspace وحده؛ تكافؤ مع المرجع المحلي عند وجود بيانات مهاجرة. | عزل موجب/سالب لكل مسار. |
| MO-10 | كتابة مالية والاتصال مقطوع أو الخادم فاشل. | رفض صادق؛ لا «محفوظ» بلا تأكيد خادم؛ لا كتابة محلية بديلة صامتة. | عرض الحالة الصادق. |
| MO-11 | إعادة إرسال كتابة مالية بعد ضعف اتصال (المفتاح نفسه). | نتيجة واحدة وأثر مالي واحد (إيصال الحتمية نفسه). | idempotency خادمي. |

## Action Points

- [ ] تربط كل شريحة تنفيذية لاحقًا بمعرفات السيناريو المتأثرة، ولا تضيف سيناريو بديلًا خارج هذه المصفوفة بدل تحديثها.
