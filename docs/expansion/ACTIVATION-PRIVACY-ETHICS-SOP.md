# Expansion — بوابة التفعيل والخصوصية والأخلاقيات

**الحالة:** `CURRENT / FUTURE ACTIVATION GATE / NOT LEGAL ADVICE`
**الغرض:** تثبيت ما يلزم قبل دعوة مورد أو شركة توصيل أو إدارة حقيقيين إلى طبقة Micro المتصلة.

## Major Discussion Points

## 1. ما الذي لا نفعله قبل التفعيل

لا نطلب من شخص حقيقي إنشاء حساب أو رفع صورة أو مشاركة عنوان/هاتف عميل أو تحديث مهمة حقيقية في تجربة L. لا نقدم وعودًا بأن Market يضمن المورد أو أن Delivery يضمن الوصول أو أن Micro وسيط دفع. لا نجمع بيانات «قد نحتاجها لاحقًا»، ولا نستعمل أرقام أو بيانات Manage لتوجيه عروض أو تحليلات أو مشاركة طرف ثالث.

## 2. بوابة A غير القابلة للتجاوز

| المجال | ما يجب أن يثبت أو يعتمد | صاحب القرار |
|---|---|---|
| الهوية | طريقة دخول واستعادة وحماية جلسة وإيقاف حساب موثقة، مع فصل استعادة Manage المحلية عن الهوية والعضوية الشبكيتين. | مالك المنتج مع مراجعة تقنية. |
| الوصول | DB/API/File/Search/Notification/Export تطبق Matrix الأدوار واختبارات الرفض. | مسؤول التقنية والمراجع المستقل. |
| البيانات | جدول غرض الحقل والإفصاح والاحتفاظ والحذف والاستعادة. | مالك المنتج مع مراجعة قانونية محلية عند الحاجة. |
| الوسائط | رفع خاص، مراجعة، نشر مشروط، إبلاغ، إزالة وسجل قرار. | Admin policy ومالك المنتج. |
| الإشعار | in-app مصدر المتابعة؛ لا يعتمد المسار على Push أو خلفية هاتف. | المنتج والتقنية. |
| الاستجابة للحوادث | بلاغ، تعليق Listing/عضوية، استعادة، واحتفاظ Audit بحدود. | مالك المنتج/التشغيل. |
| Admin ذي امتياز | حسابات فردية، MFA/إعادة تحقق مناسبة، طوارئ مدققة، ومنع انتحال Owner أو قراءة Manage. | مالك المنتج/التشغيل والمراجع الأمني. |
| Pilot | فئة ومنطقة ومسار واحد وشركاء محددون ومقاييس وعدم نجاح معلنة. | مالك المنتج. |

لا يختار Agent مزودًا أو سياسة قانونية أو جدول احتفاظ نهائيًا دون قرار موثق. يجب مراجعة نصوص الخصوصية والشروط والالتزامات المحلية المناسبة قبل جمع بيانات حقيقية؛ هذه الوثيقة ليست بديلاً عن استشارة قانونية.

## 3. مبادئ أخلاقية قابلة للاختبار

| المبدأ | التطبيق | إشارة فشل |
|---|---|---|
| الصدق | الحالة تصف ما سجله الطرف، والوعود محدودة. | «تم» أو «موثوق» بلا حدث أو سياسة. |
| أقل بيانات | لا يكشف إلا ما يلزم للمرحلة والفعل. | نقل عنوان/هاتف/مال دون Preview وموافقة. |
| عدم التفضيل الخفي | لا ترتيب مدفوع أو امتياز مورد أو Courier بلا وسم وسياسة. | ظهور نتيجة مدفوعة كأنها توصية محايدة. |
| لا سمعة مصطنعة | لا Reviews أو نجوم أو شهادات مختلقة. | بيانات اختبار معروضة كآراء حقيقية. |
| قابلية الاعتراض | سبب Moderation أو Restriction واضح ومسار تعديل/إعادة تقديم محدد. | رفض صامت أو تعطيل بلا سجل. |
| عدم تحويل الضيق إلى إجبار | لا يربط Manage المالي بتفعيل الشبكة أو تسليم بيانات أكثر. | منع Owner من استعمال مشروعه المحلي بلا حساب. |
| مسؤولية الحالة | لا يغير طرف حالة لا يملكها ولا يخفي الاستثناءات. | Courier/Owner/Admin يكتب واقع طرف آخر بلا دليل. |

## 4. إجراءات تشغيل أولية مستقبلية

| الإجراء | الحد الأدنى قبل Pilot |
|---|---|
| بلاغ محتوى | تصنيف، رابط سجل، وقت، صاحب البلاغ، مراجعة بشرية، قرار وسبب. |
| Listing مخالف | إيقاف العرض من العام، حفظ Revision/Audit، رسالة للمورد، مسار تعديل أو اعتراض. |
| تسرب/وصول مشكوك | تعليق الجلسة/العضوية وفق سياسة، حفظ الأدلة، تقييم النطاق، إبلاغ الأطراف حسب التزام قانوني/سياسة. |
| فشل Delivery | Event استثناء صريح، من عليه الفعل التالي، وعدم تغيير المال أو Order. |
| نزاع تجاري | توضيح أن الاتفاق والدفع خارج Micro؛ تسجل المنصة بلاغًا أو حالة فقط ولا تحكم مالياً بلا عقد مستقل. |
| طلب حذف/استعادة | التحقق من الهوية، فحص الأثر على Audit والتزامات الاحتفاظ، قرار مكتوب وتنفيذ يمكن تدقيقه. |

## 5. ما لا يدخل Pilot الأول

لا مدفوعات أو عمولات نسبة إلى قيمة المعاملة أو Escrow أو Cash on Delivery أو تقييمات أو توصيات أو إعلانات مخصصة أو تتبع موقع حي أو Driver app أو Dispatch أو تكاملات خارجية. ظهور ضغط تجاري أو طلب شريك لا يلغي بوابة A أو الحدود المالية.

## Action Points

- [ ] قبل دعوة أول طرف حقيقي، تراجع هذه البوابة بندًا بندًا وتكتب رابط الدليل أو القرار لكل صف.
- [ ] قبل نشر Terms/Privacy أو جمع معلومات حساسة، تراجع النصوص قانونيًا في نطاق الأردن والسوق الفعلي ولا تعتمد هذا الملخص كاستشارة.
- [ ] أي حادث أو سياسة جديدة تتطلب تحديثًا لهذا الإجراء والعقد المتأثر ومصفوفة الدور قبل توسيع Pilot.
