# Micro Manage v2 — خطة التنفيذ

> **المرجع الملزم:** `docs/manage-v2/micro-manage-spec-final.md` (v1.1). خريطة الواجهة: `micro-manage-ux-final.md`. الشرح: `micro-manage-concept-final.md`. الأثر: `IMPACT.md`.
> **هذا الملف خطة لا أوامر.** أوامر ZAI تُكتب مرحلةً مرحلة عند بدئها، من قالب `ZAI-TASK-TEMPLATE.md`.
> **القاعدة المعمارية الحاكمة (قرار المالك):** التنفيذ والحساب على **السيرفر**. الدومين في `src/domain/manage/`، ومعالجات العمليات على السيرفر (`worker/application/manage/`)، وأرقام §8/§8.2 في موديول قراءة سيرفري واحد. الواجهة عميل API رفيع + عرض + كاش قراءة، **ولا تحسب أي رقم مالي** (R-23، §14.1).

## 0. تعريف «خلص» للمشروع كاملًا

1. الشاشات الثلاث + P-01 + النماذج والنوافذ تعمل، وكل رقم معروض يرجعه السيرفر مطابقًا لـ§8/§8.2 — والعميل لا يحسب شيئًا.
2. كل اختبارات §13 (S1–S9، T1–T60) تمر، وكل اختبار ينتهي بـ`INV-1` و`INV-2`.
3. لا كود مالي قديم، ولا مسار ميت، ولا مخزن مانج محلي كمصدر بيانات، ولا استيراد من مجال محذوف؛ و`knip` نظيف لمسارات مانج وأدواتي.
4. كل عملية معاملة واحدة على السيرفر، والدفتر غير قابل للتعديل على مستوى القاعدة، ومنع التكرار **ذرّي داخل نفس المعاملة** (R-11، R-12، R-23، R-25، SRV-03).
5. التوصيل والسوق لم تُلمس، و«اسأل Micro» فُصل بالحالات المعتمدة فقط، ولا كسر فيها.
6. `pnpm check` أخضر، والوثائق وسجل الملكية محدَّثان، والمتتبّع مكتمل، وقرار الدمج مكتوب من المالك.
