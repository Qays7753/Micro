## §1 الأحمر الأول المقصود (tests-first)

**الخادم (projectState):** كُتب الاختبار قبل تشغيل الملفات؛ فشل 4/8: الثلاث الوحدية نجحت لكن المسارات 404 — **الاكتشاف الجوهري:** هوية الجلسة مُولَّدة عند الدخول (`idn-…`) وليست Google sub، فمشروع مزروع مباشرة بowner نصي لا يملكه أحد. **الحل:** اختبارات المسار تنشئ مشروعها عبر API الإعداد نفسه (نمط M4.5) — وأُثبت الفرق في السجل. كذلك `ledgerState` لا يحمل `postings` مسطحًا (داخل entries) — صُحح الاختبار.

**الخادم (saleRows):** فشل أولي واحد بعد التشغيل الكامل: وصف أول بند رجع «ورق عنب» لا «مقلوبة» — `ORDER BY sale_id, id` يرتب **UUID** (عشوائي) لا ترتيب الإنشاء. **الحل:** §3.5 يعرف `position` — الرتب الصحيحة `ORDER BY sale_id, position`.

**العميل (NowPage):** الأحمر الأول 16/16 فشلًا بثلاثة أسباب متسلسلة: (١) موك `@/application/manage/api` لم يصدّر `isNetworkFailure` فصار undefined داخل الالتقاط فعلقت الصفحة في التحميل — **الحل:** `importOriginal` للدوال النقية وموك النداءات الشبكية وحدها؛ (٢) تفكيك `rows` من `{sales}` الخاطئ — كسر `rows.filter` — صُحح التفكيك؛ (٣) قيم الاختبار (جملة الرصيد المجهول والمدفوع بالعملة) طُابقت للأصل الحرفي.
