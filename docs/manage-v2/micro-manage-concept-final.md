**النسخة 1.1 — معتمدة بتاريخ 25/11/2026.** (1.1: حدود المكوّنات وقواعد البنية، دون أي تغيير بالمنطق المالي.)
**السياق:** مايكرو مانج **مكوّن واحد** من تطبيق مايكرو (مع مايكرو ديليفري، ومايكرو ماركت، وأدواتي). تسجيل الدخول، والحساب، والتشغيل عبر الإنترنت، وقاعدة البيانات، والشريط السفلي **على مستوى التطبيق كله**، ومايكرو مانج يستخدمها ولا يبنيها.

**المرجع الملزم الوحيد للتنفيذ:** ملف المواصفات `micro-manage-spec-final.md`. القسم 13 هنا ملخص للمنطق، وعند أي تعارض تُعتمد المواصفات.

**لغة الواجهة:** كل نص يظهر للمستخدم في هذه الوثيقة مكتوب بالصيغة المعتمدة للعرض.

## 1. الهدف والمبادئ

**الهدف:** أن يعرف صاحب المشروع إن كان يربح فعلاً، وأين أمواله، وما له وما عليه، دون حاجة إلى معرفة محاسبية.

**المبادئ:**
1. **احترافي في النتائج، بسيط في الإدخال.** لا يظهر للمستخدم أي مصطلح محاسبي تقني.
2. **نبدأ من الحاضر، لا نطلب الماضي.** يبدأ النظام من وضع المستخدم اليوم، وعند عودته بعد انقطاع يكمل من وضعه في تلك اللحظة.
3. **مصدر واحد للحقيقة.** كل رقم مالي يُحسب من الحركات المسجّلة فقط.
4. **المتوقَّع منفصل عن الفعلي.** التكلفة المتوقعة (من منتجاتي) للتسعير فقط، ولا تدخل الربح الفعلي أبداً.
5. **الشفافية.** إذا كانت البيانات غير مكتملة، يُذكر ذلك صراحة، ولا يُفترض أي رقم.
6. **لا حذف للحركات المالية.** أي تعديل أو إلغاء يتم بحركة عكسية، ويبقى السجل محفوظاً.

**اختبار أي ميزة جديدة:**
1. هل تجيب عن أحد الأسئلة الخمسة (القسم 3)؟ إذا لا، تؤجَّل.
2. هل تتطلب 3 حقول إجبارية أو أقل (دون احتساب الحقول ذات القيمة الافتراضية)؟ إذا لا، تُبسَّط.
3. هل يستطيع المستخدم العودة إليها بعد انقطاع دون تسجيل ما فاته؟ إذا لا، يُعاد تصميمها.

## 2. النطاق

| ضمن النظام المالي | خارج النظام المالي |
|---|---|
| البيع والطلبات | **أدواتي**: مساحة حسابات تجريبية منفصلة تماماً، لا تقرأ أي بيانات مالية ولا تكتبها |
| متتبّع الطلبات | المخزون: لا تتبع للكميات. كل شراء يُحتسب مصروفاً |
| التحصيل والسداد والمستحقات | الضريبة والفواتير الرسمية |
| المصاريف والمشتريات | العملات الأجنبية. **الدينار الأردني فقط** |
| أموال المالك | تعدد المستخدمين والصلاحيات |
| الصناديق والمطابقة | سجلات العملاء والموردين. **الاسم نص حر** على الطلب أو المستحق أو المصروف، ولا توجد قوائم أو ملفات للعملاء أو الموردين |
| منتجاتي | |
| الحركات، مشروعي الآن، لوحة المؤشرات، التقارير | |

**التشغيل:** على مستوى تطبيق مايكرو: عبر الإنترنت فقط، وتسجيل الدخول بحساب Google. في النظام المالي: عند انقطاع الاتصال لا يُحفظ شيء، وتظهر رسالة واضحة. وفي النسخة الأولى، حساب التطبيق الواحد يملك مشروعاً مالياً واحداً.

**قاعدة التوصيل:** لكل تكلفة توصيل مكان واحد فقط:
- توصيل **المشتريات** يُسجَّل مع الشراء (5.3).
- توصيل **الطلب** الذي يدفعه صاحب المشروع يُسجَّل مع الطلب (5.1).
- **منتجاتي** تحتوي مكونات صافية دون أي توصيل.

## 3. ما يتعامل معه المستخدم

| العنصر | التعريف |
|---|---|
| **الصندوق** | مكان وجود المال: نقد، أو حساب (بنكي أو محفظة إلكترونية) |
| **المنتج** | منتج يبيعه المستخدم، بسعره ومكوناته وتكلفته. يُضاف من منتجاتي |
| **الطلب** | عملية بيع لها موعد تسليم في المستقبل |
| **البيع المباشر** | عملية بيع تُسلَّم في نفس اليوم |
| **متتبّع الطلبات** | تقويم وقائمة بالطلبات التي اختار المستخدم متابعتها |
| **المستحق** | مبلغ لك عند شخص، أو التزام عليك لشخص |
| **الحركات** | سجل بكل العمليات المسجّلة، ومنه يتم التعديل والإلغاء |

**الأسئلة الخمسة التي يجيب عنها النظام:**

| السؤال | الإجابة |
|---|---|
| **أين أموالي؟** | رصيد كل صندوق، والإجمالي |
| **ما لي وما عليّ؟** | المستحقات لك (عملاء، مستحقات سابقة، سُلف)، والالتزامات عليك (موردون، مبالغ مستدانة، مبالغ واجب ردّها لعملاء) |
| **هل أنا أربح؟** | صافي الربح الفعلي للفترة، مع الفرق غير المفسَّر إن وُجد، وإشارة «بيانات غير مكتملة» عند الحاجة |
| **هل أسعاري مناسبة؟** | لكل طلب: «الربح المتوقع من هذا الطلب X» |
| **ما القادم؟** | الطلبات المجدولة، والطلبات المتأخرة، والمستحقات المتأخرة |

## 4. البداية (أقل من دقيقة)

0. (تسجيل الدخول يتم على مستوى تطبيق مايكرو قبل الوصول للنظام المالي.)
1. **اسم المشروع.** إجباري.
2. **عدد الصناديق:** «نقد فقط»، أو «نقد + حساب».
3. **الرصيد الحالي في كل صندوق.** يتوفر خيار «لا أعرف الآن»، ويبقى الرصيد «غير معروف» حتى أول مطابقة، ولا يُفترض صفراً.

لا يُطلب أي شيء آخر. المستحقات السابقة تُضاف عند ظهورها (5.2)، والمنتجات عند الحاجة إليها.

**إضافة صندوق لاحقاً:** متاحة في أي وقت، بنفس خطوة البداية (رصيد معروف أو «لا أعرف الآن»). الحد الأقصى صندوقان.

## 5. العمليات الأربع

### 5.1 بيع أو طلب

**البيع والطلب عملية واحدة.** الفرق بينهما تاريخ التسليم فقط: إذا كان في المستقبل فهو طلب، وإذا كان اليوم فهو بيع مباشر.

**الحقول:**

| الحقل | إجباري؟ | ملاحظة |
|---|---|---|
| **البنود** | **نعم، بند واحد على الأقل** | لكل بند: منتج من منتجاتي، أو وصف نصي (مثل «كيكة عيد ميلاد»). أثناء الكتابة تظهر اقتراحات من المنتجات ومن الأوصاف السابقة. ويمكن إضافة أي عدد من البنود |
| **الكمية** لكل بند | نعم، **القيمة الافتراضية 1** | تقبل الكسور، مثل 2.5 كغ |
| **تاريخ التسليم المخطط** | نعم | للبيع المباشر: اليوم تلقائياً |
| **السعر النهائي** | **إجباري قبل التسليم فقط** | يُحسب تلقائياً من البنود (سعر الوحدة × الكمية)، ويمكن تعديله، ومنه يتم الخصم أو الاتفاق على سعر مختلف |
| **اسم العميل** | إجباري للطلب. وللبيع المباشر فقط إذا بقي مبلغ غير محصَّل | نص حر، مع اقتراحات من الأسماء السابقة |
| **هل استلمت دفعة؟** | لا | [المبلغ كاملاً] [جزء ___] [لا]، مع الصندوق |
| **تكلفة التوصيل التي دفعتها** | لا | المبلغ، والمصدر: صندوق أو من مالي الشخصي |
| **إضافة إلى متتبّع الطلبات** | تلقائي | **الطلب:** مفعَّل افتراضياً، ويمكن إلغاؤه. **البيع المباشر:** غير مفعَّل افتراضياً، ويمكن تفعيله |
| **تاريخ التسجيل** | تلقائي | يُحفظ تلقائياً، ويمكن تعديله إذا سُجِّل الطلب متأخراً. **لا أثر مالي له** |
| ملاحظة | لا | |

**البند من منتجاتي:**
- يُملأ سعر الوحدة والتكلفة المتوقعة للوحدة تلقائياً من المنتج.
- **زر «تعديل» لكل بند:** يعدّل المكونات أو التكلفة أو السعر **لهذا الطلب فقط**، ولا يتغير المنتج الأصلي.

**البند النصي:** يُدخل سعره يدوياً، ولا تكلفة متوقعة له.

**الدفعة المقدمة:** أي مبلغ يُستلم قبل التسليم (كاملاً، أو جزءاً، أو على دفعات) يُسمّى **«دفعة مقدمة»**. إذا وصل مبلغ لطلب لم يُسجَّل بعد، يُسجَّل الطلب ومعه الدفعة؛ فالسعر غير مطلوب حتى التسليم.

**التسليم:** عند «تم التسليم» يُسجَّل **تاريخ التسليم الفعلي** (الافتراضي اليوم، وإذا كان تاريخ التسليم المخطط قبل اليوم فالافتراضي هو الأحدث بين التاريخ المخطط وتاريخ آخر دفعة مقدمة. ويمكن اختيار تاريخ سابق، لكن ليس قبل تاريخ أي دفعة مقدمة مسجّلة). منه يُحتسب الإيراد. وبعد التسليم **تُقفل البنود وتاريخ التسليم المخطط**، ويبقى اسم العميل والملاحظة قابلين للتعديل. والتسليم والتحصيل الفوري حركتان منفصلتان، تظهران في السجل صفاً واحداً.

**الحالات:**

| الحالة | المعنى |
|---|---|
| **مجدول** | لم يُسلَّم بعد |
| **متأخر** | مجدول، وتاريخ التسليم المخطط قد مضى |
| **مُسلَّم – بانتظار الدفع** | سُلِّم، وبقي مبلغ على العميل |
| **مكتمل** | سُلِّم، وحُصِّل كامل المبلغ |
| **ملغى** | أُلغي قبل التسليم |

وعلى كل طلب: «المدفوع X من Y».

**تعديل الطلب قبل التسليم:** البنود والكميات والسعر والتاريخ والاسم تُعدَّل مباشرة، لأنه لا إيراد بعد. أما الدفعات المقدمة فهي حركات مالية، وتُعدَّل من الحركات (القسم 10).

**التسليم الجزئي** غير مدعوم كحالة: يُعدَّل الطلب إلى الكمية المسلَّمة، ويُسجَّل طلب جديد للباقي.

**الإلغاء قبل التسليم:**
- إذا لم توجد دفعات: يصبح الطلب «ملغى»، ولا أثر مالي.
- إذا وُجدت دفعات: **«كم المبلغ الذي ستحتفظ به؟»** (الافتراضي كامل الدفعات). المحتفَظ به يصبح إيراداً بتاريخ الإلغاء. والباقي: **[رددته الآن]** من صندوق، أو **[لاحقاً]** فيصبح التزاماً عليك للعميل.

**المرتجع بعد التسليم (كامل أو جزئي):** المبلغ فقط. يُخصم من الإيراد بتاريخ المرتجع، ثم يُخصم أولاً من المبلغ المتبقي على العميل، وما يزيد: **[رددته الآن]** أو **[لاحقاً]** فيصبح التزاماً عليك للعميل.

**الربح المتوقع للطلب** = السعر النهائي − مجموع التكلفة المتوقعة للبنود − تكلفة التوصيل التي دفعتها.
- يظهر على الطلب بعنوان «ربح متوقع».
- يظهر فقط إذا كانت لجميع البنود تكلفة متوقعة.
- **لا يدخل الربح الفعلي أبداً.**

### 5.2 تحصيل أو سداد

نفس الآلية في الاتجاهين.

| | تحصيل | سداد |
|---|---|---|
| على ماذا | مستحق لك (عميل، مستحق سابق، سلفة) | التزام عليك (مورد، مبلغ مستدان، رد لعميل، التزام سابق) |
| الحقول | الاسم + المبلغ + الصندوق | الاسم + المبلغ + الصندوق |
| أكثر من مستحق لنفس الاسم | يُوزَّع المبلغ تلقائياً من الأقدم إلى الأحدث | نفس القاعدة |
| مبلغ **أقل** من المتبقي | إذا كان التحصيل على مستحق واحد: سؤال **[يبقى مستحقاً]** أو **[لن يُحصَّل]**. وإذا كان على أكثر من مستحق لنفس الاسم: يبقى الباقي مستحقاً دون سؤال. ويمكن اختيار «لن يُحصَّل» على أي مستحق في أي وقت | يبقى الباقي التزاماً |
| مبلغ **أكثر** من المتبقي | إذا كان آخر مستحق في التوزيع متبقياً على طلب: الزيادة تُحتسب لك تلقائياً، مع رسالة «تم احتساب الزيادة 5 لصالحك». غير ذلك: غير مسموح | غير مسموح |
| الصندوق | يزيد | ينقص |
| الربح | **لا يتأثر** (باستثناء «لن يُحصَّل» و«الزيادة») | **لا يتأثر** |

**«لن يُحصَّل»:**
- على طلب: يُخصم من الإيراد بتاريخ اليوم (مثال: سلّمك المندوب 22 من 25).
- على مستحق سابق: يُخصم من الرصيد الافتتاحي.
- على سلفة: تُحتسب سحباً شخصياً.

**المستحق السابق** (من قبل بدء استخدام النظام): خيار في نفس الشاشة: «مستحق سابق: الاسم + المبلغ».
- يمكن تحصيله أو سداده فوراً، أو إضافته للمتابعة فقط (من صفحة المستحقات والالتزامات).
- **لا يؤثر على الربح**، لأنه ليس من نشاط الفترة الحالية.

### 5.3 مصروف أو شراء

| الحقل | إجباري؟ |
|---|---|
| المبلغ | نعم |
| التصنيف | نعم: مواد وتغليف، كهرباء ومياه، غاز، إيجار، تنقّل، إعلانات، أدوات، **معدات**، أخرى |
| **تكلفة التوصيل** | لا. حقل ظاهر دائماً، ويُضاف إلى نفس المصروف ونفس التصنيف |
| الدفع | نعم: **[مدفوع بالكامل]** أو **[آجل]** أو **[مدفوع جزئياً ___]** |
| مصدر الدفع | إذا دُفع شيء: صندوق، أو **من مالي الشخصي** |
| اسم المورد | إذا بقي مبلغ آجل |
| التاريخ | الافتراضي اليوم |
| ملاحظة | لا |

لا تفاصيل للأصناف أو الكميات، لأنه لا يوجد مخزون.

**الأثر:**
- إجمالي المصروف (المبلغ + التوصيل) يُخصم من الربح **بتاريخه**، مهما كانت طريقة الدفع.
- المدفوع ينقص من الصندوق، والباقي يصبح التزاماً للمورد يُسدَّد لاحقاً من 5.2.
- **من مالي الشخصي:** يُخصم المصروف من الربح، ولا يتغير أي صندوق، ويُحتسب المبلغ إيداعاً من المالك (يُسجَّل داخلياً على صندوق النقد).
- **معدات:** تُخصم من الربح كأي مصروف، ويظهر بجانب الربح «منها معدات بقيمة Y». لا إهلاك.
- **الفواتير المنزلية المشتركة:** تُسجَّل حصة المشروع فقط.
- **إرجاع بضاعة لمورد:** يُعدَّل المصروف الأصلي (القسم 10).

### 5.4 إيداع أو سحب شخصي

| | إيداع | سحب |
|---|---|---|
| الحقول | المبلغ + الصندوق + المصدر: **[من مالي الشخصي]** أو **[مبلغ مستدان من شخص]** (الاسم) | المبلغ + الصندوق + النوع: **[سحب شخصي]** أو **[سلفة لشخص]** (الاسم) |
| الصندوق | يزيد | ينقص |
| الربح | **لا يتأثر** | **لا يتأثر** |
| المستحقات | المبلغ المستدان يصبح التزاماً عليك، ويُسدَّد من 5.2. لا فوائد ولا أقساط | السلفة تصبح مستحقاً لك، وتُحصَّل من 5.2. **لا تُحتسب ضمن السحوبات الشخصية** |

## 6. الصناديق

- **صندوق أو صندوقان:** نقد، وحساب.
- مع صندوقين: كل حركة مالية تتضمن اختيار الصندوق، والافتراضي آخر صندوق مستخدم.
- **التحويل** بين الصندوقين: المبلغ، ومن أين وإلى أين. لا يؤثر على الإجمالي ولا على الربح.
- **الدمج:** يصبح الصندوقان صندوقاً واحداً برصيد مجموعهما.
- **الفصل:** يعود الصندوقان، ويُطلب مبلغ الحساب لتقسيم الرصيد.
- **الرصيد لا يُخزَّن، بل يُحسب:** الرصيد الافتتاحي + كل الوارد − كل الصادر.

---

## 7. المطابقة: «هل الرصيد صحيح؟»

**متى:** مرة أسبوعياً، وضمن العودة بعد الانقطاع، وفي أي وقت يطلبه المستخدم.

**الخطوة 1:** «رصيدك المسجَّل 340 (نقد 200 + حساب 140). هل يطابق الموجود فعلاً؟» ← **[مطابق]** أو **[غير مطابق: الموجود ___]** لكل صندوق.

**الخطوة 2: فروق متعاكسة بين الصندوقين.** إذا كان أحدهما أقل والآخر أكثر، يقترح النظام أولاً: «هل حوّلت 50 من النقد إلى الحساب؟» وعند التأكيد يُسجَّل تحويل، ويُستكمل الباقي بالخطوة 3.

**الخطوة 3: أسئلة الفرق.** كل إجابة تسجّل عمليتها مباشرة وتقلّص الفرق:

| الموجود **أقل** من المسجَّل | الموجود **أكثر** من المسجَّل |
|---|---|
| هل دفعت مصروفاً لم تسجّله؟ ← مصروف | هل حصّلت مبلغاً من أحد؟ ← تحصيل (أو مستحق سابق) |
| هل سحبت مبلغاً لنفسك؟ ← سحب شخصي | هل بعت شيئاً لم تسجّله؟ ← بيع مباشر |
| هل سددت التزاماً؟ ← سداد | هل أودعت من مالك الشخصي؟ ← إيداع |
| هل أعطيت سلفة لأحد؟ ← سلفة | هل استدنت مبلغاً من أحد؟ ← مبلغ مستدان |
| **للحالتين:** هل راجعت كل أماكن المال؟ | |

- كل حركة ناتجة عن المطابقة تُسجَّل **بتاريخ المطابقة**، وعلى **الصندوق الذي فرقه بنفس الاتجاه**.

**الخطوة 4:** ما يتبقى يُسجَّل **«فرق غير مفسَّر»**. يصحح رصيد الصندوق، **ولا يدخل الربح**، ويظهر **بجانب** الربح:
- عند النقص: «يوجد نقص 20 غير مفسَّر».
- عند الزيادة: «توجد زيادة 20 غير مفسَّرة».

لا يُطلب سبب، و«لا أعرف» إجابة مقبولة.

## 8. العودة بعد الانقطاع

**متى:** عند فتح التطبيق بعد 14 يوماً أو أكثر دون أي حركة. تظهر **بطاقة في أعلى «مشروعي الآن»** (التطبيق يفتح عليها دائماً)، وتبقى حتى إكمال الخطوات.

1. «مرّ 35 يوماً على آخر تسجيل. لنبدأ من وضعك الحالي».
2. **الطلبات المتأخرة:** لكل طلب: [تم التسليم] / [أُلغي] / [ما زال قائماً]. عند التسليم دون سعر، يُطلب السعر. والتحصيل اختياري.
3. **المستحقات والالتزامات المفتوحة:** لكل منها: [حُصِّل أو سُدِّد] / [ما زال قائماً].
4. **المطابقة** (القسم 7). تأتي أخيراً، حتى تُحتسب الإجابات السابقة في الرصيد قبل مقارنته بالواقع.

**إشارة «بيانات غير مكتملة»:** تظهر بجانب ربح أي فترة تتضمن الانقطاع، **إلا إذا** انتهت مطابقة العودة دون أي فرق ودون تسجيل أي حركة من أسئلة الفرق.

لا يُطرح أي سؤال عن مبيعات أو مصاريف تقديرية لفترة الانقطاع.

## 9. منتجاتي

- قائمة المنتجات. لكل منتج: **الاسم**، و**الوحدة** (اختياري: قطعة، كغ، صحن...)، و**سعر البيع للوحدة**، و**المكونات** (الاسم + التكلفة، **دون توصيل**).
- **تكلفة الوحدة** = مجموع تكاليف المكونات. منتج بلا مكونات: تكلفته **غير معروفة**.
- إضافة وتعديل وأرشفة في أي وقت.
- **تعديل المنتج لا يغيّر الطلبات المسجَّلة سابقاً**، لأن كل طلب يحفظ نسخته من البنود.
- لا تسجّل منتجاتي أي حركة مالية، بل تملأ الطلب بقيم مقترحة فقط.
- منفصلة تماماً عن أدواتي.

## 10. الحركات والتصحيح

### 10.1 الحركات

سجل واحد بكل العمليات:
- **المحتوى:** كل عملية مسجّلة: بيع أو طلب، دفعة مقدمة، تسليم، تحصيل، سداد، مصروف، إيداع، سحب، سلفة، تحويل، مطابقة.
- **لكل حركة:** التاريخ، والنوع، والمبلغ، والصندوق، والاسم أو الوصف.
- **الترتيب:** الأحدث أولاً.
- **التصفية:** حسب النوع وحسب الفترة، مع بحث بالاسم. قائمة المبيعات هي نفس السجل مصفّى بنوع «بيع».
- **عند فتح أي حركة:** التفاصيل، مع **«تعديل»** و**«إلغاء»**.
- **الحركة المعدَّلة أو الملغاة** تبقى ظاهرة مع إشارة «معدَّلة» أو «ملغاة».
- **الطلب** يعرض داخله سجله المالي: الدفعات المقدمة، والتسليم، والتحصيل، والمرتجعات.
- الطلب الذي لم يُضَف إلى المتتبّع ولا دفعات عليه يظهر في الحركات بحالته «مجدول» حتى لا يُنسى.
- **البيع المباشر** (إنشاء وتسليم وتحصيل بنفس اللحظة) يظهر في السجل **صفاً واحداً**، وتفاصيله تعرض كل حركة على حدة.
- **إلغاء الطلب نهائي**، ولا تراجع عنه. ولإعادة الطلب يُسجَّل طلب جديد.

### 10.2 التصحيح

- من داخلياً: حركة عكسية للأصل، ثم الحركة الصحيحة. لا حذف.
- يتم التصحيح **بتاريخ الحركة الأصلية**، فتُصحَّح أرقام الفترة التي وقع فيها الخطأ.
- **التصحيح يُنفَّذ كاملاً أو لا يُنفَّذ.** إذا كان سيؤدي إلى مستحق أو التزام أو دفعة مقدمة بقيمة سالبة، يُرفض مع رسالة توضح ما يجب تصحيحه أولاً. وتظهر تحت الرسالة الحركات المرتبطة التي يجب تعديلها أولاً.
- **تعديل السعر بعد التسليم** (خطأ في التسجيل): يُصحَّح الإيراد بتاريخ التسليم. وإذا أصبح المحصَّل أكثر من السعر الجديد، يصبح الفرق التزاماً عليك للعميل.
- **إلغاء التسليم** (سُجِّل التسليم بالخطأ): يُلغى الإيراد، ويعود الطلب «مجدولاً»، وتتحول المبالغ المحصَّلة بعد التسليم (ومعها أي زيادة محصَّلة) إلى دفعات مقدمة، ولا يتغير الصندوق.
- **تعديل بيانات الطلب غير المالية** (البنود قبل التسليم، الاسم، الملاحظة، المتتبّع) ليس حركة مالية، ولا يظهر في الحركات.
- **الحركة المعدَّلة:** يعرض السجل النسخة الحالية مع إشارة «معدَّلة»، والنسخ السابقة من تفاصيلها. ويمكن تعديلها مرة أخرى.
- **الخصم بعد التسليم** ليس تصحيحاً: إذا دفع العميل أقل فهو «لن يُحصَّل» (5.2)، وإذا رُدَّ له مبلغ فهو مرتجع (5.1).

## 11. متتبّع الطلبات

- **المحتوى:** الطلبات التي اختار المستخدم متابعتها (5.1).
- **العرض:** تقويم وقائمة. الطلب المجدول يظهر بتاريخ التسليم المخطط، والمسلَّم بتاريخ التسليم الفعلي.
- **الاحتفاظ:** لا يُحذف أي طلب من المتتبّع تلقائياً، مهما كانت حالته. يمكن الرجوع لأي يوم سابق لمعرفة ما كان مطلوباً فيه.
- **تغيير الحالة من المتتبّع:** هو نفس العملية المالية. «تم التسليم» من المتتبّع يسجّل التسليم والإيراد، و«إلغاء» يطبّق قواعد الإلغاء.
- **الحذف من المتتبّع:** إخفاء فقط. **لا يؤثر على أي رقم مالي**، وتبقى العملية في الحركات.
- **الإضافة لاحقاً:** أي عملية بيع غير مضافة يمكن إضافتها للمتتبّع من الحركات.

## 12. ما يعرضه النظام

### 12.1 مشروعي الآن

صورة اللحظة، دون فترة زمنية:
- **رصيدك ___** (ومع صندوقين: نقد ___ وحساب ___).
- **المستحقات لك ___، والالتزامات عليك ___ (منها ___ دفعات مقدمة لطلبات قادمة).**
- **طلبات اليوم والغد، والطلبات المتأخرة** (كل الطلبات، سواء كانت في المتتبّع أم لا).
- **مستحقات متأخرة:** «محمد: 50 منذ 3 أسابيع».
- **المطابقة:** «رصيدك المسجَّل 325. هل يطابق الموجود فعلاً؟» عند حلول موعدها.
- **تنبيه:** إذا أصبح رصيد صندوق معروف بالسالب.

### 12.2 لوحة المؤشرات: 6 بطاقات

أزرار الفترة: **[أسبوع] [شهر] [سنة] [منذ البداية]**. هذا اختيار فترة، وليس مقارنة.

| البطاقة | النص | عند الضغط |
|---|---|---|
| **صافي الربح** | «صافي ربحك 700» | قائمة الدخل + **أعمدة الربح** (آخر 8 أسابيع، أو آخر 12 شهراً، أو كل السنوات، حسب الفترة) |
| **صافي قيمة المشروع** | «إذا حصّلت مستحقاتك وسددت التزاماتك، يتبقى لك 300» | المركز المالي. **لا تتغير مع الفترة** |
| **الأعلى مبيعاً** | «منسف: 1,000 (40 صحناً)» | **أشرطة أفقية** للمنتجات |
| **الأعلى ربحاً** | «منسف: 200 ربح متوقع (5 للصحن)» | **أشرطة أفقية** للمنتجات |
| **أكبر بند مصروف** | «المواد والتغليف: 320 من أصل 450» | **أشرطة أفقية** للتصنيفات |
| **الربح والسحوبات** | «من كل 10 دنانير مبيعات يتبقى لك 6 ربحاً. سحوباتك الشخصية 400» | دون رسم |

**قواعد البطاقات:**
- **بطاقتا المنتجات:** تحسبان بنود منتجاتي فقط (لا البنود النصية)، وتستبعدان الطلبات التي عليها مرتجع. الترتيب حسب **الإجمالي**، مع قيمة الوحدة بجانبه. «الأعلى ربحاً» تحمل عبارة «حسب تكلفة منتجاتك»، وتستبعد المنتجات ذات التكلفة غير المعروفة. تظهر البطاقتان فقط عند وجود بنود من منتجاتي في الفترة.
- **على بطاقة صافي الربح:**
  - «منها معدات بقيمة Y» إذا وُجدت معدات في الفترة.
  - «مشتريات المواد في هذه الفترة 900، وقد تكفي لفترات قادمة» إذا تجاوزت المواد نصف صافي المبيعات.
  - «بيانات غير مكتملة» عند الانقطاع أو الرصيد الافتتاحي غير المعروف.
  - الفرق غير المفسَّر إن وُجد.
- **مستخدم جديد:** بدلاً من أصفار: «سجّل أول عملية بيع، وستظهر مؤشراتك هنا».

### 12.3 التقارير (من البطاقات)

**قائمة الدخل** (للفترة المختارة):
```
المبيعات                        1,200
المرتجعات والخصومات               −50
صافي المبيعات                   1,150
المصاريف حسب التصنيف             −450
صافي الربح                        700
(منها معدات: 0)
```

**المركز المالي** (في هذه اللحظة):
```
ما لديك:        النقد + الحساب + المستحقات لك
ما عليك:        الموردون + المبالغ المستدانة + الردود للعملاء + الدفعات المقدمة لطلبات قادمة
صافي قيمة المشروع = ما لديك − ما عليك
```

**مصادر صافي القيمة:**
```
الرصيد الافتتاحي (أرصدة الصناديق الأولى + المستحقات والالتزامات السابقة)
+ الإيداعات الشخصية
− السحوبات الشخصية
+ صافي الربح منذ البداية
± الفرق غير المفسَّر
= صافي قيمة المشروع
```

- المعدات **لا تظهر** ضمن «ما لديك»، لعدم وجود إهلاك.
- مع صندوق رصيده الافتتاحي غير معروف: يظهر صافي قيمة المشروع «غير معروف حتى المطابقة».
- **صافي قيمة المشروع يساوي مصادره دائماً.** هذا فحص سلامة داخلي.

### 13.2 الكيانات

**الصندوق:** النوع (نقد / حساب)، الحالة (فعّال / مدموج)، حالة الرصيد الافتتاحي (معروف / غير معروف). **الرصيد لا يُخزَّن.**

**المنتج:** الاسم، الوحدة (اختياري)، سعر البيع للوحدة، المكونات (اسم + تكلفة)، مؤرشف أم لا. التكلفة = مجموع المكونات، أو «غير معروفة» إذا لم توجد مكونات.

**الطلب (يشمل البيع المباشر):**
- تاريخ التسجيل (تلقائي، قابل للتعديل)، تاريخ التسليم المخطط، تاريخ التسليم الفعلي (عند التسليم)، اسم العميل (نص حر)، ملاحظة، **مُضاف إلى المتتبّع** (نعم/لا)، **مخفي من المتتبّع** (نعم/لا).
- **البنود (واحد على الأقل):** الوصف (مرجع منتج + اسمه وقت التسجيل، أو نص)، الكمية، سعر الوحدة (قد يكون فارغاً للنص)، التكلفة المتوقعة للوحدة (فارغة للنص أو لمنتج بلا مكونات)، المكونات بعد التعديل. **نسخة ثابتة لا تتأثر بتعديل المنتج، وتُقفل بعد التسليم.**
- **السعر النهائي:** افتراضياً مجموع قيم البنود، قابل للتعديل، إجباري قبل التسليم.
- **الحالة مشتقة** (13.7).

**خط المستحق:** الاتجاه (لك / عليك)، النوع، الاسم (نص حر)، تاريخ النشوء، مرجع اختياري (طلب أو مصروف).
- أنواع «لك»: متبقٍ على طلب، مستحق سابق، سلفة.
- أنواع «عليك»: مورد، التزام سابق، مبلغ مستدان، رد لعميل.
- **المتبقي لا يُخزَّن.**

**القيد:** النوع (13.4)، التاريخ الفعلي، المبلغ، المراجع (صندوق، طلب، خط مستحق، تصنيف)، وقت الإنشاء، مرجع التصحيح (اختياري)، ومرجع **العملية** التي أنشأته. **لا يُحذف ولا يُعدَّل أبداً.**

**العملية:** ما يقوم به المستخدم (بيع، تحصيل، مصروف...). تنتج قيداً أو أكثر. **الحركات (10.1) تعرض العمليات، لا القيود.**

**حدث انقطاع:** تاريخ البداية (آخر حركة قبل الانقطاع)، تاريخ النهاية (يوم العودة)، مكتمل أم لا (حسب نتيجة مطابقة العودة، القسم 8).

**مطابقة:** التاريخ، الموجود لكل صندوق، المسجَّل لكل صندوق وقتها.

### 13.4 جدول القيود (القاعدة الوحيدة)

**لا توجد أي طريقة أخرى لتغيير أي رقم.** المبالغ موجبة، والاتجاه محدد في الجدول.

| # | القيد | الأثر |
|---|---|---|
| Q1 | رصيد افتتاحي لصندوق (k, a) | `BOX[k] += a`، `OPEN += a` (a ≥ 0) |
| Q2 | مستحق سابق لك (اسم, a) | خط «لك» جديد: `AR += a`، `OPEN += a` |
| Q3 | التزام سابق عليك (اسم, a) | خط «عليك» جديد: `AP += a`، `OPEN −= a` |
| Q4 | دفعة مقدمة (o, k, a) | `BOX[k] += a`، `PRE[o] += a` |
| Q5 | تسليم (o, P, تاريخ فعلي) | أدناه |
| Q6 | تحصيل (d, k, a) | `BOX[k] += a`، `AR[d] −= a` |
| Q7 | سداد (d, k, a) | `BOX[k] −= a`، `AP[d] −= a` |
| Q8 | مصروف مدفوع (c, k, a) | `BOX[k] −= a`، `EXP[c] += a` |
| Q9 | مصروف آجل (c, اسم, a) | خط «عليك» نوع مورد: `AP += a`، `EXP[c] += a` |
| Q10 | إيداع شخصي (k, a) | `BOX[k] += a`، `OWN_IN += a` |
| Q11 | مبلغ مستدان (k, اسم, a) | `BOX[k] += a`، خط «عليك» نوع مبلغ مستدان: `AP += a` |
| Q12 | سحب شخصي (k, a) | `BOX[k] −= a`، `OWN_OUT += a` |
| Q13 | سلفة لشخص (k, اسم, a) | `BOX[k] −= a`، خط «لك» نوع سلفة: `AR += a` |
| Q14 | تحويل (k1→k2, a) | `BOX[k1] −= a`، `BOX[k2] += a` |
| Q15 | إلغاء طلب له دفعات (o, محتفَظ m) | أدناه |
| Q16 | مرتجع (o, r) | أدناه |
| Q17 | لن يُحصَّل (d, a) | أدناه |
| Q18 | زيادة محصَّلة على طلب (o, k, e) | `BOX[k] += e`، `REV += e` (نوع: زيادة محصَّلة) |
| Q19 | تسوية مطابقة (k, diff) | `BOX[k] += diff`، `UNEXP += diff` (diff موجبة أو سالبة) |
| Q20 | عكس قيد (q) | آثار q بالسالب، **بتاريخ q الأصلي**، ومرتبط به |

**Q5 — التسليم (o, P):**
1. `REV += P` بتاريخ التسليم الفعلي.
2. p = `PRE[o]`، و`PRE[o] −= p`.
3. إذا P > p: خط «لك» نوع متبقٍ على طلب بقيمة `P − p`.
4. إذا p > P: خط «عليك» نوع رد لعميل بقيمة `p − P`.

**Q15 — إلغاء طلب له دفعات (o, m):** p = `PRE[o]`، و0 ≤ m ≤ p.
1. `PRE[o] −= m`، `REV += m` بتاريخ الإلغاء (نوع: دفعات محتفَظ بها).
2. الباقي r = p − m. [الآن] (k): `BOX[k] −= r`، `PRE[o] −= r`. [لاحقاً]: `PRE[o] −= r`، وخط «عليك» نوع رد لعميل: `AP += r`.

**Q16 — المرتجع (o, r):** على طلب مُسلَّم، وr ≤ صافي إيراد الطلب (P + الزيادات المحصَّلة − «لن يُحصَّل» − المرتجعات السابقة).
1. `REV −= r` بتاريخ المرتجع (نوع: مرتجع).
2. x = min(r, `AR` المتبقي على الطلب): `AR −= x`.
3. y = r − x. [الآن] (k): `BOX[k] −= y`. [لاحقاً]: خط «عليك» نوع رد لعميل: `AP += y`.

**Q17 — لن يُحصَّل (d, a):** a ≤ `AR[d]`. `AR[d] −= a`، ثم حسب نوع الخط:
- متبقٍ على طلب: `REV −= a` بتاريخ اليوم (نوع: خصم).
- مستحق سابق: `OPEN −= a`.
- سلفة: `OWN_OUT += a`.

### 13.6 الحالات المرفوضة والتنبيهات

**مرفوض** (برسالة واضحة):
- تحصيل باسم ليس عليه أي مستحق مفتوح، دون اختيار «مستحق سابق».
- مبلغ احتفاظ أكبر من الدفعات المقدمة عند إلغاء طلب.
- سداد أكثر من الالتزامات المفتوحة بنفس الاسم.
- تحصيل أكثر من المتبقي على غير الطلبات.
- تسليم دون سعر نهائي.
- طلب دون بنود.
- مرتجع على طلب غير مُسلَّم، أو أكبر من صافي إيراده.
- مبلغ صفر أو سالب، أو كمية صفر أو سالبة.
- تاريخ مستقبلي لأي حركة مالية (تاريخ التسليم المخطط في المستقبل مسموح، لأنه ليس حركة مالية).
- إلغاء طلب مُسلَّم (البديل: مرتجع، أو إلغاء التسليم).
- تعديل البنود بعد التسليم.
- عكس قيد Q20.
- أي حركة على صندوق مدموج.
- أكثر من صندوقين.
- أي عملية تجعل `AR` أو `AP` أو `PRE` سالباً.

**مسموح مع تنبيه:**
- **رصيد صندوق معروف بالسالب:** «أصبح رصيدك بالسالب، قد تكون هناك عملية غير مسجّلة»، مع اقتراح مطابقة. لا يظهر التنبيه لصندوق رصيده الافتتاحي غير معروف.

### 13.7 حالة الطلب (مشتقة)

| الحالة | الشرط |
|---|---|
| **ملغى** | أُلغي |
| **مجدول** | لم يُسلَّم ولم يُلغَ |
| **متأخر** | مجدول، وتاريخ التسليم المخطط قبل اليوم |
| **مُسلَّم – بانتظار الدفع** | سُلِّم، والمتبقي على الطلب > 0 |
| **مكتمل** | سُلِّم، والمتبقي على الطلب = 0 أو لا يوجد خط متبقٍ |

**«المدفوع X من Y»:**
- قبل التسليم: X = `PRE[o]`، وY = السعر النهائي (إن وُجد).
- بعد التسليم: Y = صافي إيراد الطلب، وX = Y − المتبقي على الطلب. وإذا وُجد خط «رد لعميل» مفتوح على الطلب، يظهر بجانبه: «مستحق للعميل Z».

### 13.8 معادلات كل رقم معروض

f = الفترة المختارة. «في f» = القيود التي يقع تاريخها الفعلي ضمن f.

| الرقم | المعادلة |
|---|---|
| رصيد الصندوق k | مجموع آثار كل القيود على `BOX[k]` حتى اليوم. إذا كان الرصيد الافتتاحي غير معروف: «غير معروف حتى المطابقة» |
| رصيدك (الإجمالي) | مجموع `BOX` للصناديق الفعّالة |
| المستحقات لك | مجموع `AR` |
| الالتزامات عليك | مجموع `AP` + مجموع `PRE`، مع إظهار مجموع `PRE` منفصلاً: «منها ___ دفعات مقدمة» |
| المبيعات (f) | مجموع Q5 + الجزء المحتفَظ به من Q15 + Q18، في f |
| المرتجعات والخصومات (f) | مجموع Q16 + Q17 من نوع «متبقٍ على طلب»، في f |
| صافي المبيعات (f) | المبيعات − المرتجعات والخصومات |
| المصاريف (f) | مجموع `EXP[c]` لكل التصنيفات في f |
| **صافي الربح (f)** | صافي المبيعات − المصاريف |
| منها معدات (f) | `EXP[معدات]` في f |
| السحوبات الشخصية (f) | مجموع `OWN_OUT` في f (يشمل السُّلف التي «لن تُحصَّل»، ولا يشمل السُّلف القائمة) |
| من كل 10 دنانير (f) | تقريب(صافي الربح × 10 ÷ صافي المبيعات) لأقرب 0.1. **يُخفى** إذا كان صافي المبيعات ≤ 0. وإذا كان الربح سالباً: «مصاريفك في هذه الفترة أكبر من مبيعاتك» |
| أكبر بند مصروف (f) | التصنيف صاحب أكبر `EXP[c]` في f: «X: Y من أصل Z» |
| تنبيه المشتريات (f) | يظهر إذا كان `EXP[مواد وتغليف]` في f > 50% من صافي المبيعات في f |
| الربح المتوقع للطلب | السعر النهائي − مجموع (الكمية × التكلفة المتوقعة للوحدة) − مجموع «توصيل طلب» المرتبط بالطلب. **فارغ** إذا كان أي بند دون تكلفة متوقعة، أو لا يوجد سعر نهائي |
| الأعلى مبيعاً (f) | بنود منتجاتي في الطلبات المسلَّمة في f (غير الملغى تسليمها، ودون مرتجعات)، مجمّعة حسب المنتج: مجموع قيم البنود، ومجموع الكمية. الترتيب حسب مجموع القيم |
| الأعلى ربحاً (f) | نفس البنود، للمنتجات ذات التكلفة المعروفة: مجموع (قيمة البند − الكمية × التكلفة المتوقعة). الترتيب حسب المجموع، والقيمة للوحدة = المجموع ÷ الكمية. **الخصم على السعر النهائي والتوصيل لا يُوزَّعان على المنتجات** |
| الفرق غير المفسَّر (f) | مجموع `UNEXP` في f. يظهر فقط إذا لم يكن صفراً، بصيغة النقص أو الزيادة |
| أعمدة الربح | صافي الربح لكل فترة: آخر 8 أسابيع، أو آخر 12 شهراً، أو كل سنة منذ البداية. الفترات غير المكتملة تظهر بتمييز مختلف |
| **صافي قيمة المشروع** | `مجموع BOX + مجموع AR − مجموع AP − مجموع PRE`. «غير معروف حتى المطابقة» إذا وُجد صندوق فعّال رصيده الافتتاحي غير معروف |
| **مصادر صافي القيمة** | `OPEN + OWN_IN − OWN_OUT + صافي الربح منذ البداية + UNEXP` |
| مستحقات متأخرة | خطوط «لك» متبقيها > 0، وعمرها ≥ 14 يوماً |
| «بيانات غير مكتملة» على f | إذا تقاطعت f مع حدث انقطاع غير مكتمل، أو وُجد صندوق فعّال رصيده الافتتاحي غير معروف |

**أي رقم غير وارد في هذا الجدول أو في §8.2 بالمواصفات لا يُعرض.**

### 13.9 الثوابت التي يجب أن تتحقق دائماً

| # | الثابت |
|---|---|
| I1 | **صافي قيمة المشروع = مصادر صافي القيمة**، في أي لحظة وبعد أي عملية |
| I2 | كل `AR` و`AP` و`PRE` ≥ صفر |
| I3 | كل رقم معروض يُحسب من القيود. وأي تخزين مؤقت لأرقام محسوبة يجب أن يعطي نفس النتيجة عند إعادة الحساب من الصفر |

### 13.10 تدفقات خاصة

**أ) المطابقة:**
1. لكل صندوق فعّال: المسجَّل = `BOX[k]`. يُدخل المستخدم الموجود، أو يختار «مطابق».
2. إذا كان أحد الفرقين موجباً والآخر سالباً: اقتراح Q14 بقيمة min(|Δ1|, |Δ2|). بعد التأكيد يُعاد حساب الفروق.
3. لكل صندوق بقي فيه فرق Δ: إذا Δ < 0 أسئلة «أقل»، وإذا Δ > 0 أسئلة «أكثر». كل إجابة تُنشئ قيدها بتاريخ المطابقة على ذلك الصندوق، ثم يُعاد حساب Δ.
4. «إنهاء»: Q19 لكل صندوق بفرقه المتبقي.
5. يُحفظ سجل المطابقة.

**ب) العودة بعد الانقطاع:**
1. عند فتح التطبيق، إذا كان عمر آخر حركة ≥ 14 يوماً: يُنشأ حدث انقطاع.
2. الطلبات المتأخرة: [تم التسليم] ← Q5 (مع السعر إن كان فارغاً، والتحصيل اختياري) / [أُلغي] ← قواعد الإلغاء / [ما زال قائماً].
3. المستحقات والالتزامات المفتوحة: [حُصِّل أو سُدِّد] ← Q6 أو Q7 بكامل المتبقي / [ما زال قائماً].
4. المطابقة (أ).
5. إذا انتهت المطابقة دون أي فرق ودون أي قيد من أسئلة الفرق: حدث الانقطاع «مكتمل». وإلا: «غير مكتمل».

**ج) الرصيد الافتتاحي غير المعروف:**
- يقبل الصندوق الحركات بشكل طبيعي، دون تنبيه الرصيد السالب.
- **أول مطابقة:** الرصيد الافتتاحي المحسوب = الموجود − مجموع آثار القيود على الصندوق منذ البداية.
  - إذا كان ≥ 0: Q1 **بتاريخ البداية** بهذه القيمة، دون أسئلة فرق ودون Q19.
  - إذا كان < 0: Q1 بقيمة صفر بتاريخ البداية، ثم يُعامل الفرق السالب المتبقي بأسئلة «أقل» (أ-3) ثم Q19.
- بعدها يصبح الصندوق «معروف».

**د) البداية:** اسم المشروع، وعدد الصناديق، ورصيد كل صندوق أو «لا أعرف الآن». لا إدخال إجباري آخر.

## 15. خارج النسخة الأولى

- تتبع المخزون والكميات.
- التسليم الجزئي كحالة.
- قيمة ساعة العمل.
- «كم يمكنني أن أسحب لنفسي؟».
- الالتزامات الشهرية ونقطة التعادل.
- المقارنات بين الفترات (أسهم ونسب)، وأي تحليلات خارج لوحة المؤشرات.
- الضريبة والفواتير.
- أي ربط بين أدواتي ومنتجاتي.
- أكثر من صندوقين.

يعود أي بند منها فقط إذا ظهرت حاجة فعلية، وبعد اجتياز اختبار القسم 1.
