# قرار 25 — Micro Core + Activity Profiles + مشاريع مختلطة

**الحالة:** `APPROVED / PRODUCT DIRECTION / NO IMPLEMENTATION AUTHORIZATION`
**التاريخ:** 25 أغسطس 2026

## Major Discussion Points

### المشكلة المرتبطة

Problem Statement v4 يثبت أن المالك قد يدير أكثر من نوع من العمل، وأن قالب حرفة واحد لا يفسر تكلفة الطعام أو الخدمة أو الزراعة أو السياحة أو المورد المشترك بين نشاطين.

### الأدلة وقوتها

| النوع | الدليل | القوة والحد |
|---|---|---|
| دليل منتجي | السيناريوهات الحالية P01–P10 تغطي طعامًا وخدمات وزراعة وإعادة بيع، وتكشف أن النواة لا ينبغي أن تفترض نوع عمل واحد. | مفهومي فقط؛ ليس Pilot. |
| دليل خارجي | FAO يميز enterprise/activity وحدود المدخلات والمخرجات في المشاريع الزراعية المختلطة؛ OECD يصف تغاير وتجزؤ السياحة الصغيرة. | يبرر الحذر التصميمي، لا ترتيب السوق. |
| دليل ميداني | خبرة المؤسس 14 عامًا ومشكلة الإدارات اليومية المتداخلة. | قوي للمشكلة، لا يثبت تبني كل Profile. |

### التوصية

اعتماد نواة مالية مشتركة مع Profiles اختيارية قابلة للتركيب، وسياق على مستوى الواقعة لا هوية مشروع واحدة مفروضة.

### البدائل المرفوضة

| البديل | سبب الرفض |
|---|---|
| حرفة ثم نسخ الشاشات لكل قطاع | يخلق استثناءات ونتائج تكلفة مضللة. |
| نموذج عام يحمل كل الحقول | يحول Micro إلى ERP ويزيد العبء قبل القيمة. |
| اختيار قطاع واحد دائمًا عند التأسيس | لا يخدم مشروعًا مختلطًا ويقيد التاريخ المستقبلي. |
| بناء Profiles كلها الآن | لا دليل ترتيب ولا حدود عقود ولا اختبار هاتف/Pilot. |

### مخاطر القرار

الخطر هو استخدام كلمة Profile لتبرير Features عشوائية أو توزيع مشترك مخفي أو ادعاء دعم قطاع لم يختبر. يمنع ذلك بعقود Profile وبوابة G15/G16 وبناء Slice واحد فقط بعد اختيار موثق.

### معيار النجاح والفشل

ينجح القرار إن استطاع Agent أو مالك وصف أين تنتهي النواة وأين يبدأ Profile، وإن لم يفرض UI الحالي قالبًا قطاعيًا على واقعة لا تحتاجه. يفشل إذا أنتج أي Profile رقمًا نهائيًا من وحدة/فترة/عنصر تكلفة غير معروف أو إذا بُني قبل دليل قرار.

## Action Points

يُراجع القرار بعد G16 أو عند ظهور دليل قطاعي قوي. لا يفتح هذا القرار مشروع كود أو schema أو import migration تلقائيًا.
