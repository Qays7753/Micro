# قرار H01-A: مركز قيادة «مشروعي اليوم»

**الحالة:** معتمد للتنفيذ في H01-B داخل `bridge/micro-experience-repair-program` فقط.

## سؤال القرار والمستخدم

سؤال القرار هو: **هل يرى مالك المشروع وضع مشروعه وأولويته وفعلًا واضحًا من أول شاشة، من دون لوحة أرقام تدّعي ما لا يعرفه النظام؟** المستخدم هو صاحب مشروع صغير يفتح Micro من الهاتف ويحتاج إلى اختيار فعل تشغيلي واحد قبل قراءة التفاصيل، مع فهم مصدر كل حقيقة وحدودها.

## حدود القرار

Home ليست Dashboard مالية ثانية وليست Finance أو Orders مختصرة. لا تعرض صافي ربح المشروع، أو قيمة المشروع، أو رسومًا بيانية، أو KPI عامة، أو توصية آلية، ولا تضيف CRM أو POS أو Sync أو Auth أو Billing أو Calendar أو reminders. لا يضيف القرار مخزنًا جديدًا، ولا يغير دلالات المال أو التاريخ أو الوقت، ولا يقرأ IndexedDB مباشرة من React.

## عقد أول viewport

يجب أن يعرض أول viewport، بترتيب بصري واضح وعلى عرض 360–430 بكسل، اسم النشاط، التاريخ المحلي الحالي، أولوية تشغيلية واحدة، CTA رئيسيًا واحدًا، وtruth line قصيرة. تكون الأولوية مشتقة من بيانات محلية قائمة، ويكون الـCTA مسارًا حقيقيًا مثل «طلب جديد» أو «استأنف المسودة». لا يُعرض زر وهمي أو CTA ثانٍ ينافس القرار الرئيسي.

## الحقائق المالية الأربع

تُعرض أربع حقائق مستقلة: الكاش المسجل، لي عند العملاء، عليّ للموردين، ومال المالك. كل حقيقة تحمل قيمتها بوحدة JOD، ومصدرها، والفترة أو تاريخ القراءة، وحالة المعرفة. قيمة `known` فقط تُعرض كرقم؛ `incomplete` و`not_initialized` لا تتحولان إلى صفر، بل تعرضان «غير مكتمل» أو «غير مهيأ» مع سبب وفعل تالٍ عند الحاجة. لا تغير Home العلاقة بين الكاش والتحصيل، أو الدين والربح، أو مال المالك والمبيعات/المصاريف.

## طبقة الانتباه

تعرض Home بحد أقصى ثلاثة عناصر فعلية مرتبة بالأولوية. الأنواع المسموح بها هي مسودة، طلب مرحلي، تحصيل أو دين، متابعة، سعة، أو نقص بيانات تكلفة. كل عنصر يذكر عنوانًا، وسبب ظهوره، وCTA حقيقيًا. تُزال العناصر المكررة بالمعرف، ولا يُستعمل رقم عام أو alert غير قابل للفعل. عند غياب العناصر تظهر حالة هادئة مع CTA الرئيسي بدل مساحة أرقام فارغة.

## الوحدات الاختيارية والتغيرات

لا تظهر وحدة المخزون، أو الجدول، أو التزامات الموردين، أو نتيجة الفترة إلا إذا كانت متاحة أو لها إعداد ذي صلة. الوحدة الفارغة بلا بيانات لا تظهر؛ الوحدة `needs_setup` قد تظهر فقط مع CTA إعداد واضح. تعرض Home آخر 3–5 تغيرات مفيدة فقط، لا سجل الأحداث الكامل، مع الحفاظ على رابط فعلي ومعلومة تاريخ محلي.

## التخصيص والحدود

يمكن اختيار نقطة البداية المعتادة أو إظهار الوحدات المفعلة فقط، لكن لا توجد widgets حرة ولا وسيلة لإخفاء تحذير حرج. أي تخصيص يجب أن يمر عبر تفضيلات قائمة ومحدودة، وأي نقص حرج يبقى ظاهرًا. لا تنشئ H01-A تفضيلًا جديدًا قبل أن يثبت H01-B الحاجة إليه.

## عقد الـView Model

ينفذ `buildHomeControlCenterViewModel` تحويلًا نقيًا من مدخلات Application جاهزة إلى نموذج عرض. النموذج يحفظ اسم النشاط والتاريخ المحلي وtruth line والـCTA الرئيسي والحقائق الأربع، ويضمن أن القيم غير المعروفة `null`، وأن الانتباه لا يتجاوز ثلاثة عناصر ولا يكرر المعرف، وأن الوحدات الاختيارية الفارغة لا تظهر، وأن التغيرات لا تتجاوز خمسة. لا يحتوي النموذج على استدعاءات تخزين أو آثار جانبية.

ينفذ H01-B خدمة Application تجمع البيانات من `PrototypeLocalStore` والخدمات القائمة فقط، ثم تمررها إلى هذا النموذج. لا يُسمح بربط React بـIndexedDB مباشرة، ولا بإعادة حساب أو تسمية حقائق تختلف عن خدمات Finance وFinancialPulse وDailyFollowUp القائمة.

## اختبارات القبول لـH01-A/H01-B

| الحالة | النتيجة المطلوبة |
| --- | --- |
| حقيقة معروفة | تظهر قيمة JOD، المصدر، الفترة، والحالة المعروفة |
| حقيقة ناقصة أو غير مهيأة | لا تظهر كصفر؛ يظهر سبب أو إعداد مناسب |
| عناصر انتباه كثيرة أو مكررة | تُرتب بالأولوية، تُزال المكررات، وتُقص إلى ثلاثة |
| وحدات اختيارية بلا بيانات | تختفي ولا تُنشئ widget فارغة |
| وحدة اختيارية ذات إعداد ذي صلة | تظهر بدعوة إعداد واضحة فقط |
| تغيرات كثيرة | يعرض النموذج آخر خمسة مفيدة كحد أقصى |
| لا انتباه | حالة هادئة مع CTA حقيقي |
| بيانات مالية في Home | لا تُسمى ربحًا، ولا تُخلط مع التحصيل أو الدين أو المخزون |
| الوصول إلى البيانات | يتم عبر Application/service؛ لا تماس React مباشر مع IndexedDB |

## ما يبقى لـH01-B

تُنفذ في H01-B خدمة القراءة، تحويل البيانات الحقيقية، واجهة Home phone-first وRTL، الوحدات المشتقة المحدودة، المسارات الفعلية لكل CTA، والحالات الجديدة/المسودة/الطلب الجاهز/الدين/المتابعة/السعة/البيانات الناقصة. تؤكد H01-B عدم وجود أثر مالي من القراءة، وتختبر Light/Dark وkeyboard/focus وreload على Chromium؛ أما قبول الهاتف الحقيقي وoffline وPilot فليسا ضمن H01-B.
