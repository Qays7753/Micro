# قرار واجهة V5: تسمية صادقة ورجوع آمن

## سؤال القرار

**هل يشرح كل label وزر ما سيفعله فعليًا، وهل أستطيع الرجوع أو الحفظ من دون وعد مضلل أو فقد عمل؟**

## القرار

تستبدل الواجهة كلمة `English` التقنية الظاهرة للمستخدم بصياغة عربية قصيرة مثل **أرقام 0–9**، مع بقاء إدخال ASCII والتحقق والسلوك العددي كما هو. لا يصف النص تنفيذًا داخليًا أو اسم طبقة برمجية.

يستخدم زر الرجوع في Draft نمط حماية التعديلات غير المحفوظة الموجود في التطبيق: عند وجود تغييرات يظهر خيار احفظ واستمر أو اخرج دون حفظ أو إلغاء، ومن دون حفظ صامت. يبقى **حفظ المسودة** فعلًا ثانويًا، ويظل **احسب التكلفة** الفعل الأساسي عندما تتوافر متطلباته.

يوضح Settings المظهر الحالي والفعل التالي الفعلي، بينما تبقى أيقونة الرأس اختصارًا accessible لا إعدادًا غامضًا مكررًا. تختصر Suppliers وCatalog وAgreement التفسير المتكرر خلف «لماذا؟» أو صياغة موجزة، مع إبقاء الحقيقة المالية وحدود المعرفة والاستعادة. لا يُعدل Orders ما لم يثبت من markup أو keyboard وجود targets متداخلة أو ترتيب focus غير منطقي.

## حدود عدم التغيير

لا تغيير في الخط أو palette أو design system أو آلية الأرقام أو Domain المالي أو Schema أو Export/Import أو حدود local-first. لا تغيير في معنى العربون أو Snapshot أو التكلفة، ولا إضافة Auth/Sync/cloud أو ميزات تشغيلية جديدة.

## معيار القبول

لا يظهر وصف تقني للمستخدم، ولا يظهر زر رجوع يحفظ ضمنيًا، ولا تتكرر بطاقات أو نصوص تفسيرية قبل الفعل الأساسي. تبقى RTL وLight/Dark مفهومة ومتباينة، وتظل حدود المعرفة والصدق المالي ظاهرة عند الحاجة.

## التحقق

تُراجع الصفحات المعدلة بالاختبارات المناسبة وفحص typecheck/build وQA محلي اصطناعي للمسودة، الرجوع، الحقول الرقمية، Settings، Suppliers، Catalog، Agreement، وOrders. لا تُسجل هذه المراجعة قبولًا لجهاز فعلي أو Android/iOS أو Offline أو Pilot أو Production.
