# مسودة أمر UXR-01 — جاهزية الرئيسية والتجهيز

**الحالة: READY_TO_LAUNCH_AFTER_OWNER_MESSAGE.** هذا أمر UXR-01 المنشور؛ لا يبدأ كود قبل إنشاء Claim صالح والتحقق من الفرع والرأس. الدفعة الأولى وحدها.

## دورك والمنتج

أنت مهندس React/TypeScript وLocal-first في ZAI، والمنفذ الوحيد لكود المنتج في هذه الدفعة. Micro تطبيق ويب للهاتف لأصحاب المشاريع الصغيرة والمنزلية في الأردن؛ عربي RTL وأرقام 0–9 وعملة د.أ. يخزن محليًا بـIndexedDB خلف خدمات Application. لا Auth أو Cloud أو Sync أو AI الآن. Manus هو المراجع المستقل؛ ChatGPT غير مطلوب. لا تقبل عملك بنفسك ولا تدمج main.

المستودع: https://github.com/Qays7753/Micro . ابدأ بالتحقق من main وbranch وbase وClaim المنشورة في الأمر النهائي. المرجع عند إعداد المسودة `111cd9dd3ffa8ee78b951fd4394b11b6b3cb0521`، وليس ضمانًا لرأس التنفيذ لاحقًا. إذا تغير الرأس صالح الفروق ذات الصلة، دون جرد النظام من البداية.

## القراءة وبطاقة الفهم

ابدأ `AGENTS.md` واتبع جدول القراءة والسلطة الحي، ثم Claim وOperations Control المرتبطين بالأمر. حزمة المهمة بعد نشرها في `docs/implementation/micro-product-remediation-20261105/`:

- 00 و01 للسياق والحدود.
- 04 لبطاقات F-001 وPERF-001 وPERF-004 فقط.
- 05 لبيت التجهيز، و06 لتجربة A01 وقبول الأداء.
- بطاقة UXR-01 ومراجع العقود والمهارات التي يوجه إليها AGENTS حسب الملفات الفعلية.

هذه قائمة إحالات للمهمة، وليست جدول قراءة ينافس AGENTS. لا تحمل كل التقارير التاريخية دون سبب.

قبل الكود: نفذ تحققات Git وControl، وافحص التداخل، وثبّت بطاقة الفهم: المستخدم ومهمته، النطاق وخارجه، الملفات والدوال والاختبارات، ثوابت المال، السبب المرجح وحدود الدليل، القبول، أثر schema/export، آخر التزام آمن للتراجع، وما بقي مجهولًا. افتح الكود؛ التقرير لا يثبت نسخة تغيرت.

## المشكلة

المالك يرى «جارٍ تجهيز مشروعك…» ثم قد تعمل الرئيسية لاحقًا. رصد تقرير الأداء REV1 عدم الجاهزية ضمن 30 ثانية في عدة محاولات، لكن ملفات القياس الخام القديمة غير مرفقة. ظهر في المصدر استخدام `homeControlCenterService` داخل قيمة useMemo دون اعتمادية مقابلة، واستيراد ديناميكي دون مخرج رفض في عدة مواضع. هذه قرائن وحقائق مصدرية؛ لا تسم سببًا واحدًا مؤكدًا لكل تأخر أو تدع تعليقًا أبديًا قبل التتبع.

## التنفيذ المحدد

1. أعد إنتاج الإقلاع كاملًا في حالة فارغة وببيانات اصطناعية، بلا كتابة بعد التحميل. سجل خطًا زمنيًا آمنًا: بدء تجهيز الخدمة ونهايته، نشرها في السياق، بدء قراءة Home ونهايتها، وأول محتوى موثوق وفعل قابل للعمل.
2. تحقق من اعتماديات memo وeffects وقيم السياق وعمر الخدمات. أصلح السبب المثبت بأقل تغيير موضعي في `app/PrototypeServicesContext.tsx` و`pages/Home.tsx` وما ثبت اتصاله المباشر. لا eager لكل الخدمات، أو reset للبيانات، أو رفع dataVersion بكتابة مالية، أو تأخير ثابت، أو جاهزية كاذبة.
3. عالج رفض التحميل أو التجهيز والمستهلكين المتأثرين بخطأ صريح وإعادة محاولة فعالة. إن كان استيراد URL نفسه بعد فشل غير ممكن في متصفح معين، استخدم إجراء استعادة آمنًا مطابقًا لعقد تحديث التطبيق؛ لا زر retry لا يغير شيئًا. جرد المواضع المتصلة دون تغيير 15 مسارًا عشوائيًا.
4. أثبت حالات منفصلة: import rejection، رفض Promise إعداد الخدمة، نتيجة قراءة فاشلة، retry ناجح في ظروف سليمة يوصل إلى Home جاهزة؛ stale result بعد unmount أو محاولة أحدث يُهمل، ولا تنشأ قراءات مكررة. افصل الفشل عن الفراغ. لا تسجل مبالغ أو أسماء أو بيانات شخصية أو استثناءات خام. التشخيص المحلي ضمن حقوله المقيدة فقط؛ اختبر ببيانات اصطناعية.
5. اكتب فحوصًا للسبب والإقلاع والرفض والاستئناف والحالات. إن لم يتكرر العيب، قارن البيئات وأثبت حدود الدحض؛ لا إصلاح متخيل ولا إغلاق من تنقل SPA بعد كتابة.

## خارج هذه الدفعة

لا إعادة تصميم صفحات أو نصوص عامة، ولا إصلاح لوحة المالية أو المصروف، ولا تغيير خط أو ألوان أو الثيم الحالي أو CI، ولا نقل ملفات أو تقسيمها أو تنظيم بنيوي أو ميزات أو سحابة، ولا تعديل معادلة مالية أو schema/export. مرجع مسح S11 لا يمنح إذن تنفيذ موجة S-1..S-5؛ أي حاجة بنيوية جديدة تُسجل وتنتظر قرار المالك. هذه دفعة جاهزية واحدة.

## فحوص القبول والتسليم

- إقلاع كامل فارغ وممتلئ دون كتابة، ثم عودة SPA وفتح عميق؛ النجاح لا يعتمد على حدث تسجيل.
- رفض شظية وفشل قراءة وإعادة محاولة وشبكة متقطعة وتشغيل دون شبكة بعد التهيئة؛ لا تحميل دائم بلا مخرج فشل أو نجاح كاذب.
- قياس جاهزية المحتوى والفعل قبل/بعد بنفس البيئة والعينات المعلنة؛ لا LCP الإعداد بديلًا للرئيسية ولا حكم جهاز بلا اختبار.
- لا أحداث مالية جديدة أو أرقام قديمة بعد تغير dataVersion أو الاستعادة أو الجيل؛ لا تسريب أو قراءات متكررة عند العودة.
- شغل الفحوص المركزة والبوابات الحالية المطلوبة من package.json وAGENTS. لا تختزل pnpm check أو ترفع الميزانية لتنجح.
- سلّم تقرير Markdown: base/candidate، commits والملفات، السبب المثبت، القياسات الآمنة، الاختبارات وما لم ينفذ، أثر المخطط والتصدير، التراجع، الحالة والخطوة التالية.
- حدّث مصدر Control والحالة واللوق وفق الأمر، ولا تعدل generated يدويًا أو تنشئ tracker منافسًا. ارفع التغييرات للفرع المحدد بصلاحية مأذونة إن أتيحت، دون حفظ رمز الوصول.

**نقطة الوقف:** بعد تسليم UXR-01 على candidate معلوم. لا تنفذ UXR-02 ولا تقبل أو تدمج main؛ يسلّم العمل إلى Manus لمراجعة مستقلة خفيفة على الرأس نفسه ثم ينتظر قرار المالك. لا يتطلب ChatGPT.
