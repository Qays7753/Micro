# المحتوى ومعايير التطبيق والقبول

## 1. قاموس النصوص الحرفية

البديل يستخدم فقط عندما يطابق المعنى. لا search/replace عام؛ يثبت كل مستهلك وحالته في diff.

| COPY-19 | قراءة موحدة بلا أثر مالي | المتابعة | عند كون المهمة متابعة؛ لا تسمية كل قارئ متابعة |
| COPY-20 | مُدار من activatedOn | متابعة المخزون منذ … | لا «آخر جرد مؤكد» |

| COPY-24 | storage_stale | تغيرت البيانات. راجع أحدث القيم ثم حاول مجددًا. | بلا كتابة أو reset صامت للمدخلات |
| COPY-25 | حصة التخزين | مساحة التخزين غير كافية لإتمام العملية. | لا ادعاء أنه الخادم؛ دليل معالجة قابل للتنفيذ دون مسح آلي |
| COPY-26 | جارٍ تجهيز المشروع | جارٍ تجهيز مشروعك… | أثناء عملية حقيقية؛ الفشل له حالته وليس تحميلًا دائمًا |
| COPY-27 | فشل الرئيسية | تعذر تحميل مشروعك | «إعادة المحاولة» مع بقاء تنقل سليم إذا أمكن |
| COPY-28 | رصيد بداية | رصيد البداية ليس إيرادًا ولا إضافة من المالك. | عند إدخال الافتتاح، لا في كل زيارة للنقد |
| COPY-29 | تحويل | ينقل النقد بين المحافظ دون تغيير إجمالي النقد. | قبل أول تأكيد/شرح التحويل حسب الحاجة |
| COPY-30 | استهلاك أصل | الاستهلاك يخفض نتيجة الفترة ولا يسحب نقدًا. | عند الاستهلاك أو تفسير أثره |
| COPY-31 | تخصيص زائد | تخصيص النقد غير مطابق | «راجع توزيع النقد»؛ التفاصيل تحفظ علاقة التصحيح/العكس المطلوبة، لا عكس تلقائي |
| COPY-32 | تحقق شامل للبيانات | لم نكتشف مشكلة ضمن الفحوص المنفذة. | مع عدد النتائج وأنواعها ونطاقها |
| COPY-33 | استعادة/استيراد ملف | استعادة نسخة | الاستبدال الكامل فقط؛ ملف البداية يسمى «استيراد بيانات البداية» |
| COPY-34 | مزامنة | لا تستخدمها للحفظ المحلي | «حفظ»؛ لا إيحاء بسحابة غير موجودة |
| COPY-35 | المزيد عام وغامض | كل الوظائف/عرض التفاصيل/عرض المزيد | بحسب الفعل الحقيقي؛ ليس عنوان وجهة غامضًا |

**قواعد المصطلح:** هامش الربح = الربح÷سعر البيع، والزيادة على التكلفة = الربح÷التكلفة؛ المصطلحان ليسا مترادفين. المصروف المستحق ليس سدادًا، والشراء ليس تكلفة بيع تلقائيًا لكل مادة متتبعة، والعربون ليس ربحًا تلقائيًا. لا تجعل «سجل» و«كشف» و«دفتر» أسماء متبادلة لنفس المهمة دون سبب.

**قواعد الصياغة:** فعل ثم مفعوله في الأزرار، اسم واضح في العناوين، خطاب عربي مهني مبسط، لا اعتذار أو مقدمة في كل شاشة، لا وعد «ذكي/دقيق 100%/كل شيء تمام» بلا دليل. تُراجع صياغة الأعداد والمفرد والجمع، والأسماء الطويلة، والمصطلحات المترجمة بمعناها لا صوتها.

## 2. SOP التصميم والمحتوى — يطبق على كل صفحة

| المعرف | المعيار | ما يثبت النجاح |
|---|---|---|
| SOP-01 | لكل صفحة مهمة وفعل أساسي ومصدر بيانات معروف | يمكن وصفها بجملة، والتفاصيل لا تزاحم الفعل |
| SOP-02 | عنوان واحد واضح، دون تمهيد معماري مكرر | لا «وجهة» فوق كل H1، وسياق الرجوع ظاهر |
| SOP-03 | كل نص له فائدة حالية أو شرط أو موطن تفصيل | قائمة الحالي→البديل→الشرط→الموطن؛ لا حذف كلمة لمجرد العدد |
| SOP-04 | تفسير عام عند الطلب، والتحذير المؤثر عند القرار | لا صندوق دائم لكل شرح ولا رمز! يخفي الخطر |
| SOP-05 | لكل إزالة/دمج سبب ومالك وجهة بديلة | خريطة نقل وقدرة ما زالت تعمل |
| SOP-06 | القيم مع الاسم والفترة/الوحدة وحالة المعرفة عند الحاجة | معلوم 0 ≠ غير مسجل ≠ غير متاح ≠ تقدير |
| SOP-07 | التراتب بصري قبل الزخرفة | الفعل والرقم المقصودان يبرزان، ولا شبكة بطاقات متطابقة لكل شيء |
| SOP-08 | تبويب الوجهات يختلف عن مفتاح العرض والتصفية | الـ 5 وجهات محفوظة؛ radio القائمة/التقويم مختصر، والتصفية زر مخصص |
| SOP-09 | لمس وكتابة عربية مريحان | الأهداف الحرجة 44px على الأقل كهدف تصميم للويب، دون تداخل؛ مدخل النص 16px إذا وافق نظام UI وظهر لزومه على iOS |
| SOP-10 | CSS/shared primitives مالك المظهر | لا hex/namespace/زر محلي موازٍ أو استيراد fixture |
| SOP-11 | الرجوع والإغلاق والإلغاء مفهومة وتحفظ السياق | back الجهاز/المتصفح/الواجهة، Escape، مسودة معدلة، إعادة تحميل |
| SOP-12 | الحالة الصادقة قبل الرسالة الجميلة | loading/error/empty/no-results/partial/known0/negative/success منفصلة |
| SOP-13 | لا تسجيل أو أثر مالي بفتح قارئ أو تقويم | تحقق الحالة قبل/بعد القراءة والرجوع |
| SOP-14 | العميل والمورد والمخزون لا يفرضون خارج حاجتهم | بيع/شراء مدفوع دون جهة، والجهة القديمة لا تعاد كتابتها |
| SOP-15 | الأرقام LTR داخل RTL دون انقلاب الإشارة/الوحدة | مبالغ سالبة وكبيرة وتواريخ وأسماء طويلة على الهواتف الثلاثة |
| SOP-16 | التمرير والكيبورد والـ safe-area جزء من العقد | آخر إجراء والتركيز والخطأ لا تحجبها chrome/keyboard |
| SOP-17 | أداء مقاس في البيئة والبيانات نفسها | جاهزية الشاشة والفعل والحفظ، لا LCP/setup كبديل للرئيسية |
| SOP-18 | معيار إضافي: أي خلل غير مغطى لا يتجاهل | يصنف NEW/DEEPENS/DUPLICATE/REOPENED/FALSE_POSITIVE، يربط بمالكه وقبوله قبل الإغلاق |
| SOP-19 | لا يتحول معيار عددي إلى هدف شكلي | لا حد إجمالي للشاشات/الكلمات، ولا إخراج الأرقام دون شرطها ليقصر العرض |
| SOP-20 | اختبار بصري في المنتج قبل قبول UI | قبل/بعد في المقاس والبيانات نفسيهما؛ DOM/CI لا يكفيان |

## 3. مرجع المعيار مقابل الإرشاد مقابل قرارنا

| النوع | المرجع الرسمي | تطبيقه هنا |
|---|---|---|
| معيار ويب قابل للاختبار | [WCAG2.2](https://www.w3.org/TR/WCAG22/): 1.4.3، 1.4.4، 1.4.10، 2.4.6، 2.4.11، 2.5.8، 3.3.1، 3.3.2، 3.3.4، 4.1.3 | تباين وقراءة وتكبير وإعادة تدفق، تسمية وتركيز ولمس، أخطاء ومنع أخطاء المال وحالة الإجراء. لا ندعي مطابقة شاملة |
| توضيح مستوى | WCAG2.5.8 هو 24×24 CSSpx مع الاستثناءات؛ 2.5.5 هو 44×44 لمستوى AAA |44px هدفنا المريح، وليس تعريف الحد AA في كل الحالات |
| إرشاد ويب غير تشريعي | [WAI APG Radio](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) و[Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) | نستخدم radio أصليًا أو عقد اختيار كامل؛ aria وحده لا يصنع لوحة مفاتيح سليمة |
| إرشاد منصة | [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) و[Android Touch Targets](https://support.google.com/accessibility/android/answer/7101858?hl=en) | Apple44pt و Android48dp إرشادان للراحة؛ لا نساوي وحداتهما آليًا بـ CSSpx |
| قرار منتج | هذه الحزمة ونمط Micro | فهرس المالية، اختصار المقدمة، إبقاء التنقل، النبرة المهنية؛ ليست أوامر WCAG |

الأولوية تقليل الحاجة للفهم المسبق، مع عدم إخفاء أثر مالي أو قرار يتطلبه العقد. دعم قارئ شاشة وتكبير على جهاز فعلي يحتاج اختبارًا، لا يكفي ذكر السمات في الكود.
