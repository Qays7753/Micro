# تكليف مانوس — مراجعة ونشر حزمة UXR

## المطلوب الآن

استلم هذه الحزمة باعتبارها إنهاء إعداد برنامج تحسين Micro بعد S01–S18. لا تطلب إعادة تحليل شامل من ZAI، ولا تنفذ كود منتج، ولا تغير الهوية أو CI. راجع اكتمال حدودها وتبعياتها ثم انشر مراجع المنفذ وأمر أول دفعة فقط بأسلوب الأوامر المستقلة المعتمد بيننا.

## خطواتك

1. ثبّت `origin/main` الحي وقارن مع `111cd9dd3ffa8ee78b951fd4394b11b6b3cb0521`. افحص PRs والـ Claims والحالة الحية. حالة docs القديمة لا تطابق الدمج الحالي؛ لا تعتبرها VERIFIED أو تسمح بتجاوزها. شغل Control validator وفق `AGENTS.md` وصالح مصدر الحالة واللوق و Item/Claim وتوليد Views.
2. اقرأ الحزمة عبر 00 ومواضيع الدفعة، ثم طابقها مع العقود ومواضع الملفات الحية. لا تستبدل توصياتها بتصحيحات N13/نتيجة الطلبات القديمة المسحوبة. مصادر الهوية الحالية/المستقبلية تصالح؛ لا نسخ لتنسيق المعاينة إلى runtime.
3. أنشئ فرع تكامل واحد جديد من main الحي حسب الاتفاق، بعد حسم التداخل والـ Claims، و Draft PR واحدة إذا وافق البروتوكول الحي. لكل دفعة commits مستقلة؛ التصحيحات إضافية بلا إعادة كتابة التاريخ. لا main write أو دمج تلقائي.
4. انشر محتويات `package/` في `docs/implementation/micro-product-remediation-20261105/` كحزمة تنفيذ مفوضة، وسجّلها بالفهرس canonical. لا تصبح `sources/` سلطة أعلى من العقود، ولا تنشر private-helper أو بيانات/أسرار. `AGENTS.md` يبقى جدول التوجيه الوحيد؛ هذه حزمة مهمة يحيل إليها الـ Claim.
5. اربط ملفات UNIT الأصلية النطاقية بالتعديلات التي تحل محل تعليمات العرض فيها، دون نسخ 45 ملفًا أو إعلان تطابقها المالي تلقائيًا. أعد استعمال العمل الصحيح ولا تعيد تنفيذ الوحدات من الصفر.
6. استخدم مسودة `stages/UXR-01-EXECUTION-PROMPT-AR.md` لإصدار **أمر UXR-01 فقط** بأسلوبك المعياري، مع base/branch/Claim وروابط SHA ثابتة ونطاق ووقف وأدلة. لا تكتب أوامر جميع الدفعات مقدمًا؛ كل أمر مستقل عن المحادثة السابقة ويحمل مراجعه المنشورة وقت إصداره.
7. سلّم روابط الحزمة والأمر ورأس النشر، وملاحظاتك المصنفة عائق/تصحيح/ملاحظة، وحالة Control، وأمر تشغيل قصير للمالك ينسخه إلى ZAI. يراجع Manus أمر 01 ومراجعَه بنفسه؛ لا يشترط ChatGPT. أي تغيير يلمس معنى المال أو الهوية أو البنية يخضع لباب القرار المحدد في البرنامج، ولا يتوسع النطاق.

## ضمان الاستقلال عن Drive والمحادثات

ZAI يبدأ بمحادثة جديدة، لا يعرف Micro ولا يملك Drive. أمره المنشور يشرح المنتج ودوره والمرحلة ويحدد قراءة AGENTS ثم Claim والمراجع الدقيقة. لا يحتاج اعتمادًا لقراءة مستودع عام. اعتماد الكتابة إن وفره المالك يستخدم في آلية آمنة ضمن نطاقه؛ لا يكتب في ملف أو prompt أو commit أو log، ولا يطلب إعادة إرسال رمز مكشوف قديم.

## حدود الإغلاق في هذه الدفعة 00

PASS يعني نشرًا متحققًا ومصالحة فعلية للحالة والـ Claim ومراجعة مسودة 01، لا نجاح البرنامج كله. احتفظ بحالتَي PLANNING_COMPLETE و CODE_NOT_STARTED منفصلتين. ملاحظات البوابة الخارجية مثل الجهاز و PRE-PILOT لا تمحى. أعط المالك الخطوة العملية التالية مباشرة؛ لا سلسلة موافقات لغوية أو تقرير عام جديد.
