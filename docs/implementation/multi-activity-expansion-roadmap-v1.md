لا ننتقل من Prototype الحرفة مباشرة إلى «دعم كل المشاريع». الترتيب يحمي النواة من الاستثناءات ومن التوسع في واجهات لا يستخدمها أحد.

```text

→ G15 قبول الهاتف والإنتاج

→ Pilot قطاعي محدود
→ تركيب نشاطين عند دليل مشروع مختلط

```

## 3. كيف يختار Profile الأول؟

لا توجد أولوية ثابتة للطعام أو الخدمات أو الزراعة أو السياحة. بعد G16 يسجل القرار في جدول مرجح:

| معيار | السؤال |
|---|---|
| الضرر | هل تتكرر خسارة/خلط/تأخر يمكن أن تمنعه النواة الحالية؟ |
| قوة الدليل | هل لدينا Pilot أو دراسة قطاعية أو ملاحظة متعددة لا رأي واحد؟ |
| وضوح Slice | هل يمكن أن نعرّف واقعة واحدة ونتيجة وفعلًا بدون بناء نظام كامل؟ |
| خطر الحقيقة | هل يمكن حماية الكاش/الربح/المخزون والتاريخ من دون افتراضات خفية؟ |
| قابلية الاستخدام | هل يقل الإدخال أو يزيد الفهم بدل إضافة قالب جديد؟ |
| قابلية التركيب | هل يخدم نشاطًا مختلطًا دون توزيع/حجز/تكامل غير صادق؟ |

يجب أن يفوز Profile واحد بالقرار؛ إن لم يفز أي Profile بوضوح، يبقى مؤجلًا وتتحسن النواة بناءً على دليل G16.

## 4. تعريف الكمال الواقعي

لا تعني «الكمال» أن Micro يملك كل Module. تعني أن كل سياق مدعوم يفي بهذه القواعد: واقعة مفهومة، أقل إدخال، معنى مالي صحيح، معرفة ظاهرة، تاريخ قابل للتدقيق، قرار تالٍ، اختبار هاتف، ودليل ميداني. أي Profile لا يحقق هذه الشروط لا يسمى مدعومًا بعد.
