# مطابقة عقود الشريحة مع Domain Core

## الغرض

هذا الملف هو جدول المطابقة التنفيذي بين عقود المجال وسلوك النواة الحالية. لا يضيف متطلبات منتج جديدة؛ بل يوضح ما هو مطبق، وما هو مؤجل عمدًا إلى طبقة الهاتف أو التخزين أو SaaS.

| العنصر | العقد يقول | الكود الحالي | القرار |
|---|---|---|---|
| موعد التسليم | جزء من اتفاق الطلب ويجب أن يقود الفعل التالي | غير موجود في `CraftOrder` المحلي | مؤجل إلى Prototype الهاتف وعقد التخزين؛ لا يُوصف بأنه مطبق في النواة |
| agreement source | مصدر الاتفاق جزء من سياق الطلب | غير موجود في `CraftOrder` المحلي | مؤجل إلى طبقة الطلب/التخزين، مع بقاء المواصفات وسجل الأحداث مطبقين |
| workspace ownership | عزل ملكية السجل مطلوب في SaaS | لا يوجد `workspace_id` أو Auth أو RLS في Domain Core | مؤجل صراحة إلى حدود SaaS؛ ممنوع إدخاله ضمن هذه المهمة |
| on_hold | إيقاف الطلب بسبب مادة أو قدرة يحتاج حالة وفعلًا تاليًا واضحين | لا توجد حالة `on_hold` في `OrderStatus` المحلي | مؤجل إلى عقد Use Case مستقل؛ لا يُعاد استخدام `needs_review` بدلًا منه |
| customization | التخصيص يجب أن يؤثر في المواصفات والتكلفة والنسخة | `specifications` و`reviseOrderCost` ينشئان Snapshot جديدًا وحالة `needs_review` | مطبق على مستوى شريحة الحرفة الحالية، دون BOM أو Activity Profile قطاعي جديد |
| calculation version | مقارنة الحسابات عبر الإصدارات تحتاج نسخة قواعد | غير موجودة في `CostSnapshot` | مؤجل؛ لا يجوز ادعاء مقارنة نتائج عبر إصدارات مختلفة |
| cost knowledge state | يصف صدق مدخلات التكلفة وحداثتها وتغيرها | `known` و`estimated` و`variable` و`incomplete` و`stale` مطبقة وقابلة للاختبار؛ `partial` نوع محفوظ للمرحلة اللاحقة | مطبق جزئيًا بوسم صريح؛ لا تستخدم `partial` في مسار لا يملك سياسة إدخالها بعد |
| craft missing time | غياب وقت الحرفة المؤثر يمنع ادعاء نتيجة نهائية معروفة | `time === null` أو وقت معروف بدقائق/سعر ساعة صفري يصنف Snapshot الحرفة `incomplete`، وتبقى النتيجة بلا ربح نهائي | مطبق ومختبر؛ لا يُفترض أن غياب الوقت أو صفره يساوي تكلفة عمل مكتملة |
| revision quantity match | تعديل التكلفة يجب أن يبقى مرتبطًا بكمية الطلب الأصلية | `reviseOrderCost` يرفض Snapshot بكمية تختلف عن `order.quantity` | invariant مطبق ومختبر |
| post-delivery review guard | لا يعاد فتح طلب مسلّم أو تغيير نتيجته بصمت | دخول الطلب المسلّم إلى `needs_review` يحجب الربح، ويمنع `transitionOrder` و`cancelOrder` و`reviseOrderCost` والآثار المالية العامة من الخروج حتى Use Case تصحيح موثق | مطبق ومختبر على المسارات العامة؛ `correctDelivery` نفسه مؤجل |
| financial result status | يميز النهائي والتقديري والناقص والمراجعة المطلوبة | `CraftOrder.resultStatus` مطبق؛ لا يحسب `profitIndicatorMinor` إلا مع `known` عند التسليم/التسوية | مطبق |
| cancellation settlement | الإلغاء لا يحذف التاريخ، والعربون يحتاج ردًا أو احتفاظًا أو مراجعة | `cancelOrder` هو مسار الإلغاء المخصص، والانتقال العام إلى `cancelled` غير مسموح؛ يضع `needs_review` عند وجود عربون، وعمليات التسوية مستقلة وقابلة لإعادة المحاولة | مطبق ومختبر على المسارات العامة |
| deposit vs collection | العربون قبل التسليم، والتحصيل المتبقي بعد التسليم، والدين لا يزيد الكاش | `collectDeposit` و`collectRemaining` و`registerDebt` منفصلة مع حواجز الحالة | مطبق |
| historical snapshots | تعديل التكلفة لا يغير الماضي بصمت | `costSnapshots` يحتفظ بالنسخ، و`reviseOrderCost` يضيف نسخة جديدة؛ Snapshot ومدخلاته ومصفوفة التاريخ تُنسخ وتُجمّد، مع تحقق تطابق الكمية داخليًا | مطبق ومختبر، دون تخزين دائم |
| settlement transition events | كل تغيير حالة حساس يحتاج أثرًا تاريخيًا واضحًا | قبض المتبقي الكامل وتسجيل الدين، والدفع الكامل قبل التسليم، وRevision والإلغاء تضيف `status_changed` بوضوح `fromStatus/toStatus` | مطبق ومختبر داخل الكائن المحلي فقط |
| idempotency | كل أثر مالي حساس يعاد بأمان دون تكرار | الأحداث تحمل `idempotencyKey` غير فارغ، والفحص يميز نوع الحدث حتى لا يمنع مفتاح عملية مختلفة؛ ما زال محليًا داخل الكائن | مطبق ومختبر داخل الكائن المحلي فقط |
| أحداث المال العامة محليًا | الكاش والالتزامات ومال المالك تحتاج سجلًا مستقلًا عن الطلب | `FinancialEvent` و`ProjectFinancialService` وLocalStore محليًا تسجل الاستثمار والسحب والمصروف المدفوع أو المستحق وتسديد الالتزام مع idempotency | مطبق محليًا، وليس Ledger أو Workspace أو SyncQueue أو عزل SaaS |
| سياق المصروف التشغيلي | مصروف المشروع أو حصته المشتركة يحتاج علاقة وسلوكًا وغرضًا ودرجة معرفة، ولا يخلط بالسحب أو الشراء | `OperatingExpenseContext` يحفظ الحصة المشتركة الجديدة مع مصدرها: ثابت معلن أو تقدير مالك أو يحتاج مراجعة؛ وتبقى الحصص القديمة بلا مصدر صالحة وموسومة للقراءة | مطبق محليًا؛ لا توزيع على طلب أو منتج، ولا إجمالي فاتورة بيت، ولا أصل أو مخزون أو مورد بعد |
| شراء مواد ومورد ودفعة جزئية | شراء المواد يغير الكاش أو ذمة المورد، ولا يصبح مصروفًا أو تكلفة بيع قبل الاستهلاك | `SupplierPurchase` و`SupplierPurchaseService` يحفظان المورد والشراء والمدفوع والمتبقي ودفعات idempotent؛ `ProjectFinancialService` يضيفان أثر الكاش والذمة فقط | مطبق محليًا؛ يستلمه G4 صراحة كمخزون، ولا توجد مرتجعات أو خصومات أو ضريبة أو تصحيح للشراء نفسه |
| استمرارية الكاش ومحافظه | الافتتاح والتحويل والضبط والعكس تحفظ كأثر مستقل، ولا تتحول إلى دخل أو مصروف أو مال مالك | `CashWallet` و`CashContinuityEntry` و`CashContinuityService` تحفظ الافتتاح والضبط والتحويل المتوازن والعكس المسبب مع مفاتيح idempotency؛ `ProjectFinancialService` يجمع كاش المحافظ مع التدفقات غير الموزعة | مطبق محليًا مع IndexedDB schema 15 وexport v7؛ لا توزيع تلقائي لتحصيلات الطلبات أو المصاريف أو شراء المواد على المحافظ، ولا تسوية بنكية أو كشف حساب |
| مواد المخزون والاستهلاك والهدر | الافتتاح والاستلام يزيدان كمية وقيمة المادة، والاستهلاك لطلب والهدر والضبط والعكس تحفظ كحركات منفصلة؛ الشراء لا يصبح COGS تلقائيًا | `Material` و`InventoryMovement` و`InventoryMaterialService` تحفظ الكمية بأجزاء ألفية والقيمة بوحدات JOD الصغرى، ومتوسط تكلفة متحرك؛ تستقبل شراء G2 صراحة، وتمنع الرصيد السالب والعكس المكرر | مطبق محليًا مع IndexedDB schema 15 وexport v7؛ لا يغير `CostSnapshot` أو نتيجة الفترة، ولا يدعم وحدات محولة أو وصفات أو LOT/expiry أو مرتجع مورد أو POS |
| فرق المادة المنفذة للطلب | يقارن مادة Snapshot المخططة باستهلاك المادة المرتبط بالطلب، ويستبعد الاستهلاك المعكوس؛ لا يساوي وحده COGS كاملة أو ربحًا فعليًا | `InventoryMaterialService.readOrderActualMaterialComparison` يشتق المخطط والمنفذ والفرق من LocalStore عند القراءة، وتعرضه `OrderDetail` بحالة غير مسجلة أو تحتاج مراجعة؛ وتستخدم قراءة G3 الحركات المؤهلة فقط لمكوّن COGS الاختياري في الفترة | مطبق محليًا بلا Schema أو Export جديدين؛ لا يغير `CostSnapshot` أو سعر أو `recognizedCostMinor` أو هامش اسم العمل، ولا يحمل الهدر أو الوقت أو المصاريف العامة على الطلب |
| مؤشرات الفترة والربحية والتغطية والسيولة السابقة | تقرأ الفترة المسجلة حسب مصدر معلن، وتفصل هامش اسم العمل والتغطية والسيولة عن صافي الربح والذمم والمخزون | `ProjectFinancialService.readFinancialInsights` يشتق اسم العمل من طلبات `final`، وتركيب Snapshot، ومؤشر تغطية محافظ، وتغطية كاش بعد الالتزامات؛ لا يحفظ نتيجة جديدة | مطبق محليًا كـView Model سابق؛ لا يمثل سياسة G5 الجديدة ولا إعلان تحصيل/التزام قصير |
| نتيجة الفترة المسجلة | تجمع فقط الطلبات المسلّمة النهائية ومصاريف التشغيل العامة ضمن فترة معلنة، مع درجة معرفة | `ProjectFinancialService.readRecordedPeriodResult` يشتق الإيراد والتكلفة من طلبات `final` وفق يوم تسليم `Asia/Amman`، ويضيف دلتا المصروف التشغيلي عند `occurredOn` ويستبعد غير النهائي | مطبق محليًا كـ`recorded_only` أو `incomplete`؛ ليس صافي ربح نهائيًا أو دفتر فترة كاملًا |
| نتيجة الفترة الأوسع G3 | تفصل مصروف المشروع وحصة المشروع من المصروف المشترك والسجل القديم، وتقرأ COGS اختيارية من استهلاك مثبت مرتبط بعمل مكتمل، مع Snapshot كبديل معلن عند غياب الدليل وسبب نقص ظاهر | `ProjectFinancialService.readRecordedPeriodResult` يقرأ الحصة المشتركة مرة واحدة، ويستبعد الشراء والهدر والاستهلاك غير المرتبط أو المعكوس من COGS، ويستبدل مكوّن المواد فقط عند وجود استهلاك مؤهل مع إبقاء بقية Snapshot مرة واحدة؛ الرقم التشغيلي يبقى رقميًا في كل فترة صالحة، وتعرض Finance المصدر وحالة COGS والفعل التالي | مدمج على Bridge عبر PR #98 وPR #99؛ غير مدمج في `main`. لا COGS قانونية أو كاملة خارج الدليل المثبت، ولا توزيع على طلب/منتج أو ضرائب أو صافي ربح نهائي، ولا Schema/Export migration جديدة |
| كتالوج اختياري G4-A | نواة عامة للعمل المتكرر: `CatalogItem` متوافق، وحدات ذات بُعد، تحويلات مباشرة صريحة، وقالب مكونات/yield اختياري؛ دون كتابة تاريخية تلقائية أو أثر مالي | `CatalogItem` و`CatalogService` توسعا مع `unitId` الاختياري؛ `MeasurementUnit` للأبعاد الستة؛ `DirectConversion` بعامل موجب دقيق داخل البعد؛ `CatalogTemplate` بمكونات وyield وحالة readiness ومراجعة؛ React `/catalog`، Memory/IndexedDB، schema 24/export 15، وLocalTransferService كلها منفذة محليًا | منفذ على فرع G4-A تحت عقد `15-catalog-reference-prototype-contract.md`؛ اختبارات Domain/Application/Storage/Transfer تمر؛ لا SKU أو متجر أو مخزون منتج نهائي أو ربط تلقائي أو تكلفة/COGS أو إنتاج/إيراد، ولا قبول جهاز/Production/Pilot بعد |
| وقت ومدة الموعد G4-B | الموعد يملك يومًا ووقتًا ومدة فقط عند المعرفة، ويحتفظ بالتعديل ولا يغير المال | `ScheduleEntry` يحفظ زوج `scheduledTime/durationMinutes` أو `null/null`، وسجل `timing_changed`؛ schema 8 يرحل الموعد القديم إلى وقت غير محدد | مطبق محليًا ضمن حدود G4-B؛ لا نافذة تكرار أو موارد متعددة أو سعة مخزون |
| تعارض وقدرة الموعد | التقاطع وضغط السعة تحذيران لا حظر، وسعة اليوم اختيار مستخدم | `ScheduleService.overview` يشتق تقاطع الفترات المعروفة ويقارنها بسعة محلية معلنة؛ ويسوي الموعد إلى مكتمل عند حدث التسليم | مطبق محليًا على سبعة أيام، وليس dispatch أو حجزًا أو تقويم شهر |
| ledger/workspace/sync | يحتاج دفترًا عامًا وتخزينًا وعزلًا ومزامنة حقيقية | لا يوجد Ledger عام أو Workspace أو SyncQueue أو حالات `synced/conflict` | مؤجل عمدًا إلى مراحل لاحقة |

## حد النموذج المالي

الحقول `collectedMinor` و`receivableMinor` و`recognizedRevenueMinor` و`recognizedCostMinor` و`profitIndicatorMinor` تمثيل أولي على مستوى طلب واحد. سجل `FinancialEvent` المحلي يكمل الكاش والالتزامات ومال المالك، ونتيجة الفترة المسجلة تشتق مجموعة معلنة من الطلبات النهائية والمصروفات العامة. لا يحول أي من ذلك النظام إلى دفتر عام أو ربح مشروع نهائي أو مخزون أو فترة محاسبية كاملة.

## ملاحظات G4-A التنفيذية

| الضمان | الدليل الحالي | الحد |
|---|---|---|
| التاريخ والمال | إنشاء/تعطيل/مراجعة الكتالوج والقوالب لا يلمس الطلب أو `CostSnapshot` أو `recognizedCostMinor` أو الحركات المالية/المخزون؛ اختبار الهامش المسجل بقي على الطلبات المرتبطة صراحة | لا توجد مراجعة هاتف فعلي أو Pilot بشري |
| الوحدات والتحويل | الأبعاد `count/mass/volume/time/distance/area`، كميات `quantityMilli`، رفض cross-dimension والعامل غير الموجب أو غير الدقيق، وتعطيل غير حاذف | لا يوجد تحويل متعدد الخطوات أو كثافة أو اشتقاق عكسي تلقائي |
| القالب والعائد | `CatalogTemplate` اختياري؛ `not_configured` بلا yield، `ready` عند تطابق/تحويل مباشر، `needs_conversion` عند نقص التهيئة؛ مراجعة ذرية تحفظ المصدر | لا استهلاك أو Purchase أو COGS أو مخزون منتج نهائي |
| الاستعادة | migration من schema/export السابق يضيف `unitId: null` ومصفوفات فارغة فقط؛ تحقق العلاقات والعوامل والعائد قبل replacement الذري | لا مزامنة أو Cloud أو استعادة بين أجهزة |

## معيار القراءة

إذا تعارضت وثيقة مستقبلية مع هذا الجدول، يجب تحديث العقد وسجل القرار والاختبارات معًا. لا يجوز إضافة حقل مؤجل إلى واجهة مستخدم على أنه متاح في النواة قبل تنفيذ عقده واختباره.
