## 1. الأدوار وطريقة الفرع

| الطرف | مسؤوليته |
|---|---|
| المالك | اعتماد النطاق والمراحل والانتقال والدمج؛ توفير اعتماد ZAI خارج الأوامر والملفات |
| ChatGPT | المواصفات والتبعيات والمراحل؛ مراجعة الأوامر والمنتج والعربية والمنطق المالي والمعرفة والبيانات والرحلات؛ لا كود منتج |
| Manus | مراجعة الخطة والبنية؛ كتابة ونشر أمر المرحلة الحالية فقط؛ مراجعة التنفيذ والتخزين والمهاجرات والفحوص؛ نشر التوثيق |
| ZAI | كاتب كود المنتج الوحيد؛ تنفيذ أمر READY المثبت في GitHub، والاختبار والتسليم ثم التوقف |

ينشأ فرع تكامل جديد واحد من origin/main الحي عند بدء البرنامج. تثبت تسميته وقاعدة إنشائه في تكليف النشر؛ لا فرع من main لكل مرحلة. كل المراحل تكمل على الفرع نفسه، ولكل مرحلة commits واضحة لا تخلط نطاق مرحلتين. التصحيحات commits إضافية للمرحلة ذاتها؛ لا إعادة كتابة لتاريخ المراحل المقبولة.

لا كتابة مباشرة إلى main، ولا دمج بين المراحل. الدمج النهائي بموافقة المالك بعد مراجعة البرنامج. يحتاج هذا التنظيم مصالحة موثقة مع SOP الحالي في S01؛ هذا الملف لا ينسخ السياسة بصمت. إذا تغير main لاحقًا بعمل خارجي، يسجل الانحراف وطريقة إدخاله للتكامل واختباراته قبل الاستمرار.

## 2. مصدر الحقيقة والنسخ المجمدة

AGENTS نقطة الدخول والتوجيه الوحيدة. Operations Control للحالة والـClaims، وcurrent-state للحالة الحية. جدول المراحل يصف الخطة والروابط؛ لا يعتبر دليل تنفيذ ولا ينشئ Tracker منافسًا.

ملفات UNIT الـ45 في 02-SPECIFICATIONS نسخ تسليم مجمدة من الملفات القائمة، مع المحافظة على الأسماء والترقيم. لا تعدل نسخة تسليم وتترك أصلها دون فرق وتتبع. يثبت Manifest مصدر الموافقة ونسخة المصدر وبصمته وبصمة النقل بعد تحويل الروابط. ZAI يقرأ GitHub عند commit محدد؛ روابط Drive في provenance لا تفرض الوصول إليه. تغيير مواصفة بعد التجميد يحتاج نسخة وفرقًا ومراجعة أثر قبل تحديث أمر جارٍ.

مواصفتا 001 V3 و002 V5 في docs/product/components لهما سلطة مسجلة سابقًا. في S01 تسجل إحالة السلطة بينهما وبين نسخة التسليم الأحدث ضمن النطاق المعتمد؛ لا يبقى أصلان قابلان للتعديل، ولا يمحى المحتوى التاريخي. رقم V9 أو V11 وحده ليس إثبات أولوية: يسجل القرار الأحدث ومجاله وفرق المتطلبات. ولا يتحول وصف «مقترح» قديم إلى اعتماد تنفيذي لمجرد نقل الملف.

العقد المشترك وP3 والسياسات المعتمدة مدخلات تصميم، وتحتاج تسجيل نطاق سلطتها ومصالحة أي حكم حاكم متعارض قبل الكود. المخازن الأربعة المرشحة تمثيلات هندسية محتملة وليست أوامر إنشاء. كل تغيير دائم له تصميم ملموس ومهاجرة وتصدير ووارد ومهايئان واختبارات، واعتماد للأرقام المحروسة حيث يلزم. لا يعاد فتح PD-01 أوPD-02 أوACC-01 المحسومة؛ أي قرار عمل جديد غير محسوم يعرض باسمه وأثره ودليله.

## 3. حدود المنتج

العربية RTL والأرقام 0–9 والهاتف وLight Mode فقط؛ العمل على المنتج الفعلي، مع فصل الهوية ومكتبة UI وShowcase. مهمة بسيطة ومصطلحات مباشرة ومساعدة عامة عند الطلب؛ خطأ الحقل أو الأثر الضروري لاتخاذ القرار لا يخفى داخل أيقونة. المقاسات: 390×844 و360×800 و430×932، مع فصل المحاكاة عن دليل الجهاز الحقيقي.

النقد غير الإيراد وغير الربح؛ الدين غير النقد؛ المقدم لا يثبت ربحًا؛ مال المالك ليس بيعًا؛ المجهول غير 0 والتقريبي غير المؤكد. كل أصل وكاتب ومعادلة مشتركة لها ملكية واحدة. كل حذف أو دمج له سبب وبديل ومصير بيانات ومستهلكون وفحص قبول سلبي.

لا Auth أوCloud أوSync أوERP أو قروض جديدة أو تشغيل سوق أو حجز سيارة أوAskMicro. الخدمات القادمة تبقى ظاهرة بصدق وفق قراراتها. لا تعديل لسياسة CI أو تخفيف اختبار أو حارس أو رفع سقف من أجل السرعة؛ البوابات الحالية واجبة حتى يعتمد تكليف مستقل غير موجود هنا.

## 4. دورة المرحلة والمراجعتين

1. تعتمد بطاقة المرحلة ومدخلاتها الموجودة في GitHub. يكتب Manus أمرها فقط ويراجعه ChatGPT.
2. ينشر الأمر بنسخة وcommit معلومين. لا يصبح READY قبل اكتمال المراجعة؛ يتلقى المالك رسالة قصيرة بمساره وSHA وقاعدة التنفيذ.
3. يثبت ZAI الحالة الحية وClaim النطاق، وينفذ ويختبر ويرفع commits المرحلة وتقريرها؛ يتوقف ولا يبدأ التالية.
4. يفحص ChatGPT وManus نفس base..candidate والأدلة. بعد أي commit جديد تعاد مراجعة الفرق وتوابعه على الرأس الجديد؛ تقرير ZAI وحده ليس اعتمادًا.
5. بعد إغلاق الملاحظات واعتماد المالك، يسجل قبول المرحلة على فرع التكامل. توثق هذه الحقيقة ضمن سجلات Operations Control بصيغ وحقول يقبلها مدققه الحالي؛ لا enum جديد مخترع ولا VERIFIED على main قبل الدمج.
6. يجهز الأمر التالي من آخر رأس مقبول فعليًا على فرع التكامل. يفصل أمر النشر بين commit نص الأمر وقاعدة التنفيذ؛ لا يطلب SHA ذاتيًا لنفس commit قبل إنشائه.
7. بعد S18 وموافقة المالك فقط يتم الدمج. يبقى MERGED_UNVERIFIED إلى أن يتحقق main الفعلي، ثم VERIFIED في حدود الأدلة. لا تغلق البوابات الخارجية تلقائيًا.

RESULT ومراجعتا GPT وManus تعرف candidate الكودي المفحوص. إذا أدى حفظ التقرير إلى commit توثيقي لاحق، يثبت فرق الرأسين ولا تدعى فحوص لم تجر على الرأس الجديد. لا تكرر فحوص موثقة بلا سبب، ولا تتجاوز required checks الحالية. قبول مكون ضمن مرحلة يبقى جزئيًا إذا كان هناك عقد أو تكامل لازم لم يكتمل.

المراجعون الداخليون إن طلبهم الأمر قراءة فقط؛ لا يستبدلون المراجعتين الخارجيتين. استقلال الأمر لا يعني نسخ جميع المواصفات داخله، لكنه لا يعتمد على ذاكرة دردشة. لا تكتب أوامر المراحل المستقبلية الآن.

## 6. التسليم المطلوب الآن من Manus

راجع تبعيات المراحل وملكية العقود وحجم الشرائح وحدودها ومصالحة 3584aa1. أعد قبولًا أو فروقًا محددة بمعرف المرحلة/العقد والسبب والتعديل المقترح، دون إعادة تصميم المنتج أو تشغيل ZAI. لا يفهم القبول السابق لـ001 على أنه تطابق تلقائي مع آخر مواصفة.

نُفذت S01 التوثيقية بتكليفها المعتمد؛ أمر مرحلة التطوير الأولى لا يُكتب ولا يُنشر حتى تكتمل مراجعة S01 واعتماد المالك. لا يوجد PROMPT.md تنفيذي لـS02 أو أي مرحلة لاحقة في هذه الحزمة.

## 7. المتابعة على GitHub وDrive

سجل المراحل والاستئناف في الحزمة هو فهرس التسليم المشترك، مستندًا إلى Operations Control وRESULT والمراجعتين. مرآته على Drive يتولى ChatGPT تحديثها بعد قراءة الأدلة؛ لا وصول Drive مطلوب من Manus أوZAI ولا مزامنة تلقائية مفترضة. كل نسخة تعرّف مرجعها ووقت آخر مطابقة، وأي اختلاف يراجع من المصدر الحي.

كل أمر يحدد كيف يحدث ZAI وقائع التنفيذ وما لا يحق له اعتماده. تحفظ تعليمات الاستئناف والعوائق وقرار الانتقال والـSHA، بحيث يمكن لمحادثة أو حساب مختلف استكمال المرحلة دون إعادة تنفيذ عمل مؤكد.
