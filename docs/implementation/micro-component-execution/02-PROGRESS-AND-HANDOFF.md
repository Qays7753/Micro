## 4. بطاقة تسليم إلزامية عند كل توقف

لا يكتفى بجدول مختصر. عندما يبدأ تكليف المرحلة يوضع رابط بطاقة مفصلة في RESULT.md وأمرها، وتملأ الحقول التالية بدل حملها في المحادثة:

| الحقل | ما يجب تسجيله |
|---|---|
| الهوية | Stage ID ونسخة الأمر وcommit نصه ومساره؛ نسخة الحزمة وManifest |
| الحالة الرسمية | معرف Item/Workstream ورابط مصدره وحالته كما يثبتها Operations Control |
| مكان العمل | اسم فرع التكامل، PR، base SHA، candidate SHA كامل؛ الفرق بين رأس الكود ورأس التقرير إن وجد |
| نطاق الإنجاز | UNIT/ACD/DUP/SDF المعالجة؛ ما ثبت إبقاؤه وما تغير وما حذف وسببه وبديله |
| التغييرات | ملفات ومسؤوليات ومنافذ؛ لا قائمة ملفات وحدها دون تفسير سلوكها |
| المال والبيانات | القواعد المتأثرة، زوج المخطط/التصدير، العائلات والمهاجرات وأثر النقل؛ أو لا ينطبق بسبب محدد |
| الفحوص | أمر كل فحص، النتيجة، البيئة والرأس المفحوص ورابط الدليل؛ لا نجاح من رأس آخر |
| الهاتف والرحلة | ما جرب من أحجام ورجوع وإلغاء وخطأ وتكرار وفراغ؛ محاكاة مقابل جهاز حقيقي وحدود غير مجتازة |
| مراجعة ChatGPT | الحكم وSHA المراجع والملاحظات المفتوحة والمغلقة وروابط الأدلة |
| مراجعة Manus | الحكم وSHA المراجع والملاحظات المفتوحة والمغلقة وروابط الأدلة |
| العوائق | معرف ثابت، السبب، الدليل، المالك، وما يلزم لإزالته؛ لا DEFER عام لعيب داخل النطاق |
| التقدم الجزئي | آخر فعل مؤكد وما لم يكتمل؛ بعد انقطاع الرد يحسم مآل الكتابة قبل تكرار القصد |
| الرجوع | آخر رأس آمن وخطة بيانات متوافقة؛ لا rollback كودي يخفض المخطط أو يمحو أعمالًا |
| قرار الانتقال | مسموح/غير مسموح مع السبب وموافقة المالك؛ المرحلة التالية وتبعياتها المتحققة |
| تعليمات الاستئناف | الفعل التالي الدقيق، والملفات التي تقرأ، والاختبارات التي تعاد بسبب محدد؛ دون «أكمل مثل السابق» |
| المطابقة | وقت تحديث GitHub، والرأس الذي نقل منه ملخص Drive، واسم المحدث؛ إذا اختلفا فالمرآة قديمة |

كل finding له معرف ثابت وتصنيف ودليل وأثر ومالك وفحص قبول. بعد إصلاحه تحفظ العلاقة بالـcommit والدليل؛ لا تمحى ملاحظته القديمة. اسم المرحلة التالية في البطاقة ليس إذن تشغيل لها.

## 5. من يكتب كل جزء؟

ZAI يحدث النتيجة ووقائع التنفيذ والفحوص والسجل التشغيلي المسموح في تكليفه. لا يكتب قبول GPT أوManus باسمهما، ولا يعتمد نفسه أو ينقل المرحلة تلقائيًا. كل مراجع يكتب حكمه المستقل على candidate نفسه، أو يسلم نصه للناشر المفوض مع حفظ نسبته ومصدره. موافقة الانتقال والدمج للمالك.

بعد كل دورة مراجعة، يقرأ ChatGPT الحالة والأدلة من GitHub ويحدّث مرآة Drive. لا توجد مزامنة آلية مفترضة. عند اختلاف النصين يراجع المصدر الحي والدليل، ولا يختار أحدث وقت تعديل وحده. يضاف أي تصحيح أو مصالحة كتحديث معلوم لا محوًا لنتائج سابقة.

## 6. الاستئناف من محادثة أو حساب ZAI مختلف

1. يرسل المالك رابط المستودع والمسار المنشور لهذا السجل وcommit الأمر الحالي. لا يلزم إرسال محادثة سابقة أو ملفات Drive.
2. يقرأ الوكيل AGENTS وCORE وOperations Control الحية والسجل وManifest وأمر المرحلة المستقل ومدخلاته.
3. يتحقق من الفرع وPR والرأس الحي، وآخر مرحلة مقبولة والمرشح والمراجعتين. لا ينشئ فرعًا ثانيًا ولا يكتب فوق عمل غير ملتزم أو كاتب نشط.
4. إذا كانت هناك محاولة كتابة مجهولة أو عمل غير مكتمل، يتحقق من المستودع والاختبارات ومآل القصد قبل إعادة الفعل. الاستئناف من وظيفة محددة، لا إعادة مرحلة كاملة تلقائيًا.
5. إذا تغير الرأس أو كانت مرآة Drive قديمة، يثبت الفرق ويجري المصالحة المطلوبة قبل الكتابة. لا يتجاوز قرارًا ماليًا أو مانع قبول من محادثة جديدة.
6. لا تنفيذ إلا لأمر READY المنشور وتفويض المالك لتلك المرحلة. حالة PLANNED أو بطاقة مرحلة تالية لا تمنح إذنًا.

## 7. شرط الانتقال والإغلاق

candidate صالح للمراجعة لا يعني قبول المرحلة. القبول يحتاج نطاقًا مكتملًا وأدلة وفحوصًا واجبة ومراجعتين على الرأس نفسه وإغلاق العوائق، ثم اعتماد المالك. القبول على فرع التكامل لا يعني ready for merge لكل البرنامج، ولا VERIFIED على main. جاهزية الدمج تأتي بعد S18، والتحقق على main بعد الدمج وفحص رأسه الفعلي فقط.

## 8. متطلب ثابت لأول أمر ولكل أمر لاحق

يلزم Manus كل أمر مستقل بأن يقرأ هذا السجل، ويحدد بطاقة المرحلة وما يسمح لـZAI بتحديثه فيها، ويسجل توقفه وفعله التالي قبل التسليم. هذا وصف لمتطلب صياغة الأوامر؛ لا يوجد أمر تنفيذ منشور حاليًا.
