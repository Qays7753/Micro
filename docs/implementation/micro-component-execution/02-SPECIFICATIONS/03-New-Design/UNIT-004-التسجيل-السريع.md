### P3.2 — الحقول والملكية والأثر المالي

هذا **فرق البيانات** اللازم فوق قاموسB الموجود؛ لا يلغي الحقول الصحيحة أو يسقط سبب ظهورها/إلزامها. التسميات التقنية المقترحة أدناه تصف عقد المعنى، ولا تدعي أن كل حقل مضاف موجود حاليًا. لا نسخ كامل لقاموس جديد منافس.

| العنصر محل التعديل | التمثيل والقيد ومصير القديم |

| input payload | نفس أنواع وتحقيق صاحب العملية؛ رقاقة فئة المصروف لا تعوض بندًا مطلوبًا. |
| commandId / draft | نفس القصد عند الاسترداد؛ إغلاق الورقة لا يبرر مفتاحًا جديدًا لحفظ مجهول النتيجة. |

**الأثر وحد الالتزام:** ينتظر اكتمال معاملة صاحب العملية. لا يعاد بيع نجح لاستكمال حفظ طرف اختياري أو ربط إضافي فشل.

**تخزين/ترحيل هذا المكون:** لا مخزنquick-record أو سجل أحداث موازٍ؛ تكييف المسودة بالجيل والمعرفة وحدود الحجم.

**العائلات القائمة المحتمل لمسها:** `form-drafts` هذه قائمة نطاق، وليست أمرًا بإدراج كل مخزن في كل معاملة.044 يراجع كل عائلات اللقطة في§19، لا هذه القائمة المختصرة فقط.

**الحرس العام عند وجود كتابة:** الأمر بهوية قصد وحمولة ونسخ مصادر وجيل، والمبلغ الصحيح بوحدةminor والتاريخ الفعلي؛ فحص الحالة الحية داخل حد الكتابة. نجاح مؤكد أو فشل بلا أثر أو مآل مجهول يسترد بالقصد نفسه. عند تغيير النوع/المخزن: المهايئان والتصدير والوارد والعلاقات والمهاجرات في الشريحة نفسها. المخازن المشتركة المرشحة في§8 ليست منشأة تلقائيًا، ولا يختار المنفذ أرقامschema/export من هذا الملف. القراءة البحتة لا تنشئcommand-receipt أو حركة مال لإثبات أنها فُتحت.

**شرط إغلاق المكوّن لاحقًا:** حسم السلوك والسياسات المطلوبة، وتحديد أجزاء التنفيذ، وإنجاز ما يلزم مع الجيران، ونجاح القبول المحلي والمشترك والرجوع والإلغاء والخطأ والتكرار والفراغ على الهاتف بحسب النطاق، ثم تسجيل الأدلة والحدود. المتحقق في هذه الجولة هو اتساق الوثيقة فقط.

**تتبع منفصل:** اعتماد القرار ≠ اكتمال التصميم ≠ التنفيذ ≠ نجاح الاختبار. لا يدمج هذا التحديث أعداد ORG-AC مع فحوص ACD القديمة ولا يدعي نجاحها.

**طريقة القراءة:** المقارنة ثم A لتجربة المستخدم؛B للمواصفة، و C للدليل. القرارات وسجل التحديث آخر الملف.

## UNIT-004-A — ما الذي سيستخدمه صاحب المشروع؟

**المهمة:** تسجيل بيع مباشر أو مصروف مشروع مدفوع، دون إنشاء طلب أو مغادرة الرئيسية. **النتيجة:** سجل واحد ومعنى مالي واضح، ثم العودة للعمل أو بدء عملية أخرى.

### البيع السريع

| الترتيب | ما يظهر | السلوك |
|---|---|---|
| الترويسة | **تسجيل بيع**، إغلاق، وأيقونة معلومات. | يفتح مباشرة من 003؛ الشرح العام عند الضغط فقط. |
| الرقم الأساسي | **إجمالي البيع (د.أ)** | فارغ حتى يكتبه المستخدم؛ هو السعر الكامل دائمًا. |
| حالة القبض | **قُبض كاملًا**؛ ويمكن اختيار **قبض جزئي — الباقي دين** أو **لم يُقبض — المبلغ دين**. | الافتراضي الكامل ظاهر؛ في الجزئي يظهر المقبوض واسم العميل، وفي عدم القبض يظهر الاسم ويكون المقبوض 0 بقرار صريح. |
| النقد عند وجود قبض | **المقبوض إلى: اسم المحفظة أو نقد غير موزع** | يمكن تغييره؛ لا إنشاء محفظة مطلوب لإتمام البيع. |
| سطر التكلفة | **التكلفة: غير معروفة — إضافة** | إضافة تكلفة تكشف مبلغًا فارغًا؛ إدخال 0 صريح صالح. تركها مجهولة يبقيها null، وقد يمنع عرض نتيجة مالية مكتملة حسب سياسة المصدر. |
| التاريخ والتفاصيل | **التاريخ: اليوم — تغيير**، و**تفاصيل إضافية** مطوية. | التاريخ واضح ويمكن تغييره لبيع سابق؛ التفاصيل للوصف الاختياري. لا يخفى قرار القبض أو وجهة المال هنا. |
| قبل الحفظ | إجمالي البيع، المقبوض، والمتبقي دينًا عند وجوده، ووجهة القبض. | ملخص أرقام قصير من القيم الصالحة؛ بلا فقرة تعليم مالي. |
| الإتمام | **حفظ البيع**؛ مدخل ثانوي **النموذج الكامل**. | الحفظ يؤكد ما يظهر؛ النموذج الكامل للكمية/المرجع/قرار فرق آخر أو التفاصيل، مع نقل المدخلات وفق X01 قبل التنفيذ. |

**مثال:** إجمالي 15.00، قبض جزئي 5.00، العميل«خالد». قبل الحفظ يظهر: «إجمالي البيع 15.00 د.أ · المقبوض 5.00 د.أ · المتبقي دينًا 10.00 د.أ»، ووجهة 5.00. لا توزع 15.00 على المحفظة ولا يسجل الدين قبضًا. مع تكلفة مجهولة لا نخترع ربحًا أو تكلفة 0.

### المصروف السريع

| الترتيب | ما يظهر | السلوك |
|---|---|---|
| الترويسة | **تسجيل مصروف للمشروع**، إغلاق، وأيقونة معلومات. | هذا مصروف مدفوع يخص المشروع؛ الشخصي/المشترك أو غير المدفوع ليس المعنى الافتراضي لهذه الورقة. |
| المدخلان الرئيسيان | **المبلغ المدفوع (د.أ)** ثم **وصف المصروف**. | كلاهما مطلوب؛ مثال الوصف«أكياس تغليف». المبلغ فارغ لا 0.00 افتراضية. |
| مصدر النقد | **الدفع من: اسم المحفظة أو نقد غير موزع** | بلا محافظ بعد نجاح القراءة: غير الموزع. واحدة: معينة ظاهرًا وقابلة للتغيير. متعددة: اختيار مطلوب، دون تذكر آخر مصدر تلقائيًا. |
| التاريخ والتفاصيل | **التاريخ: اليوم — تغيير**، و**تفاصيل إضافية**. | التاريخ قابل للتحرير؛ داخل التفاصيل تصنيف اختياري منفصل عن الوصف. حد التاريخ المستقبلي اقتراح قاعدة D08 غير معتمد. |
| قبل الحفظ | **المدفوع X د.أ · من«المصدر»** | يوضح المبلغ ومصدر خروجه؛ لا يزعم رصيدًا كافيًا دون قراءة وفحص المصدر. |
| الإتمام | **حفظ المصروف**؛ مدخل ثانوي **مصروف مشترك أو تفاصيل أكثر**. | التفاصيل تفوض إلى 015 بقيم غير محفوظة وفق X01؛ لا يتحول المصروف المدفوع لدين أو سحب مالك من الورقة. |

**بعد نجاح العملية:** نتيجة مختصرة«تم حفظ البيع» أو«تم حفظ المصروف»، ومبالغ العملية الفعلية. الأفعال: **تم**، **عملية جديدة**، **عرض السجل**. عملية جديدة تفتح نموذجًا نظيفًا ومفتاحًا جديدًا، ولا تكرر السابق. لا نحتاج عرض إجمالي نقد المشروع في نتيجة كل عملية؛ الرئيسية تقرأه من مصدرها.

**إذا حُفظ السجل ولم ينجح ربط النقد بالمحفظة:** تظهر هذه الحقيقة باختصار، مع **إكمال ربط النقد** وفتح السجل؛ لا زر يوحي بإعادة تسجيل البيع أو المصروف. تظهر الحالة المالية المهمة مباشرة، لا وراء علامة التعجب.

**عند الإغلاق مع تعديل:** «لديك مدخلات غير محفوظة» مع **متابعة التعديل**، **حفظ مسودة وإغلاق**، **تجاهل المدخلات**. المسودة لا تسجل مالًا. إذا تعذر حفظها يبقى النموذج ويفهم المستخدم ذلك؛ لا يدعي التطبيق أنه احتفظ بها.

الحقول والأفعال من مكتبة UI المعتمدة، والهاتف و RTL والأرقام 0–9. لا معالج متعدد الخطوات، ولا شاشة تأكيد ثانية لكل حفظ عادي؛ المعاينة والتحقق والتصحيح من المصدر وسائل الحماية هنا.

### مقابلة015 — نواة المصروف ونقل الإدخال والنتيجة

## B-DUP — الملكية والإلغاء ضمن التصميم المتكامل

هذا القسم جزء من مواصفة المكوّن،لا قائمة تصحيحات خارجية.التغيير المحدد والسبب والبديل والبيانات والقبول أدناه كافية لفهم المطلوب محليًا.روابط الجيران لتنسيق الطرف المقابل،ولا تجيز حذف وظيفته ضمن تعديل منفرد.الحالة المالية المعتمدة تحتاج قرارها الأصلي؛النص الجديد لا يحسمها.

**بوابة الإزالة:** لا يزيل المهندس حقلًا أو مدخلًا أو كاتبًا قديمًا قبل إثبات أن البديل يستقبل البيانات والنية والرجوع،وأن التاريخ والأثر المالي محفوظان.إن لم يجهز الطرف الآخر،يبقى الجزء غير جاهز للتنفيذ،ولا يستبدل بقيمة0 أو نص وهمي أو فقد وظيفة.

## UNIT-004-C — الدليل والبدائل والمشكلات

### C1. الحقائق وحدود التحقق ومصالحة التقرير السابق

قرئت الورقة والنموذجان، ومواصفة المصروف ومساعد الربط والأنواع ومكوّن الرقم، وخدمة البيع تسجيلًا وتعديلًا، ومحررا 005/015، وخدمة كتابة الأحداث والتخصيص وسياسات الحدث وخطاف المسودة ومقترحات التصنيف و resultFeedback على الالتزام المثبت. التقرير 02 و ZAI سياق منقول؛ لا جلسة تشغيل جديدة أو تعديل كود.

**تصحيحان للدليل المنقول:**

- وصف بقاء النموذجين بعد النجاح ليس دقيقًا في الشرط المقروء: `mode !== "receipt"` يستبدل النموذجين عند عرض النتيجة. بقاء القيم أثناء الرجوع للقائمة لا يثبت بقاءها بعد النجاح أو إغلاق Drawer. لا أسجل ذلك عطلًا مؤكدًا من التقرير وحده.
- ما وصف بأنه«فشل صامت» في المصروف له رسالة formError و role=alert في المصدر. المثبت هو الإرشاد المتناقض، وفصل التصنيف والوصف، وموضع الخطأ وربطه. لا أدعي غياب رسالة حالية أو أتبنى استدلال تقرير سابق كحقيقة.

سياسة الحدث تتحقق من صلاحية التاريخ المحلي دون حد للمستقبل ظاهر في createFinancialEvent؛ ورقة المصروف لا تضيف حدًا. البيع السريع يرفض المستقبل صراحة. لذلك D08 يغير مسموحية الإدخال ويحتاج اعتمادًا وتوحيدًا، ولا ينفذ كتعديل نص.
