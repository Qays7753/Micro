# UNIT-019 — تكرار المصروف

**النسخة:** V5 متكاملة · **التاريخ:** 2026-10-27 · **التصميم:** معتمد من المالك في نطاق CONS-DEC ذات الصلة؛ التفاصيل غير المغطاة بحدودها. التنفيذ والاختبار لم يبدآ، ولا إغلاق شامل.

**مهمة المستخدم:** أطلب تذكيري بمصروف يتكرر، ثم أسجّل ما وقع فعلًا عند كل موعد، دون إعادة تعريف المصروف أو تسجيله مرتين.

**المعتمد تنظيميًا:** [ORG-011](02-STRUCTURE-DECISIONS-AR.md#org-011): خيار «يتكرر» داخل نموذج المصروف015/004، مع إعادة استعمال إعداد التكرار القائم. الاعتماد لا يشمل تلقائيًا سياسات الحصة والتاريخ أو إضافات البيانات المقترحة هنا.

**المراجع:** [الفهرس](00-COMPONENTS-INDEX-AR.md) · [المعايير V6](../01-Standards/01-Component-Criteria-AR.md) · [BASE-01/019](../02-Current-System/02-Current-Components-AR.md#unit-019) · [التراكر](01-OWNERSHIP-AND-DUPLICATION-AR.md).

**خط أساس الأدلة:** مصدر Micro عند `5ef4ce08841bcd4ff7c5fb185a0fe2eeef6852fd`. الفحص قراءة للكود والعقود؛ لا تشغيل جديد أو تجربة مستخدمين أو إثبات أن المصدر الحالي لم يتغير. لا يعدل هذا العمل كود المنتج أو الهوية البصرية أو الرحلات العامة النهائية.

**طريقة القراءة:** المقارنة وA للتجربة؛ B للحقول والسلوك والحالات والقبول؛ B-DUP للإزالة والدمج والسبب والبديل وشروطهما؛ C للدليل والنتائج والقرارات. التعليمات متكاملة في هذا الملف، والتراكر روابط وحالات.

## P3 — تكليف UNIT-019 المحدّث: المنتج والبيانات وبنية التنفيذ

**التاريخ:**2026-10-27 · **الحالة:** تكليف تعديل/دمج حسب القرار المعتمد؛ التخطيط موثق، والتنفيذ والاختبار والإغلاق لم تبدأ بهذه الجولة.
**طريقة القراءة:** هذا القسم جزء من ملف المكون نفسه، لا ملف بديل أو تصميم موازٍ. اقرأ المهمة والتصميم والحقول والمحتوى فيA/B، ثم تعليماتP3 والحذف المعلل وB-DUP والقبول. المعرف والاسم والمشكلات والأدلة وACD/DUP السابقة محفوظة. أي وصف للمصدر عندSHA أقدم يبقى دليلًا تاريخيًا لا حقيقة حية عن الكود الحالي.

### P3.2 — الحقول والملكية والأثر المالي

هذا **فرق البيانات** اللازم فوق قاموسB الموجود؛ لا يلغي الحقول الصحيحة أو يسقط سبب ظهورها/إلزامها. التسميات التقنية المقترحة أدناه تصف عقد المعنى، ولا تدعي أن كل حقل مضاف موجود حاليًا. لا نسخ كامل لقاموس جديد منافس.

| العنصر محل التعديل | التمثيل والقيد ومصير القديم |
|---|---|
| series/revisions/effectiveFrom | تعديل المستقبل غير المعالج؛ لا رجوع على مصروف مؤكد. |
| occurrenceKey/expenseRef | دورة ثابتة ومصروف واحد؛ اختيار مصروف قائم لا يعيد الأصل أو دفعته. |
| dueOn/occurredOn/paidOn | التذكير والوقوع والدفع تواريخ مختلفة، والمبلغ المقترح ليس مدفوعًا. |

**الأثر وحد الالتزام:** الدورة ونسختها والمصروف والدفعة المختارة والروابط والإيصال داخل حد واحد؛ نافذتان لا تؤكدان مصروفين.

**تخزين/ترحيل هذا المكون:** المخازن الثلاثة ومرجعfinancial-events تبقى؛ تحفظ نسخ الماضي والأسباب ولا تعريف مكرر لكل فاتورة.

**العائلات القائمة المحتمل لمسها:** `recurring-expense-series`, `recurring-expense-revisions`, `recurring-expense-occurrences`, `financial-events` هذه قائمة نطاق، وليست أمرًا بإدراج كل مخزن في كل معاملة.044 يراجع كل عائلات اللقطة في§19، لا هذه القائمة المختصرة فقط.

**الحرس العام عند وجود كتابة:** الأمر بهوية قصد وحمولة ونسخ مصادر وجيل، والمبلغ الصحيح بوحدةminor والتاريخ الفعلي؛ فحص الحالة الحية داخل حد الكتابة. نجاح مؤكد أو فشل بلا أثر أو مآل مجهول يسترد بالقصد نفسه. عند تغيير النوع/المخزن: المهايئان والتصدير والوارد والعلاقات والمهاجرات في الشريحة نفسها. المخازن المشتركة المرشحة في§8 ليست منشأة تلقائيًا، ولا يختار المنفذ أرقامschema/export من هذا الملف. القراءة البحتة لا تنشئcommand-receipt أو حركة مال لإثبات أنها فُتحت.

# A — التجربة المقترحة لصاحب المشروع

## A1. أسجّل مصروفًا وأطلب تكراره

1. يفتح **تسجيل مصروف** من015 أو المدخل المختصر004؛ يدخل المبلغ والوصف وحالة الدفع حسب المهمة.
2. يظهر **يتكرر** غير محدد افتراضيًا للمصروف الجديد. تحديده يكشف فقط **التكرار: كل شهر** و**التذكير القادم: تاريخ قابل للتغيير**.
3. يعاد استعمال الوصف والفئة، دون اسم سلسلة ثانٍ أو تعريف مورد قائم مجددًا. التفاصيل غير المعتادة في **خيارات التكرار**.
4. قرب الحفظ تظهر خلاصة: **مصروف هذه المرة: 100.00 د.أ · التذكير القادم: 2026-11-05**. معنى مدفوع/غير مدفوع ظاهر في015؛ الاقتراح المستقبلي لا يدخل إجمالي المصروف.
5. **حفظ المصروف** ينتج مصروفًا حاليًا واحدًا وإعداد تكرار واحدًا بقصد مترابط. إن تعذر الإعداد بعد ثبوت المصروف، يقال ذلك ويستكمل الإعداد وحده.

إلغاء تحديد الخيار قبل حفظ مصروف جديد يلغي إعداد التكرار غير المحفوظ فقط. عند سلسلة قائمة لا يعني إلغاء تحديده إنهاءها سرًا؛ الإنهاء فعل منفصل معلوم الأثر. هذا تصميم داخل المكوّن وعقده المباشر، وليس رحلة النظام العامة.

## A2. أريد تذكيرًا قبل وقوع المصروف

من سياق المصروف أو إعداده يختار **تذكير فقط**. نفس مكوّن الإدخال بوضع صريح، وليس مصروفًا وهميًا بقيمة0.

| الترتيب | ما يظهر | السلوك |
|---|---|---|
| 1 | رجوع · **تذكير بمصروف** · ! | عنوان يميز المهمة عن تسجيل واقعة؛ الرجوع إلى المصدر. |
| 2 | **وصف المصروف** | مطلوب، يعاد استعمال الموجود إن بدأ من مصروف محفوظ. |
| 3 | **التكرار** · **التذكير القادم** | كل شهر اقتراح جديد؛ التاريخ يراجع قبل الحفظ. |
| 4 | **مبلغ مقترح — اختياري** · **تفاصيل إضافية** | الفراغ يعني إدخال المبلغ عند الوقوع؛ لا0 أو دفع أو صندوق مفروض. |
| 5 | **حفظ التذكير** | سلسلة وإعداد تشغيلي فقط؛ لا مصروف أو دين أو دفع. |

لا خطوة إلزامية «احفظ مسودة ثم فعّلها». المسودات القديمة تفتح وتستكمل؛ مسودة النموذج المحلي ليست سلسلة مفعلة. إن اختير حفظ مسودة صراحة، تصف النتيجة أنها غير مفعلة.

## A3. عند الموعد: مراجعة دورة محددة

تظهر مهمة واحدة في **المتابعة**012/018: **راجع مصروف الإيجار · أكتوبر2026**، وتاريخ التذكير و**100.00 د.أ مقترح** إن وجد. التأخر تأخر مراجعة، لا دين مؤكد.

يفتح نموذج015 نفسه بعنوان **مصروف الإيجار — أكتوبر2026**. الوصف والفئة والمبلغ اقتراحات من قاعدة هذه الدورة؛ لا إقرار بالوقوع أو الدفع. يراجع المبلغ والتاريخ وحالة الدفع، ولا يملأ المخزون أو الإهلاك أو الحصة المشتركة إذا لم يحتجها.

| الحالة | الفعل الرئيسي | الثانوي عند الحاجة |
|---|---|---|
| دورة غير مسجلة | **حفظ المصروف** بعد المراجعة | **ذكّرني لاحقًا**، **تخطي هذه الدورة**، **إعداد التكرار**. |
| حفظ جارٍ | **جارٍ الحفظ** | لا تغيير حمولة أو إرسال آخر؛ الخروج يحافظ على القصد ويحسم النتيجة. |
| نتيجة غير مؤكدة | **التحقق من التسجيل** | لا مصروف جديد أو تخطٍ يخفي نتيجة ربما حفظت. |
| مصروف مسجل | **فتح المصروف** | التصحيح عند مالك العملية، لا «مراجعة أخرى» توحي بحفظ ثانٍ. |

| سبق تسجيله يدويًا | **اختيار مصروف مسجل** إذا اعتمدD06 | اختيار صريح ومراجعة المصدر، لا تطابق آلي أو تخطٍ يوهم بالتسجيل. |

لا حوار تأكيد إضافي لكل حفظ عادي؛ المعاينة والتصحيح قبل الحفظ. التخطي يوضح: **لن يُسجل مصروف لهذه الدورة**؛ السبب اختياري ما لم توجد قاعدة مجال معلنة بخلافه. إذا وقع المصروف خارج التطبيق، تسجل الواقعة أو يربط سجلها؛ التخطي لا يحتسبها.

## A4. الإعداد والتاريخ والإيقاف

الخلاصة: **كل شهر · التذكير القادم2026-11-05 · مبلغ مقترح100.00 د.أ**. الإجراء المطلوب الآن أولًا، ثم **إعداد التكرار** و**الدورات السابقة**، دون عرض جميع القواعد والأفعال في الرأس.

- **تعديل هذه المرة:** يغير الواقعة الحالية فقط، لا مبالغ المستقبل تلقائيًا.
- **تعديل التكرار القادم:** يراجع أول دورة ستتأثر وتاريخها قبل الحفظ. لا وصف «المستقبل» مع فترة قديمة مخفية.
- **إيقاف مؤقت:** يوقف توليد الجديد بحسب المصدر الحالي؛ الدورات المحفوظة الباقية تظل معلومة. يظهر عددها إذا أمكن التحقق منه.
- **استئناف:** من الشهر الحالي دون إنشاء مصاريف أو ملء أشهر التوقف آليًا؛ القديم الباقي يظهر منفصلًا.
- **إنهاء التكرار:** وفق حد المصدر الحالي يلغي المخطط/المؤجل بعد اليوم؛ اليوم والماضي يحتاجان قرارًا. لا سداد لديون أو عكس مصاريف.
- **أرشفة:** تنظيم للسجل، لا مرادف للإنهاء؛ أثر الاستعادة يشرح قبلها.

لا نحذف اختلاف هذه الوظائف باسم تبسيط الأزرار. تغيير أثر الإيقاف ليشمل الدورات القائمة يحتاج قرارًا آخر؛ ليس ضمن هذه التوصية.

**المصروف الأول:** لا ينشئ إعداد التكرار دورة حالية ثانية مفتوحة لنفس الواقعة. يحفظ مصدر الربط أو حد البدء الذي يجعل أول تذكير جديد هو القادم. تاريخ إدخال مصروف قديم لا يحدد وحده أي دورة يمثل؛ العلاقة ظاهرة في المعاينة. إذا لم يجهز هذا العقد يبقى مصروف واحد مع إعداد لاحق واضح، لا جمع ناقص مخفي.

**لم أعثر على التسجيل:** نتيجة قراءة لها حدود، لا إثبات دائم بأن الحدث لم يكتب. محاولة أخرى أو فشل قراءة يبقي المآل غير محسوم. أي استئناف لنفس القصد بنفس المفتاح، مع حرس حي في التخزين.

**الرجوع والإلغاء والتحديث:** الرجوع قبل الحفظ يعالج المسودة الصالحة ولا يعلم الدورة منتهية. إغلاق تفاصيل لا يمحو إدخالًا؛ بعدcommit تفتح النتيجة وتعود مرة واحدة. تحديث الصفحة يسترد القصد ويحسم المآل قبل الإرسال، ولا يبدأ إنشاء سلسلة من الصفر.

**عقد الربط الموجود D06 عند اعتماده:** يختار المستخدم حدث مصروف مدفوع أو غير مدفوع قائمًا وغير معكوس، لا دفعة سداد أو قرضًا أو شراء أصل أو مجرد تشابه اسم. يتأكد الكاتب حيًا من صلاحية المصدر والنسخة وحصرية ربط الحدث بدورة واحدة، مع السماح بإعادة نفس الربط فقط. لا يفرض تساوي مبلغ الاقتراح والفعلي لأن المصروف قد يتغير. يحفظ أصل الربط ونسخته وهوية المصدر في معاملة القرار، دون تغيير مفتاح الحدث أو دلتا مالية. التصحيح اللاحق يظهر عند المصدر مع بقاء التاريخ؛ لا فك ربط وإعادة تسجيل آليين. البيانات القديمة بلا provenance لا تملأ بالتخمين. هذه إضافة مقترحة لا مسار موجود مثبت.

# B-DUP — الملكية والإلغاء داخل المواصفة

<a id="dup-007"></a>
## DUP-007 — إدخال المصروف ونموذج تأكيد الدورة

**ما يلغى أو يتغير هنا:** حقول المبلغ والوصف والحصة والجهة والدفع والتحقق والمعاينة المستقلة في نموذج التأكيد.

**السبب الحرفي:** كلا النموذجين يسجل واقعة المصروف نفسها؛ النسخة الدورية لا تجمع الحصة اللازمة وتفقد حالات نتيجة. نقل الشكل وحده يبقي الازدواج.

**ما يبقى وأين، والبيانات والقصد المنقولان:** نموذج وموسّع015 ومدخل004، ومحوّل019 يملك التزام الدورة. ينتقلseriesId/occurrenceId/revision/key/rawDraft والحقول والعودة.

**شرط التجهيز والترتيب وحفظ البيانات والأثر:** تجهيز الحمولة والنتيجة في015/004 ثم اختبار الحصة والدفع والتعافي قبل إحلال النموذج. تبقى الأحداث والمفاتيح والروابط؛ لا كاتب عادي ثمconfirm.

**U019-ACD007:** المدفوع وغير المدفوع والمشترك عبر004/015/019 تعطي نفس المعاينة وواقعة واحدة وعودة صحيحة؛AC07–10/20/33.

<a id="dup-018"></a>
## DUP-018 — السجل المالي وتاريخ الدورات

**ما يلغى أو يتغير هنا:** رابط مالية عام عند معرفة الحدث، أو صف تذكير مالي يجمع كأنه مصروف.

**السبب الحرفي:** التذكير قرار متابعة والواقعة مصدر مالي واحد؛ الخلط يضلل الجمع والعثور على التصحيح.

**ما يبقى وأين، والبيانات والقصد المنقولان:** التاريخ التشغيلي019، والحدث وفتحه017 وتصحيحه015. ينتقلeventId/occurrenceId/seriesId ونوع المصدر والعودة.

**شرط التجهيز والترتيب وحفظ البيانات والأثر:** تجهيز تركيز المصدر والتصحيح في017 قبل إحالة الزر؛ كل مراجع وتاريخ السابق محفوظة.

**U019-ACD018:** لا تذكير كمصروف؛ الحدث له صف واحد ويفتح بعينه ويعود للدورة؛AC28/35.

<a id="dup-020"></a>
## DUP-020 — كاتب الواقعة وعدم التكرار

**ما يلغى أو يتغير هنا:** حفظ015 ثمconfirm آخر لنفس المصروف، أو إنشاء سلسلة أخرى لإصلاح فشل تفعيل سابقة.

**السبب الحرفي:** دمج الواجهة لا يربط كاتبين لنفس الواقعة؛ ID عشوائي لكل إعادة لا يحمي إنشاء السلسلة.

**ما يبقى وأين، والبيانات والقصد المنقولان:** موسّع مشترك ومحوّل019 للحدث/الدورة ومنسقD07. ينتقل القصد والمفتاح واللقطة ونتائج الأجزاء.

**شرط التجهيز والترتيب وحفظ البيانات والأثر:** تجهيز حرس المعاملة والاسترداد قبل إلغاء النموذج أو خطوة التفعيل. لا تغيير مفاتيح قديمة أو حذف سلسلة مثبتة لإخفاء الجزئي.

**U019-ACD020:** فشل تفعيل/تخصيص وانقطاع ونافذتان لا تنتج مصروفًا أو سلسلة ثانية؛AC05/06/20–25.

<a id="dup-022"></a>
## DUP-022 — المصروف ومصدر النقد

**ما يلغى أو يتغير هنا:** تخصيص صندوق لغير المدفوع، وإعادة تأكيد مالي لإصلاح التخصيص وإخفاء رسالة فشله.

**السبب الحرفي:** الذمة ليست دفعًا، والتخصيص يسند صرفًا ثابتًا ولا ينشئ مصروفًا جديدًا.

**ما يبقى وأين، والبيانات والقصد المنقولان:** الحدث عند015/019 والتخصيص والتغطية022/024. ينتقل النوع والمرجع والمبلغ المعتمد ومفتاحattribute ومآله، لاwalletId غير منطبق.

**شرط التجهيز والترتيب وحفظ البيانات والأثر:** حرس خدمة ونتيجة جزئية واسترداد ربط قبل تبسيط النجاح. يبقى الحدث؛ أيallocation خاطئ سابق يحتاج تصحيحًا موثقًا مستقلًا لا حذفًا صامتًا.

**U019-ACD022:** غير المدفوع بلاallocation؛ المدفوع يصلح مصدره وحده مرة؛AC09/22/23.

## DUP-032 — نطاق الدورة والعودة ونسخة الإعداد

**U019-ACD036:** الفئة تختار مرة وتعاد بحق تعديل هذه الدورة دون الماضي؛AC11–14/37.
