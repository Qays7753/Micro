## المرحلة3 — اكتمل تجهيز الملفات القائمة بشقّي التكليف والبنية —2026-10-27

حدّثت ملفاتUNIT الـ45 **نفسها**، دون ملفات مكونات موازية أو تغيير أرقام/أسماء/روابط. يحتوي كل ملف الآنP3 على تعليمات التعديل والحذف المعلل والبديل، وفرق الحقول والمال والكتابة/القراءة والترحيل، والتبعيات وفحوص القبول؛ ويحتوي خريطة المستودع والطبقات والمنافذ ومسارات الكود والاختبارات من [تقريرZAI الثانيV3](../02-Current-System/03-As-Is-Audit-2026-10-27-fd5d7ce/02-Repository-Structure-and-Implementation-Map-AR.md). تحقق وجود254 مسارًا قائمًا، عبر623 مقابلة مصدر/اختبار، لا اختبارات تشغيل جديدة أو قراءة سطرية جديدة لكل ملف.

**المراجع الحالية:** [فهرس المكونات](../03-New-Design/00-COMPONENTS-INDEX-AR.md) ← ملفUNIT/P3 وتصميمهA/B وB-DUP ← [العقد المشترك](02-Shared-Data-and-Financial-Contract-AR.md) و[قبولSDF](03-Shared-Data-Acceptance-Cases-AR.md) ← [تراكر الملكية](../03-New-Design/01-OWNERSHIP-AND-DUPLICATION-AR.md).427 معرفACD و38DUP محفوظة، وكلACD محلي له مقابلة داخل ملفه، وحالاتSDF الـ72 ما زالت مخططة غير مشغلة. PD-01/PD-02 معتمدتان كاملتين في حدودهما، وقرارات الإلغاء/الدمج/التأجيل باقية.

**معنى الاكتمال:** اكتمال تجهيز الوثائق المطلوبة في المرحلة3، لا تنفيذ أو ترحيل أو شهادة سلامة مالية/إتاحة أو إغلاق المكونات. كل إضافة نوع/مخزن/منفذ تمثل فرقًا مقيدًا في بيت المصدر، وليست إذنًا بإعادة هيكلة عامة أو تنفيذWP-A. التمثيل الهندسي يطابق عندSHA التنفيذ، ومخطط38/export30 حالة مصدر حالية لا رقمًا مستهدفًا جاهزًا.

**التالي:** أجنت آخر ينفذ شريحة مترابطة من ملفاتUNIT المحدثة، يفحصSHA وAGENTS والطبقات والحراس، ثم يثبت قبول المصدر/التخزين/النسخ/الهاتف والتبعيات قبل إعلان الإغلاق. لا نعيد جردZAI كاملًا أو تصميم هوية، ولا تشغيلCloud/Auth/Sync أو فرض قدرات اختيارية.

## 1. كيفية التنفيذ والإثبات

يجهز أجنت التنفيذ بيانات اصطناعية معزولة، ويثبتSHA وإصداراتschema/export. يفحص الحساب النقي ثم العقد نفسه علىMemory وIndexedDB، مع حقن فشل قبل/بعد كل حد كتابة مؤثر، وبعدها الرحلة على هاتفRTL. يسجل لكل حالة: بيانات الحالة، الأمر، المخازن قبل/بعد، الناتج والحقوق والمعرفة، التكرار والفشل، والدليل. لا يكفي نجاح إشعار أو مطابقة لقطة.

**درجات النتيجة:** مخطط/جاهز للتنفيذ/ناجح/فاشل/متعذر بسبب محدد/ينتظر قرار. لا يملأ «ناجح» بدليل هذه الوثيقة. إذا عدل جزء مرتبط يعاد فقط نطاق الفحوص المتأثر بدليل التبعيات، ويختبر044 مع كل امتداد دائم.

## 3. ما يفحصه التشغيل فوق أمثلة الأرقام

- الحدود: مبلغ صفر أو سالب أو خارج العدد الصحيح الآمن، كسور أدق من المسموح، نص غير صالح، كمية ووحدة غير متوافقتين، نسبة بمقام0، وفترة معكوسة.
- المعرفة: مؤكد/تقريبي/لا يوجد/مجهول/لم يستكمل/غير منطبق، وتغير حالتها دون تزييف الماضي؛ استقلال معرفة الكمية عن معرفة التكلفة.
- الزمن: حدود اليوم والشهر والسنة بتوقيت عمّان، وقبض متأخر وقياس بقطع غير محسوم؛ لا تاريخ مستقبلي لحركة منفذة.
- الالتزام: نجاح وتراجع، نسخة حية أحدث، نفس المفتاح مع نفس الحمولة أو غيرها، تعطل المتصفح بعد الالتزام وقبل الإشعار، واستعادة في تبويب آخر.
- الاستعادة: ذاكرة ومتصفح، فارغ وممتلئ، كل عائلة وتبعياتها، ملف قديم/أحدث/تالف، نقص مساحة، رجوع دائم، الجيل والمسودات والقدرات الملغاة.
- الهاتف: الرجوع والإلغاء وتكرار النقر وإعادة التحميل والفراغ، إدخال0–9، أسماء الأزرار والأخطاء وقارئ الشاشة وتكبير النص. لا ادعاء مطابقة إتاحة من كتابة الحالة.

## 4. تحقق حسابي مكتبي محدود

فحصت10 علاقات حسابية مستقلة للأمثلة خارجMicro؛ منها البيع15/5/6 ثم تحصيل10، وتغطية200/120/80 ناقص80/30/20، والفاتورة60/30، والشراء غير المتتبع10 وكلفة جديدة2 وبيع25، وإجمالي10 لكمية3، وتوصيتاPD01/02. هذه الحسابات لا تثبت تطبيقها في المنتج أو التخزين، اعتماد السياسة مصدره موافقة المالك2026-10-27، لا نتيجة هذه الحسابات.

**تحديثP3:** ربطت الحالات بملف كلUNIT وتبعياته ومساراته واختباراته؛ التالي إضافة أدلة التنفيذ دون تغيير المعرفات أو إعلان الإغلاق من عد الصفوف.
