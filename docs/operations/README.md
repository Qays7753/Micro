# نظام تسليم الوكلاء في Micro

**الحالة:** `CURRENT / OPERATIONAL SYSTEM`

هذا المجلد يجعل GitHub، لا ذاكرة محادثة أو حسابًا معينًا، مصدر الاستمرارية بين الوكلاء. لا يغير معنى المنتج أو المال أو العقود؛ يوضح فقط **ما هو موجود الآن، وما المسموح أن يفعله الوكيل التالي، وكيف يسلم الشريحة بأمان**.

## الملفات الثلاثة التي يحتاجها كل Agent

| الترتيب | الملف | الغرض |
|---:|---|---|
| 1 | [`current-state.md`](current-state.md) | الحقيقة التنفيذية الحية: `main`، ما اندمج، ما يعمل، ما توقف، والخطوة التالية المسموحة. |
| 2 | [`micro-thinking-charter-v1.md`](micro-thinking-charter-v1.md) | هدف Micro وطريقة التفكير وحدود البساطة والصدق والاختيارية التي يجب فهمها قبل الكود. |
| 3 | [`agent-handoff-protocol-v1.md`](agent-handoff-protocol-v1.md) | قواعد الاستلام والتنفيذ والتسليم وحدود سلطة كل ملف. |
| 4 | [`slice-handoff-template.md`](slice-handoff-template.md) | القالب الذي يستخدمه الوكيل عند فتح أو إغلاق Slice. |

## قاعدة المصدر الواحد

لا يوجد ملف «محادثة ملخصة» موازٍ. عند اختلاف الملفات، تظل العقود والسياسات المالية صاحبة سلطة السلوك، ويظل `current-state.md` صاحب سلطة **حالة التنفيذ الحالية فقط**. لا يملك هذا المجلد أن يبيح ميزة تناقض عقدًا أو أن يعلن قدرة منفذة بلا PR وCI ودمج على `main`.

## بداية سريعة لوكيل جديد

```bash
gh repo clone Qays7753/Micro
cd Micro
git switch main
git pull --ff-only origin main
```

بعد ذلك اقرأ `AGENTS.md`، ثم الملفات الأربعة أعلاه بالترتيب. لا تبدأ تعديلًا قبل نشر بطاقة فهم وبطاقة استلام داخل PR أو Issue توضّح سياق المستخدم ونطاق الشريحة ومعيار قبولها وما لن يتغير.
