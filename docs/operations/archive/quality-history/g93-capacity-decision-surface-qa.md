# G9.3 — سطح قرار قيد التشغيل وQA

## التغيير المثبت

يستهلك `/schedule` الآن `buildCapacityDecisionViewModel` من طبقة Application، والذي يستدعي `deriveCapacityDecision`. يعرض سطح `DecisionPanel` للحالة المختارة، أو لليوم الأول في الأسبوع عند عدم اختيار يوم، مع `truth` و`nextAction` و`label` و`tone` القادمين من القرار؛ لا يعيد React حساب السعة ولا يقرأ التخزين مباشرة. يبقى التعارض رسالة مستقلة عن قرار السعة.

## اختبار الواجهة الحية ببيانات اصطناعية

تم إنشاء مشروع ومواعيد اصطناعية فقط داخل IndexedDB في متصفح sandbox، ثم التحقق من المسار `/schedule` وإزالة كل محتوى قاعدة البيانات بعد الانتهاء.

| السيناريو | الدليل الظاهر في `/schedule` |
|---|---|
| لا سعة معلنة | «سعة اليوم غير محددة»، «لا يعرض Micro رفضًا أو سعة صفرية»، والفعل «حدد سعة يومية فقط إذا كانت لديك قاعدة عملية قابلة للقياس» |
| 3 مواعيد، 160 دقيقة، سعة 240 | «ضمن القيد المعلن»، «لا يعني ذلك ضمان توفر كامل»، والفعل التشغيلي التالي دون badge قبول أو توصية |
| 3 مواعيد، 160 دقيقة، سعة 120 | «تحذير سعة — ليس رفضًا»، «الوقت المعروف يتجاوز القيد اليومي المعلن»، والفعل «راجع الموعد أو أجّل العمل بقرار المالك» |
| مدة مجهولة مع السعة | «تحتاج مراجعة المدة»، مع «لم تحول البيانات الناقصة إلى صفر» وفعل مراجعة الموعد؛ أزيلت هذه الحالة قبل اختبار over-limit حتى لا تُخفي البيانات الناقصة التجاوز |
| تعارض | «التعارض مستقل عن قرار السعة» مع عدد الموعد المتعارض، ولم يندمج مع `over_limit` |
| إزالة السعة | عاد القرار إلى `unknown` مع بقاء المواعيد والسجلات التشغيلية؛ ثم مُسحت جميع سجلات QA الاصطناعية |

لم ينفذ النقر على صفوف المواعيد أي كتابة؛ التوجيه إلى الموعد القائم وحده لا يغير الموعد أو الكاش أو الذمة أو النتيجة.

## RTL والمظهر والأحجام

تحقق المتصفح من `dir="rtl"`، وعُرضت الواجهة في Light وDark؛ كما التُقطت لقطات smoke للأبعاد 360×800 و390×844 و430×932 في `screenshots/`. هذه اللقطات تختبر shell التأسيس المتجاوب، بينما اختبار الحالات التفاعلية أعلاه نُفذ في متصفح sandbox بواجهة تشغيلية أكبر؛ لا أدّعي اختبار جهاز فعلي أو قبول iOS/Android.

## الفحوص والتنظيف

اجتازت اختبارات `capacityDecisionService` و`capacityDecisionViewModel` و`pnpm check` و`git diff --check`. بعد الاختبار أُفرغت مخازن IndexedDB الخمسة عشر، فعاد `/schedule` إلى شاشة التأسيس النظيفة. لا تغير هذه الشريحة `CashWallet` أو `FinancialEvent` أو الذمم أو `CostSnapshot` أو السعر أو نتيجة الفترة أو طلبًا تاريخيًا.

## الحدود

لا تقويم خارجي، ولا Dashboard، ولا حجز، ولا موارد متعددة، ولا مادة حرجة، ولا reminders، ولا توصية ملزمة، ولا أثر مالي. الفحص الحي محاكاة sandbox ببيانات اصطناعية فقط، وليس Pilotًا أو قبول إنتاج متعدد الأجهزة.
