# Micro UX — تقرير قبول G20

**التاريخ:** 27 أغسطس 2026
**النطاق:** M-11 إلى M-15، وM-24 عند ثبوت بقاء المشكلة على `main` الجديد.
**حالة QA المحلي:** PASS اصطناعي؛ لا يمثل قبول جهاز حقيقي أو Pilot.

## سؤال القرار

هل يستطيع صاحب المشروع من أول viewport في Finance أن يعرف وضع الكاش وفعل المراجعة التالي، ثم يفتح تفاصيل الفترة وG5 وO1 والسجل عند الحاجة، وهل تعرض بطاقة شراء المورد الحقيقة التشغيلية كاملة دون خلط الشراء بالمصروف أو تكلفة البيع؟

## التحقق

تم إنشاء بيانات اصطناعية محلية فقط. القيم المالية التي ظهرت في QA هي:

| الواقعة                                 |        قبل طبقات/نقل العرض |        بعد طبقات/نقل العرض | الحكم                                             |
| --------------------------------------- | -------------------------: | -------------------------: | ------------------------------------------------- |
| رصيد المحفظة                            |                 100.00 د.أ |                 100.00 د.أ | لم يتغير الحساب                                   |
| استثمار                                 |                  50.00 د.أ |                  50.00 د.أ | بقي منفصلًا عن الكاش والربح                       |
| استحقاق المالك                          |                  25.00 د.أ |                  25.00 د.أ | بقي منفصلًا عن المحفظة                            |
| سحب لتسوية الاستحقاق                    |                  10.00 د.أ |                  10.00 د.أ | بقي حركة مال مالك موثقة                           |
| مصروف مدفوع                             |                 200.00 د.أ |                 200.00 د.أ | بقي مصروفًا لا سحبًا شخصيًا                       |
| الكاش غير الموزع                        |                -150.00 د.أ |                -150.00 د.أ | ظهر تنبيه المراجعة دون تصحيح صامت                 |
| شراء مورد: الإجمالي / المدفوع / المتبقي | 120.00 / 30.00 / 90.00 د.أ | 120.00 / 30.00 / 90.00 د.أ | ظهرت القيم في البطاقة مع الاستحقاق وCTA دفع واحدة |

كما تم التحقق من أن طبقات O1 الست تبدأ `open=false` برمجيًا، وأن `summary` قابلة للتركيز وتفتح بـEnter، وأن Finance تعرض قرار الكاش في أول viewport. شُوهدت الواجهة في RTL وLight/Dark، مع تحقق headless محدود عند 360×844 و390×844 و430×844 على `/setup`؛ لم يُعتبر ذلك اختبار جهاز فعلي.

الفحوص الآلية النهائية بعد التنفيذ شملت التثبيت المجمد، audit بمستوى moderate، `format:check`، `lint`، `pnpm check` بما فيه الاختبارات وtypecheck وprototype check وbuild، و`git diff --check`، وجميعها PASS. التحذيرات غير المانعة اقتصرت على placeholders المعروفة لـUmami وتحذير حجم bundle المعروف.

## حدود صادقة

لم يتغير Domain أو Application أو LocalStore أو `schema=26` أو `export=17` أو أي معنى للحسابات والتاريخ والعكس. لم تُضف بيانات QA أو لقطات إلى المستودع، ونُظفت IndexedDB وCache Storage وService Worker وlocal/session storage وأُوقف خادم QA المحلي بعد التجربة.

لم يتم ادعاء اختبار Android أو iOS حقيقي، أو keyboard نظامية، أو PWA/Offline production، أو Cloudflare Production، أو Pilot بشري. بقي M-26 خارج الكود؛ لم يُمنع السحب ولم تُغيّر حقيقة الكاش السالب.
