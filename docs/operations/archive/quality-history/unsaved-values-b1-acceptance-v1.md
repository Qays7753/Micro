# سجل قبول B1 — حماية التعديلات غير المحفوظة

## سؤال القرار والنطاق

يسأل B1: «إذا أدخلت تكلفة أو اتفاقًا أو موعدًا ثم رجعت، هل أحافظ على عملي أو أقرر بوضوح تركه؟» لذلك يضيف حارسًا مشتركًا محدودًا إلى `CostEditor` و`AgreementEditor` و`ScheduleEditor`، مع إبقاء الحفظ فعلًا صريحًا من المستخدم وعدم تعديل أي معنى مالي أو عقد تخزين.

## ما تم تنفيذه

يقارن كل محرر القيم الأولية بالقيم الحالية. النموذج غير المعدل يمرر التنقل الداخلي مباشرة، بينما النموذج المعدل يوقف المسار ويعرض Drawer RTL بثلاثة أفعال: «احفظ واستمر»، «اخرج دون حفظ»، و«إلغاء». لا يحفظ الحارس تلقائيًا. إذا فشل التحقق أو الحفظ، تبقى الصفحة والـDrawer مفتوحين؛ وإذا نجح الحفظ فقط يستمر التنقل. يمرر App Shell أيضًا Bottom Navigation وQuick Action order عبر الحارس.

لا يدّعي هذا الإصلاح اعتراض browser back أو tab close، ولم يُستخدم `beforeunload` كبديل لتجربة الهاتف. لا يشمل الحارس `DraftEditor` أو `G5DeclarationEditor` أو بقية النماذج لأن الحد الأدنى المفوض حُصر في المحررات الثلاثة.

## الاختبارات الآلية

| المجال | الدليل |
|---|---|
| dirty/no-dirty | اختبارات `navigationDecision` تثبت المرور المباشر للحالة النظيفة وفتح القرار للحالة المعدلة. |
| الاختيارات الثلاثة | اختبارات `resolveUnsavedExit` تثبت save/discard/cancel كقرارات مستقلة. |
| الحفظ الصحيح | اختبار `completeSaveNavigation` يثبت أن النجاح ينفذ التنقل بعد الحفظ. |
| الحفظ الفاشل | اختبار `completeSaveNavigation` يثبت أن الفشل لا ينفذ التنقل. |
| النوع والبناء | `pnpm --filter @micro/prototype-web exec tsc --noEmit` و`pnpm check` ناجحان. |
| مراجعة المسار | `git diff --check` ناجح بعد اكتمال التعديلات. |

## QA حي ببيانات اصطناعية

أُجريت الجولة في Chromium sandbox على Vite محلي (`http://localhost:3001`) بواجهة RTL وببيانات اصطناعية فقط: ملف `اختبار B1`، مسودة `اختبار حارس التكلفة`، وعميل `عميل B1 اصطناعي`. لم تُستخدم بيانات مالك أو إنتاج.

| السيناريو | النتيجة المرصودة |
|---|---|
| CostEditor، تعديل مبلغ ثم Bottom Navigation | ظهر Drawer التعديلات غير المحفوظة بدل التنقل. |
| CostEditor، إلغاء | أُغلق Drawer وبقيت قيمة `5.00` المعدلة داخل المحرر. |
| CostEditor، خروج دون حفظ | انتقل إلى `/orders` وبقيت المسودة بلا Snapshot تكلفة جديد. |
| AgreementEditor، تعديل مصدر الاتفاق ثم Bottom Navigation | ظهر Drawer المشترك في RTL. |
| AgreementEditor، حفظ واستمر مع بيانات ناقصة | ظهر خطأ التحقق `سجل اسم العميل قبل تثبيت الاتفاق.` وبقي المسار وDrawer مفتوحين. |
| ScheduleEditor، تعديل المدة فقط ثم حفظ واستمر | رفض الحفظ برسالة اقتران الوقت والمدة، وبقي Drawer مفتوحًا. |
| ScheduleEditor، استكمال الوقت `14:00` ثم الحفظ | حُفظت `14:00 · 15 دقيقة` وأُضيف سجل تعديل محلي، ثم أصبح النموذج نظيفًا. |
| ScheduleEditor بعد الحفظ، Bottom Navigation | انتقل مباشرة إلى `/orders` بلا Drawer، وهو مسار no-dirty. |
| Dark mode وRTL ولوحة المفاتيح | بقي ScheduleEditor وDrawer مقروءين في Dark/RTL، وأثبت ضغط Tab أن أفعال Drawer عناصر قابلة للوصول عبر لوحة المفاتيح. |

## التنظيف والحدود

بعد الجولة أُلغيت التعديلات غير المحفوظة. حُذفت جميع قواعد IndexedDB المكتشفة، ومُسحت Cache Storage وlocalStorage وsessionStorage، وأُزيلت تسجيلات service worker؛ أكد المتصفح نجاح العمليات الأربع. هذه محاكاة متصفح محلي ببيانات اصطناعية وليست قبولًا على Android أو iOS أو Cloudflare Pages production، ولا تثبت اعتراض browser back أو tab close.

لا يغيّر B1 `src/domain` أو `CostSnapshot` أو schema/export أو التاريخ المالي أو الطلبات السابقة. لا يضيف Backend أو Auth أو Sync أو POS أو تقويمًا خارجيًا أو reminders أو قرارًا آليًا.
