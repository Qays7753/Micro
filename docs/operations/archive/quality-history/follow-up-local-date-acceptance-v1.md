# قبول A1 — تصنيف موعد المتابعة المحلي

**الحالة:** `LOCAL ACCEPTANCE RECORDED`

**النطاق:** إصلاح تصنيف موعد متابعة محفوظ محليًا في `Asia/Amman` وعرضه للمستخدم بصيغة `DD/MM/YYYY`. لا يغير هذا الإصلاح قيمة `followUpDate` المخزنة بصيغة `YYYY-MM-DD`، ولا ينشئ موعد تسليم أو Schedule أو Reminder أو أثرًا ماليًا.

## سؤال القرار

صاحب المشروع يريد أن يعرف من شاشة الطلب هل المتابعة **متأخرة** أو **مستحقة اليوم** أو **قادمة**، من دون أن تتغير النتيجة بسبب صيغة تاريخ العرض أو اتجاه RTL.

## ما تغير

أضيفت طبقة pure صغيرة في `client/src/application/agreements/followUpDate.ts`. تستخرج اليوم المحلي من اللحظة الزمنية في `Asia/Amman`، وتصنف التاريخ إلى `none` أو `invalid` أو `overdue` أو `today` أو `upcoming`، وتعرض التاريخ الصحيح بصيغة `DD/MM/YYYY` مع عزل LTR. يستخدم `AgreementContextService` و`OrderDetail` الطبقة نفسها بدل تكرار المقارنة أو الاعتماد على نص `Intl` المعروض.

## الاختبارات الآلية

| السيناريو | الدليل | النتيجة |
|---|---|---|
| بلا تاريخ | `classifyFollowUpDate(null, "2026-08-24")` | `none` |
| قبل اليوم | `2026-08-23` مقابل `2026-08-24` | `overdue` |
| اليوم | `2026-08-24` مقابل `2026-08-24` | `today` |
| بعد اليوم | `2026-08-25` مقابل `2026-08-24` | `upcoming` |
| تاريخ تقويمي غير صالح | `2026-02-30` | `invalid` |
| عبور UTC إلى اليوم المحلي | `2026-08-23T22:30:00.000Z` | `2026-08-24` في عمّان |
| العرض | `2026-08-24` | `24/08/2026` |

## QA حي ببيانات اصطناعية فقط

شُغلت نسخة production preview محليًا عبر `/orders/order-c61300d3-2bd3-4bc4-9598-09ea67d90ca2` ببيانات مؤقتة أنشأها المسار الحقيقي للواجهة. اختُبرت الحالات التالية من بطاقة «ذاكرة الاتفاق» في `OrderDetail`:

1. حفظ `2026-08-23` أعاد `متابعة متأخرة` و`23/08/2026`.
2. تغيير الموعد إلى `2026-08-24` مع سبب مكتوب أعاد `متابعة مستحقة اليوم` و`24/08/2026`.
3. تغيير الموعد إلى `2026-08-25` مع سبب مكتوب أعاد `متابعة قادمة` و`25/08/2026`.
4. إزالة الموعد مع سبب مكتوب أعادت `لا يوجد موعد متابعة`، وسجلت التاريخ السابق والجديد والسبب في تاريخ المتابعة.
5. محاولة إزالة الموعد دون سبب رُفضت برسالة واضحة، وبقي التاريخ المحفوظ كما هو.

تحققت الشاشة في RTL وLight/Dark ضمن المعاينة المحلية. بعد انتهاء الفحص حُذفت قاعدة IndexedDB `micro-prototype-local`، ومُسحت `localStorage` و`sessionStorage` وCache Storage؛ نتيجة التحقق النهائية: لا قواعد بيانات، ولا مفاتيح تخزين، ولا caches متبقية.

## حدود القبول

هذا قبول مصدر/اختبار آلي ومعاينة محلية فقط. لم يُدّعَ اختبار جهاز Android أو iOS فعلي، ولم يُدّعَ اختبار عنوان Cloudflare Pages production، ولم تُستخدم بيانات مالك حقيقية. اختبار أبعاد الهاتف الفعلية 360/390/430 ولوحة المفاتيح والرجوع يبقى ضمن QA الشامل المطلوب للمسارات اللاحقة.

## الحواجز

لم يتغير Domain أو `CostSnapshot` أو schema أو export أو السعر أو العربون أو الدين أو الكاش أو موعد التسليم أو Schedule. لا توجد رسائل أو CRM أو Reminder أو مزامنة أو Backend أو Auth أو POS أو Calendar خارجي.
