# سجل قبول A3 — فصل المجهول عن الصفر المعروف

**التاريخ:** 24 أغسطس 2026

**الفرع:** `fix/unavailable-values-known-zero`

**سؤال القرار:** هل الرقم الذي يراه المالك متاح فعلًا، وما الذي دخل في القراءة أو منع اكتمالها؟

## التغيير المحدود

أصبحت نتيجة الفترة في Application تحمل `resultMinor: null` وحالة `invalid` عندما تكون حدود الفترة غير صالحة، وتحمل `resultMinor: null` عندما تكون الفترة `incomplete`. بقيت المجاميع الجزئية المعروفة — مثل الإيراد النهائي المسجل والتكلفة المباشرة والمصروف القديم — مرئية كي لا تختفي البيانات الصحيحة بسبب نقص جزء آخر. أما الفترة الخالية من أي أثر مؤثر فتبقى `recorded_only` مع `resultMinor: 0` بوصفه صفرًا معروفًا.

في Finance لا تعرض القراءة الإجمالية `0.00` عندما تكون النتيجة غير متاحة. تعرض الواجهة `غير متاح`، وتذكر السبب والفعل التالي، وتُظهر في صيغة الفترة أن المصروف التشغيلي يشمل «القديم بلا سياق». وفي G5 تبقى قيمة التوقع `غير متاح` عندما تكون `projectedCashMinor` غير موجودة، مع إبقاء الكاش المسجل والتدفقات الصفرية المعروفة منفصلة.

لم يتغير Domain G5 أو `CostSnapshot` أو schema/export أو أي عملية كتابة مالية. هذا إصلاح محدود لحدود Application والعرض فوق العقود القائمة؛ لا يحول القراءة إلى صافي ربح نهائي أو COGS فعلي أو توصية مالية.

## مصفوفة الحالات

| الحالة | السلوك المقبول | الدليل |
|---|---|---|
| فترة معروفة بلا سجلات | `recorded_only` و`resultMinor: 0`، وتظهر `0.00` | اختبار Application |
| فترة ناقصة بسبب طلب مسلّم غير نهائي | `incomplete` و`resultMinor: null`، مع بقاء المجاميع المعروفة والصفر الجزئي منفصلًا | اختبار Application ورسالة السبب |
| فترة ناقصة بسبب مصروف تقديري أو حصة مشتركة أو مصروف قديم | `incomplete` و`resultMinor: null`، مع إظهار مبالغ البنود المسجلة وأسباب النقص | اختبارات Application وFinance |
| حدود فترة غير صالحة | `invalid` و`resultMinor: null`، دون نتيجة رقمية بديلة | اختبار Application |
| G5 بلا أساس أفق كافٍ | الكاش والتدفقات المعروفة تبقى ظاهرة، والتوقع يظهر `غير متاح` | اختبار Domain وG5 وQA حي |

## QA حي اصطناعي

شُغّلت نسخة الإنتاج المحلية على `http://localhost:4173/finance` بملف نشاط اصطناعي فقط. في الفترة الفارغة ظهر `0.00` للنتيجة الأوسع لأن الحالة معروفة ومسجلة بلا سجلات، بينما بقي الهامش لكل وحدة ونقطة التعادل `غير متاحين` لعدم وجود كمية نهائية موجبة. في بطاقة السيولة ظهر الكاش والتدفقات الصفرية المعروفة، وظهر التوقع بعد المعلن `غير متاح` مع سبب أن الأفق القصير غير مكتمل.

تمت معاينة السطح في RTL وDark mode مع إشعار التثبيت/التحديث الموجود في النسخة المحلية. لم تُنشأ سجلات مالية اصطناعية في A3، ولم تستخدم QA بيانات مالك حقيقية. أزيلت بيانات المتصفح الاصطناعية بعد الجولة السابقة، وسجل `/tmp/micro-repair-qa.md` تفاصيل المشاهدة المحلية.

## الحدود

هذا السجل يثبت الاختبارات المصدرية والبناء ومعاينة Finance/G5 المحلية فقط. لم يُدّعَ اختبار Android أو iOS فعلي أو Cloudflare Pages production بعنوان عام. تبقى أي قراءة ناقصة أو غير صالحة موسومة بوضوح، ولا تُستبدل بصفر أو باستنتاج مالي جديد. يجب على أي مرحلة لاحقة الحفاظ على الفصل بين subtotal معروف والنتيجة غير القابلة للاعتماد، وعدم تغيير الحساب أو Domain لجعل النص أجمل.
