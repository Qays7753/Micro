# عرض النقل والتوافق والذهبيات (Transfer / Legacy / Golden View)

## 1. الحدود المحروسة الثابتة

| الثابت | القيمة الحية | مكانها الحاكم |
|---|---|---|
| زوج المخطط/التصدير | `localSchemaVersion=38` / `localExportVersion=30` | `storage/local/types.ts` (رفعهما قرار مالك بdiff مزدوج — AGENTS §10) |
| عقد مظروف النقل | تكامل الملف، الختم، العدادات، رفض التلاعب | `docs/contracts/39-export-envelope-integrity-contract.md` |
| الاستيراد | تحقق كامل قبل `replaceSnapshot` الذري + نسخة احتياطية مُتحقّقة (EXE-014) | `application/transfers/localTransferService.ts` + العقد 39 |

## 2. الأزواج التاريخية (Legacy Acceptance)

الأزواج التاريخية المقبولة تُهاجر بأمان فقط؛ قائمتها الكنسية وقاعدة «اختياري-عند-الغياب» داخل `localTransferService` والعقد 39، وتثبتها اختبارات القبول التاريخية (مثل `ownerEntitlementTransfer.test.ts`). **لا يُغيَّر قبول تاريخي بلا قرار نسخة موثق.**

## 3. الذهبيات وMANIFEST

| السؤال | المصدر |
|---|---|
| أين الذهبيات وكيف تُحدَّث رسميًا؟ | مجلد ذهبيات النقل + `GOLDEN_UPDATE=1` عبر المسار الرسمي فقط (المسار موثق في العقد 39 وتقارير موجات النقل) |
| ما يثبت سلامة المجموعة؟ | ملف MANIFEST (بصمات الذهبيات) + اختبارات دورة ذهبية كاملة (تصدير → استيراد → تحقق) |
| رفض التلاعب | اختبارات tamper (إسقاط عائلات/ختم/عدادات من ملف مُعاد ختمه) — التشغيل: `pnpm --filter @micro/prototype-web test -- --run tamper transfers` |

## 4. قاعدة الدمج مع موجات النقل

أي موجة تلمس النقل: (1) لا تحديث ذهبيات إلا عبر المسار الرسمي وبسبب موثق؛ (2) أي انحراف بايت/رفض/قبول تاريخي غير مقصود = توقف مع `SEMANTIC_CHANGE_MANIFEST`؛ (3) الفحوص المركزة: transfers + export + migration + tamper + adapterConformance + typecheck + check-entity-touchpoints (قائمة R10-B2 الكنسية).

## 5. ماذا يثبت هذا العرض وماذا لا يثبت

**يثبت:** مسارًا واحدًا لكل من يحتاج فهم حماية النقل دون بحث. **لا يثبت:** صحة الذهبيات أو سلامة أي ملف — الدليل هو نجاح اختبارات المصادر أعلاه. هذا عرض إحالي: عند أي تغيير مستقبلي تُحدَّث المصادر أولًا ثم يُحدَّث هذا الملف بالإحالة.

## 6. نقطة العودة (Rollback)

عرض توثيقي إحالي؛ إرجاعه commit توثيقي واحد بلا أثر تشغيلي.
