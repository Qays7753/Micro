### 3.1 تكامل التخزين والاستعادة

الزوج الحي: schema `43` وexport `34` (`storage/local/types.ts`؛ ارتفع بأمر المالك 12AA 2026-11-24 — مخزن فتحة مفتاح تشفير النسخ؛ كان 42/34 بعد S14). سجل `RELEASED_LEGACY_EXPORT_PAIRS` يقبل 29 زوجًا موروثًا (34/42 صار موروثًا)، والإجمالي مع الزوج الحالي 30؛ كتابة الأزواج في السجل بصيغة export/schema، بينما الزوج الحي هنا schema/export. تاريخيًا كان زوج S12 schema `40`/export `33`، وصار 32/40 (export/schema) موروثًا؛ وأضافت S14 الزوج 33/40. الاستيراد يتحقق قبل `replaceSnapshot` الذري من العلاقات والعقود، ويهاجر الأزواج المقبولة تمثيلًا دون إعادة أعمال. **الحدود:** لا مزامنة ولا استعادة بين أجهزة ولا Cloud backup؛ التصدير اليدوي مطلوب قبل تغيير الهاتف أو مسح بيانات المتصفح.

## 4. حدود مالية غير قابلة للتفاوض

> collection ≠ profit، debt ≠ cash، purchase ≠ COGS، owner money ≠ sale/expense، missing ≠ zero.

لا تصف أي سطح بأنه COGS كاملة أو صافي ربح نهائي أو قيمة مشروع أو توقع مضمون. في G3، COGS اختيارية من دليل استهلاك فقط؛ عند غياب الدليل يبقى Snapshot بديلًا معلنًا. لا يغير أي مسار `CostSnapshot` أو طلبًا تاريخيًا بصمت. لا توزع مصروفًا أو هدرًا أو استهلاكًا عامًا على طلب/منتج بلا عقد وأساس ظاهر. لا تحول وقت التنفيذ إلى أجر أو تكلفة فعلية أو سعر مقترح. كل تصحيح حساس بعكس أو تسوية موثقة؛ لا حذف صامت أو restatement.
