# حالة Micro الحية — مصدر الاستلام التنفيذي

**الحالة:** `CURRENT / UPDATE WITH EVERY MERGED SLICE`
**آخر تحديث:** 24 أغسطس 2026
**مرجع Git:** شغّل `git switch main && git pull --ff-only origin main && git rev-parse --short HEAD`؛ لا تعتمد رقم commit ثابتًا داخل وثيقة حية.

> هذا الملف يجيب عن سؤال واحد: **«إذا فتحت المستودع الآن، ما الذي أستطيع قوله أو تغييره بأمان؟»** لا يغير العقود ولا يحل محلها.
>
> **حالة الدمج الحالية:** PWA مدمجة على `main` عبر PR #54 وG5 عبر PR #53 وG6-A عبر PR #57، كما اندمجت G6-B وG7-A عبر PR #60. لا توجد شريحة وظيفية مفتوحة؛ `main` هو مرجع القدرات المدمجة.

## 1. قاعدة التشغيل الحالية

| الحقل | القيمة |
|---|---|
| الفرع المعتمد | `main` فقط |
| لغة العمل | العربية؛ الإدخال الرقمي ASCII/LTR |
| نمط Prototype | Web-first، RTL، phone-first، local-first عبر IndexedDB |
| التدفق المعتمد | React → Application Service → Domain → `PrototypeLocalStore` → IndexedDB |

| حساب المستخدم/السحابة | Auth والمزامنة والبيانات الحقيقية غير منفذة؛ PWA تشغيلية محلية/ثابتة فقط بلا حساب أو سحابة |

## 3. الحدود غير القابلة للتفاوض

لا تصف أي سطح حالي بأنه COGS فعلي أو صافي ربح نهائي أو قيمة مشروع أو توقع نقدي. لا يغير أي تعديل `CostSnapshot` أو طلبًا تاريخيًا بصمت. لا توزع مصروفًا مشتركًا على طلب أو منتج بلا عقد وأساس معلن. لا تحول الوقت الفعلي إلى أجر أو تكلفة فعلية أو سعر مقترح. لا تحذف حدثًا حساسًا؛ صححه بعكس أو تسوية موثقة.

## 4. الحالة المتوقفة عمدًا

**لا تبدأ أي مجموعة أو قدرة مالية/بنية جديدة الآن.** اكتملت G4-B وG5 وG6-A وG6-B وG7-A، وأضيفت PWA التشغيلية المصرح بها كطبقة نشر ثابتة فقط. لا توسع G6-B إلى daily/RRULE/reminders أو التقويم الخارجي أو الحجز أو الموارد. لا توسع G7-A إلى CRM أو رسائل أو تذكيرات تلقائية. لا تنتقل إلى POS أو مزامنة أو Auth أو أي معنى سحابي قبل طلب صريح جديد من مالك المنتج. لا توسّع الوقت الفعلي إلى أجر أو تكلفة أو توصية سعر، ولا توسّع G5 إلى صافي ربح نهائي أو COGS فعلي أو تنبؤ/توصية من دون عقد مستقل.

## 7. ما يجب تحديثه عند الإغلاق القادم

عند إغلاق/دمج شريحة جديدة، يعدل الوكيل هذا الملف في نفس PR ليحدث: commit/PR، جدول «ما هو منفذ»، جدول «الحالة المتوقفة عمدًا»، إصدارات schema/export إن تغيرت، ومسار القراءة التالي. PWA مدمجة على `main` عبر PR #54 وG5 عبر PR #53 وG6-B/G7-A عبر PR #60، وA1 عبر PR #70، وA2 عبر PR #71. إصلاح A3 على الفرع الحالي ولم يُفتح PR له بعد؛ لا تبدأ B1 قبل دمج A3 بفرع وPR مستقلين. يظل اختبار iOS الفعلي مطلوبًا قبل إعلان قبول PWA الإنتاجي متعدد المنصات. ثم يحدث `todo.md` فقط بما يطابق الواقع المندمج.

## 8. قرار G8.1 — الثقة والاستعادة المحلية

أثبتت مراجعة `main` أن طبقة PWA والاستعادة المحلية المطلوبة في G8.1 موجودة ومختبرة محليًا: التثبيت اختياري وصادق، التحديث بقرار المستخدم، وApp Shell يعمل دون اتصال بعد زيارة ناجحة، بينما يظل السجل المالي محليًا على الجهاز. لا يَعِد Micro بنقل البيانات بين الأجهزة؛ يجب تصدير ملف محلي قبل حذف بيانات المتصفح أو تغيير الجهاز. لم يتغير Domain أو `CostSnapshot` أو schema/export أو LocalStore في هذه المرحلة.

القبول المتاح هو قبول مصدر/بناء/محاكاة محلية فقط. لا يُعلن قبول Android أو iOS أو Cloudflare Pages الإنتاجي قبل اختبار جهاز فعلي وعنوان الإنتاج. يبقى `iOS physical acceptance pending` و`Cloudflare Pages production verification pending` حدّين صريحين.

يوجد في التفويض مرجع إلى `docs/decisions/remaining-capabilities-review-v2.md`، لكنه غير موجود في `main`؛ المرجع الموجود هو v1 وأقدم من الحالة الحية. لذلك اتُّبعت الحالة الحية والعقود، وسُجل هذا الفرق بدل اختلاق ملف أو حالة جديدة.

## 9. قرار G8.3 — الاستيراد الافتتاحي الموجّه

أصبح في فرع G8.3 معالج Application مستقل يقرأ ملفًا افتتاحيًا محدودًا، يتحقق منه كاملًا قبل الكتابة، يبني سجلات Domain افتتاحية للكاش والمادة، ويستخدم `replaceSnapshot` الذري على Store فارغ فقط. المعالج يرفض الملف الناقص أو التالف أو غير المدعوم، يرفض Store غير الفارغ، ويحافظ على التكرار الآمن عبر مفاتيح deterministic مرتبطة بـ`importId`. الواجهة تعرض معاينة عربية قبل التأكيد وتوضح أن الموقف الافتتاحي ليس مبيعات أو ربحًا.

لم تتغير schema/export العامة، ولم تُضف مزامنة أو حسابات أو تاريخ مالي مختلق. قبول هذه القدرة في `main` مشروط بمرور CI/Cloudflare في PR؛ QA الجهاز الفعلي وCloudflare الإنتاجي يظلان خارج بيئة sandbox.

## 10. قرار G9.2 — قراءة قيد السعة

تضيف طبقة Application دالة قرار صريحة فوق `ScheduleDay` القائم. تعيد `unknown` عند عدم تفعيل السعة، و`needs_review` عند مدد ناقصة، و`within_limit` أو `over_limit` عند وجود بيانات كاملة. يبقى التعارض منفصلًا، ولا ينتج القرار كتابة أو تغييرًا ماليًا أو تعديلًا للموعد.

## 11. قرار G9.3 — سطح قرار التشغيل

يستهلك `/schedule` الآن `buildCapacityDecisionViewModel` من طبقة Application ويعرض عبر `DecisionPanel` الحالة والحقيقة المعروفة والفعل التالي لليوم المختار أو اليوم الأول في الأسبوع. يعرض التعارض كتحذير مستقل؛ لا تحسب React السعة ولا تكتب إلى التخزين. الحالات الفارغة والناقصة منفصلة، والقرار النهائي يبقى للمالك.

تم اختبار الواجهة الحية ببيانات اصطناعية فقط لحالات عدم وجود سعة، وضمن الحد، وفوق الحد، والمدة المجهولة، والتعارض، وإزالة السعة، ثم أُفرغت مخازن IndexedDB. أضيفت لقطات smoke للأبعاد 360/390/430، وتحقق RTL وLight/Dark؛ لا يُعلن قبول جهاز فعلي أو Pilot أو إنتاج متعدد الأجهزة.

## 12. تصحيح قبول G9 — ربط القرار بالواجهة

صُحح نطاق G9.2/G9.3: القرار لم يعد دالة معزولة؛ صار مستهلكًا فعليًا في `/schedule` عبر view model و`DecisionPanel`. لا يغير الربط أي مال أو طلب أو Snapshot أو موعد عند القراءة أو التوجيه، ولا يضيف قدرة تشغيلية جديدة.

## 13. قرار G9.4/G9.5 — لا توسعة متابعة جديدة الآن

راجعت الشريحة الحالية فوق G7-A وسيناريوهات المتابعة المحلية. لم تثبت فجوة واحدة محددة ومدعومة تمنع قرارًا متكررًا؛ G7-A يعبر عن المصدر والملخص والموعد والسبب وتاريخ التغيير/الإزالة. لذلك لا تضاف وظيفة جديدة ولا حقول CRM، وتبقى G9.5 محققة بقرار عدم التوسعة. إعادة الفتح تحتاج دليل Pilot حقيقيًا على فقد معلومة محلية لا يمكن تمثيلها حاليًا.
