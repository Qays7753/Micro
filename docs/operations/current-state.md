# حالة Micro التشغيلية الحية

**الحالة:** `CURRENT / UPDATE WITH EVERY MERGED SLICE`
**آخر تحديث:** 13 سبتمبر 2026 (المجموعة ١٠ — خطة المعالجة الرباعية: بوابة تحقيق التقريب ومطابقة محوّلات التخزين وخدمة النقل — قرار «الإبقاء على سلوك التقريب الحالي»، مصفوفة مطابقة ٢٨×٢ للمحوّلين، تفكيك دورة الحياة/الترحيلات/البدائيات/محرك اللقطة وحدود النقل/العدادات/المهايجات خلف الواجهات نفسها — §39؛ المخطط/التصدير ٣٥/٢٧ بلا تغيير ولا كتابة مالية)
**قاعدة العمل:** العربية، RTL، phone-first، والأرقام المالية ASCII/LTR.

> هذا السجل يجيب عن سؤال واحد: **«إذا فتحت المستودع الآن، ما الذي أستطيع قوله أو تغييره بأمان؟»** لا يحل محل العقود أو فحوص Git. قبل أي عمل على البرنامج المالي نفّذ دائمًا `git fetch origin --prune` واقرأ رأس الـBridge البعيد؛ لا يُعامل أي SHA مذكور هنا كرأس حالي بعد commits لاحقة.

### 3.2 حدود شريحة First-use الحالية

هذه الشريحة لا تغيّر العقود المالية أو Snapshot أو schema `26` أو export `17`، ولا تغيّر مسار UI → Application → Domain → `PrototypeLocalStore` → IndexedDB. كل حقل رقمي قابل للتحرير في Prototype يمر عبر `EnglishNumberInput` أو `EnglishQuantityInput`؛ رصيد O1 الافتتاحي يستخدم `signedInteger` صراحة، وحقول رصيد البداية لا تستثني سلوك الصفر الافتراضي. لم تُضف سياسة تاريخ أو دعم decimal جديد لكمية الطلب؛ `12.000` في عقد integer يبقى غير صالحًا ظاهرًا ويمنع الحفظ بدل تضخيمه. هذه حدود تاريخية لشريحة First-use المدمجة؛ ما زال قبول الجهاز الفعلي وPWA المثبتة وOffline الإنتاجي وAndroid/iOS وCloudflare Pages production وPilot البشري غير منفذ.

## 4. حدود مالية غير قابلة للتفاوض

> collection ≠ profit، debt ≠ cash، purchase ≠ COGS، owner money ≠ sale/expense، missing ≠ zero.

لا تصف أي سطح بأنه COGS كاملة أو صافي ربح نهائي أو قيمة مشروع أو توقع مضمون. في G3، COGS اختيارية من دليل استهلاك فقط؛ عند غياب الدليل يبقى Snapshot بديلًا معلنًا. لا يغير أي مسار `CostSnapshot` أو طلبًا تاريخيًا بصمت. لا توزع مصروفًا أو هدرًا أو استهلاكًا عامًا على طلب/منتج بلا عقد وأساس ظاهر. لا تحول وقت التنفيذ إلى أجر أو تكلفة فعلية أو سعر مقترح. كل تصحيح حساس بعكس أو تسوية موثقة؛ لا حذف صامت أو restatement.

## 7. متطلبات الإغلاق القادم

## §24. المجموعة ٢ — المخزون الانتقائي (عقد ٢٨، 2026-09-04)

**ما يمكن قوله الآن بأمان:**
- لكل مادة قرار متابعة صريح (`Material.tracking`)؛ غياب الحقل = متتبَّعة (إرث). غير المتتبَّعة هوية تكلفة: بلا رصيد ولا حركة، وتُرفض حركاتها الجديدة برسالة صدق.
- رصيد البداية معرفة معلنة: «غير محدد بعد» يعرض شرطة لا صفرًا؛ «صفر مؤكد» حالة مستقلة؛ والمؤكد الموجب حركة بداية مع المادة ذرّيًا.
- الحركات تحمل وسم معرفة تكلفة: قيمة صفرية ⇐ غير معروفة؛ والمجهول يُصرَّح به في كل سطح (الموضع، مقارنة الطلب، هدر الفترة) لا يُعرض 0.00 واثقة.
- الشراء لا يزيد المخزون قبل استلام صريح؛ جسر «استلم المواد في المخزون» يعبّئ بلا كتابة؛ الاستلام الجزئي يسوّى بحدود قيمة وكمية، والتعديل لا يقلّ تحت المستلم.
- النقص سجل موثق موجب الكميات (D-027) — لا رصيد سالب مخزن أبدًا؛ الحل صريح ببيان، و MIC-8 يُظهره WARN.
- إيقاف المتابعة بحوار عواقب؛ الحركات كلها تبقى؛ وإعادة التفعيل تعيد الرصيد «غير محدد بعد» حتى يؤكد.
- الهدر غير نقدي: سطر قراءة الفترة مُسنَد إلى حركات الهدر بأساس occurredOn، خارج نتيجة الفترة عمدًا.
- الاستهلاك لطلب أو ببيان مشروع؛ ومقترحات مواد التقدير تعبّئ بلا أي حركة أو حدث.

**ما لا يجب فعله:** لا تكتب حركة مخزون من أي واجهة خارج مسار الخدمة؛ لا تعتبر غياب tracking/opening/costKnowledge حالة خاصة (إنه الإرث)؛ ولا تعتمد PASS من MIC-8 مع نقص مفتوح (إنه WARN بالتصميم).
