## معيار موحد لحقول الأرقام

عند عرض `0.00` أو `0` كقيمة افتراضية غير معدلة، يفرغ التركيز العرض فقط كي يكتب المستخدم مباشرة. إذا خرج المستخدم بلا إدخال، يعود العرض الافتراضي ويظل الصفر قيمة مخزنة عند فرضه العقد. إذا عدّل المستخدم القيمة، بما في ذلك إدخال صفر حقيقي، لا يمسحها التركيز تلقائيًا. الحقول الاختيارية ذات القيمة `null` تبقى فارغة ولا تُحوّل إلى صفر. الإدخال غير الصالح غير الفارغ يبقى ظاهرًا مع حالة invalid قابلة للإصلاح؛ لا يتحول إلى آخر رقم صالح بصمت.

طبّق المعيار عبر `EnglishNumberInput` و`EnglishQuantityInput` على جميع حقول الأرقام القابلة للتحرير في Prototype، بلا استثناء لحقول رصيد البداية؛ يبقى الصفر الافتتاحي مسموحًا كقيمة مخزنة، لكن الصفر الافتراضي غير المعدّل يفرغ عرضيًا عند التركيز ويعود عند الخروج فارغًا. أضيف وضع `signedInteger` صريح لرصيد O1 الافتتاحي، مع بقاء `-` الوسيط مرئيًا وغير صالح و`-500` صالحًا. جرى نقل مبلغ G5 وحقول Catalog الرقمية إلى primitives نفسها، بينما بقيت `date` وحقول النصوص الأصلية تحت سيطرة الصفحة.

## النطاق والحدود

تم استخدام بيانات اصطناعية فقط. لم تُمسح أو تُعدّل بيانات مستخدم حقيقية. تم تشغيل typecheck، suite المستودع، suite Prototype المستهدفة، build، و`git diff --check`. اختبار Export موجود في المنتج خارج تعديل التخزين؛ Import وOffline الحقيقي والهاتف الفعلي وPWA المثبتة وiOS/Android وPilot لم تُثبت بهذه الشريحة. السحب الذي يجعل الكاش سالبًا وتقرير التصميم القادم وExpansion بقيت خارج النطاق.
