# Micro — بروتوكول محاكاة الشخصيات والسياقات v1

**الحالة:** `CURRENT / EXECUTION PROTOCOL / DERIVED`
**المالك:** Manus Agent 1
**تاريخ الإنشاء:** 23 أغسطس 2026

## الغرض والسلطة

هذا الملف يضيف **غلاف سياق تنفيذ** إلى مجموعة [`scenario-test-set-v1.md`](../scenarios/scenario-test-set-v1.md)، ولا يستبدلها ولا يغيّر شخصياتها أو حالاتِها أو أسئلتها. تبقى الشخصيات P01–P10، والحالات المئة، والأسئلة المئة هي المصدر canonical. يضيف البروتوكول فقط شروط اليوم والاستخدام التي قد تكشف خللًا في التجربة: ضغط الوقت، التعب، الغضب، النسيان، الطلبات المتزامنة، المقاطعة، القناة، ودرجة المعرفة.

> هذه محاكاة حتمية على بيئة اختبار محلية وبيانات اصطناعية. هي لا تثبت قبول السوق، أو الفهم البشري، أو العودة، أو الاستعداد للدفع. هذه الأسئلة لا تُحسم إلا عبر Pilot محدود مع أصحاب مشاريع حقيقيين.

## Major Discussion Points

## 1. نطاق التنفيذ الحالي

المحاكاة تقيس **Prototype المنفذ فعليًا**، لا الرؤية الكاملة في الوثائق. النطاق التنفيذي الحي هو مسار `custom_craft` المحلي: مسودة طلب أو تصميم مخطط، تكلفة مواد/وقت/تغليف/توصيل/هدر، سعر حماية، اتفاق وموعد وعربون، انتقالات تنفيذ، تسليم، تحصيل المتبقي أو تسجيل دين، ونتيجة طلب محدودة بدرجة معرفة. لا يوجد في التنفيذ الحالي Ledger عام أو مخزون عام أو POS أو تقارير ربح مشروع أو نقطة تعادل أو مصاريف مشتركة أو مزامنة أو إشعارات خلفية.

| مستوى النتيجة | المعنى | ما يثبت في هذا البروتوكول |
| --- | --- | --- |
| `PASS_CURRENT` | يكمل المسار الحي النتيجة المطلوبة ضمن حدوده، من دون خرق عقد مالي. | قدرة تنفيذية حالية محددة، لا تبنٍ بشري. |
| `PARTIAL_CURRENT_UX_GAP` | توجد نواة مفيدة، لكن هناك نقص في مدخل، سياق، توجيه، استئناف، أو عرض يضعف اكتمال حالة الشخصية. | فجوة محددة تربط برحلة أو route، لا اقتراح عام. |
| `CONCEPT_VALID_DEFERRED` | تعالج الوثائق/العقود سؤال الشخصية منطقيًا، لكن Prototype لا يملك مسارًا أو عقدًا أو بيانات كافية. | تأجيل صريح، لا نجاح تنفيذي. |
| `REJECT_AVOID` | الفكرة تطلب سلوكًا يخالف عقود Micro أو يحوله إلى ERP/POS عام، أو تعرض رقمًا غير صادق. | قرار رفض موثق، لا فجوة بناء. |
| `PILOT_NEEDED` | السؤال يتعلق بالفهم أو الثقة أو العودة أو مدى ملاءمة التدخل في الحياة اليومية. | فرضية تجربة بشرية، لا نتيجة محاكاة. |

## 2. نموذج السياق الحتمي

لكل تشغيل، نثبت قيمة واحدة من كل بعد في الجدول التالي قبل فتح التطبيق. لا يحق للمشغّل تعديل السيناريو بعد رؤية النتيجة؛ إذا فشل المسار، يسجل الفشل كما حدث.

| البعد | القيم المحددة | ماذا يختبر؟ |
| --- | --- | --- |
| نمط اليوم | عادي، ذروة طلبات، يوم هادئ، يوم بلا طلب، نهاية دورة/موسم | هل يبقى الفعل التالي مفيدًا خارج لحظة البيع؟ |
| ضغط الوقت | منخفض، متوسط، عالٍ | وضوح الأولوية، طول المسار، وحفظ التقدم. |
| الحالة المعرفية/العاطفية | مرتاح، متعب، منزعج، متردد، نسيان جزئي | هل تقلل الواجهة الحمل بدل شرح مالي عام؟ |
| التزامن | طلب واحد، طلبان مستقلان، طلبان مرتبطان، مقاطعة ثم استئناف | ترتيب العمل، ثبات المسودات، وعدم دمج السياقات. |
| قناة الاتفاق | محادثة، مكالمة، لقاء مباشر، أخرى | حفظ مصدر الاتفاق فقط من دون فعل مشاركة خارجي مزيف. |
| ثقة البيانات | معروف، تقديري، ناقص، متغير | ظهور درجة المعرفة ومنع الصفر/النتيجة القطعية. |
| التسوية | بلا عربون، عربون، تحصيل متبقٍ، دين بعد التسليم، حالة تحتاج مراجعة | الفصل بين الكاش والنتيجة والدين والتسليم. |
| الانقطاع | لا انقطاع، رجوع آمن، إعادة تحميل، إعادة ضغط | المسودة المحلية، الاستئناف، وidempotency. |

## 3. قواعد إجراء موحدة

تبدأ كل حالة من قاعدة بيانات اختبار نظيفة، مع ملف مشروع تجريبي لا يحمل بيانات أشخاص حقيقيين. يسجل المشغّل route الفعلي، المدخل الأدنى، الحالة المعرفية، النتيجة المرئية، الفعل التالي، وأثره المالي المسموح. لا تنفذ المحاكاة اتصالًا، مشاركة WhatsApp، دفعًا، مزامنة، أو أي نشاط خارجي.

عند كون الحالة خارج نطاق `custom_craft`، لا نعيد تسميتها أو نختلق شخصية جديدة. تُختبر أقرب بنية مشتركة فقط، ويشار إلى الاختلاف باسمها؛ مثال ذلك أن خدمة تنظيف قد تستخدم وقتًا وموادًا وتوصيلًا في المسار الحالي، لكن لا يقال إن Micro نفذ «Service Profile» أو عقد شركات أو جدول تحصيل لأن هذه غير موجودة.

## 5. حزمة الاختبارات العابرة

تطبق الحزمة التالية على الشخصيات المتأثرة من الجدول السابق، لا على حالة واحدة مريحة فقط. هذه امتداد للسياقات العابرة في المجموعة canonical وليست حالات مالية بديلة.

| الرمز | التشغيل | الشخصيات | الدليل المطلوب | التصنيف إن لم يكتمل |
| --- | --- | --- | --- | --- |
| CTX-01 | حفظ مسودة ثم رجوع واستئنافها | P01، P02، P04، P10 | تبقى القصة والكمية والتخصيص كما هي؛ لا يصنع طلبًا ماليًا مبكرًا. | `PARTIAL_CURRENT_UX_GAP` أو خلل تخزين. |
| CTX-02 | رقم إنجليزي صحيح، رقم عربي مرفوض، نص رقمي غير مكتمل | P01، P02، P04، P06 | تتغير صحة الحقل فقط؛ لا تتحول القيمة المؤقتة إلى صفر. | خلل current حرج. |
| CTX-03 | وقت معروف مقابل وقت متروك ناقصًا | P01، P02، P04، P05، P06، P07، P10 | لا تظهر نتيجة نهائية حين يكون الوقت مؤثرًا ناقصًا. | خلل حقيقة مالية حرج. |
| CTX-04 | سعر دون سعر الحماية مع إقرار واضح | P01، P02، P04، P05 | التحذير يشرح السبب ولا يمنع الاتفاق آليًا. | `PARTIAL_CURRENT_UX_GAP` إن غاب السبب. |
| CTX-05 | عربون ثم تسليم ثم تحصيل المتبقي | P01، P03، P04، P07، P10 | العربون كاش مرتبط، والتسليم لا ينشئ قبضًا، والنتيجة تتبع المعرفة. | خلل حقيقة مالية حرج. |
| CTX-06 | تسليم ثم تسجيل دين بدل التحصيل | P06، P07، P08، P09 | الدين لا يزيد القبض المسجل؛ الفعل التالي يذكر أن التحصيل اللاحق خارج النطاق. | خلل حقيقة مالية حرج. |
| CTX-07 | طلبان مستقلان تحت ضغط الوقت | P02، P04، P08 | لا تختلط مسودة أو تكلفة أو عربون طلب بآخر؛ تعطى قائمة الطلبات أولوية واحدة مفهومة. | `PARTIAL_CURRENT_UX_GAP` أو خلل عزل بيانات. |
| CTX-08 | مسار يوم بلا طلب | P03، P06، P07، P09 | لا تعرض Home ربحًا أو كاشًا عامًا؛ تعرض حدود الصورة المحلية فقط. | `CONCEPT_VALID_DEFERRED` إذا احتاج مشروعًا كاملاً. |
| CTX-09 | طلب غير ملائم لنطاق الحرفة | P03، P05، P06، P08، P09، P10 | يوضح التقرير حد النشاط بدلاً من ادعاء دعم وصفة/مخزون/خدمة/موسم. | `CONCEPT_VALID_DEFERRED`، لا فشل واجهة. |

## 6. صيغة سجل التنفيذ

لكل صف في النتائج، تستخدم البنية التالية:

| الحقل | ما يسجل |
| --- | --- |
| الشخص/الحالة | رمز Pxx-Cxx الأصلي والـCTX إن وجد. |
| الغلاف | قيم الأبعاد الثمانية من القسم 2. |
| المسار الحي | المسارات أو الأفعال الفعلية التي جرى تنفيذها. |
| المدخل الأدنى | معلومات اصطناعية فقط، مع ما بقي تقديريًا/ناقصًا. |
| الملاحظة | ما ظهر، وما لم يظهر، وأي رسالة أو حارس. |
| الأثر المالي المفترض | السعر/التكلفة/العربون/التحصيل/الدين/النتيجة حسب العقد؛ لا نضيف Ledger. |
| الحالة | واحدة من الحالات الخمس في القسم 1. |
| نوع الفجوة | Current defect، UX gap، concept deferred، reject/avoid، أو pilot-needed. |
| الإجراء | إصلاح، توثيق، تأجيل، رفض، أو تصميم Pilot. |

## Action Points

1. يشغّل Manus Agent 1 الحزمة P01–P10 أعلاه على نسخة Prototype النظيفة، ويجمع دليل route وحالة ونتيجة فقط.
2. لا تعدل المجموعة canonical أو عقود المال أو الواجهة أثناء التشغيل. إذا ظهر خلل حقيقي، يسجل أولًا ثم يعالج في Slice مستقل بعد قرار واضح.
3. تنظف IndexedDB التجريبية بعد الاختبار، إلا إذا لزم حفظ لقطة محلية قصيرة لإعادة الإنتاج؛ وفي هذه الحالة توسم صراحة بأنها بيانات اختبار.
4. تجمع النتائج في تقرير تابع تحت `docs/quality/` مع فصل واضح بين الملاحظة الحية والاستنتاج والتأجيل وPilot، ثم تحدث مصفوفة التغطية وسجل القرار فقط إذا فرضت النتائج قرارًا جديدًا.
