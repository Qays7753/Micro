# تقرير قبول G22 — نماذج مركزة وصياغة عربية

## سؤال القرار

هل يستطيع المالك تسجيل مصروف أو إعلان G5 من خلال الواقعة الأساسية أولًا، ثم فتح السياق والمعرفة والربط والملاحظة عند الحاجة، مع بقاء التاريخ والعملة والجمع العربي واضحين، ومن دون تحويل الإعلان إلى حركة مالية أو تغيير معنى المصروف؟

## النطاق والقرار

غطّت G22 المشكلات **M-20 إلى M-22** فقط. بقي نموذج المصروف مركزًا على المبلغ والتاريخ والجهة وما حدث، ووُضعت علاقة المشروع والتصنيف والمعرفة وحصة المصروف المشترك داخل طبقة «أضف سياقًا للمصروف». بقي نموذج G5 مركزًا على نوع التدفق والمبلغ والتاريخ والمصدر، ووُضعت المعرفة والربط والملاحظة داخل «تفاصيل الإعلان». أضيفت قواعد جمع عربية للحدود 0/1/2/3–10/11–99/100+، ووُحّدت التسميات الظاهرة إلى «د.أ» أو «الدينار الأردني»، مع إبقاء أرقام المال ASCII/LTR والتخزين بوحدات minor كما هو.

لم تتغير حسابات المال، أو Domain، أو LocalStore، أو schema/export. التعديلات النصية في خدمات Application لا تغيّر إلا صياغة عددية عرضية؛ لا تغيّر حالة الطلب أو الدين أو السعة أو أي أثر مالي.

## QA اصطناعي حي

نُفّذ QA على `localhost:3005` ببيانات اصطناعية فقط، ثم نُظّفت الجلسة وأُوقف الخادم. لم تُستخدم حسابات أو بيانات حقيقية ولم يُدّع جهاز حقيقي أو Production أو Pilot بشري.

## الفحوص

نجحت الحزمة النهائية: `pnpm install --frozen-lockfile`، و`pnpm audit --audit-level moderate`، و`pnpm format:check`، و`pnpm lint`، و`pnpm check`، و`git diff --check`. كما نجحت الاختبارات المستهدفة للـformatters والمتابعة اليومية: **13 اختبارًا**. التحذيرات غير المانعة مقتصرة على placeholders الخاصة ببيئة Umami، وتحذير حجم bundle المعروف.

## الحدود الصادقة

الـQA استخدم متصفح Sandbox محليًا ومشروعًا اصطناعيًا واحدًا. لم يُدّع اختبار Android أو iOS حقيقي، ولا لوحة مفاتيح نظامية، ولا PWA/Offline production، ولا Cloudflare Production، ولا Pilot بشري. لا تشمل G22 Market أو Delivery أو Services أو Auth أو Cloud، ولم يُنفّذ M-26.
