# Micro UX — تقرير قبول G21

**التاريخ:** 27 أغسطس 2026
**النطاق:** M-16 إلى M-19 فقط؛ لا تغييرات في Domain أو Application أو التخزين أو العقود المالية.
**حالة QA المحلي:** PASS اصطناعي؛ يستلزم قبولًا نظيفًا مستقلًا بعد نجاح بوابات PR.

## سؤال القرار

هل يستطيع صاحب المشروع العربي أن يبدأ بالمرجع والعمل اليومي والفعل المتاح، ثم يفتح إعدادات القياس أو القالب أو التقويم أو الاستعادة فقط عندما يحتاجها، من دون أن تبدو الأفعال المشروطة متاحة أو أن تختلط التفضيلات اليومية بالعمليات الحساسة؟

### التحقق

تمت تهيئة مشروع اصطناعي محلي باسم «مشروع QA G21» على `localhost:3003` فقط. في `/catalog` ظهر إنشاء مرجع العمل وقائمة «أعمال متكررة» قبل طبقات القياس والتحويلات والقالب وفترة القراءة وقراءة المراجع، وأكد console أن الطبقات الأربع `open=false`. في `/schedule` ظهر قرار السعة والـempty state والفعل التالي قبل طبقتي العرض والتكرار، وأكد console أن كلتيهما `open=false`. في `/settings` ظهرت الحقيقة المحلية ومجموعات التفضيل والمظهر والبيانات الحساسة منفصلة، وأكد console أن النسخ/الاستعادة مغلقة بينما التفضيلات اليومية والمظهر مفتوحان عمدًا.

في حالة Cash بلا محافظ ظهر «محفظة ورصيد بداية» متاحًا، بينما ظهر تحويل المحافظ كفعل «لاحقًا» مع شرط إضافة محفظة ثانية. وفي حالة Inventory بلا مواد ظهر إنشاء مادة ورصيد بداية، بينما ظهر استلام الشراء والاستهلاك والهدر كأفعال «لاحقًا» مع شرط إضافة مادة أولًا. لم تُنشأ أية حركة مالية أو مادة أو محفظة في هذا المسار، لذلك لا توجد قيم قبل/بعد لتغيير حسابي؛ بقيت الأرقام المحلية الفارغة `0.00`، ولم تُلمس أي خدمة مالية.

| الواقعة في QA الاصطناعي | قبل التغيير | بعد التغيير | الحكم |
| --- | --- | --- | --- |
| مرجع Catalog أو قالب أو سياسة | لا بيانات | لا بيانات، مع بدء المرجع أولًا وتفاصيل اختيارية مغلقة | لا كتابة مالية ولا تغيير تاريخي |
| مواعيد Schedule | لا مواعيد | empty state وفعل «بدء طلب» أولًا، والعروض الثانوية مغلقة | لا موعد ولا تكرار أُنشئ |
| محافظ Cash | 0.00 د.أ، محفظة ثانية غير موجودة | إنشاء المحفظة متاح، والتحويل مؤجل بشرط واضح | لا تحويل ولا قيد مالي |
| مواد Inventory | لا مادة | إنشاء مادة البداية متاح، وبقية الأفعال مؤجلة بشرط واضح | لا حركة مخزون أو تكلفة |
| Settings والاستعادة | بيانات محلية فارغة | التفضيل/المظهر منفصلان، والاستيراد/البداية خلف فتح مقصود | لا استيراد ولا استبدال |

شُوهدت الواجهات في RTL وLight/Dark ضمن المتصفح المحلي، واستخدمت الأرقام/التواريخ الموجودة في التطبيق دون إدخال بيانات حقيقية. تم اختبار التركيز على summaries في المتصفح بصورة مباشرة، ولم يُعتبر استخراج Markdown لمحتوى `details` المخفي دليلًا على فتحه؛ اعتمد الحكم على اللقطة وحالة DOM الفعلية.

نجحت الحزمة الآلية النهائية: `pnpm install --frozen-lockfile`، و`pnpm audit --audit-level moderate`، و`pnpm format:check`، و`pnpm lint`، و`pnpm check` بما فيه الاختبارات وtypecheck وprototype check وbuild، و`git diff --check`. بقيت فقط تحذيرات Umami placeholders وتحذير حجم bundle المعروف، من دون فشل حاجب.

### حدود صادقة

لم يتغير Domain أو Application أو LocalStore أو IndexedDB أو schema/export أو أي معنى مالي أو تاريخي. لم تُضف بيانات QA أو لقطات أو build artifacts إلى المستودع، وستُحذف بيانات QA المحلية وتُوقف خدمة الاختبار قبل الدفع. لم يُنفذ M-20 أو M-21 أو M-22 أو M-23 أو M-24 أو M-26، ولم يُضف أي نطاق Market أو Delivery أو Auth أو Cloud أو Backend.

لا يدّعي هذا السجل اختبار Android أو iOS حقيقيًا، أو لوحة مفاتيح نظامية، أو PWA/Offline production، أو Cloudflare Production، أو Pilot بشري. القبول النهائي المشروط يتطلب الفحوص الكاملة وCI وCloudflare وقبول worktree نظيف مستقل.
