# G16 — حزمة Pilot وبوابة قرار Finance/Review

**الحالة:** حزمة تخطيط وقياس مستقلة داخل `bridge/micro-experience-repair-program`. لم يبدأ Pilot فعلي، ولم تُجمع بيانات مستخدمين أو بيانات مالية حقيقية، ولا يوجد في هذا الملف ادعاء قبول أو نتيجة ميدانية.

## سؤال القرار

هل يفهم أصحاب مشاريع حقيقيون ما يرونه في Micro، ويعرفون الفعل التالي، ويعودون إلى التطبيق خلال يوم عمل؟ إذا أثبتت الملاحظة أن المستخدم لا يجد الفعل أو يخلط الحدود المالية، نحدد أصغر تغيير ضروري في Finance/Review بدل إعادة التصميم بالحدس.

## شروط البدء والحدود

لا يبدأ Pilot إلا بعد موافقة المالك على هذه الحزمة وعلى بروتوكول G15. العينة المقترحة 5–8 مشاريع متنوعة لمدة 30 يومًا، وتتضمن مستخدمًا أقل خبرة مالية ومستخدمًا أكثر خبرة، من دون وضع أسماء أو أرقام هواتف أو مبالغ حقيقية أو ملفات تصدير حقيقية في المستودع. تُستخدم معرّفات مثل `P01` إلى `P08`، وتُحفظ الملاحظات خارج GitHub في مكان يختاره المالك.

حزمة G16 لا تعدل Finance أو Review أو Home، ولا تضيف Tracking أو Analytics أو CRM أو Sync أو حساب مستخدم. لا يجوز أن يقرر الباحث نيابة عن المستخدم ما هو ربح أو سعر أو قبول مالي؛ دوره تسجيل الفهم والسلوك كما ظهرا، مع إبقاء حدود Micro المالية صريحة.

## بروتوكول الجلسة

تتكون كل جلسة من بداية قصيرة، مهام صامتة، أسئلة فهم، ومراجعة خروج. لا يشرح الميسّر معنى الزر قبل أن يسجل ما فهمه المستخدم تلقائيًا. يسمح للمستخدم بالتوقف أو تخطي مهمة، ولا تُسجل الشاشة أو الصوت إلا بموافقة مستقلة وخارج هذا المستودع.

| المرحلة | ما يفعله الميسّر | ما يسجل |
| --- | --- | --- |
| البداية | يعرّف Micro كأداة محلية ويؤكد أن البيانات تجريبية | وقت البدء، المعرّف، الخبرة المعلنة، الموافقة |
| المهمة | يقرأ السيناريو ولا يعطي خطوات النقر | أول فعل اختاره، التردد، الأخطاء، طلب المساعدة |
| الفهم | يسأل أسئلة مفتوحة بعد المهمة | الإجابة الحرفية المختصرة، لا تفسير الباحث |
| الخروج | يسأل عن العودة والاستخدام اليومي | ما الذي سيعيده، ما الذي أوقفه، وما الذي بقي غير مفهوم |
| اليوم 1/7/14/30 | يتابع بإشارة مجدولة إن وافق المستخدم | هل عاد، ما الذي فتحه، وما الذي توقف عنده |

## السيناريوهات الإلزامية

كل سيناريو يستخدم بيانات محلية اصطناعية، ويُنفذ مرة واحدة على الأقل عند ملاءمته للمشروع. لا تُحوّل الإجابة أو الخطأ إلى حكم على المستخدم.

| السيناريو | المهمة المحايدة | الحقيقة التي يجب مراقبتها |
| --- | --- | --- |
| أول طلب | «ابدأ بتسجيل طلب جديد كما ستفعل عادة.» | هل يجد CTA ويعرف أن المسودة لا تسجل قبضًا؟ |
| تكلفة/وقت ناقص | «سجل ما تعرفه عن التكلفة واترك ما لا تعرفه.» | هل يقرأ النقص كغير مكتمل لا كصفر أو وقت مجاني؟ |
| سعر أقل من الحماية | «ثبت الاتفاق بالسعر الذي قررته، إن كان أقل من القراءة الظاهرة.» | هل يفهم أن الإقرار يسجل قرارًا وليس توصية آلية؟ |
| تنفيذ وتسليم | «أكمل الطلب حتى الجاهزية والتسليم.» | هل يجد الفعل التالي، ويفصل التسليم عن التحصيل؟ |
| تحصيل أو دين | «سجل ما حدث بعد التسليم دون تغيير الحقيقة.» | هل يميز الكاش المحصل عن الدين وعن الربح؟ |
| موعد وسعة | «ضع موعدًا أو راجع موعدًا قائمًا.» | هل يفهم أن السعة غير المحددة لا ترفض الطلب؟ |
| واقعة Finance | «اقرأ حدثًا ماليًا عامًا مسجلًا.» | هل يميز الاستثمار والسحب والمصروف والتسديد؟ |
| تصحيح محلي | «راجع واقعة اختبارية وصححها وفق المسار الظاهر.» | هل يفهم العكس الكامل والرابط وبقاء الأصل دون restatement؟ |
| export/import | «صدّر نسخة اختبارية وراجع Preview قبل الاستبدال.» | هل يعرف أن التأكيد يسبق الاستبدال وأن الإلغاء لا يغير البيانات؟ |

## أسئلة الفهم الموحدة

| السؤال | إجابة المستخدم المختصرة | التصنيف |
| --- | --- | --- |
| ما الذي يجب فعله الآن؟ |  | واضح / متردد / غير واضح |
| هل `40.00` كاش أم ربح؟ ولماذا؟ |  | صحيح / خلط / غير متأكد |
| ماذا تعني نتيجة الطلب؟ |  | صحيح / خلط / غير متأكد |
| ما الذي لا يعرفه النظام هنا؟ |  | ذكر النقص / افترض قيمة / غير متأكد |
| أين زر التسليم؟ |  | وجده / احتاج مساعدة / لم يجده |
| ما الفرق بين التحصيل والدين؟ |  | صحيح / خلط / غير متأكد |
| ما الذي يحدث عند عكس واقعة Finance؟ |  | ذكر بقاء الأصل / ظن الحذف / غير متأكد |
| هل يغيّر Preview بياناتك قبل التأكيد؟ |  | صحيح / خلط / غير متأكد |

الإجابة الصحيحة لا تُلقّن أثناء المهمة. تُسجل الكلمات التي استخدمها المستخدم، ثم يرمز الباحث إلى الفئة بعد الجلسة وفق تعريفات ثابتة.

## المقاييس وتعريفاتها

| المقياس | التعريف التشغيلي | طريقة الحساب |
| --- | --- | --- |
| زمن أول قيمة | من بدء المهمة إلى أول سجل/قراءة مفيدة يفهمها المستخدم | دقيقة تقريبية لكل جلسة |
| الوصول إلى CTA | هل وجد المستخدم CTA المقصود دون مساعدة | `yes` أو `after_help` أو `no` |
| التردد | لحظة توقف أو سؤال قبل فعل مقصود | عدد الوقائع مع وصف محايد |
| خطأ | فعل يؤدي إلى رسالة أو رجوع غير مقصود | عدد قابل للإعادة لكل سيناريو |
| فهم الكاش/الدين/النتيجة | إجابة الأسئلة الثلاثة دون خلط | نسبة `clear` داخل كل فئة |
| فهم النقص | هل يذكر المستخدم ما لا يعرفه بدل افتراض صفر | ترميز السؤال الرابع |
| العودة | فتح Micro أو إكمال مسار في اليوم المحدد | `yes` / `no` / `unknown` |
| نقطة التوقف | آخر خطوة قبل ترك المهمة | معرف سيناريو وخطوة فقط |

لا تُجمع المقاييس لتصنيف الأفراد أو مقارنة مشاريعهم ماليًا. الهدف هو كشف حدود التصميم، وليس حساب نجاح تجاري أو صافي ربح.

## بوابة قرار Finance/Review

لا يُفتح redesign لمجرد وجود رأي منفرد أو طلب إضافة. تُراجع الأدلة بعد اكتمال الجولة أو عند ظهور خطر مالي واضح، ثم يُختار أصغر تغيير يحافظ على العقد.

| سؤال البوابة | لا حاجة لتغيير واسع عندما | إشارة تستحق تغييرًا أصغر عندما |
| --- | --- | --- |
| الوصول إلى الفعل | يجد أغلب المشاركين CTA ويذكرون الخطوة التالية | تكرر عدم العثور على نفس الفعل في سيناريو واحد |
| الكاش والدين | يميز المشاركون بين الكاش والتحصيل والدين | يتكرر خلط `40.00` كاشًا مع الربح أو الدين |
| نتيجة الطلب | يصفها المشاركون كقراءة طلب محدودة | يصفونها كصافي ربح المشروع أو ضمان نهائي |
| النقص | يلاحظون غير المكتمل ولا يخترعون صفرًا | يتحول النقص المتكرر إلى قرار «مجاني/صفر» |
| Finance correction | يفهمون بقاء الأصل والرابط والعكس الكامل | يظنون أن التصحيح حذف أو restatement |
| كثافة السطح | لا يوقف النص المالك عن الفعل | تظهر نفس نقطة التوقف بسبب ترتيب أو copy |

إذا ظهرت إشارة، يجب تسجيل: السيناريو، عدد الجلسات المتأثرة، الاقتباسات المختصرة بلا هوية، الخطوة التي فشل فيها المستخدم، العقد الذي يجب ألا ينكسر، وأصغر تعديل مقترح. لا يُنفذ التعديل في G16، ولا يُفتح نطاق Finance/Review قبل قرار مستقل.

بعد أي تجربة اصطناعية تُزال IndexedDB وCache Storage و`localStorage` و`sessionStorage` وService Workers وملفات JSON ولقطات QA المؤقتة من البيئة التجريبية. لا تُرفع ملاحظات المشاركين أو ملفاتهم إلى GitHub. لا يبدأ جمع فعلي قبل تحديد مكان حفظ آمن وموافقة المالك.
