# G15 — بروتوكول قبول الجهاز والإنتاج لـMicro

**الحالة:** بروتوكول قبول يدوي داخل `bridge/micro-experience-repair-program`؛ لا يحول الفحوص المحلية أو Preview إلى قبول Android أو iOS أو Production.

## سؤال القرار

هل تعمل تجربة Micro الحالية كما تعد به فعلًا على هاتف المالك، من دون حساب أو Authorization أو قاعدة بيانات خارجية؟

هذا الملف يفصل بين ما يستطيع Agent إثباته في Chromium وBuild وCloudflare Pages Preview، وبين ما يجب أن يختبره المالك بنفسه على Android وiOS. كل خانة لا تحمل دليلًا مباشرًا تبقى `لم يُختبر` أو `ينتظر المالك`، ولا تُملأ بـ`PASS` بالاستنتاج.

## حدود G15

G15 مجموعة توثيق وQA فقط. لا تضيف Backend أو Auth أو Sync أو Billing أو قاعدة بيانات خارجية، ولا تعدل دلالات المال أو التاريخ أو Offline. لا تُستخدم بيانات حقيقية؛ يجب أن تكون كل سجلات الاختبار اصطناعية، ثم تُزال من المتصفح والملفات بعد الجولة. لا يغيّر هذا البروتوكول native date إلى Date Picker مخصص، ولا يعلن أن Cloudflare Production أو Android/iOS اجتازا قبل دليل المالك.

## حالات النتيجة

| الحالة | المعنى |
| --- | --- |
| `PASS — Agent` | تحقق قابل لإعادة الإنتاج في بيئة Agent المحددة، مع رابط أو أمر أو لقطة دليل |
| `PASS — Owner` | تحقق المالك على جهاز فعلي وسجل الموديل والنظام والتاريخ |
| `FAIL` | ظهر خلل قابل للإعادة؛ اذكر المسار والشرط والدليل ولا تتجاوزه بالوصف |
| `PARTIAL` | جزء من المسار تحقق، لكن شرطًا أساسيًا بقي غير محسوم |
| `لم يُختبر` | لم تُنفذ الجولة بعد |
| `ينتظر المالك` | لا يمكن لـAgent إثبات الشرط بدلًا عن المالك |
| `خارج النطاق` | لا يدعي المنتج أو هذا البرنامج دعم الشرط في هذه المرحلة |

## قرار القبول

لا تصبح G15 «مقبولة» بمجرد نجاح CI أو Cloudflare Pages. بعد أن يملأ المالك نتائج Android وiOS وinstall وstandalone وupdate وdirect route وoffline/reload وFiles وkeyboard/date/back/focus/touch والمقاسات والمظهر والأداء، تُحفظ نتيجة القرار في نسخة لاحقة من هذا الملف أو في محضر قبول مستقل. تبقى كل الخانات غير المنفذة معلقة بوضوح.

**النتيجة الحالية قبل اختبار المالك:** `لم يُقبل الجهاز أو Production بعد`.
