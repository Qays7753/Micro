# قرار التدقيق الموحد وإغلاق الحواجز — Micro

**الحالة:** `CURRENT / QUALITY GATE`

**النسخة:** بعد `f1856caf`، قبل دمج حزمة الإصلاح الحالية

## الغرض

يجمع هذا الملف نتيجة تقارير التدقيق المستقلة وتقييم Zed AI وحزمة الأدلة متعددة المسارات في قرار واحد قابل للتنفيذ. لا تُعامل التقارير المرفقة أو القديمة كسلطات مستقلة؛ هذا الملف يحدد ما ثبت، وما هو قرار منتج، وما هو مؤجل.

## الحكم

مفهوم Micro واضح وقيمته الأساسية هي مساعدة صاحب المشروع على تحويل الحدث اليومي إلى تكلفة ونتيجة وكاش وذمة وفعل تالٍ، مع إظهار درجة المعرفة بدل الدقة الزائفة. النواة الحالية قوية ضمن `CraftOrder` لطلب حرفة واحد، لكنها ليست Ledger مشروعًا أو مخزونًا عامًا أو تقارير تراكمية.

الحكم التنفيذي هو:

> **إغلاق حواجز Domain Core المؤكدة، ثم بناء Prototype محلي لمسار الحرفة لمستخدم واحد.**

لا يغيّر ذلك مفهوم Micro، ولا يحوله إلى تطبيق طلبات أو LMS، ولا يجعل Auth أو Roles أو Workspace شرطًا للـPrototype الشخصي. هذه طبقات MVP تجاري لاحق عند ثبوت الحاجة.

## ما ثبت في التدقيق

أعيد فحص المسارات العامة على `main` الحالية، وثبتت النقاط التالية قبل الإصلاح:

| الملاحظة | الحكم |
|---|---|
| طلب مسلّم يدخل `needs_review` ثم يمكن لبعض العمليات العامة تغييره | حاجز مؤكد |
| `transitionOrder(to=cancelled)` يتجاوز مسار سبب الإلغاء وتسوية العربون | حاجز مؤكد |
| Snapshot ومدخلاته يمكن تعديلها عبر مراجع خارجية | حاجز مؤكد |
| مفتاح idempotency فارغ مقبول | حاجز مؤكد |
| `reviseOrderCost` و`cancelOrder` يغيران الحالة دون `status_changed` مرافق | فجوة عقد/تدقيق مؤكدة |
| الدفع الكامل مقدمًا ثم التسليم يترك فعل تحصيل مضللًا | عيب سلوكي مؤكد منخفض الأثر المالي |
| `safetyBufferMinor` | محسوم لكل وحدة؛ يحتاج توضيحًا لا قرارًا جديدًا |
| `stale` للوقت | غير ممثل حاليًا؛ يضيق العقد إلى أسعار المواد |
| Auth/Roles/Workspace/Inventory/Ledger/Break-even | مؤجلة عمدًا وليست Blockers للـPrototype الشخصي |

## حزمة الإصلاح الحالية

1. يوجد حارس موحد يمنع تغيير الحالة أو Snapshot أو الأثر المالي بعد دخول طلب مسلّم إلى `needs_review` حتى يضاف Use Case تصحيح موثق.
2. الإلغاء العام أزيل من الانتقالات العامة، ويجب أن يمر عبر `cancelOrder` مع سبب وتسوية العربون.
3. تُنسخ CostSnapshot ومدخلاتها وتُجمّد، وتُجمّد مصفوفة التاريخ، ويجب تطابق الكمية العلوية مع كمية الإدخال.
4. تُرفض مفاتيح idempotency الفارغة، ويُفحص المفتاح ضمن نوع الحدث حتى لا يمنع عملية مختلفة بصمت.
5. عند التسليم مع `receivableMinor = 0` و`settlementStatus = paid` تنتقل الحالة إلى `settled` ويصبح الفعل التالي مراجعة النتيجة.
6. كل تغيير حالة مباشر يضيف `status_changed` واضحًا، بما في ذلك Revision والإلغاء والتسوية التلقائية.

## ما بقي خارج النطاق

لا تنفذ هذه الحزمة Auth أو Permissions أو Workspace أو RLS أو SyncQueue أو Ledger عام أو Inventory أو Owner Draw أو Break-even أو تقارير شهرية أو Food/Service Profiles. لا تُستخدم `needs_review` بدل `on_hold` أو `correctDelivery`، ولا تُخترع سياسات الإرجاع أو التسليم الجزئي أو الضمان أو المصروف المشترك.

## معيار الانتقال إلى Prototype

بعد نجاح typecheck والاختبارات، يبنى Prototype محلي single-user لمسار: إنشاء طلب الحرفة، التكلفة، درجة المعرفة، سعر الحماية، الاتفاق، العربون، التنفيذ، التسليم، التحصيل أو الدين، النتيجة والفعل التالي. يجب أن يضم Adapter وLocalStore و`local export/import` قبل استقبال بيانات مستخدمين حقيقية.

## مراجع السلطة

تُحكم دلالة المال بالعقود والسياسات المالية، وتُحكم هوية المنتج بالـBlueprint، وتُحكم المرحلة ببوابة Pre-build وخارطة التنفيذ، وتُستخدم هذه الوثيقة كحارس جودة قبل Prototype. تقارير التدقيق القديمة تبقى أدلة تاريخية ولا تتغلب على الكود والعقود الحالية.
