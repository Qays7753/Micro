# سجل قبول A2 — عرض المال والتاريخ والاتجاه

**التاريخ:** 24 أغسطس 2026

**الفرع:** `fix/unified-money-date-display`

**النطاق:** طبقة عرض مشتركة فوق الأسطح الحالية في Micro. لا يغير هذا الإصلاح قيمة التخزين، أو الحسابات، أو خدمات Domain/Application، أو `CostSnapshot`، أو schema/export. تبقى حقول التاريخ الداخلية بصيغة ISO، وتبقى حقول الأرقام ومدخلاتها الإنجليزية كما هي.

## عقد العرض المقبول

| القيمة | العرض المرئي | حد الحقيقة |
|---|---|---|
| المال | `formatMoneyMinor` من وحدات minor إلى رقم JOD بعلامة عشرية ثابتة وأرقام ASCII واتجاه LTR؛ يذكر السياق `(د.أ)` مرة على مستوى البطاقة أو السطح | لا تحويل أو تقريب جديد في الحساب؛ التحويل للعرض فقط |
| التاريخ المحلي | `DD/MM/YYYY` عبر `formatLocalDate` داخل `bdi dir="ltr"` مع عزل Unicode/CSS | لا تغيير لقيمة ISO المخزنة |
| التاريخ والوقت | تاريخ عمّان المحلي ثم الوقت المعروف بصيغة معزولة عبر `formatLocalDateTime` | لا إعادة تفسير للحدث أو للـtimestamp |
| الشهر | اسم عربي مع سنة بأرقام لاتينية عبر `formatMonthLabel` | مفتاح الفترة يبقى `YYYY-MM` داخليًا |
| الكمية | `formatQuantityMilli` مع الحفاظ على أجزاء الألف | لا تغيير لوحدة أو قيمة المخزون |

غطت الاختبارات الآلية المال الموجب والسالب والصفر، ورفض التاريخ غير الصحيح، و`DD/MM/YYYY`، وتحويل لحظة UTC إلى تاريخ عمّان الصحيح، وتنسيق تاريخ/وقت، واسم الشهر مع سنة لاتينية. اختبارات A1 وAgreementContext بقيت ناجحة بعد إعادة استخدام primitives التاريخ المشتركة.

## QA حي ببيانات اصطناعية فقط

شُغّل البناء الإنتاجي المحلي على `http://localhost:4173`. بعد إدخال اسم نشاط اصطناعي لم يُنشأ أي سجل مالي أو شراء أو مخزون، فظهرت شاشة `/finance` بقيم `0.00` بأرقام ASCII وبسياق `(د.أ)`. بقي حقل فترة النتيجة `2026-08` بصيغة ISO داخل عنصر `month`، بينما ظهرت واجهة RTL دون إعادة ترتيب الأرقام.

عُرض السطح نفسه في Light ثم Dark. في الحالتين بقيت قيم `0.00`، وسياق الدينار، والعناوين، وحقل الفترة مقروءة مع توكنات Micro الحالية. التقط سجل QA المحلي تفاصيل المشاهدة؛ أُفرغت بيانات المتصفح الاصطناعية بعد QA السابق، ولم تُستخدم بيانات مالك حقيقية.

## حدود القبول

هذا السجل يثبت قبول المصدر، الاختبارات، البناء، ومعاينة محلية RTL/Light/Dark فقط. لم يُدّعَ اختبار جهاز Android أو iOS فعلي، ولا اختبار إنتاج Cloudflare Pages بعنوان عام. لا يثبت A2 صحة سياسة مالية جديدة؛ فهو إصلاح عرض فقط. يجب اختبار الأسطح النهائية على هاتف فعلي عند توفر عنوان الإنتاج، مع مراجعة اتجاه الأرقام والتواريخ في حالات المال الموجب والسالب والصفر.
