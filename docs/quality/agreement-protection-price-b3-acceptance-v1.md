# سجل قبول B3 — فصل سعر الحماية عن السعر المتفق عليه

## سؤال القرار والنطاق

يسأل B3: «هل أعرف أن قيمة الحماية مشتقة من التكلفة، وأن السعر المتفق عليه هو قراري واتفاقي الفعلي؟» لذلك يفصل السطح بين قيمة الحماية المشتقة من Snapshot وبين الحقل الذي يسجل السعر المتفق عليه، ويجعل استخدام قيمة الحماية كبداية فعلًا صريحًا قابلًا للمراجعة قبل التثبيت.

## ما تم تنفيذه

يعرض `AgreementEditor` بطاقة مستقلة بعنوان «سعر الحماية المشتق من Snapshot» مع شرح أنها قيمة مشتقة وليست السعر المتفق عليه. يبدأ حقل «السعر المتفق عليه» فارغًا بدل أن يُملأ بصمت بقيمة الحماية أو `0.00`. يظهر زر «استخدم سعر الحماية كبداية»؛ وعند ضغطه فقط تُنسخ قيمة الحماية إلى حقل الاتفاق ليعدلها المستخدم أو يراجعها قبل الحفظ. يبقى عقد `AgreementService` كما هو، ويستقبل فقط السعر الذي أدخله المستخدم.

لدعم الحالة الفارغة بصريًا، أصبحت `EnglishNumberInput` تقبل قيمة `null` وتعرضها فارغة؛ لم يتغير تحليل الأرقام أو تنسيق القيم الرقمية المحفوظة. لا توجد قيمة حماية أو سعر اتفاق جديدان في schema أو export.

## الاختبارات الآلية

| المجال | الدليل |
|---|---|
| الحالة الأولية | `agreementPrice.test.ts` يثبت أن السعر المتفق عليه يبدأ `null` وأن `0` ليس سعرًا صالحًا. |
| الفعل الصريح | الاختبار يثبت أن `applyProtectionPriceAsStart(1250)` يعيد القيمة فقط عند استدعاء الفعل، وأن غياب الحماية يبقى `null`. |
| الصلاحية | الاختبار يثبت قبول minor units الصحيحة الموجبة ورفض السالب والكسور. |
| العرض الرقمي | `englishNumeric.test.ts` يثبت أن `null` يظهر فارغًا، مع بقاء تنسيقات المال/الكمية السابقة. |
| العقد الموجود | `agreementService.test.ts` اجتازت اختبارات الاتفاق والعربون والإعادة وبدء التنفيذ دون تغيير العقد. |
| النوع | `pnpm --filter @micro/prototype-web exec tsc --noEmit` ناجح. |

## QA حي ببيانات اصطناعية

أُجريت الجولة في Chromium sandbox على Vite محلي (`http://localhost:3001`) بواجهة RTL وببيانات اصطناعية فقط: ملف `اختبار B3`، مسودة `صندوق B3 اصطناعي`، وعميل `عميل B3 اصطناعي`.

| السيناريو | النتيجة المرصودة |
|---|---|
| تكلفة معروفة | أُدخلت 60 دقيقة بسعر 10.00 JOD/hour مع درجة معرفة `معروف`، فأظهر CostEditor سعر حماية مشتقًا قدره `10.00`. |
| تحميل AgreementEditor | ظهر سعر الحماية في بطاقة مستقلة مع عبارة أنه مشتق من التكلفة وليس السعر المتفق عليه. حقل السعر المتفق عليه كان فارغًا. |
| استخدام الحماية كبداية | ضغط المستخدم زر «استخدم سعر الحماية كبداية»، فظهر `10.00` في حقل الاتفاق فقط بعد الفعل الصريح. |
| تعديل مستقل | غُيّر حقل الاتفاق إلى `15.00`، بينما بقيت بطاقة سعر الحماية `10.00`. |
| الخروج دون حفظ | ضغط Bottom Navigation، فظهر حارس B1 ذو الخيارات الثلاثة؛ أدى «إلغاء» إلى إبقاء `15.00` داخل المحرر. |
| حفظ صحيح | أُدخل تاريخ التسليم `2026-09-15` وحُفظ الاتفاق. عرض OrderDetail السعر المتفق عليه `15.00` والتاريخ `15/09/2026`، دون تسميته سعر حماية أو ربحًا. |
| التنظيف | حُذفت IndexedDB، ومُسحت Cache Storage وlocalStorage وsessionStorage، وأُلغيت service workers. |

## الحدود

لم يتغير `AgreementService` أو `CostSnapshot` أو Domain أو schema/export أو سجل تاريخي. لا يفرض B3 رقمًا، ولا يقدم توصية سوق، ولا يغير Snapshot، ولا يضيف Dashboard أو CRM أو POS أو Auth أو Sync أو reminders. QA محلي اصطناعي في RTL/Light فقط، ولا يدّعي قبول Android أو iOS أو Cloudflare Pages production، ولا يشمل browser back أو tab close.
