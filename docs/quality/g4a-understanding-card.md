# بطاقة فهم G4-A — نواة الكتالوج الاختيارية

## المستخدم
صاحب مشروع صغير أو منزلي يدير منتجات أو خدمات متكررة بنفسه أو بفريق محدود، ويحتاج إلى تذكر طريقة تجهيز العمل دون أن يصبح محاسبًا أو مدير مخزون.

## الموقف
يكرر صاحب المشروع عملًا أو خدمة أو ناتجًا متشابهًا، لكنه لا يريد إعادة الوصف من الصفر في كل مرة. يريد مرجعًا اختياريًا يوضح ما يكرره، وقد يريد تذكر مكونات وعائد متوقعين، من دون تحويل المرجع إلى وصفة قطاعية أو أمر إنتاج.

## الضرر
إعادة الإدخال تستهلك وقتًا وتزيد اختلاف الأسماء، بينما قد يؤدي ربط مرجع جديد بالاسم أو استخدام قالب كأنه تكلفة فعلية إلى تغيير طلب تاريخي أو Snapshot أو نتيجة مالية بصمت، أو إلى خلط الشراء بالاستهلاك والمخزون بالربح.

## سؤال القرار
كيف أكرر عملًا أو خدمة أو إنتاجًا من دون أن يغير المرجع الجديد اتفاقًا أو Snapshot قديمًا؟

## أقل إدخال
مرجع عمل: نوع منتج/خدمة، اسم عملي، ووحدة منظمة اختيارية. وبفعل مستقل اختياري: وحدة ذات بعد مسموح، تحويل مباشر صريح داخل البعد نفسه، أو قالب بمكونات موجبة ووحداتها وملاحظة اختيارية وyield اختياري.

## ما يعرفه النظام وما لا يعرفه
يعرف النظام أن المرجع أو الوحدة أو التحويل أو القالب سجلها المستخدم، وأن التحويل مباشر وصريح ودقيق، وأن yield متوافق أو يظل غير مهيأ مع سبب واضح. لا يعرف من هذه الطبقة وحدها سعرًا أو COGS أو استهلاكًا أو مخزون منتج نهائي أو تكلفة فعلية أو إنتاجًا أو ربحًا نهائيًا.

## المعنى المالي
الكتالوج والقالب والوحدة والتحويل طبقات مرجعية وتخطيطية فقط. لا تنشئ شراءً أو كاش أو مخزونًا أو استهلاكًا أو COGS أو إيرادًا أو هامشًا. قراءة «الهامش المباشر المسجل حسب مرجع العمل» تبقى مشتقة من الطلبات النهائية المرتبطة صراحة و`recognizedCostMinor` التاريخية فقط.

## ما لن يتغير
لن يعاد ربط طلب تاريخي بالاسم، ولن يتغير `CostSnapshot` أو السعر أو `recognizedCostMinor` أو الإيراد أو نتيجة الفترة. لن تفرض وحدة أو قالبًا، ولن نضيف Profile قطاعيًا أو BOM متعدد المستويات أو استهلاكًا تلقائيًا أو تحويلًا بين أبعاد مختلفة أو محرك تحويل متعدد الخطوات.

## السيناريوهات المتأثرة
إنشاء منتج وخدمة بلا أثر مالي؛ ربط مسودة جديدة بمرجع صراحة؛ بقاء طلب قديم بلا `catalogItemId` بلا ربط تلقائي؛ تعطيل مرجع/وحدة/تحويل مع بقاء القراءة القديمة؛ وحدات count/mass/volume/time/distance/area؛ تحويلات صريحة مثل kg→g ورفض kg→liter؛ قالب بلا yield، وقالب بمكونات وyield متوافق، ورفض yield غير صالح؛ export/import والترحيل الذري؛ وعدم تحوّل القالب إلى حركة Inventory أو Purchase أو Consumption أو COGS.

## معيار القبول
تُحفظ الكيانات الجديدة بـidempotency، تُرفض القيم غير الموجبة أو غير الدقيقة أو العلاقات المكسورة قبل الكتابة، وتنجح اختبارات Domain/Application/Storage/Transfer/UI والترحيل والـround-trip دون كتابة جزئية. يعمل السطح بالعربية RTL وبأرقام ASCII/LTR على المقاسات المستهدفة مع حالات empty/error/needs-review والرجوع الآمن.
