# 05 — القدرات غير القابلة للوصول

> كل قدرة في طبقة `هـ` — موجودة في الكود بلا مسار من الواجهة أبدًا.
> المالك دفع ثمن بنائها ولا يستطيع استخدامها.

## المنهجية

تم البحث عمدًا وليس بالصدفة: لكل طريقة عامة في كل خدمة تطبيق، تم البحث في كل ملفات `src/pages/*.tsx` و`src/components/*.tsx` عن استدعاء لها. الطرق التي لم يُعثر على استدعاء لها في أي ملف واجهة هي القدرات غير القابلة للوصول.

## القدرات السبع غير القابلة للوصول

### F-077 — مؤشرات مالية تفصيلية

| الحقل | القيمة |
|---|---|
| **الخدمة** | `ProjectFinancialService` |
| **الطريقة** | `readFinancialInsights(from, to)` |
| **موقع الكود** | `application/finance/projectFinancialService.ts` |
| **ما تفعله** | يجمع مؤشرات الفترة: هامش أسماء الأعمال، تكلفة البيع (COGS)، التغطية، السيولة، نقطة التعادل. |
| **هل هي مكتملة؟** | نعم — مغطاة باختبار خدمة، والمنطق منفذ بالكامل. |
| **ما الذي يحجبها؟** | صفحة المالية تستخدم `readPosition` و`listEvents` و`readRecordedPeriodResult` لكنها لا تستدعي `readFinancialInsights`. لا توجد صفحة أو مكوّن يعرض هذه المؤشرات. |
| **ما الذي يلزم لإظهارها؟** | إضافة قسم في صفحة المالية (أو المراجعة) يستدعي الطريقة ويعرض المؤشرات الخمسة. البيانات موجودة، يحتاج فقط واجهة عرض. |
| **العقد الحاكم** | `docs/contracts/12-financial-insights-g5-prototype-contract.md` |
| **تغطية الاختبار** | مغطى (في خدمة)، لكن لا اختبار واجهة لأنه لا توجد واجهة. |

### F-078 — متابعات مستحقة

| الحقل | القيمة |
|---|---|
| **الخدمة** | `AgreementContextService` |
| **الطريقة** | `dueFollowUps()` |
| **موقع الكود** | `application/agreements/agreementContextService.ts` |
| **ما تفعله** | يقسّم الطلبات ذات متابعات إلى مستحقة اليوم وقادمة، مرتبة زمنيًا. |
| **هل هي مكتملة؟** | نعم — المنطق منفذ. |
| **ما الذي يحجبها؟** | صفحة الطلبات تستخدم `dailyFollowUp.read()` التي تجمع المتابعات بشكل مختلف. `dueFollowUps` لا يُستدعى من أي صفحة. |
| **ما الذي يلزم لإظهارها؟** | إضافة قسم في Home (أو صفحة متابعات مستقلة) يعرض «متابعات مستحقة اليوم» و«قادمة» من هذه الطريقة. تعطي قراءة أدق من `dailyFollowUp` لأنها مصنفة بالاستحقاق. |
| **العقد الحاكم** | `docs/contracts/20-agreement-source-follow-up-g7-a-contract.md` |
| **تغطية الاختبار** | بلا اختبار مباشر للطريقة في واجهة. |
| **ملاحظة خاصة** | هذه قدرة **يومية** محجوبة بالكامل. المتابعات المستحقة هي أولوية يومية للمالك، ووجودها في الكود بلا مسار يعني أن المالك يفتقد قراءة كان يمكن أن تساعده كل صباح. |

### F-079 — قائمة المتوقعات G5

| الحقل | القيمة |
|---|---|
| **الخدمة** | `G5Service` |
| **الطريقة** | `listDeclarations()` |
| **موقع الكود** | `application/g5/g5Service.ts` |
| **ما تفعله** | يعرض كل متوقعات G5 المسجلة (تحصيل متوقع / التزام متوقع). |
| **هل هي مكتملة؟** | نعم. |
| **ما الذي يحجبها؟** | صفحة المالية تستخدم `readDecision` التي تقرر بناءً على المتوقعات لكنها لا تعرض القائمة. `G5DeclarationEditor` يستخدم `listLinkOptions` و`createDeclaration` لكن لا يستخدم `listDeclarations`. لا يوجد سجل للمتوقعات السابقة. |
| **ما الذي يلزم لإظهارها؟** | إضافة سجل متوقعات في صفحة المالية أو في محرر G5 يعرض ما سُجل سابقًا مع إمكانية التراجع. |
| **العقد الحاكم** | `docs/contracts/12-financial-insights-g5-prototype-contract.md` |

### F-080 — تأجيل موعد (اختصار)

| الحقل | القيمة |
|---|---|
| **الخدمة** | `ScheduleService` |
| **الطريقة** | `postpone(id, scheduledFor, reason)` |
| **موقع الكود** | `application/scheduling/scheduleService.ts` |
| **ما تفعله** | اختصار لتأجيل موعد بتاريخ وسبب. |
| **هل هي مكتملة؟** | نعم — لكنها مكررة منطقيًا مع `updateTiming`. |
| **ما الذي يحجبها؟** | `ScheduleEditor` يستخدم `updateTiming` مباشرةً. `postpone` هو wrapper راحة لم يُستخدم في الواجهة. |
| **ما الذي يلزم لإظهارها؟** | لا شيء ضروري — الطريقة تكرار وظيفي لـ `updateTiming`. يمكن دمجها أو حذفها دون أثر. |
| **العقد الحاكم** | `docs/contracts/07-schedule-capacity-prototype-contract.md` |

### F-081 — قائمة سياسات التوزيع

| الحقل | القيمة |
|---|---|
| **الخدمة** | `RecurringWorkService` |
| **الطريقة** | `listPolicies(catalogItemId?, includeInactive?)` |
| **موقع الكود** | `application/recurring-work/recurringWorkService.ts` |
| **ما تفعله** | يعرض سياسات توزيع الأعمال المتكررة لمرجع معيّن أو للكل. |
| **هل هي مكتملة؟** | نعم. |
| **ما الذي يحجبها؟** | صفحة الكتالوج تستخدم `readRecurringWork` التي تضم السياسات داخل قراءة شاملة. `listPolicies` كطريقة مستقلة لا تُستدعى. |
| **ما الذي يلزم لإظهارها؟** | إدارة سياسات مستقلة في الكتالوج: قائمة، تعديل، إيقاف. حاليًا يمكن إنشاء سياسة وخليفة لكن لا يمكن إيقاف سياسة توزيع من الواجهة. |
| **العقد الحاكم** | `docs/contracts/15-catalog-reference-prototype-contract.md` |

### F-082 — إيقاف سياسة توزيع

| الحقل | القيمة |
|---|---|
| **الخدمة** | `RecurringWorkService` |
| **الطريقة** | `deactivatePolicy(policyId)` |
| **موقع الكود** | `application/recurring-work/recurringWorkService.ts` |
| **ما تفعله** | يوقف سياسة توزيع دون حذفها للحفاظ على السجل التاريخي. |
| **هل هي مكتملة؟** | نعم. |
| **ما الذي يحجبها؟** | لا يوجد زر أو نموذج في الكتالوج يستدعي `deactivatePolicy`. السياسة تُنشأ وتُعدّل لكن لا يمكن إيقافها من الواجهة. |
| **ما الذي يلزم لإظهارها؟** | زر «إيقاف» بجانب كل سياسة فعّالة في قسم قراءة المراجع. |
| **العقد الحاكم** | `docs/contracts/15-catalog-reference-prototype-contract.md` |
| **ملاحظة خاصة** | هذا يعني أن سياسة توزيع خاطئة تبقى فعّالة للأبد ما لم تُستبدل بخليفة. الإيقاف خيار إداري مهم لا يمكن الوصول إليه. |
