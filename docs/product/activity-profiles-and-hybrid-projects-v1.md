# Micro — النواة العامة وActivity Profiles والمشاريع المختلطة v1

**الحالة:** `CURRENT / PRODUCT ARCHITECTURE / NO NEW FEATURE`
**الغرض:** تعريف طريقة توسع المنتج. لا يغير Domain أو schema أو local import أو UI الحالية، ولا يعلن أن Profile مستقبلي منفذ.

## Major Discussion Points

## 1. القرار

> **يعتمد Micro نواة مالية وتشغيلية مشتركة، فوقها Activity Profiles اختيارية وقابلة للتركيب. المشروع لا يُقيد بهوية قطاعية واحدة؛ كل واقعة أو طلب يمكن أن يستدعي السياق الذي يغير معناها فقط.**

هذا ليس نظام Plug-ins تقنيًا منفذًا الآن. هو حد منتجي وعقد تفكير يمنعنا من تحويل الحرفة إلى قالب إلزامي للطعام أو الخدمات أو الزراعة أو السياحة، ويمنعنا كذلك من وضع كل خصائص القطاعات في الإعداد الأولي.

## 2. ما يبقى في النواة؟

| طبقة النواة | المعنى الثابت |
|---|---|
| المشروع والمالك | العملة، المدة، المحافظ، المالك، وسجل الأحداث؛ لا Profile واحد مفروض. |
| الحدث | بيع، طلب، قبض، دين، شراء، مصروف، استثمار، سحب، تحويل، عكس أو تسوية. |
| الأطراف | عميل، مورد، طرف مستحق أو دائن؛ لا CRM أو رسائل ضمن النواة. |
| الحقيقة المالية | الكاش ≠ الربح، الدين ≠ الكاش، الشراء ≠ COGS، السحب ≠ المصروف، المجهول ≠ صفر. |
| المعرفة والتاريخ | source وknowledge ووقت الحدث وidempotency وrevision/reversal؛ لا تعديل صامت. |
| القرار | مصدر/فترة/درجة معرفة/فعل تالٍ، لا Dashboard رقمية عامة. |

## 3. ما الذي يملكه Profile؟

| مسؤولية Profile | مثال | ما لا يملكه |
|---|---|---|
| سياق العمل | حرفة مخصصة، دفعة طعام، خدمة ميدانية، محصول/موسم، تجربة/باقة | لا يغير معنى الكاش أو الدين أو السحب. |
| عناصر التكلفة ووحداتها | حصة، ساعة، كيلوجرام، هكتار، مقعد، ليلة، رحلة | لا يفرض وحدة على نشاط آخر. |
| دورة التنفيذ | جاهز للتسليم، دفعة مكتملة، خدمة منجزة، حصاد/تجهيز، تجربة منفذة | لا يجعل الإتمام قبضًا تلقائيًا. |
| البيانات التشغيلية الإضافية | وصفة، checklist، مورد رحلة، فترة موسم، capacity | لا يضيف سجلًا بلا سؤال قرار. |
| سياسة الفعل التالي | أكمل وصفة، راجع فاقدًا، أكد توافرًا، حصّل متبقيًا | لا يحجز أو يرفض أو يوصي إلزاميًا بلا عقد. |

## 4. Profiles المرشحة وليست وعودًا

| Profile | سؤال القرار الأول | أقل Slice صادق لاحق | خارج النطاق في Slice الأولى |
|---|---|---|---|
| الحرفة المخصصة | هل يغطي السعر المواد والوقت والتغليف/التوصيل؟ | الموجود حاليًا في Prototype | BOM متعدد المستويات أو مصنع. |
| الطعام/الدفعات | كم كلفت الدفعة والحصة بعد الهدر؟ | وصفة + دفعة + yield + هدر + تغليف | مطبخ إنتاج كامل أو تتبع سلامة/صلاحية تشريعي. |
| الخدمات | هل السعر يغطي المدة والتنقل والمواد عند انطباقها؟ | مدة متوقعة + وقت/تنقل/مواد + إتمام | timesheet مؤسسي أو جدولة فرق. |
| الزراعة | ما تكلفة/نتيجة محصول أو موسم معلوم الحدود؟ | enterprise/activity + فترة موسم + مدخلات/فاقد + yield | إدارة مزرعة شاملة أو طقس/IoT أو تتبع قانوني. |
| السياحة/التجارب | هل تغطي الباقة الموردين والعمولات والسعة المعروفة؟ | باقة/تنفيذ + مورد/عمولة إن عرفت + إتمام | OTA integration أو booking engine أو دفع. |
| التجارة وإعادة البيع | ما هامش البيع بعد التكلفة والمرتجع والشحن؟ | توسعة عقد مخزون/مرتجع مسبب عند الدليل | POS أو متجر أو fulfillment خارجي. |

## 5. المشروع المختلط

المشروع المختلط حالة أصلية وليست استثناءً. مثال: مزرعة تبيع محصولًا مباشرًا وتقدم تجربة قطف موسمية، أو مشروع طعام يبيع وجبات ويقدم ورش طبخ. تبقى المحافظ والذمم ومال المالك والسجل المالي للمشروع كله؛ يمكن للسجل أن يحمل **سياقًا اختياريًا معلومًا أو غير معلومًا** لنشاط/موسم/دفعة/خدمة عند الحاجة.

لا يسمح ذلك بالتوزيع التلقائي. إذا كان الوقود أو كهرباء أو وقت يخدم نشاطين، يسجل الأصل وسياقه ودرجة معرفته؛ لا يحمّل Micro حصة على كل Profile إلا بعقد وسياسة أساس توزيع ظاهرة.

## 6. قواعد الحماية

1. لا يظهر سؤال Profile عند التأسيس إلا إذا كان يغير أول قيمة؛ وتبقى الإضافة اللاحقة متاحة.
2. لا يظهر حقل قطاعي إلا عند اختيار واقعة تتطلبه؛ عدم الاختيار ليس صفرًا ولا «لا ينطبق» ضمنيًا.
3. لا يعرض Micro ربحًا أو تكلفة كاملة إذا غاب عنصر مؤثر في Profile.
4. لا يغير Profile لاحقًا Snapshot أو حدثًا تاريخيًا؛ ينشئ revision أو سياقًا جديدًا حسب العقد.
5. لا يخلط Profile بتقسيم تجاري/قانوني أو `workspace` أو entitlement؛ هذه طبقات SaaS مؤجلة.

## 7. بوابة أي Profile جديد

| البوابة | دليل القبول |
|---|---|
| مشكلة مثبتة | ضرر محدد يرتبط بـProblem Statement، لا قائمة ميزات قطاعية. |
| بطاقة قرار | مستخدم، موقف، أقل إدخال، نتيجة، مخاطر، بديل، قبول وفشل. |
| سيناريوهات | حالات للقطاع وللمشروع المختلط، تشمل الكاش والربح والمخزون/المورد والذمم ودرجة المعرفة. |
| عقد | تعريف event/context/unit/cost/completion/reversal بدون كسر P0. |
| Prototype ضيق | Slice واحد في UI → Application → Domain → Store؛ لا React→IndexedDB مباشر. |
| دليل ميداني | G15 ثم Pilot أو دراسة قطاعية توضح الفهم والعودة قبل توسعة ثانية. |
