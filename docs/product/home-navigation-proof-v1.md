# Micro — إثبات Home والتنقل المتكيف v1

**الحالة:** مراجعة التصميم قبل الاعتماد  
**النطاق:** رسم Home، مقارنة موضع العمل/الطلبات، وإثبات التراكمية بثلاث حالات  
**لا يتضمن:** تنفيذًا، إعادة توزيع للـ83 قدرة، أو بناء البيع المباشر وحذف المسودة

---

## 1. قاعدة القراءة

هذا المستند لا يعتبر كل رابط داخل Home «سطحًا» مستقلًا. السطح هو وحدة بصرية
تطلب من المستخدم قرارًا أو قراءةً مستقلة. الرقم أو الرابط الصغير داخل بطاقة لا
يُحسب سطحًا ثانيًا.

السهم في المسارات أدناه يعني: يبدأ المستخدم من العنصر الأول ويتعمق إلى العنصر
الذي يليه. صيغة الـbreadcrumb المكافئة هي:

```text
Home ← الوضع المالي ← محافظ الكاش
```

لا نستخدم عدد النقرات كبرهان رئيسي؛ المسار يوضح التبعية الفعلية.

## 2. رسم Home الكامل — الترتيب النهائي المقترح

### 2.1 الهيكل من أعلى إلى أسفل

الرسم التالي هو Home في حالة لديها نشاط مسجل، لا شاشة تعليمية ولا قائمة بكل
وحدات النظام:

```text
┌──────────────────────────────────────┐
│  مشروعي الآن              ⚙          │  رأس التطبيق
│  السبت، 29 آب                         │
├──────────────────────────────────────┤
│                                      │
│  1. بطاقة الوضع المالي               │
│  ┌──────────────────────────────────┐ │
│  │ الكاش المعروف الآن                │ │
│  │ 84.00 د.أ · درج المحل             │ │
│  │ آخر حركة: مصروف 6.00 د.أ          │ │
│  │ الوضع المالي  ›                   │ │
│  └──────────────────────────────────┘ │
│                                      │
│  2. الأولوية الآن                    │
│  ┌──────────────────────────────────┐ │
│  │ طلب «طاولة صغيرة»                │ │
│  │ الفعل التالي: راجع السعر          │ │
│  │ متابعة واحدة مستحقة  ›            │ │
│  └──────────────────────────────────┘ │
│                                      │
│  3. اليوم                             │
│  ┌──────────────────────────────────┐ │
│  │ اليوم: موعدان · متابعة واحدة      │ │
│  │ متأخر 1 · قادم 2                  │ │
│  │ افتح اليوم  ›                     │ │
│  └──────────────────────────────────┘ │
│                                      │
│  4. ما أبيعه                         │
│  ┌──────────────────────────────────┐ │
│  │ المنتجات والخدمات والمراجع        │ │
│  │ 3 مراجع · قراءة التكلفة والمهام    │ │
│  │ افتح ما أبيعه  ›                  │ │
│  └──────────────────────────────────┘ │
│                                      │
│  [لا توجد بطاقات مستقلة للموردين أو  │
│   المواد أو المتابعات أو الكاش هنا]  │
│                                      │
├──────────────────────────────────────┤
│ مشروعي الآن │ العمل │ ＋ │ المراجعة   │
└──────────────────────────────────────┘
```

### 2.2 ما الذي عُدّ وما الذي لم يُعدّ؟

| ما طُرح سابقًا كعنصر في Home | موضعه في الرسم | هل هو سطح مستقل؟ |
|---|---|---|
| الوضع المالي | بطاقة 1 + رابط واضح | نعم، سطح واحد |
| حقيقة الكاش | السطر الأول داخل بطاقة الوضع المالي | لا؛ قراءة أساسية داخل السطح نفسه |
| اليوم | بطاقة 3 | نعم، سطح واحد |
| المتابعات المستحقة | عدد/أولوية داخل «اليوم» و«الأولوية الآن» | لا؛ ليست بطاقة ثانية |
| أولوية الطلب الجاري | بطاقة 2، تعرض بندًا واحدًا فقط | نعم، عند وجود أولوية |
| ما أبيعه | بطاقة 4 | نعم، سطح واحد |
| الموردون | ليس في Home؛ من الوضع المالي | لا |
| المواد | ليست في Home قبل التفعيل؛ بعد التفعيل سطر داخل بطاقة الوضع المالي أو تنبيه واحد | لا كسطح مستقل |

إذًا Home لا يحمل ثمانية أسطح. في الحالة الغنية يحمل **أربعة أسطح محتوى**:

1. بطاقة الوضع المالي.
2. الأولوية الحالية.
3. اليوم.
4. ما أبيعه.

في حالة الداخل والخارج فقط يحمل **سطحين فعليين**، وفي حالة بلا بيانات قد يحمل
بطاقة مالية وبطاقة ما أبيعه مع حالتي فراغ صحيحتين.

### 2.3 القياس الرأسي والتمرير

على عرض التصميم الأساسي 390px، وبالاعتماد على مقاييس الهاتف المعتمدة في
`mobile-ui-ux-reference-v1.md`:

| الجزء | الارتفاع التقريبي |
|---|---:|
| safe area + الرأس | 88px |
| بطاقة الوضع المالي | 104px |
| الفراغ بين الأقسام | 12px × 3 |
| الأولوية الآن | 104px |
| اليوم | 88px |
| ما أبيعه | 72px |
| هامش سفلي فوق الشريط | 16px |
| **المجموع التقريبي** | **508px** |

**النتيجة:**

- في 390×844: العناصر الأربعة كاملة في أول شاشة، بلا تمرير.
- في 360×800: العناصر الأربعة تبقى في أول شاشة عند النص المختصر، بلا تمرير.
- لا يسمح «الأولوية الآن» بأكثر من بند واحد؛ إن وجدت أولويات أخرى يظهر نص
  `+2 في اليوم` بدل بطاقات إضافية.
- التفاصيل، السجل الكامل، الموردون، المواد، وقراءة الهامش لا تتمدد داخل Home؛
  تفتح مسارًا مستقلًا.
- إذا احتاجت ترجمة أو حالة فراغ أكثر من سطرين، يتحول العنصر إلى رابط مختصر
  لا إلى بطاقة خامسة.

### 2.4 ما لا ينتمي إلى Home

```text
ليس في Home:

[الموردون] ─────────────── Home ← الوضع المالي ← الموردون
[المواد] ───────────────── Home ← الوضع المالي ← المواد
[المتابعات كقائمة] ─────── Home ← اليوم ← المتابعات المستحقة
[تفاصيل الكاش] ─────────── Home ← الوضع المالي ← محافظ الكاش
[هامش مرجع كامل] ───────── Home ← ما أبيعه ← مرجع ← الهامش
[سجل مالي كامل] ────────── Home ← المراجعة ← السجل
[أفعال التسجيل] ────────── Home ← FAB
```

بهذا لا نحل الدفن بتسطيح كل شيء. نضع مدخلًا واحدًا صادقًا، ثم نحافظ على شجرة
واضحة داخله.

## 3. قرار معتمد: «العمل» اسم ثابت للموضع الثاني

الإعدادات تنتقل إلى الرأس كما تم الاتفاق. اسم الموضع الثاني هو **«العمل»**
ويبقى ثابتًا في الأنماط الثلاثة:

```text
┌──────────────┬──────────┬────┬──────────┐
│ مشروعي الآن  │  العمل   │ ＋ │ المراجعة │
└──────────────┴──────────┴────┴──────────┘
```

### سلوك «العمل» حسب النمط

- **الداخل والخارج فقط:** يفتح «العمل» المبيعات المباشرة عند وجودها، أو
  حالتها الفارغة الصادقة. لا يظهر قسم «الطلبات» ولا جدول طلبات فارغ.
- **طلبات:** يفتح «العمل» قائمة الطلبات. تبقى المبيعات المباشرة قدرة متاحة من
  الـFAB، وتظهر داخل الوجهة بعد تسجيل أول بيع مباشر.
- **هجين:** يفتح «العمل» الوجهة نفسها مع قسمي «المبيعات المباشرة» و«الطلبات»
  عندما يكون لكل منهما سجل؛ ويُقدَّم القسم ذو الأولوية الحالية أولًا دون تغيير
  اسم الوجهة أو موضعها.

تُستنتج الأنماط من السلوك والسجلات المحفوظة، لا من اختيار إلزامي في الاستبيان.
الموضع الفيزيائي والأيقونة لا يتغيران. «الطلبات» ليست حالة فارغة تُعرض مسبقًا:
تظهر كقسم بعد أول طلب محفوظ، وتبقى متاحة بعد ذلك. يمكن إنشاء أول طلب من الـFAB
حتى لو بدأ المستخدم بالداخل والخارج فقط.

### قاعدة ظهور الطلبات

صاحب المحل المباشر يرى داخل الموضع:

```text
العمل
└── مبيعاتي
```

لا يظهر «لا توجد طلبات» كسطر أو تبويب لصاحب الداخل والخارج. بعد حفظ أول طلب
يتحول العرض إلى:

```text
العمل
├── مبيعاتي
└── طلباتي
```

يُسمح برسالة تفعيل خفيفة في سياق إنشاء الطلب من الـFAB، لا بقسم فارغ داخل
«العمل». بهذا لا يحتل الموضع مساحة بما لن يفتحه المستخدم، ولا تُحجب إمكانية
الانتقال إلى الطلبات.

### أثر القرار على السوق مستقبلًا

يبقى `السوق` وجهة مستقلة متفقًا عليها مستقبلًا، ولا يُعاد تسمية «العمل» أو
دمجه معه حسب نمط المستخدم:

```text
مشروعي الآن | العمل | [FAB] | المراجعة
                                  ↓ مستقبلًا
مشروعي الآن | العمل | [FAB] | السوق | المراجعة
```

بعد نقل الإعدادات إلى الرأس، يملأ «السوق» الخانة الخامسة المتاحة من دون دمج
«العمل» أو إعادة تسميته أو نقل الـFAB. هذا هو ترتيب التوسعة المعتمد؛ أما إضافة
وجهة سادسة لاحقًا فتحتاج قرارًا معماريًا جديدًا. ويبقى Delivery قسمًا مستقلًا من
رمز السيارة في الرأس.

## 4. ثلاث شاشات Home تثبت التراكمية

### 4.1 الحالة الأولى — الداخل والخارج فقط

```text
┌──────────────────────────────────────┐
│  مشروعي الآن              ⚙          │
│  السبت، 29 آب                         │
├──────────────────────────────────────┤
│  الوضع المالي                         │
│  ┌──────────────────────────────────┐ │
│  │ الكاش المعروف                     │ │
│  │ 84.00 د.أ · درج المحل             │ │
│  │ آخر حركة: مصروف 6.00 د.أ          │ │
│  │ افتح الوضع المالي  ›              │ │
│  └──────────────────────────────────┘ │
│                                      │
│  لا توجد أولوية طلب اليوم             │
│  لا توجد طلبات؛ هذا لا يمنع تسجيل     │
│  بيع أو مصروف.                        │
│                                      │
│  ما أبيعه                       ›     │
│  مراجع اختيارية للتعرف على التكلفة   │
│                                      │
├──────────────────────────────────────┤
│ مشروعي الآن │ العمل │ ＋ │ المراجعة   │
└──────────────────────────────────────┘
```

#### ما فيها

1. بطاقة الوضع المالي، وفيها حقيقة الكاش.
2. حالة أولوية صادقة، لا بطاقة طلب معطلة.
3. مدخل مستقل إلى «ما أبيعه».
4. الشريط الثابت باسم «العمل».

#### ما ليس فيها

- لا «طلبات» كقسم بارز.
- لا متابعات.
- لا موردون.
- لا مواد.
- لا جدول فارغ.
- لا بطاقة «نتيجة الفترة» إذا لم توجد نتيجة.
- لا كاش منفصل عن الوضع المالي.

#### المسارات

```text
Home ← الوضع المالي
Home ← الوضع المالي ← محافظ الكاش
Home ← الوضع المالي ← سجل حركة
Home ← ما أبيعه
Home ← FAB ← سجّل بيعًا
Home ← FAB ← سجّل مصروفًا
```

هذه الحالة كاملة ضمن نطاقها: تعرف الكاش، وتسجل الداخل والخارج، وتفصل المجهول
عن الصفر. لا تحتاج أن تتحول إلى حالة الطلبات كي تكون صالحة.

```text
│  السبت، 29 آب                         │

│  │ افتح الطلب  ›                     │ │
│  └──────────────────────────────────┘ │

│  ┌──────────────────────────────────┐ │

└──────────────────────────────────────┘
```

#### ما فيها

1. بطاقة الوضع المالي.
2. أولوية طلب واحدة.
3. قسم «اليوم» الذي يحمل المتابعات والمواعيد معًا.
4. مدخل «ما أبيعه».

#### ما ليس فيها

- لا بطاقة مستقلة للمتابعة.
- لا بطاقة مستقلة للموعد.
- لا قائمة الطلبات كاملة؛ مكانها `العمل`، وتظهر بعد أول طلب محفوظ.
- لا تفاصيل التكلفة والاتفاق؛ تفتح داخل الطلب.
- لا موردون أو مواد إلا إذا نشأ تنبيه فعلي يغير الأولوية.

#### المسارات

```text
Home ← الأولوية الآن ← الطلب الجاري
Home ← اليوم ← المتابعات المستحقة
Home ← اليوم ← جدول المواعيد
Home ← العمل ← الطلبات
Home ← العمل ← الطلب ← محرر التكلفة
Home ← الوضع المالي ← الموردون
```

#### ما فيها

1. بطاقة مالية واحدة تحمل سطر المواد بعد التفعيل.
2. أولوية واحدة فقط: قد تكون مادة أو طلبًا، لا الاثنان كبطاقتين كاملتين.
3. اليوم.
4. ما أبيعه.

#### ما ليس فيها

- لا إعادة ترتيب للشريط.
- لا نقل للكاش إلى قسم جديد.
- لا إعادة إدخال للمبيعات القديمة.
- لا تقرير تاريخي يدعي أن المخزون كان مُدارًا قبل تاريخ التفعيل.
- لا تظهر مواد صفرية إذا كان المجال غير مفعّل؛ تظهر «غير مفعّل» قبل التفعيل.

#### المسارات

```text
Home ← الوضع المالي ← المواد
Home ← الأولوية الآن ← المواد ← استلام شراء
Home ← الوضع المالي ← المواد ← استهلاك لطلب
Home ← ما أبيعه ← مرجع ← الهامش المسجل
Home ← المراجعة ← قراءة فترة ← مؤشرات مالية
```

## 5. الانتقال من الحالة الأولى إلى الثانية

### مع الشريط الثابت

```text
الحالة الأولى: الداخل والخارج فقط
Home
 └── العمل: المبيعات المباشرة فقط

المستخدم يختار:
Home ← FAB ← أضف طلبًا

الحالة الثانية: يعمل بطلبات
Home
 ├── الأولوية الآن: الطلب الجاري
 ├── اليوم: المتابعات والمواعيد
 └── العمل: المبيعات + الطلبات
```

- الموضع لا يتحرك.
- الأيقونة لا تتغير.
- المبيعات السابقة لا تتغير.
- لا يظهر «قسم طلبات» فارغ قبل أول طلب محفوظ.
- أول طلب يضيف طبقة، ولا يعيد تأسيس المشروع.

لا توجد حالة انتقال اسمية متكيفة. إذا بدأ المستخدم بطلبات فقط فاسم الوجهة
«العمل» منذ البداية؛ وإذا بدأ بالداخل والخارج ثم حفظ طلبًا، يظهر قسم الطلبات في
الموضع نفسه. لا تُمحى المبيعات ولا تُنقل، ولا يحدث تبديل صامت لنص أساسي في
الشريط.

### انتقال الحالة الثانية إلى الثالثة

```text
Home ← الوضع المالي ← تفعيل المواد
       ↓
إدخال لقطة يوم التفعيل
       ↓
Home
 ├── بطاقة الوضع المالي + سطر المواد
 ├── أولوية مادة أو طلب واحدة
 ├── اليوم
 └── ما أبيعه
```

لا يتغير الشريط ولا يصبح المخزون شرطًا للبيع المباشر أو للمصروف.

## 6. قرار التصميم الناتج عن الرسم

التصحيح ليس نقل كل قدرة إلى Home. القرار هو:

1. Home يملك **أربع وحدات محتوى كحد أقصى** في الحالة الغنية.
2. الوضع المالي والكاش بطاقة واحدة، لا سطحان متجاوران.
3. اليوم والمتابعات بطاقة واحدة، لا سطحان متجاوران.
4. أولوية الطلب تعرض بندًا واحدًا، وتجمع الباقي في عدّاد.
5. الموردون والمواد لا يصيران بطاقات Home مستقلة.
6. «ما أبيعه» مدخل واحد مستقل، وتفاصيل الربحية تبقى داخله.
7. الـFAB هو مكان الأفعال، وليس Home.
8. التراكمية تغير محتوى البطاقة أو تضيف سطرًا، ولا تعيد ترتيب التنقل.
9. الموضع الثاني اسمه «العمل» ثابتًا؛ تتغير أقسامه بحسب السجلات دون تبديل الاسم.
10. قسم الطلبات مخفي قبل أول طلب محفوظ، ولا يظهر كحالة فراغ أو تبويب غير مستخدم.

## 7. عناصر تحتاج قرارًا قبل التنفيذ

| السؤال | الخياران |
|---|---|
| اسم الموضع الثاني | **محسوم: `العمل` ثابت في الأنماط الثلاثة** |
| حالة عدم وجود طلبات | **محسومة: الطلبات مخفية حتى أول طلب محفوظ؛ لا تبويب فارغ** |

| ظهور «ما أبيعه» | مدخل دائم مختصر، أو يظهر بعد أول بيع/مرجع |

هذه أسئلة عرض وتسمية، وليست إعادة فتحًا لقرارات المال أو التوزيع.
