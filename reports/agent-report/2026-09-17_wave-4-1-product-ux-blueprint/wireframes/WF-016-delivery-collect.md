# WF-016 — مراجعة التسليم ← التسليم ← التحصيل + إشعار القبض

**SCR-009 (`/orders/:id/deliver`) + SCR-030 (`/collect` ب`?source=order:<id>|sale:<id>`)** · عقد D5: لا تسليم بنقرة واحدة — سطح كامل قبل الالتزام؛ التحصيل عبر ورقة واعية بالمصدر · القوالب: TPL-B (متغير «قبل الالتزام») + TPL-C متغير إيصال (نتيجتا التسليم والقبض) · المقاسات: 360×800 / 390×844 / 430×932 · **قائم بالكامل** — يرسم `DeliveryReview.tsx` + `Collect.tsx` عند BASE_SHA؛ زر «إشعار القبض» الإضافي على نتيجة التحصيل **PROPOSED (W4-DEC-A-أ)**.

## (د) نتيجة القبض + إشعار القبض (عقد 33 — من حدث محفوظ قائم فقط)

> مثال (د) لذمة **مصدرها طلب** («صندوق خشبي مخصص» لسارة خالد) — لو كان المصدر بيعًا مباشرًا (مثال ج) لما ظهر زر الإشعار أصلًا (قاعدة 2 أدناه).

```
│  ورقة تحصيل · انسجّل القبض                     │ ← overline طور النتيجة
│  قبضت من سارة خالد                             │ ← H1
│  ▐ نتيجة التحصيل ▌                             │
│  │ المبلغ المقبوض              35.00 د.أ       │
│  │ الباقي على سارة خالد: صفر — الذمة سُدّت       │ ← أو «الباقي…
│  │ بالكامل.                                     │   الديون مستمرة»
│  │ انتقل إلى «الدرج»: 35.00 د.أ — حركة موثقة    │ ← أو «بقي الكاش غير
│  │ في دفتر المحفظة.                             │   موزع — وزّعه…»
│  │ (وجهة المحفظة لم تُنفّذ: … — إن فشل التخصيص)  │ ← إفصاح لا كذب
│  │ بياناتك محفوظة على هذا الجهاز…               │
│  [ 🧾 افتح السجل ]   [ تم ]                     │ ← البيع→تفاصيله؛
│                                                │   الطلب→تفاصيله
│  [ 📤 شارك إشعار القبض ]                       │ ← **PROPOSED
│                                                │   (W4-DEC-A-أ)**:
```

**قواعد زر إشعار القبض (PROPOSED — يبنى على عقد 33 §2.6/§7 كما هو):**
1. يظهر فقط إذا كان مصدر الذمة **طلبًا** وفيه قبض قائم (`collection_recorded`/`deposit_collected` محفوظ غير معكوس كاملًا) — المبلغ والتاريخ من الحدث نفسه والمتبقي من السجل الحي؛ لا مسودة من حقول النموذج بعد الحفظ.
2. مصدره بيع مباشر أو بلا قبض قائم: **لا زر** (تحصيل البيع يُشارك من مساره عند تقرير توسيع العقد — انظر WF-027).
3. التحصيل المعكوس كاملًا يسقط الإشعار إلى تذكير الذمة الصادق (§7.8) — المنطق في `customerShareDraft` القائم.
4. النقر يفتح SCR-052 (معاينة-تعديل-إرسال) ب`returnTo=/collect?source=…` — لا إرسال مباشر من هنا أبدًا.

## قائمة التحقق

- **العنوان:** «مراجعة التسليم» / «حصّل من مين عليه إلَي» / نتيجتان: «تم تسليم الطلب بنجاح» و«قبضت من {اسم}» — الأسماء الحرفية من الكود.
- **السياق/الملخص:** رحلة إغلاق الطلب: راجع كل الأثر (مال/مخزون/قبض) قبل التزام واحد ذرّي، ثم حصّل المتبقي بورقة واعية بالذمة — التحصيل لا يعيد فتح الطلب.
- **CTA الأساسي:** «أكّد التسليم» (commit — أعلى صنف في التطبيق) ثم «سجّل القبض» (save). «رجوع بلا تسليم» ثانوي صريح لا زر رجوع هامشي.
- **الثانويات:** خيارات النقص لكل مادة؛ خيارات متقدمة (تعديل سعر بسببه + قبض عند التسليم بوجهة)؛ تعبئة كامل/نصف المتبقي؛ «افتح السجل» من النتيجتين؛ «شارك إشعار القبض» (PROPOSED).
- **فوق الطية:** مراجعة التسليم: شبكة المال كاملة + سطر الحقيقة؛ التحصيل: الذمة المختارة + حقل المبلغ + معاينة الأثر.
- **الحالات عند اختلافها عن القالب:** «جارٍ تحضير المراجعة…»؛ «جارٍ قراءة الديون القابلة للتحصيل…»؛ «تعذر فتح ورقة التحصيل» بلا نموذج فارغ؛ المقبوض يتجاوز المتبقي: تحذير داخل المعاينة + رسالة تحقق («حصّل المتبقي أو أقل منه»)؛ فراغ الديون الصادق؛ نجاح التحصيل لا يُطمس بإعادة قراءة (doneRef).
- **الرجوع:** مراجعة التسليم → تفاصيل الطلب (`/orders/:id` محفوظة)؛ التحصيل → `returnTo` (البديل `/`)؛ النتيجتان لا تحرسان خروجًا (الوسخ يسقط بالنجاح).
- **الرسائل والتأكيدات:** أخطاء التحقيق inline تحت الحقل/النموذج role=alert؛ الإشعار التحذيري للتسليم role=status؛ لا حوارات إضافية — الالتزام نفسه هو نقطة اللاعودة المعلنة بسطر الحقيقة أعلاه.
- **ما خلف الإفصاح:** خيارات متقدمة للتسليم؛ بنود تكلفة بلا مواد مخزون؛ سلوك النقص التفصيلي؛ (في التحصيم: لا شيء — نموذج قصير عمدًا).
- **ملاحظات المقاسات:** **360×800:** شبكة المال 6 خانات تنزل 2×3 دون 380px؛ صفوف المخزون عمودًا واحدًا؛ معاينة الأثر أرقام LTR لا تنكسر. **390×844:** الأساس المرسوم. **430×932:** بطاقات المراجعة ≤640px؛ زر commit يبقى لاصقًا أسفل حيث الإبهام؛ لوحة النقص لا ترفع الحقول (قانون عدم الاهتزاز).
