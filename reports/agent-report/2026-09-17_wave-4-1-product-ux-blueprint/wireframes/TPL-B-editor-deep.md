# TPL-B — محرر عميق (Deep Editor)

**يستخدم لـ:** كل مسار يخفي الشريط السفلي **عمدًا** (`deepFlowPatterns` في `routeClassifier.ts`): محررات البيع المباشر، مسودة الطلب والاتفاق والتكلفة، محرر الأحداث المالية، السحب، ورقة التحصيل، عمليات الكاش، المواد وحركات المخزون، المواعيد، الحاسبة والتقدير، مراجعة التسليم، الأصل والقرض، معاينة المشاركة — والتأسيس بمتغير الخطوات.
**القاعدة الحاكمة (U-005):** «القارئ سطح، والمحرر عمق» — نفس الرحلة قد تمر بالحالتين.

## الهيكل العام (390×844)

```
┌──────────────────────────────────────────────┐
│ ◆ مايكرو · التسمية السياقية    [🚚][💬][⚙][☾]│ ← الترويسة تبقى (مخرج آمن)
├──────────────────────────────────────────────┤
│  [→ رجوع إلى المصدر] (زر نصي 44px)            │ ← returnTo القانوني
│  OVERLINE (12px)                              │
│  H1 فعل واضح (28px): «سجّل بيعًا مباشرًا»      │
│  سطر سياق: ماذا سيحدث عند الحفظ               │
│                                              │
│  ▐ بطاقة قرار/تحذير عند الحاجة ▌              │
│                                              │
│  ┌── بطاقة نموذج ──────────────────────────┐ │
│  │ تسمية الحقل (14px/600) + مؤهل (12px)     │ │
│  │ [ حقل/منتقي 48px            ]            │ │
│  │ …                                        │ │
│  └──────────────────────────────────────────┘ │
│  ▸ كشف تدريجي: خيارات متقدمة/ربط اختياري      │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ ▌ تذييل الحفظ اللاصق ▌                   │ │ ← يبقى فوق الكيبورد
│ │ [  احفظ (create/save/commit)  ]           │ │
│ └──────────────────────────────────────────┘ │
│         (لا شريط سفلي — الكروم مخفي عمدًا)     │
└──────────────────────────────────────────────┘
```

## القواعد الملزمة

1. **الرجوع:** زر نصي أعلى المحتوى يعود إلى `returnTo` (عقد 26 — لا `history.back()`)، بتسمية المصدر («مشروعي الآن»/«المالية») لا «رجوع» العمائم. غياب `returnTo` = البديل الكنوني.
2. **حارس المسودة:** الخروج بمدخل مكتوب يفتح حوار التغييرات غير المحفوظة (TPL-E). لوحة المفاتيح لا تخفي زر الحفظ: التذييل اللاصق + إخفاء الكروم عند فتح الكيبورد (`data-keyboard-open`).
3. **الحقول:** ارتفاع 48px؛ تسمية ≥13px والمؤهل داخلها («بالدينار الأردني»، «اتركه فارغًا إذا قبضت كامل السعر»). حقول المال والكميات: أرقام إنجليزية فقط، `direction: ltr` معزولة، خط أرقام أحادي، `inputMode=decimal`.
4. **الخطأ:** نص inline تحت الحقل بحبر الخطأ (13px) + حد أحمر للحقل؛ لا يخفى بالتمرير ولا بالكيبورد؛ يقال الشرط بلغة المستخدم («المقبوض لا يتجاوز السعر المتفق»).
5. **الحفظ:** زر أساسي واحد بصنف الملاءمة (create للإنشاء الجديد، save للاعتيادي، commit للالتزام عالي الأثر). أثناء الحفظ: «جارٍ الحفظ…» + الزر معطّل (منع الإرسال المزدوج). النجاح يفتح شاشة/لافتة نتيجة تشرح الأثر (ما سُجّل، أين ذهب المال، الفعل التالي) — لا إعادة تحميل فوق النتيجة.
6. **الإفصاح التدريجي:** الحقول التي لا تغير القرار خلف «خيارات متقدمة»/details — لا نموذج طويل مكتمل الظهور.
7. **التواريخ:** DD/MM/YYYY بلا أسماء شهور كلمية؛ الافتراضي اليوم وقابل للتعديل.

## قائمة فحص الحالات

| الحالة | الشكل |
|---|---|
| Loading | لوحة قصيرة «جارٍ تجهيز النموذج…» |
| Error قراءة المصدر | بطاقة خطأ بالاسم («تعذر قراءة محافظ الكاش») + إعادة محاولة — لا نموذج فارغ يوهم الضياع |
| Error تحقق | inline تحت الحقل |
| Saving | زر معطّل + «جارٍ الحفظ…» |
| Success | شاشة نتيجة/لافتة تشرح الأثر + الفعل التالي |
| Unsaved | حوار التغييرات غير المحفوظة (TPL-E): البقاء أولًا، التدميري مفصول أخيرًا |
| Draft-restored | مسودة محلية تُعرض كعرض صريح («استعدها وأكمل / ابدأ من جديد») لا تطبيق صامت |

## قواعد المقاسات الثلاثة

- **360×800:** عمود واحد إجباري؛ الحقول المزدوجة (كمية/سعر) تنزل عمودًا؛ التذييل اللاصق بعرض كامل.
- **390×844:** الأساس.
- **430×932:** بطاقة النموذج ≤640px فلا يطول وصول الإبهام للحقول العليا؛ الحقول الحرجة (مبلغ/قبض) تبقى في النصف السفلي حيث أمكن.
