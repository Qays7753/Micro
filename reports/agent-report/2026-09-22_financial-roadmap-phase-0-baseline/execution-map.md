## Wave 1 technical plan (WS-173 — FIN-003/FIN-007)

**Layer discipline:** all financial math in application/domain layers; React only renders view models; no page/component touches `@/storage/local/*` or localStorage; no new Writer is introduced (read-only capability); ESLint guards enforce boundaries.

1. **Period presets + partial marker (FIN-007):** extend the period-selection surface with preset family (this-week/this-month/this-quarter/custom; previous-period variants derive via shortcut) + quarter preset (currently missing); a period containing "today" (Amman) is marked partial/incomplete in the reading header — comparison involving it is qualified, never silently treated as completed. Presets never forced: custom range always available.
2. **Comparison reader (FIN-003):** new pure application module (e.g. `application/finance/periodComparisonService.ts`) that composes two `readRecordedPeriodResult` calls (canonical reader — no second math path) into a comparison view model: per-line deltas (revenue, direct cost, project/shared/legacy expenses, non-cash lines, result), excluded-count/reasons for each side, statuses per side, and honest comparison state (if either side `incomplete`/`invalid` or partial → comparison carries that status with reasons; empty periods handled; invalid ranges rejected).
3. **Previous-equal-period shortcut:** derives the immediately preceding period of equal length ending the day before `from` (local Amman inclusive arithmetic), used only as a selection convenience — it produces the same comparison as manually selecting those dates.
4. **Profit→cash bridge (FIN-003):** numeric, source-traceable bridge from recorded period result to recorded cash delta over the same period: result + non-cash items (depreciation/write-off/disposal deltas) ± receivables/payables deltas (operating/material split) ± owner capital/withdrawal ± amanah ± outgoing-loan principal flows ± retained-deposit movements = cash delta; every line carries its source; missing knowledge stays `incomplete`, never zero-filled; incoming loans line honestly zero/absent until FIN-001. Composed from existing canonical reads (`readPosition`, events) — no new store, no writes.
5. **Surface wiring (minimum functional):** extend existing period surfaces (Statement/Finance) to expose presets, comparison, and bridge without visual redesign and without UX-001 work; density caps respected (documented per-entry like FinanceMore 37→39 precedent).
6. **Tests (focused only):** comparison math incl. empty/invalid/partial periods; Amman month-boundary & DST-free local-date arithmetic; previous-equal-period derivation; bridge balances to recorded cash delta with traceable lines; no-write proof (full-store deep-equality before/after reads); excluded-final visibility both sides; statuses propagation.

**Rollback boundary for Wave 1:** the last verified `main` SHA immediately before the wave branch (recorded in the claim's `base_sha` at implementation time). Revert = single revert of the squash merge; no history rewrite.

## Sub-agent team (per wave, one shared objective, no conflicting writers)

- **Contract & Tracker auditor** (read-only): reconcile wave scope vs contracts vs live code before code (done for Phase 0; refreshed per wave).
- **Domain/application implementer:** pure calculations + use cases; financial invariants; zero financial rules in React.
- **Storage/export integrity implementer:** only for waves that touch persistence (2, 6, 7-field changes): migrations, round-trip, reject-before-write, idempotency, touchpoint registration.
- **Test/CI/quality agent:** focused tests for changed behavior; secrets/test-focus/entity-touchpoints/budgets checks; regression scope.
- **Independent reviewer & report synthesizer:** final wave diff vs acceptance matrix; evidence honesty; wave report.

Only the coordinator (or one explicitly assigned writer) mutates the shared implementation branch at a time. Parallel agents are read-only. Every agent reads `AGENTS.md` + the wave's governing contracts before work.
