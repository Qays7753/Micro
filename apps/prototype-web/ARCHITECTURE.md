# معمارية Web App لـMicro Prototype

> حدث هذا الملف مع دمج إعادة تصميم التدفق المالي (8ede6b2، 2026-08-31) وتصحيحات Phase-1؛
> المصدر المعتمد الموحد للسلوك النهائي هو `docs/product-source-of-truth.md`، والسجل التشغيلي الحي
> هو `docs/operations/current-state.md`. أرقام الإصدارات هنا حالية لا تاريخية.

## نطاق الحزمة الحالي

تحتوي هذه الحزمة Web UI للـPrototype المالي والتشغيلي الكامل: النواة المالية (دخل/خرج/كاش/أحداث
مالية ومراجعاتها)، المحافظ وتخصيص الكاش غير الموزع وعدّ الصندوق، الأمانات (Amanah)، الطلبات
الحرفية بمسوداتها واتفاقاتها وتسليمها وتحصيلها، البيع المباشر (نقدي/آجل بزبون مستقل)، مشتريات
الموردين، المواد وحركات المخزون المؤرخة، الكتالوج المرجعي، حق المالك (O1)، قراءات الفترة (G3)
والتعادل (G5)، الوقت الفعلي والهامش (G4-B)، دفتر الأطراف (تجميع اسمي)، و«أدواتي / My Tools»
وجهة مستقلة تضم حاسبة التكلفة كأداة تقدير غير مالية. تعمل الحزمة كـPWA مثبتة (registerType:
prompt) عبر `vite-plugin-pwa`. لا تنفذ Cloud Sync أو Auth أو SaaS أو تعدد مستخدمين.

## مسار المسؤولية

```text
React UI
  → Application services (31 خدمة عبر 25 مجلدًا — G6-R5-9)
  → Micro Domain Core في ../../src/domain (11 وحدة نطاقية + معينات shared)
  → LocalStore port (PrototypeLocalStore)
  → IndexedDB adapter (IndexedDbLocalStore — 27 مخزن كائنات، مخطط 30)
```

لا تستورد مكونات React `IndexedDbLocalStore` ولا تضع قواعد المال فيها. كل مال/كمية يمر عبر
المدخلات الرقمية الموحدة (`EnglishNumberInput`/`EnglishQuantityInput` — أرقام ASCII/LTR،
المال بمقياس 1/100 دينار، الكمية بالملي 1/1000) والمنسقات المشتركة (`presentation/formatters.ts`
و`presentation/cashCountMessages.ts` لنصوص العدّ). `LocalTransferService` يقرأ ويحلل ويتحقق
من ملف النقل، ثم يستدعي LocalStore فقط بعد تأكيد صريح من المستخدم؛ تصديره المُتحقق يعيد دورة
كاملة (تصدير → استيراد → تحقق) قبل إعلان جهوزية النسخة.

## ما يحفظه Prototype محليًا

الملف الشخصي، التفضيلات، المسودات، الطلبات (`StoredCraftOrder`)، المبيعات المباشرة، الأحداث
المالية، محافظ الكاش وقيود استمراريته، مشتريات الموردين، المواد وحركات المخزون وتفعيله المؤرخ،
عناصر الكتالوج ووحداته وتحولاته وقوالبه، الوقت الفعلي، إعلانات G5، سجلات حق المالك، سياسات
التخصيص، والتقديرات المستقلة (`CostEstimate`). ربط المسودة بالطلب وحفظهما يتم عبر
transaction واحدة في IndexedDB، حتى لا ينجح أحد السجلين منفردًا.

يستخدم Adapter إصدار مخطط IndexedDB صريحًا `schemaVersion = 30` وصيغة تصدير `version = 22`
(`micro-prototype-local-export`؛ رُقّيا مع مخزن ملف المالك في aa78757 — المجموعة ١). المبيعات
المباشرة تحمل حقل زبون مستقلًا اختياريًا (`customerName`) بلا مخزن/فهرس جديد، فتتقاطع ملفات
النسخ السابقة المقبولة والجديدة سليمًا في الاتجاهين.
لا تغير أي مسار نسخة تكلفة أو حدثًا تاريخيًا بصمت.

## قواعد السعر والتنفيذ والنتيجة

سعر الحماية ناتج من Domain ويمثل تكلفة القطعة مع هامش الحماية المدخل، لا سعر سوق ولا ربح ولا
قرار قبول. العربون كاش محصل لا ربح تلقائي ولا تسليم. الدين لا يزيد الكاش؛ التحصيل ليس ربحًا؛
الأمانة مال موجود ماديًا لكنه ليس رأس مال النشاط ولا إيراده ولا ربحه. حارس الاستيراد يقبل كل
سلوك تنتجه الوحدة (القبض الكامل/الجزئي، مراجعات التعديل/الإلغاء/تخفيض السعر الموثق) بشرط بنيوي:
المقبوض لا يتجاوز المتفق.

## Export/Import المحلي

ينشئ التصدير ملف JSON محليًا بالصيغة `micro-prototype-local-export` مع `version` و`schemaVersion`
ووقت التصدير وSnapshot كامل للمخازن أعلاه. لا يحتوي أسرارًا أو مفاتيح، ولا يمثل Backup سحابيًا
أو مزامنة. عند الاستيراد، يقرأ التطبيق الملف دون كتابة، ثم يتحقق من الصيغة والإصدارات (تُقبل
إصدارات الموجات السابقة وتُهاجر) والتواريخ والحقول والعلاقات، ويعرض ملخصًا قبل التأكيد؛ بعد
التأكيد فقط ينفذ `replaceSnapshot` داخل transaction واحدة. الملف التالف أو الناقص أو غير المدعوم
لا يلمس البيانات الحالية. تغطي الاختبارات round-trip كاملًا لبيع آجل بزبون مستقل ولبيع بخفض
سعر موثق وملفات تالفة/جزئية وغير مدعومة واستبدال سجلات قائمة.

## أدوات التطوير

أدوات بيئة التوليد ليست جزءًا من المنتج: تُخزّن خارج `public/` في `dev-tools/` وتُقدّم في التطوير
فقط عبر وسطاء خادم Vite (`devOnlyPlugins`، و`MICRO_DEV_TOOLS=0` يعطلها في التطوير أيضًا)، ولا
تدخل أي بناء إنتاجي.

## حدود لا تتغير

لا توجد Cloud Sync أو Workspace أو Auth أو صلاحيات أو تعدد مستخدمين. لا يوصف الحفظ بأنه نسخة
سحابية أو Backup تلقائي — التصدير المُتحقق يدويًا هو بوابة أي إعادة تعيين أو تغيير جهاز. لا يوصف
Prototype بأنه جاهز تجاريًا أو محاسبيًا عامًا قبل الاختبارات الحقلية.
