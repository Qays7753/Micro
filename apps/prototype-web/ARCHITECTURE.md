# معمارية Web App لـMicro Prototype

## نطاق الحزمة الحالي

تحتوي هذه الحزمة Web UI للـPrototype. اكتملت فيها **Slice 0** للغلاف العربي RTL، و**Slice 1** للتأسيس والمسودة المحلية، و**Slice 2** لـSnapshot التكلفة وسعر الحماية، و**Slice 3** للاتفاق والعربون وبداية التنفيذ، و**Slice 4** للجاهزية والتسليم والتحصيل أو الدين ونتيجة الطلب. لا تنفذ هذه الحزمة بعد التصدير أو الاستيراد أو استعادة البيانات أو PWA أو Cloud Sync.

## مسار المسؤولية

```text
React UI
  → Application services / view state
  → Micro Domain Core في ../../src/domain/craft-order
  → LocalStore port
  → IndexedDB adapter + export/import محلي لاحقًا
```

لا تستورد مكونات React `IndexedDbLocalStore` ولا تضع قواعد مال فيها. `CostService` يستدعي `calculateCostSnapshot`، و`AgreementService` يستدعي `createCraftOrder` و`transitionOrder` و`collectDeposit`، و`FulfillmentService` يستدعي `transitionOrder` و`collectRemaining` و`registerDebt` من نقطة الدخول العامة لـDomain Core.

## ما يحفظه Prototype محليًا الآن

يحفظ التطبيق ملف النشاط، ومسودات قبل Domain، وتاريخ Snapshots تكلفة غير قابل للتعديل، و`StoredCraftOrder` عند تثبيت الاتفاق. يحمل سجل الطلب الموعد ومصدر الاتفاق بالإضافة إلى `CraftOrder` المجمّد. ربط المسودة بالطلب وحفظهما يتم عبر `commitOrderFromDraft` داخل transaction واحدة في IndexedDB، حتى لا ينجح أحد السجلين منفردًا.

يستخدم Adapter إصدار مخطط IndexedDB صريحًا `schemaVersion = 4`. ينقل migration المسودات السابقة بإضافة تاريخ Snapshots ومعرّف الاتفاق الفارغ، ويضيف مخزن الطلبات المحلي. Export/Import والتحقق الذري عند الاستيراد وإعادة الضبط الآمنة لا تزال نطاق **Slice 5**.

## قواعد السعر والاتفاق

سعر الحماية ناتج من Domain ويمثل تكلفة القطعة مع هامش الحماية المدخل، لا سعر سوق ولا ربح ولا قرار قبول. يمكن أن يكون السعر المتفق عليه أدنى منه، لكن الواجهة تطلب تأكيدًا نصيًا صريحًا قبل التثبيت. لا يجعل ذلك التكلفة أو النتيجة نهائية تلقائيًا.

العربون المسجل عبر `collectDeposit` هو كاش محصل مرتبط بهذا الطلب؛ لا يصبح ربحًا، ولا يسجل تسليمًا، ولا يلغي المتبقي. منع الربط المكرر للمسودة يعيد الاتفاق المحفوظ بدل تكرار أحداث العربون أو الكاش.

## قواعد Slice 4

لا يمكن تسجيل الجاهزية إلا من `in_progress`، ولا التسليم إلا من `ready`. التسليم يعترف بالإيراد والتكلفة على مستوى الطلب وفق Domain، لكنه **لا** يزيد `collectedMinor`. بعد التسليم يصبح الفعلان المنفصلان هما تحصيل المتبقي عبر `collectRemaining` أو تسجيله دينًا عبر `registerDebt`؛ الدين يغيّر حالة التسوية ولا يزيد الكاش.

النتيجة الرقمية (`profitIndicatorMinor`) تظهر فقط عندما تكون `resultStatus = final`. عند تكلفة ناقصة أو متغيرة أو تحتاج مراجعة، تعرض الواجهة سبب الحجب وحقول الإيراد/التكلفة التي اعترف بها Domain دون ادعاء ربح نهائي. تعاد المحاولات الحساسة إلى الحالة المحفوظة ولا تضيف حدث قبض أو دين أو انتقال ثاني.

## حدود لا تتغير

لا توجد Cloud Sync أو Workspace أو Auth أو صلاحيات أو Service Worker أو PWA مكتمل. لا يوصف الحفظ بأنه نسخة سحابية أو Backup حتى تنفذ دورة الحماية المحلية واختباراتها. لا يوصف Prototype بأنه جاهز تجاريًا أو محاسبيًا عامًا قبل استكمال المسار والاختبارات الحقلية.
