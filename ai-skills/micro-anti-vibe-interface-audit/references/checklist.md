# قائمة تدقيق قصيرة

## مصدر القرار

| السؤال | علامة الفشل |
| --- | --- |
| هل للشاشة فعل أساسي واحد أو رقم واحد واضح؟ | كل العناوين والبطاقات متساوية الوزن. |
| هل لكل رقم معنى ونطاق ومعرفة؟ | رقم مزخرف أو label فضفاض مثل «الإجمالي». |
| هل كل بطاقة إدخال أو حالة أو فعل بوضوح؟ | بطاقة ثابتة تشبه input، أو card قابل للنقر لا يبدو زرًا. |
| هل النص يصف واقع المستخدم لا فلسفة المنتج؟ | «لنرتب»، «لا تقلق»، «الفهم قبل الرقم» يحل محل معلومة أو فعل. |
| هل اللون يؤدي معنى واحدًا؟ | لون الهوية نفسه للزر والحالة والتحذير والوسم الثابت. |

## إشارات التصميم المولد التي تتطلب تدقيقًا

1. surface مستدير وظل خفيف لكل عنصر بلا فرق وظيفي.
2. صورة أو texture أو icon tile يلفت الانتباه قبل المهمة.
3. ثلاث بطاقات معلوماتية ملونة متجاورة بلا اختلاف في القرار أو الأولوية.
4. CTA صغير أسفل شرح طويل أو فعل أساسي مخفي خلف scroll.
5. لغة مطمئنة متكررة بدل مصطلح مالي صحيح ومحدد.
6. رقم يعرض عملة/موقعًا/دقة بطريقة متعارضة مع العقد أو لا توضح مصدره.
7. عدم وجود focus أو pressed أو سبب لحالة disabled.

## مراجع مهنية

- NN/g، [Visual Hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/): استخدم اللون والحجم والتجميع لتوجيه الانتباه نحو الأهم، لا لتلوين كل سطح.
- MDN، [`inputmode`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/inputmode): اعتبره تلميح لوحة مفاتيح فقط، لا تحققًا للرقم.
- Boldare، [Design system for vibe coding teams](https://www.boldare.com/blog/vibe-coding-design-system/): افهم التوكنات ووثائق المكونات وبوابات المراجعة كممارسات قابلة للتكييف، لا كمعيار ملزم.
