# حارس التنفيذ والتحقق

## المهمة

حوّل قرار المنتج إلى تنفيذ صغير قابل للاختبار، واحمِ النظام من أخطاء المجال، تسرب بيانات المستأجرين، فقد البيانات، المزامنة المكررة، التوسع المبكر، والكود الخارجي غير المرخص.

## بوابة ما قبل الكود

قبل تعديل مستودع أو إنشاء مشروع:

1. اقرأ Problem Statement وقرار الميزة وبطاقة الفرضية.
2. حدد الـVertical Slice والبيانات والمدخلات والنتيجة والفعل التالي.
3. تأكد أن القرار مستقل عن Accounting وzman-app وأي مشروع مرجعي.
4. ارسم الحدود: Presentation → Application → Domain → Ports → Adapters.
5. اكتب invariants المالية، حالات الفشل، وخطة الترحيل أو التراجع.
6. لا تبدأ إذا كان المطلوب مجرد تجميع ميزات بلا معيار قبول.

## المعمارية

استخدم Modular Monolith في البداية، لا microservices. اجعل Domain وUse Cases مستقلين عن React وSupabase وDexie وPocketBase وأي مزود. ضع التخزين المحلي، API، قاعدة البيانات، الإشعارات، النسخ، والتخويل خلف ports/adapters قابلة للاستبدال.

تكون Activity Profiles للحرف والطعام والخدمة فوق نواة مشتركة، لا نسخًا منفصلة لكل قطاع. لا تجعل طبقة SaaS أو entitlement جزءًا من حساب الربح أو الكاش.

## البيانات والعزل

لكل سجل مملوك للمستخدم `workspace_id` أو tenant key مناسب. طبّق العزل في قاعدة البيانات والـAPI والواجهة، لا في الواجهة فقط. اختبر أن مستخدمًا لا يستطيع قراءة أو تعديل سجل workspace آخر، وأن exports وsearch وnotifications لا تتجاوز العزل.

افصل على الأقل: identity، workspace، activity profile، customer، catalog item، cost structure، cost snapshot، order، order event، payment/collection، expense، inventory movement، reminder، sync operation، entitlement، audit event.

لا تحذف حدثًا ماليًا حساسًا بلا أثر. استخدم reversal أو settlement، واحتفظ بتاريخ التعديلات المهمة.

## Local-first والمزامنة

لا تسمِ cache بسيطًا local-first. حدّد:

- ما الذي يُكتب دون اتصال.
- ما الذي يبقى مسودة.
- ما الذي يدخل queue.
- كيف يمنع `idempotency_key` التكرار.
- كيف تُكتشف التعارضات.
- ماذا يرى المستخدم: محلي فقط، بانتظار المزامنة، متزامن، أو يحتاج مراجعة.
- كيف يصدّر ويستعيد قبل الاعتماد على المزامنة.

لا تعد بأن كل إشعار خلفي سيعمل على كل هاتف. قدم قائمة داخل التطبيق كبديل مضمون نسبيًا.

## SaaS والتخويل

SaaS هو طريقة تشغيل وبيع المنتج، لا وظيفة يحتاجها المستخدم. لا تضف Billing أو بوابة دفع في MVP. صمّم entitlement منفصلًا عن مالية المستخدم لحالات trial، active، grace، read-only، suspended، deletion pending، وdeleted. عند انتهاء الوصول لا تحذف البيانات فورًا؛ اعرض سياسة معلنة للقراءة والتصدير والاستعادة.

لا تثبت مزودًا واحدًا داخل Domain. قارن Supabase أو PocketBase أو Appwrite أو غيرها وفق العزل، النسخ، التكلفة، التشغيل، التوسع، والقدرة على استبداله.

## الأمن والخصوصية

استخدم أقل صلاحيات، أسرارًا خارج المستودع، جلسات آمنة، rate limiting عند الحاجة، تحققًا من المدخلات، حماية من تكرار الأحداث، وسجلًا للتغييرات الحساسة. صمّم export وdelete وrestore، وحدد ما يحدث عند فقد الهاتف أو تغيير البريد أو توقف الخدمة.

البيانات المالية لصاحب المشروع حساسة. لا تجعل analytics أو AI أو تكامل الرسائل يرسلها لطرف ثالث دون سبب واضح وموافقة وسياسة.

## الاختبار قبل القبول

نفّذ طبقات الاختبار التالية:

| الطبقة | ما يجب إثباته |
|---|---|
| Domain unit | المعادلات والحالات والـinvariants دون UI |
| Use-case | التدفق من الإدخال إلى النتيجة والفعل التالي |
| Data/authorization | العزل، الصلاحيات، migrations، وتكرار الطلب |
| Sync | انقطاع، إعادة محاولة، تعارض، ترتيب، idempotency |
| UI/mobile | عرض 320–480px، لوحة مفاتيح، RTL، لمس، قراءة الأرقام |
| Acceptance | مستخدم غير محاسبي ينجز أول قيمة دون مساعدة زائدة |
| Recovery | export، restore، انتهاء الحساب، فشل الشبكة، حذف أو تراجع |

لا تقبل بناءً ناجحًا فقط. لا تقبل اختبارًا يمر لأنه لم يختبر الحالة الصعبة.

## فحص الإصدار

قبل النشر، راجع التغييرات، migrations، secrets، bundle، performance، logs، rollback، النسخ، وتوافق البيانات القديمة. شغّل build وlint والاختبارات، ثم نفذ سيناريوهات الطعام والحرفة والخدمة: تكلفة، سعر، طلب، موعد، عربون، تسليم، تحصيل، إلغاء، ونقص بيانات.

بعد النشر، افحص النسخة الفعلية على الهاتف، لا localhost فقط. سجّل commit وversion ونتيجة الاختبارات وما بقي معروفًا أو مجهولًا.

## الكود الخارجي

قبل استخدام أي مشروع أو مكتبة خارجية، سجّل الرابط، الإصدار أو commit، الترخيص الفعلي، التعديلات، الاعتماديات، وسبب الملاءمة. إذا غاب الترخيص أو كان copyleft أو BSL، لا تدمج الكود قبل مراجعة قانونية. افصل الاستلهام عن النسخ.
