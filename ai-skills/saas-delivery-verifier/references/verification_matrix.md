# مصفوفة التحقق

| المستوى | أسئلة القبول |
|---|---|
| Problem | هل يعالج الإصدار سؤالًا موثقًا؟ |
| Domain | هل تصحح المعادلات والحالات والsnapshots؟ |
| Data | هل schema وmigration تحفظان التاريخ ولا تفقدان البيانات؟ |
| Authorization | هل يعزل كل workspace عن الآخر؟ |
| Sync | هل الانقطاع وإعادة المحاولة والتعارض واضحة ولا تكرر الأثر؟ |
| UX | هل يبدأ المستخدم دون محاسبة، ويفهم النتيجة والفعل التالي؟ |
| Mobile | هل يعمل بلمس وRTL وعرض 320–480px؟ |
| Notifications | هل تقود الرسالة إلى فعل، وهل البديل داخل التطبيق موجود؟ |
| Recovery | هل export وrestore وانتهاء الحساب واختفاء الشبكة مختبرة؟ |
| Ops | هل logs وhealth وrollback والنسخ معروفة؟ |
| License | هل كل كود خارجي موثق ومرخص؟ |
| Pilot | هل قيس الإكمال والعودة والأخطاء، لا الإعجاب فقط؟ |

## بوابات الإصدار

### بوابة 0 — قرار

Problem Statement، بطاقة الفرضية، أقل نطاق، ومعيار الفشل مكتوبة.

### بوابة 1 — مجال

Domain unit tests تمر، والمال لا يخلط بين قبض وإيراد وربح ودين وسحب ومخزون.

### بوابة 2 — بيانات

migrations قابلة للتراجع أو الاستعادة، والعزل مختبر ببيانات مستخدمين مختلفين.

### بوابة 3 — تجربة

المستخدم ينجز أول قيمة ويرى درجة معرفة التكلفة والطلب والفعل التالي.

### بوابة 4 — تشغيل

هناك export، backup/restore، مراقبة، رسائل فشل، وخطة rollback.

### بوابة 5 — إطلاق

اختبارات الهاتف، offline، sync، accessibility، security، وacceptance مكتملة، مع تسجيل الإصدار والقيود.
