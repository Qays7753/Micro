# سياسة الكود الخارجي

## سجل المصدر

لكل مكتبة أو snippet أو مشروع سجّل الاسم، الرابط، الإصدار أو commit، تاريخ الفحص، الترخيص، الملفات المستخدمة، التعديلات، الاعتماديات، سبب الملاءمة، والمخاطر.

## بوابة الترخيص

- MIT/Apache-2.0/BSD: افحص إشعارات الإسناد والاعتماديات والـNOTICE.
- GPL/AGPL: لا تشتق أو توزع مكونات قبل مراجعة قانونية وفهم أثر copyleft على المنتج.
- BSL أو شروط خاصة: اقرأ الاستخدام التجاري والنشر والـcloud clauses.
- No license/NOASSERTION: لا تنسخ؛ استخدم الفكرة العامة فقط.

## بوابة الجودة

لا يكفي الترخيص. افحص النشاط، releases، الاختبارات، security policy، الاعتماديات، breaking changes، حجم الكود، وتناسبه مع Problem Statement. كود صغير قابل للفهم أفضل من منصة كبيرة تحتاج تشغيلًا لا نملكه.

## قرار الاستفادة

صنّف المصدر إلى: فكرة، نمط UX، نمط Domain، مرجع معماري، primitive قابلة لإعادة التنفيذ، dependency معتمدة، أو رفض. لا تضع مشروعًا كاملًا داخل النواة بسبب تشابه README.

## إثبات الأصل

احفظ الرابط والنسخة في `THIRD_PARTY_NOTICES` عند الدمج، وأعد فحص التراخيص عند التحديث. افصل كودنا عن الكود copyleft أو غير الواضح بدل خلطه في نفس الملفات.
