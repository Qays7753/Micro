# دورة الطلب والتذكيرات

## الحقول الأساسية

الزبون، مصدر الاتفاق، المطلوب، الكمية، السعر، cost snapshot، موعد/نافذة التسليم أو الخدمة، العربون، المتبقي، الحالة، الأولوية، الملاحظات، الفعل التالي، وسجل الأحداث.

## الحالات

```text
مسودة → اتفاق مبدئي → مؤكد → قيد التنفيذ → جاهز → تم التسليم → تمت التسوية
```

مسارات جانبية: مؤجل، ملغى، لم يحضر، معلق بسبب مادة أو قدرة، ورفض/تسوية. لا تستخدم «مكتمل» لتغطية التسليم والتحصيل معًا.

## انتقالات آمنة

- تأكيد الطلب لا يقبض المال.
- تسجيل العربون لا ينشئ ربحًا نهائيًا.
- التسليم ينشئ أثرًا واضحًا وفق سياسة الاعتراف ولا يسجل قبضًا تلقائيًا.
- التسوية تغلق المتبقي أو تثبت الدين.
- الإلغاء يطلب سببًا ويعالج العربون والمواد والأثر المالي دون حذف صامت.
- تغيير الموعد يسجل event وسببًا ويعيد حساب التحذير إن لزم.

## مصدر الاتفاق

استخدم قيمًا مثل WhatsApp، اتصال، Instagram، زيارة، توصية، أو إدخال مباشر. احفظ نصًا مختصرًا أو ملاحظة للاتفاق بدل تخزين محادثة كاملة في MVP.

## القدرة والتذكير

قبل التأكيد، احسب تحذيرًا بسيطًا للموعد المتعارض أو الحمل المرتفع أو مادة ناقصة. لا تحظر القرار في البداية؛ سجل أن المستخدم تابع رغم التحذير.

أنواع التذكير: متابعة الاتفاق، شراء مادة، بدء التحضير، موعد قريب، التسليم اليوم، متأخر، تحصيل متبقٍ. يجب أن يفتح كل تذكير الطلب وفعلًا قابلًا للتنفيذ.

## الشاشة اليومية

اعرض «اليوم»، «القادم»، «المتأخر»، و«يحتاج إجراء». لا تبدأ بتقويم كثيف؛ القائمة والفعل التالي هما الأساس، والتقويم دعم بصري.
