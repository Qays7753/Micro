## المعادلات

استخدم أصغر وحدة نقدية أو decimal، وثبت rounding:

```text
normalized_unit_price = source_price / conversion_factor
material_cost = Σ(quantity × normalized_unit_price)
planned_cost = materials + labor + packaging + delivery + waste + allocated_overhead
unit_cost = planned_or_actual_cost / yield
margin_amount = recognized_revenue - recognized_cost - applicable_expenses
margin_rate = margin_amount / recognized_revenue
price_from_margin = unit_cost / (1 - target_margin)
```

ارفض القسمة على صفر والسعر السالب والوحدة غير القابلة للتحويل. اعرض العملة والوحدة دائمًا.

## صدق النتائج

لا تستخدم نتيجة الربح النهائي إلا إذا كانت البنود المؤثرة معروفة أو معلنة كتقديرية. اعرض السبب الناقص: وقت، هدر، تغليف، توصيل، مصروف مشترك، أو مادة. لا تملأ الناقص بصفر بصمت.

## التاريخ

كل snapshot يسجل المدخلات، أسعار المواد، الوقت، التخصيص، التاريخ، الإصدار، والمستخدم. إعادة الحساب التاريخي عملية صريحة وليست أثرًا جانبيًا لتعديل السعر الحالي.

## Invariants

- `cash_balance = opening_cash + cash_in - cash_out` وفق الأحداث المعتمدة.
- العربون لا يظهر ربحًا نهائيًا قبل سياسة التسليم/التسوية.
- الدين لا يزيد الكاش.
- السحب لا ينقص ربح التشغيل إلا إذا كانت سياسة المنتج تنص صراحة على غير ذلك.
- إعادة إرسال الحدث نفسه لا تكرر الأثر المالي.
- حذف واجهة أو سجل لا يحذف تاريخًا ماليًا حساسًا بلا audit/reversal.
