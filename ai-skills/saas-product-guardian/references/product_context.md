# سياق المنتج

## هوية المنتج

Micro خدمة SaaS لنظام إدارة مالية وتشغيلية عملي يملكها ويشغلها مالك المنتج، ويستخدمها صاحب مشروع منزلي أو متناهٍ في الصغر أو صغير. النظام قوي ماليًا ومحاسبيًا في الداخل، لكنه يقدم للمستخدم تجربة عملية ومفهومة تبدأ من واقعة أو سؤال أو قرار، لا من مخطط حسابات. لا يحتوي MVP على بوابة دفع اشتراك داخل تطبيق المستخدم.

السوق الأول الأردن والدينار الأردني، والفئات الأولى الحرف اليدوية والأطعمة المنزلية والخدمات. الهاتف هو الجهاز الأساسي. الحرفة اليدوية المخصصة هي أول Vertical Slice لإثبات النواة، وليست تعريف المنتج النهائي.

## Problem Statement

صاحب المشروع يدير مبيعات وطلبات ومخزونًا ومصاريف وكاشًا وديونًا واستثمارات وسحوبات، لكنه لا يملك صورة مالية مترابطة ومفهومة تساعده على معرفة ما يملك وما له وما عليه، وتكلفة ما يبيع، وربحه أو خسارته، ونقطة تعادله، وأسباب النتيجة، والقرار التالي. تتوزع الأحداث بين الذاكرة والدفتر والرسائل والمشتريات والوقت، وتبقى بعض التكاليف أو الالتزامات ناقصة أو مختلطة، فيسعر أو يشتري أو يسحب أو يستمر دون صورة كافية.

## Product Goal

تمكين المستخدم من تسجيل ما يحدث بأقل جهد، وفهم أثره على التكلفة والمبيعات والمخزون والربح والكاش والذمم، ثم مراجعة وضع المشروع واتخاذ فعل عملي مناسب بدرجة صدق تتوافق مع البيانات المتاحة. لا يتطلب ذلك أن يتعلم المستخدم المحاسبة أو أن يرى التعقيد الداخلي للنظام.

## الصورة التي يجب أن يقدمها النظام

ما أملك، وما لي، وما علي، وكم ربحت أو خسرت منذ البداية أو خلال فترة، وما تكلفة المنتج أو الطلب، وما الأكثر مبيعًا والأكثر ربحًا والأكثر خسارة، وأين تذهب الأموال، وهل أستطيع الاستمرار، وما القرار التالي.

## السلسلة الأساسية

```text
حدث في المشروع
→ تسجيل بسيط
→ تصنيف ومعالجة مالية داخلية
→ تحديث التكلفة/المبيعات/المخزون/الكاش/الذمم
→ نتيجة مع درجة معرفة
→ تفسير السبب أو التنبيه
→ فعل تالٍ
```

وفي مسار الحرفة الأولى:

```text
طلب مخصص → مواد ووقت وتغليف وتوصيل → نسخة تكلفة → سعر حماية
→ اتفاق وعربون → تنفيذ واستهلاك → تسليم وتحصيل
→ نتيجة الطلب وصورة المشروع
```

## قواعد الحقيقة

- القبض ليس الربح، والعربون ليس ربحًا نهائيًا، والدين ليس كاشًا محصلًا.
- شراء المخزون ليس تكلفة بيع كاملة لحظة الشراء، والسحب ليس مصروف تشغيل، والاستثمار ليس مبيعات.
- التكلفة الناقصة لا تساوي صفرًا، والرقم المقدر لا يعرض كأنه معروف.
- تغير السعر الحالي لا يغير النتائج التاريخية بصمت؛ استخدم snapshot أو version.
- الحرفة والطعام والخدمة Activity Profiles مختلفة فوق نواة مالية مشتركة.
- الطلب كيان مالي وتشغيلي يبدأ عند الاتفاق وله تكلفة وموعد وحالة وتحصل وأحداث.
- التقارير تفسر السبب وتبين الفترة والافتراضات، ولا تعرض أرقامًا مجردة مضللة.
- التوجيه داخل سير العمل قصير واختياري التوسع؛ Micro ليس منصة تعليمية.
- مجموعة السيناريوهات `docs/scenarios/scenario-test-set-v1.md` عائلة اختبار اصطناعية وليست دليلًا إحصائيًا للسوق.
- حالة SaaS منفصلة عن مالية المستخدم، وتشمل مستقبلًا trial/active/grace/read-only/suspended/deleted.
- `Accounting` و`zman-app` ومشاريع GitHub مراجع لا مصادر تعريف أو كود تلقائي.
